# Discord 봇

`Monkeybot`은 Discord 입력과 메시지 전송을 맡는다. 모집·권한·저장은 웹 내부 API의 공통 서비스를 사용한다.
MSM1의 모집 글 갱신과 웹 편성 연결을 참고하며, 일반/경매 모두 같은 `내 신청` 화면을 사용한다.

## 실행

`.env.example`을 `.env`로 복사하고 설정한다. 웹의 `BOT_INTERNAL_TOKEN`과 같은 32자 이상의 키가 필요하다.
`DISCORD_TOKEN`은 웹의 `DISCORD_BOT_TOKEN`과 같은 애플리케이션 봇이어야 한다.
`WEB_ORIGIN`은 참가자가 여는 공개 웹 주소이고 `BOT_API_URL`은 봇이 접근하는 웹 서버 주소다.
개발 서버만 사용할 때는 `BOT_API_URL=http://127.0.0.1:5173`으로 설정한다.
Discord Developer Portal에서 Server Members Intent를 활성화한다.

```sh
pnpm dev:bot
pnpm --filter @msm2/bot register:commands
```

명령 등록의 기본 대상은 `DISCORD_TEST_GUILD_ID`이며, 운영 전역 등록에는 `--global`을 명시한다.
기동 자체는 명령을 재등록하지 않는다. 등록할 때 토큰의 애플리케이션과 `DISCORD_APPLICATION_ID`를 대조한다.

## 사용자 흐름

- `/초기설정`: 첫 활성 시즌을 준비하고 계정·채널을 설정하는 웹 서버 관리로 이동한다.
- `/내전모집`: 제목·일정·팀 수·추가 대기 정원·하드 피어리스 설정으로 내전을 만든다. 방식은 웹에서 선택한다.
- `/내전목록`: 해당 서버의 웹 내전 목록을 연다.
- `/게시복구`: 실패 작업을 자동완성으로 골라 재처리한다. 전달 여부가 불명인 새 글은 기존 메시지 ID 또는 운영자의 글 부재 확인이 필요하다.
- 모집 글의 `내 신청`: 본인만 보이는 화면에서 계정·희망 포지션을 선택하고 제출한다. 수정·철회도 같은 화면에서 처리한다.
- 개인 입력 화면은 10분 뒤 만료된다. 재시작 후에도 공개 글에서 새 신청 화면을 열 수 있다.

## 게시·동기화

작업은 한 번에 하나씩 점유한다. Discord 요청은 점유 요청 시작부터 30초 안에 종료하도록 제한하고, 서버 점유는 90초다.
새 메시지 전송의 응답 유실은 전달 불명 상태로 보고한다. 성공 보고가 실패하면 전송을 반복하지 않고 같은 보고만 다시 보낸다.
429는 Discord가 안내한 대기 시간을 전달한다. 권한·채널 오류는 운영자 복구 대상으로 남긴다.
기존 글이 삭제된 경우도 `MESSAGE_MISSING`으로 보류한다. `/게시복구`에서 글 부재를 확인하면 저장된 메시지 ID를 비우고 새 생성 작업으로 처리한다.
엔트리는 확정된 팀 구성만 보여 주며 경기 진영이나 미확정 포지션을 추정하지 않는다.
확정 경기 라인업은 해당 BO 전체의 팀별 출전 명단을 게시한다. 일반 내전의 자동 확정과 경매 내전의 경기별 확정이 같은 작업을 사용한다.
ROFL 결과 저장 후 결과 채널에 실제 세트 결과·진영·챔피언·KDA와 시리즈 점수를 게시한다. 정정 전 결과 글을 정리한 뒤 새 결과를 게시한다.

참가 안내 DM은 웹 내전의 운영자가 `참가 안내 보내기`를 요청했을 때만 생성한다. 마감 후 진행 중인 내전의 선발자 중 실제 Discord 사용자가 대상이다.
같은 내전에서 같은 사람에게 이미 요청했다면 새 DM을 만들지 않는다. 새로 선발된 사람은 다음 요청 때 추가되며, 대기·철회자는 보내지 않는다.
수신 차단과 탈퇴는 실패로 남기고, DM 전송 응답 유실은 채널 정보와 함께 전달 불명으로 남긴다. `/게시복구`의 글없음확인은 DM 수신자에게 부재를 확인한 뒤 사용한다.
중단으로 DM 채널까지 확인할 수 없는 경우에는 메시지 ID 대조를 사용할 수 없으며, 수신자 부재 확인 후에만 새 발송을 허용한다.

Gateway 이벤트는 짧게 모아서 동기화하며, 기동·재연결·5분 주기에는 서버와 알려진 서비스 멤버를 다시 확인한다.
일시 unavailable과 실제 퇴장을 구분한다. 전체 Discord 멤버를 무조건 DB로 수집하지 않는다.

`BOT_STATUS_PORT`의 `/status`는 loopback에만 열린다. `ready`는 Gateway와 최근 30초 이내의 내부 API 연결 상태를 함께 반영한다.
`gatewayReady`, `api`, `delivery`로 연결·게시 실패를 구분하며 토큰이나 메시지 본문은 반환하지 않는다.

## 검증

```sh
pnpm --filter @msm2/bot test
pnpm --filter @msm2/bot check:tests
pnpm build:bot
```

테스트는 주입한 API·Discord 응답을 사용한다. 이번 구현 검증에서는 실제 봇 로그인·명령 등록·메시지/DM 발송을 수행하지 않았다.
게시물은 Discord 네이티브 Components V2 카드이며 별도 결과 이미지 생성은 포함하지 않는다. 실제 서버 연동 검증은 지정 테스트 서버와 발송 범위를 정한 뒤 진행한다.
