# MMR 처리

소비자는 경기 상세의 처리 상태, 서버 홈·순위, 개인 전적·통계와 편성 후보 정보다.
`matches/results.ts`가 검증한 ROFL·완료 Game·확정 출전자 열 명을 저장한 뒤 같은 트랜잭션에서 호출한다. 경기 상세의 결과 취소는 역분개와 Game·대진 복원을 함께 수행한다.

구현 파일과 책임:

- `rules.ts`: 초기 점수, K 값, 동포지션 Elo와 출전자 열 명의 포지션 완전성을 검증하는 순수 계산 함수.
- `service.ts`: `applyGameMmr`로 반영 회차·원장을 생성(C)하고 현재값·revision을 갱신(U)한다. `reverseGameMmr`는 원장을 삭제하지 않고 역분개를 추가한다. 화면 조회(R)는 `records/`·`guild/`가 담당한다.
- [시즌 봇 서비스](../discord/bot-seasons.ts): 관리자 `/시즌` 명령의 현재·종료 시즌 조회와 기존 시즌 종료/새 시즌 시작을 처리한다. 최초 시즌 준비는 [봇 업무 서비스](../discord/bot-service.ts)의 `initializeBotGuild`를 재사용한다.

[MMR 저장 계약](../../../../../../docs/mmr.md)의 초기 1500, K=32, 동포지션 상대 기준 Elo를 따른다.
시즌은 내전에 고정한다. 채택 ROFL이 있는 완료 Game, 같은 내전의 서로 다른 사용자 열 명과 진영별 다섯 포지션이 필요하다. 희망 포지션이나 현재 편성·계정 연결로 당시 출전을 대체하지 않는다. 실제 계정과 확정 라인업·진영의 연결은 호출하는 결과 서비스가 먼저 검증한다.

반영·역분개 함수는 호출자가 전달한 `Transaction`만 사용하고 독립 커밋하지 않는다. 새 Game을 쓰는 결과 서비스는 사용자·계정 연결을 보호한 후 `lockMmrSeason`으로 시즌을 잠그고 내전 → 경기 → Game → 점수 순서를 지킨다. 이미 내전·경기 행을 잠근 뒤 시즌 잠금을 처음 얻어서는 안 된다. 실패는 호출자에게 전파하여 결과·출전·대진·점수·게시 예약 전체를 롤백한다.

같은 경기의 앞선 슬롯이 모두 완료·반영되어야 하며, 실제 시작 시각이 없어도 운영 슬롯과 서비스 등록 순서로 계산한다. 양 팀의 반영 전 값으로 계산하며 소수를 반올림하지 않는다. 동일 채택본의 동시 요청·재시도는 기존 유효 반영을 반환한다. 취소된 내전·경기에는 새 점수를 반영하지 않는다.

역분개는 반영 회차 ID와 사유를 받아 마지막 완료 Game만 처리한다. 현재 점수·최신 원장 revision이 일치하고 점수가 해당 결과의 반영 후 값이며, 후속 유효 경기나 관리 보정이 없어야 한다. 이미 역분개된 후속 결과는 허용하므로 마지막 게임부터 차례로 되돌릴 수 있다. 조건이 맞지 않으면 409로 거절하고 전체 재계산하지 않는다. 기존 Game 취소와 대진 복원은 호출자가 같은 트랜잭션에서 완료하고, 새 결과는 별도 Game에 등록한다. 기존 출전·ROFL·반영 회차·모든 결과 및 역분개 원장을 보존하며 과거 요청의 재시도로 취소한 결과를 되살리지 않는다.

호출자는 같은 ROFL의 진영 정정·실수 취소 복구를 같은 Match·세트·확정 라인업의 최신 요청으로 허용한다. 복구는 원본 메타데이터와 당시 계정 귀속을 유지하고 별도 Game·반영 회차·원장을 만든다. Riot 계정 재조회 없이 현재 점수에서 새 반영을 계산하며, 기존 정분개·역분개 이력은 그대로 보존한다. 오래된 요청이나 다른 슬롯의 재사용은 허용하지 않는다. 구체적인 재채택 조건은 [경기 결과 모듈](../matches/README.md)을 따른다.

봇의 `/시즌`은 옵션 없이 현재·종료한 시즌을 조회하며, 새 이름·자동완성으로 선택한 현재 시즌·명시적 전환 확인을 함께 받으면 기존 시즌 종료와 다음 시즌 생성을 원자적으로 처리한다. `actorId`의 현재 관리자 권한을 확인하고 `expectedCurrentSeasonId`가 달라졌으면 409로 거절한다. `confirm: true`가 필요하며 이름은 앞뒤 공백 제거 후 1~100자다. Bot 인증과 실제 실행자 검증을 분리하고, `interactionId` receipt가 서버·실행자·정규화한 요청·성공 결과를 같은 트랜잭션에 보존한다. 같은 요청 재시도는 저장한 결과를 반환하고 다른 내용으로 같은 식별자를 재사용하면 충돌이다. 실패하면 시즌 변경과 receipt 모두 롤백한다.

시즌 전환과 최초 준비는 guild의 `FOR NO KEY UPDATE`로 직렬화한다. 전환은 현재 시즌의 `FOR UPDATE` 잠금 아래 종료 시각과 새 시즌 시작 시각을 같은 값으로 저장한다. 신규 내전 생성은 활성 시즌을 `FOR SHARE`로 읽어 전환과 조정한다. 결과 반영·역분개는 위의 시즌 → 내전 → 경기 → Game → 점수 잠금 순서를 유지한다. 기존 진행 내전은 종료된 시즌이더라도 원래 `mmrSeasonId`에서 계속 결과를 처리하며 활성 시즌으로 옮기지 않는다.

전환 자체는 기존 `user_position_mmr`·원장·진행 경기·계정 귀속을 수정하거나 새 시즌 MMR을 복제·이월하지 않는다. 초기 1500과 미확인값의 기존 계약을 유지한다. 봇의 과거 시즌 목록 조회와 웹 전적의 과거 시즌 선택 UI는 별개이며, 공개 기본 조회를 임의로 과거 시즌으로 바꾸지 않는다.

내전의 시작 전 취소 복구와 중도 종료·재개는 기존 Game/MMR을 되살리거나 재계산하는 기능이 아니다. 전체 내전 취소의 일괄 역분개는 별도 경계로 남아 있다. 검사·실행 수치와 외부 운영 검증의 제외 범위는 [통합 검증 기록](../../../../../../artifacts/ui-review/operations/checks.json)을 따른다.
