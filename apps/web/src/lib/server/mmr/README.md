# MMR 처리

소비자는 경기 상세의 처리 상태, 서버 홈·순위, 개인 전적·통계와 편성 후보 정보다.
`matches/results.ts`가 검증한 ROFL·완료 Game·확정 출전자 열 명을 저장한 뒤 같은 트랜잭션에서 호출한다. 경기 상세의 결과 취소는 역분개와 Game·대진 복원을 함께 수행한다.

구현 파일과 책임:

- `rules.ts`: 초기 점수, K 값, 동포지션 Elo와 출전자 열 명의 포지션 완전성을 검증하는 순수 계산 함수.
- `service.ts`: `applyGameMmr`로 반영 회차·원장을 생성(C)하고 현재값·revision을 갱신(U)한다. `reverseGameMmr`는 원장을 삭제하지 않고 역분개를 추가한다. 화면 조회(R)는 `records/`·`guild/`가 담당한다.

[MMR 저장 계약](../../../../../../docs/mmr.md)의 초기 1500, K=32, 동포지션 상대 기준 Elo를 따른다.
시즌은 내전에 고정한다. 채택 ROFL이 있는 완료 Game, 같은 내전의 서로 다른 사용자 열 명과 진영별 다섯 포지션이 필요하다. 희망 포지션이나 현재 편성·계정 연결로 당시 출전을 대체하지 않는다. 실제 계정과 확정 라인업·진영의 연결은 호출하는 결과 서비스가 먼저 검증한다.

반영·역분개 함수는 호출자가 전달한 `Transaction`만 사용하고 독립 커밋하지 않는다. 새 Game을 쓰는 결과 서비스는 사용자·계정 연결을 보호한 후 `lockMmrSeason`으로 시즌을 잠그고 내전 → 경기 → Game → 점수 순서를 지킨다. 이미 내전·경기 행을 잠근 뒤 시즌 잠금을 처음 얻어서는 안 된다. 실패는 호출자에게 전파하여 결과·출전·대진·점수·게시 예약 전체를 롤백한다.

같은 경기의 앞선 슬롯이 모두 완료·반영되어야 하며, 실제 시작 시각이 없어도 운영 슬롯과 서비스 등록 순서로 계산한다. 양 팀의 반영 전 값으로 계산하며 소수를 반올림하지 않는다. 동일 채택본의 동시 요청·재시도는 기존 유효 반영을 반환한다. 취소된 내전·경기에는 새 점수를 반영하지 않는다.

역분개는 반영 회차 ID와 사유를 받아 마지막 완료 Game만 처리한다. 현재 점수·최신 원장 revision이 일치하고 점수가 해당 결과의 반영 후 값이며, 후속 유효 경기나 관리 보정이 없어야 한다. 이미 역분개된 후속 결과는 허용하므로 마지막 게임부터 차례로 되돌릴 수 있다. 조건이 맞지 않으면 409로 거절하고 전체 재계산하지 않는다. 기존 Game 취소와 대진 복원은 호출자가 같은 트랜잭션에서 완료하고, 새 결과는 별도 Game에 등록한다. 기존 출전·ROFL·반영 회차·모든 결과 및 역분개 원장을 보존하며 과거 요청의 재시도로 취소한 결과를 되살리지 않는다.
