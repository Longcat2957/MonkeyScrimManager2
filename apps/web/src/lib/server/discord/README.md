# Discord 연동

소비자는 웹의 길드·멤버 권한 확인, 서버 관리의 역할·채널 설정, 봇의 참가 interaction과 모집·엔트리·결과 게시다.
업무 규칙과 DB 저장은 웹이 소유하고 `apps/bot`은 Gateway·interaction·메시지 입출력을 담당한다.

현재 파일과 후속 책임:

- `client.ts`: Bot REST의 길드·멤버·역할·채널 조회와 응답 검증. 별도 봇 RPC를 만들지 않는다.
- `membership.ts`: 실제 소속·실효 권한 확인과 길드·사용자·현재 멤버 동기화. 탈퇴로 과거 업무 기록을 삭제하지 않는다.
- `../guild/settings.ts`: 역할·채널 선택지 저장, 봇의 실제 게시 가능 권한, 설정 변경 후 실행자 권한 검사.
- `bot-auth.ts`, `bot-http.ts`: 전용 내부 인증, 제한된 JSON 입력, 캐시하지 않는 오류 응답.
- `bot-service.ts`: 초기 시즌·모집 생성·개인 신청·Gateway 재확인·게시 복구를 기존 업무 함수에 연결.
- `bot-receipts.ts`: interaction ID·요청 해시로 중복 효과를 막고 성공 결과를 업무 변경과 함께 저장.
- `publications.ts`: 모집/엔트리 게시 예약·점유·성공/실패·재시도와 최신 버전 반영.
- `/internal/bot/`: 봇이 실제 소비하는 기능의 HTTP 어댑터. ROFL 결과 게시는 후속 기능이다.

Discord 설정의 업무 검증은 `guild/`가 담당한다. 봇 참가 interaction은 `scrims/`의 같은 신청 서비스를 호출하고 interaction ID로 중복 효과를 막는다.
인증된 내부 HTTP 어댑터에서 실행자·길드·내전 관계를 다시 확인한다. 봇이 DB를 직접 수정하거나 업무 규칙을 복제하지 않는다.

게시 작업은 내전 변경 트랜잭션에 기록하고 외부 전송은 커밋 뒤 처리한다. 메시지 ID·재시도·점유 만료를 이용해 재시작과 응답 유실을 복구한다.
권한 동기화 실패를 권한 있음으로 처리하지 않는다. 범용 Discord 프록시나 별도 메시지 브로커는 추가하지 않는다.

상세 계약은 [백엔드 계획의 Discord 연동](../../../../../../docs/backend-plan.md#58-discord-봇과-외부-api)을 따른다.

설정·명령·복구·테스트는 [봇 운영 문서](../../../../../../docs/bot.md)를 따른다.
