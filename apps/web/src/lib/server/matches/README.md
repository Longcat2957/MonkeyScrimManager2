# 경기와 결과

소비자는 `/g/[guildId]/matches`, `/matches/[matchId]`와 경기 상세의 `setSide`, `confirmLineup`, `releaseLineup`, `upload`, `revertResult` action이다. 내전 대진과 서버 홈도 같은 Match·Game을 조회한다.

- `queries.ts`: 경기·채택 Game·실출전·피어리스·MMR 공개 조회. 없는 수치·실제 시각은 null이다.
- `operation-context.ts`: 경기 단위 출전 라인업, 다음 게임 번호, 운영 권한 힌트와 정정 차단 사유 조회.
- `service.ts`: 경기 전체의 라인업 저장·확정·해제. 양 팀 다섯 포지션과 서로 다른 열 명을 검증한다.
- `lineup-bootstrap.ts`: 수동 편성에서 이미 확정한 포지션을 Match 생성 시 복사·확정한다. 경매는 경기마다 한 번 확정한다. 진출한 팀의 직전 확정 포지션도 다음 경기로 복사하며, 경매는 복사된 초안을 확정한다. 같은 경기의 후속 Game은 그 라인업을 재사용한다.
- `results.ts`: ROFL 자동 등록, Game·실출전·MMR·경기 종료·승자 진출을 한 트랜잭션에서 처리한다. 마지막 결과 취소는 역분개와 다음 경기 복원을 함께 처리한다.
- `reversal.ts`: 후속 경기 작업·MMR 변경이 생긴 결과의 정정을 막는다.

열람은 공개다. 예정 진영·라인업 변경과 결과 취소는 현재 서버 관리자만, 업로드는 현재 서버 관리자 또는 확정 출전자만 가능하다. 쓰기 전에 Discord REST로 소속을 갱신하고 트랜잭션 안에서 권한을 다시 검사한다. 취소된 결과까지 포함해 Game이 생긴 경기의 라인업은 변경하지 않는다.

운영자가 정한 블루 팀은 경기·세트 번호별로 `match_set_sides`에 보관한다. 예정 진영은 공개이며 ROFL 입력의 기본값일 뿐이다. 실제 진영을 바꿔 확인하더라도 시리즈의 A/B 팀이나 다른 세트는 바꾸지 않는다.

업로드는 Match revision·다음 Game 번호·lineupId·이번 Game의 블루 팀을 받는다. 지원하는 두 팀·열 명 ROFL의 표준 `TEAM=100`·`200`은 블루·레드로 해석해 업로드의 블루 팀 선택과 대조한다. 다른 팀 코드는 기존 계정 연결 근거가 있어야 하며 배열 순서로 진영을 추정하지 않는다. 근거와 지원 범위는 [ROFL 자동 귀속](../../../../../../docs/rofl-import.md#자동-귀속과-경기-운영)을 따른다. 게임 내 밴픽이나 진행 입력은 추가하지 않는다.

ROFL Riot ID를 실제 ACCOUNT-V1로 조회한 PUUID와 서버별 계정 연결을 대조한다. 전원이 계정 미연결이어도 표준 팀 코드·업로드의 블루 팀 선택·파일에 명시된 `TEAM_POSITION`·확정 라인업으로 실제 출전자를 연결한다. 확인된 실사용 계정은 서버별 사용자 연결과 감사 이력을 함께 저장해 다음 경기에도 재사용한다. 대표가 없을 때만 처음 확인한 계정을 대표로 지정하고 기존 대표와 명시적으로 선택한 신청 계정은 유지한다. 신청 계정이 비어 있으면 첫 실사용 계정으로 채운다. 기존 소유자·팀·포지션 충돌과 근거가 없는 팀·출전자 연결은 거절한다. 파일에 포지션이 없는 기존 연결 계정은 검증한 사용자와 이미 확정된 포지션을 사용한다. 배열 순서·희망 포지션·닉네임·리플레이 원시 PUUID로 계정이나 포지션을 추정하지 않는다.

파싱과 Riot 호출은 잠금 밖에서 처리하고, 계정 조회는 공용 전송기 상한보다 작은 묶음으로 실행한다. 저장은 사용자 → 계정 키 → 서버 연결 → 시즌 → 내전 → Match → Game → MMR 순으로 잠근다. 전역 계정의 표시정보를 다른 서버가 편집 중이면 갱신을 기다리지 않고 당시 실사용 이름을 경기 출전에 보존한다. 파일 SHA-256과 선별 결과의 정규화 지문을 별도로 검사한다. 같은 성공 요청은 기존 Game을 반환하고, 다른 파일의 동일 결과·다른 경기 재사용·취소 후 늦은 재전송은 차단한다. 등록 실패는 계정 식별·서버별 연결·감사 이력·신청 계정·ROFL 선별 자료·Game·MMR·게시 예약까지 모두 롤백한다.

마지막 결과 취소는 기존 Game을 `cancelled`로 남기고 출전·ROFL·MMR 역분개 이력을 보존한다. 다시 열린 세트의 예정 진영은 수정할 수 있으며 그 이후 세트의 계획은 제거한다. 다른 결과의 파일은 같은 번호의 새 Game으로 등록한다. 자동 생성만 된 수동 다음 경기와 미확정 경매 초안은 안전하게 제거할 수 있지만, 관리자가 수정한 다음 경기·후속 결과·후속 MMR 변경이 있으면 취소를 거절한다.

취소한 파일은 같은 Match·세트 번호·확정 라인업의 최신 revision으로 다시 제출하여 복구하거나 블루 팀 선택을 정정할 수 있다. 저장된 ROFL 메타데이터·선별 자료와 취소 Game의 실제 사용 계정·출전자·포지션·표시 이름·Riot ID를 재사용하며 Riot 계정 API나 현재 서버 계정 연결로 귀속을 다시 계산하지 않는다. 새 Game·출전·등록 이력·MMR·대진·게시 예약을 같은 트랜잭션으로 생성한다. 기존 취소 Game과 등록 이력은 보존하며 반복 취소·복구도 새 Game을 만든다. 오래된 요청·다른 Match/세트/라인업 재사용·다른 바이트의 동일 결과는 계속 차단한다. 동일 복구 요청이 동시에 오면 한 번만 반영한다.

원본 ROFL은 저장하지 않는다. P0~P2 선별 자료와 파일 지문·크기·버전·업로더·등록 시각만 저장한다. 실제 경기 시각은 모르면 null이다. 정상 파일은 별도 승인 없이 자동 등록하며 하드 피어리스는 안내만 제공한다. 같은 경기의 앞선 유효 세트에서 양 팀이 실제 사용한 챔피언 전체를 진영과 무관하게 검사하며, 취소한 세트는 제외한다. 다음 세트 안내는 양 팀 공통 목록으로 중복 없이 표시한다. ROFL 서명 진위의 암호학적 검증을 구현한 것으로 취급하지 않는다.
