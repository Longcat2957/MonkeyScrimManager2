# 경기와 결과

소비자는 `/g/[guildId]/matches`, `/matches/[matchId]`와 경기 상세의 `upload` action이다.
내전 대진과 서버 홈도 같은 경기·Game을 조회한다.

구현 상태와 책임:

- `queries.ts` 구현: 경기 목록·시리즈·채택 Game·실출전·피어리스 안내·MMR 상태 공개 조회(R). 기존 필터·페이지·Game 선택 계약을 유지한다. 누락 수치와 시각은 null이고 임시 평점·MVP를 만들지 않는다.
- `service.ts` 후속: 검증된 ROFL의 Game·실출전·선별 자료 생성(C), 시리즈 점수·경기 종료 반영(U). 대진 진출과 다음 Match 생성은 `scrims/bracket.ts`와 같은 트랜잭션으로 처리해야 한다.

현재 실제 경기의 `can.upload`는 false이며 업로드 요청은 503으로 반환한다. 아래 저장 흐름은 검증 근거를 확보한 뒤 연결할 계약이다.

기존 `rofl/`의 파서와 적재 모델을 사용하고, 참가자·계정·팀·진영·경기 식별 근거를 서버에서 검증한다.
파싱은 잠금 밖에서 수행하고 저장 직전에 권한·상태·중복을 다시 확인한다. 같은 성공 요청의 재시도는 기존 `{ order }`를 반환한다.
Match·다음 세트·확정 라인업은 MSM1처럼 서비스가 관리한다. 파일과 계정·팀·진영의 대응 및 중복을 검증하며 실제 시각은 모르면 null이다.

정상 결과는 자동 등록한다. 수동 승패 입력·자유 삭제·매번 승인 절차를 추가하지 않으며 피어리스 위반으로 등록을 막지 않는다.
원본 ROFL은 보관하지 않는다. 정상 Game·실출전·MMR·시리즈 종료·진출을 같은 트랜잭션으로 처리한다. MMR 함수가 새 트랜잭션을 열지 않게 하고 최상위 결과 서비스가 시즌부터 잠근다.

상세 계약은 [백엔드 계획의 ROFL 등록](../../../../../../docs/backend-plan.md#56-rofl-등록과-mmr)을 따른다.
