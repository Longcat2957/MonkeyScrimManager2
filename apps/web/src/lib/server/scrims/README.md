# 내전 운영

소비자는 `/g/[guildId]/scrims`와 `[scrimId]`의 요약·수동 편성·경매·대진·결과 화면이다.
기존 load와 form action을 실제 DB 서비스에 연결한다. 개발용 서버 ID만 목 저장소를 사용한다.

| 파일 | 책임 |
| --- | --- |
| `queries.ts` | 공개 내전 목록·요약·신청 현황·다음 내전 조회(R) |
| `service.ts` | 내전·신청 생성(C), 신청·설정 변경·모집 마감·철회·취소(U) |
| `operation.ts`, `validation.ts` | 입력 검증·권한·내전 잠금·revision 검사 공통 규칙 |
| `workflow.ts` | 편성 방식 선택·단계 전환·복귀·중도 종료·재개(U), 가능한 조작 조회(R) |
| `manual.ts` | 이동·교환·배정 해제·초기화·편성 확정(U), 확정 시 대진 초안 생성 |
| `auction.ts` | 설정·시작·후보·낙찰·유찰·수동 영입·복구(C/U), 이력을 보존하는 무효화 |
| `bracket.ts` | 대진 초안 생성(C), 배치·라운드 BO·확정·해제(U), 불필요한 초안 제거(D), 시작·승자 진출에 따른 Match 생성 |

철회·취소·중도 종료는 삭제가 아닌 상태 수정이다. 신청 ID와 편성·출전에 쓰는 참가자 ID를 구분하고 이력을 보존한다.
조회 중 팀·후보·대진 초안을 생성하지 않는다. 방식 변경은 요약·수동·경매에서 같은 업무 함수를 호출한다.

내전 쓰기는 Scrim 잠금 뒤 최신 권한·상태를 확인한다. 운영 변경의 `expectedRevision`, 경매 현재 후보의 `lotId`를 검증한다.
대진 시작·승자 진출 함수는 양 팀이 확정된 노드에만 Match를 생성한다. 향후 ROFL 결과 저장 서비스에서 같은 트랜잭션으로 진출 함수를 호출해야 한다.
기록된 Game과 경매 이력을 편성 초기화·되돌리기로 삭제하지 않는다.

밴픽·게임 중 진행 입력, 별도 Match 시작 버튼, 서버 경매 타이머는 이 기능의 범위가 아니다.
action별 책임과 상태 전환은 [백엔드 계획](../../../../../../docs/backend-plan.md#4-현재-화면과-crud의-대응)을 따른다.
