# 내전 운영

소비자는 `/g/[guildId]/scrims`와 `[scrimId]`의 요약·수동 편성·경매·대진·결과 화면과 경매의 공개 `auction/live` 조회다.
기존 load와 form action을 실제 DB 서비스에 연결한다. 개발용 서버 ID만 목 저장소를 사용한다.

| 파일 | 책임 |
| --- | --- |
| `queries.ts` | 공개 내전 목록·요약·신청 현황·다음 내전 조회(R) |
| `service.ts` | 내전·신청 생성(C), 신청·설정 변경·모집 마감·철회·취소·정확한 취소 복구(U) |
| `operation.ts`, `validation.ts` | 입력 검증·권한·내전 잠금·revision 검사 공통 규칙 |
| `workflow.ts` | 편성 방식 선택·단계 전환·복귀·중도 종료·재개(U), 가능한 조작 조회(R) |
| `manual.ts` | 이동·교환·배정 해제·초기화·편성 확정(U), 확정 시 대진 초안 생성 |
| `formation-records.ts` | 고정 시즌·당시 사용자 귀속의 실제 동팀 시너지·동포지션 맞대결 집계(R) |
| `auction.ts`, `auction-actions.ts` | 설정·시작·추첨·낙찰·유찰·수동 영입·유찰 복귀(C/U), 행위 원장과 직전 작업 취소 |
| `auction-profile.ts` | 경매 현재 후보의 고정 시즌 실제 승패·주력 챔피언·실출전 포지션·게임 기록(R) |
| `bracket.ts` | 대진 초안 생성(C), 배치·라운드 BO·확정·해제(U), 불필요한 초안 제거(D), 시작·승자 진출에 따른 Match 생성 |

철회·취소·중도 종료는 삭제가 아닌 상태 수정이다. 신청 ID와 편성·출전에 쓰는 참가자 ID를 구분하고 이력을 보존한다.
조회 중 팀·후보·대진 초안을 생성하지 않는다. 방식 변경은 요약·수동·경매에서 같은 업무 함수를 호출한다.

내전 쓰기는 Scrim 잠금 뒤 최신 권한·상태를 확인한다. 운영 변경의 `expectedRevision`, 경매 현재 후보의 `lotId`를 검증한다.
신규 내전 생성은 현재 활성 시즌 행을 `FOR SHARE`로 읽고 그 ID를 고정해 봇의 시즌 전환 `FOR UPDATE`와 조정한다. 기존 내전의 시즌을 현재 활성 시즌으로 다시 배정하지 않는다.
대진 시작·승자 진출 함수는 양 팀이 확정된 노드에만 Match를 생성한다. `matches/results.ts`가 ROFL 결과·MMR 저장과 같은 트랜잭션으로 진출 함수를 호출하며 최종 대진이 끝나면 내전을 자동 완료한다.
기록된 Game과 경매 이력을 편성 초기화·되돌리기로 삭제하지 않는다.

취소는 Game이 없는 `recruit`·`preparing`·`ready`에서 가능하다. 새 취소는 `cancelledFromStatus`·`cancelledAuctionStatus`에 원래 단계를 저장하고 내전·경매 상태만 취소한다. 참가자·배정·포인트·후보·lot·경매 시작/종료 시각·행위 원장은 유지한다. 복구는 같은 관리자 권한·revision·Game 부재·경매 근거를 확인한 뒤 저장한 단계로 돌아간다. 과거 취소 행의 근거가 없으면 추정하지 않고 차단 이유를 제공한다. 상태와 게시 예약은 같은 트랜잭션이다.

중도 종료는 `preparing`·`ready`·`in_progress`에서 가능하다. 실제 완료 Game의 진영과 `blueTeamSlot`으로 현재 팀 점수를 계산해 우세 팀을 중도 종료 승자로 기록하고 동점은 null로 둔다. 완료 경기·Game·ROFL·출전·MMR·라인업은 바꾸지 않고 새 후속 Match를 만들지 않는다. 결승을 치르지 않았으면 준결승 우세만으로 우승팀을 만들지 않는다. `endedEarlyFromStatus`와 Match의 기존 복원 필드로 중단 직전 단계·상태·종료 정보를 복원하고 바뀐 경기 revision을 높인다. 과거 복귀 단계가 null인 중도 종료는 기존 진행 중 재개 동작을 유지한다.

경매 직전 작업 취소는 추첨·유찰·낙찰·현재 후보 수동 배치·유찰자 수동 배치·유찰자 다시 올리기의 6종을 `auction_actions` 순서 원장에서 읽는다. 취소 뒤 `revert`를 새 행위로 남기므로 다음 새 행위 전에는 한 번만 되돌릴 수 있다. 과거 lot만으로 누락된 행위를 추정하지 않는다. 초기화·팀장 재설정·방식 변경·모집 복귀는 원장에 무효화 경계를 남기며 단순 내전 취소·복구에서는 보존한다.

편성 참고 MMR은 내전 고정 시즌, 시너지·맞대결과 경매 후보 상세는 같은 서버·시즌의 채택 ROFL 실출전을 사용한다. 취소 부모를 제외하고 중도 종료의 정상 결과와 당시 사용자 귀속을 유지한다. 미확인 포지션·시각, 미제공 선호 챔피언·외부 Riot 전적을 합성하지 않는다.

공개 `auction/live`의 소비자는 편성 중 경매 열람 화면의 자동/수동 갱신이다. 기존 공개 읽기 권한과 `private, no-store`를 사용하며 쓰기를 제공하지 않는다. 화면은 기본 5초 간격으로 읽고 실패 시 최대 30초로 늦춘다. 중복 요청·15초 지연·화면 이탈·숨김/offline·자동 갱신 중단을 처리하고, 실패에는 마지막 자료와 오류 안내를 유지한다. 단계·설정·권한 변화는 상위 load까지 재조회하며 운영자는 기존 저장 후 재조회 흐름을 사용한다.

진행 중 전체 내전 취소에 따른 Game/MMR 일괄 안전 역분개와 취소 후 모집 복귀는 별도 후속 범위다. 현재 마지막 세트 취소를 단순 반복해 그 정책을 대신하지 않는다.

밴픽·게임 중 진행 입력, 별도 Match 시작 버튼, 서버 경매 타이머는 이 기능의 범위가 아니다.
action별 책임과 상태 전환은 [백엔드 계획](../../../../../../docs/backend-plan.md#4-현재-화면과-crud의-대응)을 따른다.
검사·브라우저 실행 수치와 제외 범위는 [통합 검증 기록](../../../../../../artifacts/ui-review/operations/checks.json)을 따른다.
