# 프론트 목 데이터

화면 작업에 필요한 목 데이터는 이 디렉터리에서 관리한다.
페이지·컴포넌트 안에 임시 데이터를 흩어 놓지 않는다.

## 내 정보 화면

`me.ts`는 `/me`의 초기 표시 데이터와 계정 조회·연결·해제·공개 범위 저장 동작을 제공한다.
화면에서 사용하는 데이터 타입은 `../features/me/types.ts`에 두며 컴포넌트가 목 데이터의 구체적인 조회 방식에 의존하지 않게 한다.

개발 모드에서 `/me?preview=<상태>`로 필요한 상태를 확인한다. 이 쿼리는 개발용이며 운영 기능이 아니다.
개발 모드에서 쿼리가 없거나 지원하지 않는 값이면 `ready`를 사용한다.
운영 모드에서는 `preview` 쿼리를 무시하고 `signed-out` 상태만 제공한다. 목 개인정보는 반환하지 않는다.

| 값 | 확인할 상태 |
| --- | --- |
| `ready` | 두 개의 연결 계정과 비공개 기본 설정 |
| `empty` | 연결한 계정이 없는 상태 |
| `load-error` | 초기 조회 실패와 재시도 |
| `save-error` | 첫 공개 범위 저장 실패와 재시도 |
| `lookup-error` | 첫 Riot 계정 조회 실패와 재시도 |
| `link-error` | 첫 계정 연결 실패와 재시도 |
| `unlink-error` | 첫 계정 연결 해제 실패와 재시도 |
| `signed-out` | 로그인하지 않은 상태 |

`getMeMockData(scenario)`는 매번 독립 복사한 데이터만 반환한다. `empty`는 계정 목록을 비운다.
초기 조회 실패·로그아웃의 표시와 조회 재시도는 페이지 어댑터가 담당한다.
`createMeMockActions(scenario)`의 액션은 350ms 뒤 결과를 반환한다.
오류 시나리오의 해당 동작은 인스턴스별로 처음 한 번만 실패하며, 같은 입력으로 재시도하면 성공한다.
다른 종류의 요청은 예약된 실패를 소비하지 않는다.

계정 조회는 비어 있지 않은 이름·태그를 받아 표시 데이터를 만든다. Riot의 실제 이름 정책이나 계정 존재 여부를 검증하지 않는다.
ID는 정규화한 이름·태그로 만든 결정적인 목 식별자이며 실제 Riot 식별자·UUID가 아니다.
이미 연결한 계정의 중복 처리는 호출자가 ID 또는 대소문자를 구분하지 않는 Riot ID를 비교해 수행한다.

목 액션은 실제 Riot 요청·계정 소유권 확인·인증·DB 저장을 하지 않으며 토큰을 사용하지 않는다.
성공 후 목록·설정의 변경은 호출자가 화면 상태에 반영한다. 새로고침하면 초기 데이터와 일회성 오류 상태가 다시 시작한다.
목 데이터나 개발용 쿼리에 대한 설명을 제품의 오류·성공 문구에 넣지 않는다.
