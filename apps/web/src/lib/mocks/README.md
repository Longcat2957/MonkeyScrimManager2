# 프론트 목 데이터 보관 위치

화면 작업에 필요한 목 데이터는 이 디렉터리에서 관리한다.
페이지·컴포넌트 안에 임시 데이터를 흩어 놓지 않는다.

- 목 데이터는 라우트의 `load`가 개발 모드(`dev`)에서만 반환한다. 컴포넌트는 목 모듈을 직접 가져오지 않는다.
- 운영 모드에서는 목 개인정보를 반환하지 않는다.

| 파일 | 내용 |
| --- | --- |
| `session.ts` | 로그인 사용자, 접근 가능한 서버, 서버 문맥 |
| `scrims.ts` | 내전 문맥·목록·참가자의 가변 저장소(개발 서버 재시작 시 초기화). 모집 중 내전은 편성 방식이 비어 있고, 신청은 선발 자리가 남으면 선발·찼으면 대기다. `devScrim001` 운영자 시점(선발 10/10, 대기 1 → 모집 마감 가능), `devScrim003` 신청 가능, `devScrim006` 정원 마감, `devScrim008` 대진 준비(4팀·20명 선발·운영 권한), `devScrim004` 결승 1:1 진행 중(운영 권한, 중도 종료 확인), 지난 내전 19개로 쪽 나눔 확인. `devGuild002`는 빈 서버 |
| `workflow.ts` | 내전 단계 진행(모집 마감 + 편성 방식 선택)·이전 단계 되돌리기·중도 종료. 편성·대진 목을 함께 고친다 |
| `teams.ts` | 수동 편성·경매 상태(가변, 재시작 시 초기화). 팀 이름은 `TEAM_NAMES` 순서(포로팀·칼날부리팀·돌거북팀·바위게팀). `devScrim007` 편성 중 수동(6/10 배치), `devScrim004` 확정된 수동, `devScrim002` 경매 준비, `devScrim005` 완료된 경매(수동 배치 1건 포함). 참가자 포지션별 MMR은 `scrims.ts` |
| `bracket.ts` | 대진 배치·경기 방식·확정 상태(가변, 재시작 시 초기화). 틀은 `bracketTemplate`. `devScrim008` 4팀 빈 대진(운영자), `devScrim005` 종료된 4팀 대진, `devScrim004` 진행 중 2팀 결승 |
| `players.ts` | 사용자별 게임 기록. `ranking.ts`의 사용자·포지션 기록(게임 수·승률·주 챔피언)에 맞춰 고정 시드로 만든다. 골드·받은 피해도 포지션 기준값으로 만든다. `listMockGuildPlayers`는 서버 전체 사용자의 기록으로 서버 통계와 사용자 전적의 업적·상위 % 비교에 쓴다 |
| `admin.ts` | 서버 관리의 멤버·관리자 목록(가변, 재시작 시 초기화). `devGuild001` 30명, 관리자는 `devUser001`·`u02`. `devGuild002`는 관리자가 아니라 403 |
| `component-demo/` | `/dev/components` 검증용 데이터 |
| `me.ts` | `/me`의 Riot 계정·공개 설정. 조회 이름 `없는계정`·`조회제한`·`충돌계정`으로 예외 재현, `/me?preview=empty`로 빈 상태 |
| `matches.ts` | 경기 목록·상세·게임 기록(가변, 재시작 시 초기화). 진행 중·종료·중도 종료·취소·경기 시각 미확인 포함(팀 이름은 포로팀·칼날부리팀처럼 자동 이름), 지난 경기 22개로 쪽 나눔 확인. 게임은 `fixtures/rofl-sample.json`(샘플 ROFL 투영, 이름은 목 사용자로 바꿈)을 쓰고 두 번째 게임부터 챔피언을 바꾼다. `devMatch001`(진행 중)에 ROFL 업로드 가능. `/g/devGuild001?preview=error`로 서버 홈 조회 실패 재현 |
| `ranking.ts` | 서버 순위(고정 12명 + 조합 이름 48명). 무한 스크롤 확인용 |
| `stories.ts` | 서버 홈 이번 주 이야기 5개 |
