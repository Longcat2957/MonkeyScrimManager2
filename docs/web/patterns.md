# 화면 패턴

## 조회와 상태

- 초기 데이터는 서버 `load`가 준비한다. `lib/features/`는 화면 계약, `lib/mocks/`는 명시적 개발 샘플 전용이다. 실패한 실제 조회를 빈 결과나 목 데이터로 바꾸지 않는다.
- URL에 남기는 시즌·검색·페이지는 [라우팅](routing.md)을 따른다. 목록을 다시 읽는 동안 가능한 한 이전 결과를 유지하고 `aria-busy`로 알린다. 처음부터 비어 있는 경우와 필터에 맞는 결과가 없는 경우를 구별한다.
- 전체 페이지를 열 수 없으면 루트 오류 화면을 사용한다. 한 영역만 실패하면 이유와 재시도를 그 영역에 둔다. 정상 저장 후 바뀐 데이터가 보인다면 같은 내용을 토스트와 본문 양쪽에서 되풀이하지 않는다.
- 세션·권한은 화면 표시와 별도로 서버에서 검사한다. 공개 조회의 관리자 힌트는 동기화 후 60초까지 유효하다. Discord 장애 시 공개 읽기는 유지하되 오래된 힌트는 숨기고 쓰기 권한을 추정하지 않는다.
- [경매](pages/scrims.md)와 [서버 통계](pages/records.md)는 읽기 전용 갱신을 제공한다. 자동 갱신 중지와 일회 새로고침을 구분하고, 실패·오프라인이면 마지막 정상 화면을 보존한다.

## 입력과 변경

- 필드에는 실제 입력과 연결된 라벨을 둔다. `placeholder`는 예시일 뿐 이름이 아니다. 선택 묶음은 `fieldset`·`legend`를 쓴다. 오류를 입력과 연결하고 사용자가 고칠 수 있는 첫 필드로 포커스를 보낸다.
- 한글 조합 중 Enter가 제출로 처리되지 않게 한다. 보조 버튼은 `type="button"`, 제출은 `type="submit"`이다. 날짜·범위·권한·대상·revision은 클라이언트 표시와 무관하게 서버에서도 확인한다.
- 입력 폼은 SvelteKit form action을 사용한다. 폼 없는 조작은 [`postAction`](../../apps/web/src/lib/ui/actions.ts)을 사용한다. 요청 중 중복 전송과 작업 충돌을 막고, 검증 실패 후에는 입력을 보존한다.
- 변경을 버리거나 결과·권한을 취소할 때는 대상과 영향을 확인시킨다. 409 충돌은 최신 상태를 다시 읽고, 응답 유실은 저장 실패로 단정하지 않는다. 이미 저장됐지만 화면 갱신에 실패한 경우도 구분한다. 결과를 모른 채 변경 요청을 자동 재전송하지 않는다.

## 대화상자·목록·접근성

- 입력·상세·확인은 공통 네이티브 `Dialog`, 짧은 항목 선택은 `PopoverMenu`를 쓴다. 공통 확인창은 명시적인 취소·확인 버튼을 제공한다. 모바일 메뉴 시트는 `overlay`가 배경 조작과 포커스 이탈을 막는다.
- 열 때 제목과 첫 조작을 알 수 있어야 한다. 닫은 뒤에는 트리거 또는 남은 화면의 적절한 위치로 돌아간다. 저장 중 닫을 수 없다면 닫기 버튼뿐 아니라 Escape·배경 클릭에도 같은 정책을 적용한다.
- 이동하는 행은 실제 목적지 링크로 만들고 안에 다른 조작을 넣지 않는다. 비연결 사용자는 가짜 링크 대신 텍스트로 표시한다. 비교표는 열 머리와 현재 정렬을 제공한다. 좁은 화면에서도 필요한 열을 읽을 수 있게 이름 있는 내부 스크롤을 사용한다.
- 화면에는 하나의 주제 제목을 두고 같은 동작을 레일·본문·빈 상태에 중복하지 않는다. 상태는 색과 문구, 선택은 텍스트와 접근성 속성으로 표시한다. 드래그 배치에는 선택 후 자리 지정 방식도 제공한다.

## 완료 체크리스트

- [ ] 공개·관리자·본인 전용 조작과 정상·대기·빈 결과·오류·비활성 상태가 구분된다.
- [ ] 모바일·데스크톱과 레일 전환 폭에서 같은 조작이 중복되거나 사라지지 않는다.
- [ ] 두 테마에서 본문과 입력은 4.5:1, 큰 글자와 필요한 컨트롤 경계는 3:1 대비를 확보한다.
- [ ] 긴 한국어·영문·큰 수치, 글자 확대, 터치 조작 영역, 동작 줄이기 설정을 확인한다.
- [ ] 키보드만으로 이동·입력·정정할 수 있고 포커스 표시, 대화상자 열기·닫기와 복귀가 동작한다.
- [ ] 공통 [컴포넌트와 토큰](design-system.md), 브랜드 이름, 프로젝트의 `pnpm check` 기준을 따른다.
