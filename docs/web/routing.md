# MSM2 웹 라우트·레이아웃 설계

상태: 목표 구조 확정. `/backoffice`는 제목만 표시하는 빈 페이지와 루트의 개발용 바로가기까지 추가했다.
아래는 목표 구조이며, `[playerId]` 폴더 이동과 공통 내비게이션 구현은 아직 수행하지 않았다.
서비스 책임은 [프로젝트 목적](../purpose.md), 화면 중복 방지는 [프로젝트 규칙](../../AGENTS.md)을 따른다.
각 페이지의 역할·접근 대상·필요 정보·상호작용·상태·미결정 사항은 [페이지 요구사항](page-requirements.md)에 정리한다.
이 문서는 경로와 내비게이션 소유 위치를, 연결된 요구사항 문서는 사용자 행동을 담당한다.
[UI 배치 계획](ui-plan.md)은 헤더 교체와 컴포넌트 구성을 구체화한 문서 설계다. 실제 공통 헤더·메뉴 구현은 아직 변경하지 않았다.

## 페이지 구조

```text
/
├── me
├── docs
├── terms
├── privacy
├── backoffice                              빈 페이지 구성 완료
└── g/[guildId]
    ├── scrims
    │   └── [scrimId]
    │       ├── teams
    │       └── bracket
    ├── matches
    │   └── [matchId]                        Game 선택: ?game=<gameId>
    ├── players
    │   └── [userId]                         기존 [playerId]의 이름 변경 예정
    ├── stats
    └── admin
```

| 경로 | 책임 |
| --- | --- |
| `/` | 서비스 소개. 서버 진입은 공통 헤더의 서버 선택기를 사용 |
| `/me` | 본인 계정 연결·개인 설정·공개 범위 |
| `/docs`, `/terms`, `/privacy` | 이용 문서·약관·개인정보 처리방침 |
| `/backoffice` | 전체 서비스 운영자 영역. 세부 메뉴는 업무 범위를 정한 뒤 구성 |
| `/g/[guildId]` | 선택한 서버의 진행 중 내전과 최근 경기 요약 |
| `/g/[guildId]/scrims` | 내전 목록과 모집 생성 모달의 진입점 |
| `/g/[guildId]/scrims/[scrimId]` | 모집·참가 현황과 해당 내전의 운영 상태 |
| `/g/[guildId]/scrims/[scrimId]/teams` | 수동 팀 편성 또는 경매, 편성 완료 후 최종 팀과 구매 이력 |
| `/g/[guildId]/scrims/[scrimId]/bracket` | 라운드·대진 구성과 진행 결과 |
| `/g/[guildId]/matches` | 서버 전체 시리즈 검색·목록 |
| `/g/[guildId]/matches/[matchId]` | 시리즈 점수·선택한 Game의 결과와 통계·ROFL 업로드 |
| `/g/[guildId]/players/[userId]` | 해당 서버에서 한 사용자의 누적 전적 |
| `/g/[guildId]/stats` | 서버 전체 누적 통계 |
| `/g/[guildId]/admin` | 해당 서버의 설정·멤버·권한 관리 |

`Scrim`은 모집부터 종료까지의 운영 단위이고, `Match`는 그 안에서 두 팀이 치르는 시리즈다.
서버 전체 경기 기록에서도 직접 진입할 수 있도록 두 경로는 형제로 유지한다.
일반·경매 편성 및 10인·20인 내전은 같은 경로를 사용한다. `/teams`의 작업 방식은 해당 내전의
`formationMethod`에 따르며, 주소를 바꾸는 것으로 편성 방식을 변경하지 않는다.

웹 모집 생성은 모달로 처리하고, Discord 봇에서 만든 내전도 동일한 상세 경로로 진입한다.
별도 경매·모집 생성·ROFL 업로드·수동 결과 입력·밴픽 페이지는 추가하지 않는다.

## 공통 에러 화면

`routes/+error.svelte`에서 403·404와 그 외 페이지 오류를 공통으로 표시한다.
5xx 오류에만 새로고침 버튼을 제공한다.

## 개발용 페이지

홈 하단의 개발 도구 영역은 페이지 바로가기 목록과 분리하며, 컴포넌트 테스트와 에러 미리보기 링크를 제공한다.
두 개발용 페이지는 개발 모드에서만 접근할 수 있고 프로덕션에서는 404를 반환한다.

- `/dev/components`: 컴포넌트를 시험할 빈 작업 공간. 현재는 제목만 표시하며 컴포넌트 예제나 목 데이터는 추가하지 않았다.
- `/dev/error`: 실제 공통 에러 화면 미리보기. 기본값은 404이며 `?status=403` 또는 `?status=500`으로 상태를 선택한다. 그 외 값은 404로 처리한다.

## 참가자 전적의 식별자

- `[userId]`는 `users.id`, 즉 Discord 사용자 ID 문자열이다. Riot 계정 ID나 내전 참가 기록 ID가 아니다.
- 누적 전적은 해당 서버의 과거 `scrim_participants.user_id` 연결을 기준으로 한다. 한 사용자가 여러 Riot 계정으로 참가한 기록을 함께 다룬다.
- `ScrimParticipant.id`는 내전마다 생기는 기록이므로 프로필 URL의 식별자로 사용하지 않는다. 현재 Riot 계정 소유자만으로 과거 참가자를 다시 계산하지도 않는다.
- 사용자와 연결되지 않았거나 사용자 삭제로 연결이 사라진 기록은 경기 결과에 남긴다. 표시 이름이나 Riot ID가 같다는 이유로 특정 사용자에게 합산하지 않는다.

`[playerId]`를 `[userId]`로 바꾸어도 실제 URL 형태인 `/g/서버ID/players/사용자ID`는 동일하다.
현재 조회 로직이 없는 상태이므로 별도의 이전 ID 변환·리다이렉트 경로는 만들지 않는다.

## 레이아웃과 내비게이션의 소유 위치

| 범위 | 목표 위치 | 담당 요소 |
| --- | --- | --- |
| 전역 | `routes/+layout.svelte`, 헤더 선택 영역·`AppFooter` | 전역/서버/내전 헤더 중 하나 표시, 공통 본문 틀·정책 링크 |
| 길드 | `routes/g/[guildId]/+layout.svelte` 추가 예정 | 현재 서버 문맥·하위 페이지 영역, 전역 헤더를 대체할 서버 헤더 정보 |
| 개별 내전 | `routes/g/[guildId]/scrims/[scrimId]/+layout.svelte` 추가 예정 | 현재 내전 문맥·공통 식별 정보, 서버 헤더를 대체할 내전 헤더 정보 |
| 개별 Match | 기존 `[matchId]/+page.svelte` | 시리즈 요약과 Game 선택 탭 |
| 백오피스 | `routes/backoffice/+page.svelte` | 전역 화면 틀을 사용하고 길드 내비게이션은 포함하지 않음 |

현재 경로에 맞는 헤더 전체를 교체한다. 일반 페이지는 `GlobalHeader`, 길드 아래는 `GuildHeader`,
개별 내전 아래는 `ScrimHeader` 중 하나만 표시한다. 기존 전역 헤더 아래에 서버·내전 내비게이션을 쌓지 않는다.
현재 범위 헤더의 홈 이동은 `Monkeybot` 로고 한 곳에 둔다. 서버 선택기와 개인 메뉴도 그 헤더에서만 제공한다.
개인 메뉴는 `/me`와 운영자에게만 제공할 `/backoffice` 진입을 담당한다.
서버 선택기는 선택한 서버의 `/g/[guildId]`로 이동하며, 현재 길드 안에서는 이미 선택된 서버 항목을 다시 이동 가능한 링크로 만들지 않는다.
별도의 서버 목록 페이지는 두지 않는다.

길드 공통 메뉴는 **서버 홈·내전·경기 기록·통계·관리**로 구성한다.
개별 내전의 하위 메뉴는 **요약·팀 편성·대진**으로 구성한다.
길드 메뉴는 서버 헤더에서, 내전 메뉴는 내전 헤더에서 제공한다. 내전에서 서버 전체 목적지로 이동할 때는
내전 헤더의 서버 메뉴를 사용한다. 세 헤더의 공통 도구는 재사용하되 본문에 별도 메뉴 줄을 추가하지 않는다.
메뉴가 제공하는 동일 목적지를 페이지 본문의 이동 버튼이나 푸터에 반복하지 않는다.
목록의 특정 내전·매치·사용자 링크는 서로 다른 개별 대상을 탐색하는 용도로 둔다.

푸터는 문서·이용약관·개인정보 처리방침 링크를 담당한다.
현재 헤더의 별도 홈 메뉴와 푸터의 홈 링크는 제거 대상으로 정한다.
푸터의 워드마크·도메인은 표시용 텍스트로 두어 운영 환경에서도 홈 이동이 중복되지 않도록 한다.
GitHub 저장소 링크는 서비스 업무 메뉴에 포함하지 않는다.
모바일·데스크톱 내비게이션은 동일한 목적지 구성을 사용하되 동시에 노출하거나 조작할 수 없도록 한다.

## Match와 Game 표시

Match 상세 한 곳에서 BO 시리즈와 개별 Game 결과를 다룬다.
선택한 Game은 `?game=<gameId>`에 남겨 같은 화면의 상태를 공유하고 앞뒤 이동으로 복원할 수 있게 한다.
쿼리 값은 해당 Match에 속한 Game만 가리켜야 하며, 기본 선택과 잘못된 선택의 표시 방식은 화면 구현 때 정한다.

ROFL 업로드 진입은 Match 상세에 한 곳만 두고 모달로 처리한다.
업로드 결과는 검증·참가자 연결 후 자동 기록하는 흐름이며 별도 사람 승인 단계를 만들지 않는다.
Game 선택 탭은 결과 조회용이고 게임 내 진행·밴픽을 관리하지 않는다.

## 관리 범위와 이번 단계의 경계

`/g/[guildId]/admin`은 길드별 관리자 권한, `/backoffice`는 `users.isServiceAdmin`에 대응한다.
두 영역의 메뉴와 관리 범위를 분리하며 어느 한 권한을 다른 권한과 자동으로 동일시하지 않는다.
일반 페이지의 열람 범위는 공개 설정과 접근 정책을 함께 따르고, 메뉴 노출은 실제 접근 권한 검사를 대신하지 않는다.

인증·권한 검사, 서버 선택 데이터 조회, 공통 내비게이션, 서비스 레이어·API·DB 변경은
이번 백오피스 빈 페이지 추가에 포함하지 않는다. 위의 운영자 전용 진입과 접근 정책은 구현할 목표다.
