# 라우트·레이아웃·내비게이션

작성일: 2026-10-30. 상태: 목표 구조 확정. 현재 대부분의 페이지는 제목만 있는 빈 페이지다.

## 1. 라우트

```text
/                                        서비스 소개
├── me                                   내 계정·공개 설정
├── docs · terms · privacy               이용 문서·약관·개인정보 처리방침
├── backoffice                           서비스 운영자 영역 (업무 미정)
├── dev/components · dev/error           개발 모드 전용. 운영에서 404
└── g/[guildId]                          서버 홈
    ├── scrims                           내전 목록 + 모집 생성
    │   └── [scrimId]                    모집·참가자·운영 요약
    │       ├── teams                    편성 방식에 따라 manual/auction으로 redirect
    │       │   ├── manual               수동 편성
    │       │   └── auction              경매
    │       └── bracket                  대진
    ├── matches                          서버 경기 기록
    │   └── [matchId]                    시리즈·게임 결과, ROFL 업로드
    ├── players/[userId]                 서버 내 사용자 전적 (현재 폴더명 [playerId] → 변경 예정)
    ├── stats                            서버 통계
    └── admin                            서버 관리
```

별도 페이지로 만들지 않는 것: 서버 목록(헤더의 서버 선택기가 담당), 모집 생성(목록의 팝업), ROFL 업로드(경기 상세의 팝업), 수동 결과 입력, 밴픽.

### 1.1 식별자

| 파라미터 | 값 | 주의 |
| --- | --- | --- |
| `[guildId]` | Discord 서버 ID | `load`에서 접근 권한 확인 후 레이아웃 데이터로 내려준다 |
| `[scrimId]` | `scrims.id` | 다른 서버의 내전이면 404 |
| `[matchId]` | `matches.id` | `Match`는 내전 하위가 아니라 서버 하위. 대진·경기 기록 양쪽에서 진입 |
| `[userId]` | `users.id` (Discord 사용자 ID) | Riot 계정 ID·참가 기록 ID를 받지 않는다. 사용자 연결이 없는 과거 참가 기록은 링크를 만들지 않는다 |

### 1.2 `/teams` 진입 규칙

`load`에서 `scrims.formationMethod`를 읽어 처리한다.

| 상황 | 결과 |
| --- | --- |
| `/teams` + 방식 `manual`/`auction` | 해당 하위 경로로 `redirect(307)` |
| `/teams` + 방식 미정 | 페이지를 렌더링해 "편성 방식이 정해지지 않음"과 결정 위치(내전 요약)를 표시 |
| `/teams/manual`인데 방식이 `auction` (또는 반대) | 실제 방식 경로로 `redirect(307)` |

URL로 편성 방식을 바꾸지 않는다. 10인·20인 구분용 경로는 없다.

### 1.3 URL 상태

새로고침·공유·뒤로가기로 복원해야 하는 상태만 쿼리에 둔다. 그 외(팝업 열림, 선택 행)는 컴포넌트 상태다.

| 페이지 | 쿼리 | 기본값 |
| --- | --- | --- |
| 내전 목록 | `status=all\|recruit\|active\|done`, `page` | `all`, `1` |
| 경기 기록 | `q`, `status`, `page` | 없음, `all`, `1` |
| 경기 상세 | `game=<gameId>` | 결과가 있는 마지막 게임. 없거나 다른 경기의 게임이면 쿼리를 무시하고 기본값 |
| 사용자 전적 | `position`, `page` | 전체, `1` |
| 서버 통계 | `range` | 미결정 (기간·시즌) |

쿼리 변경은 `goto(url, { reset: false })`로 하고, `load`가 쿼리를 읽어 데이터를 다시 준비한다. 검색어 입력은 제출(Enter) 시에만 반영한다.

## 2. 레이아웃 계층

```text
routes/+layout.svelte                    ConfigProvider(ko_KR) · Feedback · AppHeader · <main> · AppFooter
└── g/[guildId]/+layout.server.ts        서버 정보·내 권한 → data.guild
    └── scrims/[scrimId]/+layout.server.ts  내전 요약 → data.scrim
        └── +layout.svelte               ScrimSummary + 하위 페이지
```

- 헤더는 루트 레이아웃 **한 곳**에서 렌더링한다. 하위 레이아웃은 헤더를 그리지 않고 `page.data`에 `guild`·`scrim`을 넣기만 한다.
- `AppHeader`는 `page.data.scrim` → `page.data.guild` → 없음 순으로 범위를 정해 메뉴를 바꾼다. 헤더를 겹쳐 쌓지 않는다.
- 경기 상세(`/matches/[matchId]`)는 내전 레이아웃 밖이므로 서버 범위 헤더를 쓴다. 소속 내전은 본문에서 링크로 보여 준다.
- `ScrimSummary`는 내전 하위 세 페이지(요약·팀 편성·대진) 위에 한 번만 표시한다. 내전 제목·상태·예정 시각은 여기에만 쓴다.

## 3. 헤더

### 3.1 구성

`AppHeader` 하나가 범위에 따라 가운데 메뉴만 바꾼다. 컴포넌트 선택 근거는 [design-system.md](design-system.md#5-서비스-공통-컴포넌트).

```text
데스크톱 (≥1024px), STDF NavBar  line=false
┌──────────────────────────────────────────────────────────────────────────────┐
│ [로고 Monkeybot] │ 범위 메뉴 링크들 ...          [서버명 ▾] [☀/☾] [계정 ▾] │
└──────────────────────────────────────────────────────────────────────────────┘
 leftChild: 로고              titleChild: ContextNav      rightChild: 서버 선택·화면 모드·계정

모바일 (<1024px)
┌──────────────────────────────────────┐
│ [로고]                [서버명 ▾] [≡] │
└──────────────────────────────────────┘
[≡] → Popup position="right": 범위 메뉴 → (내전 범위면) 서버 메뉴 → 계정 → 화면 모드
```

| 범위 | 조건 | 범위 메뉴 |
| --- | --- | --- |
| 전역 | `guild` 없음 | 없음 |
| 서버 | `guild` 있음 | 서버 홈 · 내전 · 경기 기록 · 통계 · 관리(서버 관리자만) |
| 내전 | `scrim` 있음 | 요약 · 팀 편성 · 대진 — 그리고 데스크톱에서는 메뉴 끝의 `서버 ▾` 버튼이 ActionPopover로 서버 메뉴를 연다 |

### 3.2 규칙

- 홈 이동은 로고 한 곳. 헤더·푸터에 별도 "홈" 링크를 두지 않는다. GitHub 링크는 제품 화면에서 제거한다.
- 범위 메뉴 항목은 `<a>`이고 현재 항목에 `aria-current="page"`를 둔다. 팀 편성 메뉴는 `/teams`를 가리키고 `/teams/manual`·`/teams/auction`에서도 현재 항목으로 표시한다.
- 서버 선택기에서 현재 서버는 선택 표시만 하고 이동 동작을 두지 않는다. 서버 선택은 그 서버의 홈(`/g/[id]`)으로 이동한다.
- 계정 메뉴: `내 정보`(`/me`) · `백오피스`(서비스 운영자만) · `로그아웃`(인증 구현 후). 비로그인이면 계정 메뉴 대신 `Discord로 로그인` 버튼 하나(인증 구현 후). 서버 선택기는 로그인했을 때만 표시.
- 화면 모드 전환은 데스크톱은 헤더 아이콘 버튼, 모바일은 메뉴 패널의 Cell+Switch 한 곳. 두 변형은 같은 시점에 렌더링하지 않는다.
- 모바일 메뉴 패널이 열려 있으면 서버 선택기 패널을 열지 않는다(하나의 오버레이만). 메뉴 항목을 누르면 패널을 닫고 이동한다.
- 헤더만 `sticky top-0`. 하단 탭바·플로팅 버튼·본문 내 보조 메뉴 줄을 두지 않는다.

### 3.3 푸터

`AppFooter`: 왼쪽 `Monkeybot` 워드마크와 도메인(텍스트, 링크 아님), 오른쪽 `문서 · 이용약관 · 개인정보 처리방침` 링크. 그 외 링크를 추가하지 않는다.

## 4. 오류·개발 페이지

| 경로 | 동작 |
| --- | --- |
| `routes/+error.svelte` | 403·404·그 외 공통 화면. 5xx에만 `다시 시도` 버튼. 검증된 서버 문맥이 없으면 전역 헤더 |
| `/dev/error?status=403\|500` | 공통 오류 화면 미리보기. 그 외 값은 404 |
| `/dev/components` | STDF 컴포넌트·서비스 컴포넌트의 상태별 검증 공간. 화면에 쓰기 전 여기서 키보드·다크 모드·모바일을 확인 |

두 개발 페이지는 `dev`가 아니면 `error(404)`. 홈의 개발 바로가기 목록도 `dev`에서만 렌더링한다.
