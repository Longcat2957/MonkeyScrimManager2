# 서버 홈·길드 관리 UI/UX 구성안

작성일: 2026-10-29. 상태: 구현 전 구성안. 컴포넌트나 UI 코드는 작성하지 않는다.

[공통 UI 계획](../ui-plan.md)과 [페이지 요구사항](../pages/guild.md)을 따른다.
배치·컴포넌트 책임·조작 흐름은 이번 설계안이며, 열람 범위와 관리자 정책의 확정을 뜻하지 않는다.
공통 셸은 `GuildHeader → 본문 → 푸터`다. `GuildHeader`가 전역 헤더 전체를 대체한다.
루트 헤더 영역은 `GlobalHeader`·`GuildHeader`·`ScrimHeader` 중 하나만 표시하며 고정한다.
로고·서버 선택기·계정 도구는 각 헤더 내부에서 공통 구현을 재사용한다. 헤더 아래 별도 길드 메뉴 줄은 추가하지 않는다.
본문에 서버 선택·서버 이름·내비게이션을 다시 배치하지 않는다.

## 1. `/g/[guildId]` — 서버 홈

### 목표·우선순위

1. 지금 확인할 내전을 선택한다. 진행 중 내전 영역을 본문의 첫 업무 영역으로 둔다.
2. 최근 기록된 시리즈를 확인한다. 최근 경기는 내전 영역 다음에 둔다.
3. 전체 목록·설정·통계 탐색은 `GuildHeader`가 담당한다. 요약 위의 지표 카드나 별도 업무 바로가기를 만들지 않는다.

`서버 홈` 제목은 페이지 식별용으로 짧게 표시한다. 서버 이름·아이콘은 헤더의 현재 서버 표시를 사용한다.
표시 개수·정렬·진행 중 범위는 조회 정책에서 정하며, 홈이 목록 전체를 대신하지 않는다.

### 데스크톱 배치

```text
GuildHeader: 로고 | 현재 서버·서버 선택 | 서버 메뉴 | 개인 메뉴·화면 모드
본문
  서버 홈
  진행 중 내전
  ┌ ScrimList ──────────────────────────────────────────┐
  │ 내전 제목                     운영 상태             │
  │ 예정 시각·편성 방식            신청·선발 현황        │
  │ 다음 내전 …                                        │
  └────────────────────────────────────────────────────┘
  최근 경기
  ┌ MatchList ──────────────────────────────────────────┐
  │ 두 팀·시리즈 점수              결과 상태·기준 시각   │
  │ 다음 시리즈 …                                      │
  └────────────────────────────────────────────────────┘
공통 푸터
```

- 넓은 화면에서도 두 목록을 좌우로 나누지 않는다. 현재 내전을 읽고 결과로 내려가는 순서를 유지한다.
- 내전·시리즈마다 조작 가능한 링크는 하나다. 제목 링크와 행 전체 클릭·입장 버튼을 겹치지 않는다.
- 홈의 목록 행에는 참가 신청·편성·업로드 버튼을 넣지 않는다. 상세에 진입한 뒤 현재 권한과 상태를 확인한다.

### 모바일 배치

- 같은 DOM과 같은 목록을 사용한다. `GuildHeader`는 공통 모바일 규칙을 따르고 본문은 한 열로 유지한다.
- 각 행의 제목·팀명을 먼저, 상태·인원·시각을 다음 줄에 놓는다. 긴 팀명은 줄바꿈하며 점수와 팀의 대응을 유지한다.
- 행 전체를 하나의 링크로 구성하는 경우 내부는 표시 정보만 둔다. 중첩 링크·버튼을 만들지 않는다.
- 두 번째 메뉴·하단 탭·고정 업무 버튼을 추가하지 않는다. 순서 변경이나 가로 스와이프 없이 두 목록에 접근한다.

### 컴포넌트 책임

| 컴포넌트 | 책임·입력 | 사용자 행동 | STDF 조합·재사용 |
| --- | --- | --- | --- |
| 서버 홈 페이지 | 현재 서버의 내전·최근 Match 요약과 각 조회 상태를 조립 | 개별 상세 선택 | 본문 조립만 담당. 조회·목 데이터 생성은 하지 않음 |
| `ScrimList` | 내전 요약 배열과 상세 URL. 홈에서는 조회 결과만 전달 | 내전당 단일 링크 | 내전 목록 페이지와 공유. 의미 있는 목록·링크 사용, 본문 전용 생성 조작을 포함하지 않음 |
| `MatchList` | 팀·점수·상태·시각과 상세 URL | Match당 단일 링크 | 경기 기록 페이지와 공유. 같은 표현 책임에 한해 행 구성 공유 |
| 각 목록의 대기 표현 | 실제 목록 행의 구조·대기 여부 | 없음 | STDF `Skeleton`의 `type`, `width`, `height` 범위 사용. 가상 인원·점수를 넣지 않음 |
| 각 목록의 상태 영역 | 빈 상태·실패 이유·재조회 가능 여부 | 실패 영역 재조회가 가능할 때만 실행 | 지속 문장과 STDF `Button`. 동일 안내를 상단 배너로 반복하지 않음 |

STDF 3.0.0 `List`는 각 항목을 항상 버튼으로 감싸므로 실제 링크를 내부에 넣지 않는다.
`ScrimList`·`MatchList`는 링크 의미와 새 탭 열기를 보존하는 일반 목록·앵커를 사용한다.
이 예외는 탐색 행에 한정한다. 일반 버튼·대기 표현을 별도 디자인 시스템으로 재구현하지 않는다.

### 흐름·상태

| 상황 | 표시·조작 흐름 |
| --- | --- |
| 처음 진입 | 서버 접근 확인 후 각 영역 대기 표현 → 조회된 목록. 로딩 중 빈 상태 안내를 보이지 않음 |
| 두 영역 중 하나만 성공 | 성공 영역 유지. 실패 영역에 이유와 허용된 재시도 한 곳 제공 |
| 내전 또는 경기 없음 | 해당 제목 아래 빈 상태 한 문장. 모집 생성·전체 목록 버튼을 새로 넣지 않음 |
| 내전·Match 선택 | 선택한 상세로 이동. 상세에서 최신 상태와 접근 권한 재검사 |
| 다른 서버 선택 | 공통 선택기로 새 서버 홈 진입. 이전 서버의 결과가 새 제목 아래 남지 않도록 처리 |
| 권한 없음·서버 없음 | 본문 요약을 노출하지 않고 공통 접근 오류 처리 |

### 미정 정책의 배치 영향

| 미정 항목 | 확정 후 조정할 부분 |
| --- | --- |
| 진행 중 상태 범위·정렬·개수 | 첫 목록에 포함할 데이터. 배치와 상세 진입 위치는 유지 |
| 최근 경기의 완료 조건·기준 시각 | 점수 옆 상태·시각의 의미. 업로드 시각을 경기 시각으로 바꾸어 쓰지 않음 |
| 외부인 열람·공개 범위 | 반환할 목록과 표시 정보. 잠금 표시로 원문 노출을 대신하지 않음 |
| 갱신 시점·재조회 방식 | 각 목록의 갱신·실패 상태. 자동 갱신을 이유로 추가 고정 버튼을 만들지 않음 |

## 2. `/g/[guildId]/admin` — 길드 관리

### 목표·우선순위

1. 실제 운영에 쓰는 서버 설정을 확인하고 변경한다.
2. 현재 서비스 멤버와 길드 관리자 권한을 확인하고 허용된 변경을 수행한다.
3. 개별 내전 운영과 서비스 전체 관리는 각 담당 페이지에 남긴다.

화면은 `서버 관리` 제목, 확정된 설정, 멤버·권한의 순서다. 제공할 설정이 없으면 설정 영역 전체를 생략한다.
Discord 모집·결과 채널은 아래 배치의 **조건부 후보**다. 기능이 확정되기 전 비활성 예시 폼으로 제품에 노출하지 않는다.

### 데스크톱 배치

```text
GuildHeader: 서버 메뉴에서 관리가 현재 위치
본문
  서버 관리
  게시 설정                         ← 기능 채택 시에만
    모집 채널   [현재 선택값 또는 미설정 ▾]
    결과 채널   [현재 선택값 또는 미설정 ▾]
    입력 오류·저장 결과              [변경 취소] [저장]
  멤버·권한
    사용자 표시 정보                현재 길드 권한    [권한 변경]
    사용자 표시 정보                현재 길드 권한    [권한 변경]
  권한 변경 Dialog                  ← 요청한 대상 한 명만
    대상 사용자·현재 권한 → 변경 권한
    검증 오류 또는 처리 상태        [취소] [구체적인 변경 행동]
공통 푸터
```

- 설정과 멤버 목록은 세로로 배치한다. 짧은 설정을 위해 별도 사이드바·탭·앵커 메뉴를 만들지 않는다.
- 설정 저장은 해당 폼 아래 한 곳이다. 페이지 상단이나 고정 하단에 같은 저장 동작을 복제하지 않는다.
- 권한은 켜는 즉시 저장되는 스위치보다 대상과 변경을 확인할 수 있는 단일 행 버튼·Dialog 흐름을 사용한다.
- 멤버 표시 정보는 식별용이다. 이 페이지에서 추가할 목적이 없는 프로필 탐색 링크·추방·계정 수정 메뉴를 붙이지 않는다.

### 모바일 배치

- 설정의 라벨과 입력을 위아래로 놓고, 저장·취소는 폼 끝에서만 제공한다.
- 멤버 행은 `사용자 표시 정보 → 현재 권한·권한 변경`으로 줄바꿈한다. 표를 가로 스크롤하게 만들지 않는다.
- Dialog는 화면 안에서 내용과 두 행동을 읽을 수 있게 배치하고 같은 인스턴스를 사용한다. 모바일용 두 번째 편집창을 만들지 않는다.
- 입력 후 스크롤해도 헤더 외 고정 요소가 폼과 오류를 가리지 않아야 한다. 키보드 이동 순서는 표시 순서와 같다.

### 컴포넌트 책임

| 컴포넌트 | 책임·입력 | 사용자 행동 | STDF 조합·재사용 |
| --- | --- | --- | --- |
| 길드 관리 페이지 | 서버 범위·관리 권한·설정·멤버 조회 결과 조립 | 영역별 편집 | 관리 전용 상태를 전달. 개별 내전 운영을 호출하는 만능 패널로 만들지 않음 |
| 게시 설정 폼 | 채택된 설정의 저장값·편집값·허용 채널·검증 결과 | 값 선택, 변경 취소, 저장 | 라벨을 연결한 브라우저 `select`와 STDF `Button`. 실제 설정이 확정될 때 구현 |
| 멤버 목록 | 멤버 식별 정보·현재 길드 권한·변경 가능 여부 | 대상별 권한 변경 한 곳 | 일반 목록 + 표시 전용 `ParticipantIdentity` + STDF `Button`. STDF `List` 안에 버튼을 중첩하지 않음 |
| `ParticipantIdentity` | 공개 범위가 적용된 이름·이미지, 링크 없는 표시 모드 | 없음 | 참가자 명단·경기 결과와 식별 표현 공유. 멤버에게 내전 참가 ID를 요구하지 않음 |
| 권한 변경 Dialog | 대상·현재/변경 권한·요청 상태 | 확인 후 변경, 취소 | STDF `Dialog`: `contentChild`, `primaryText`, `secondaryText`, `onprimary`, `primaryButton`, `secondaryButton` |
| 영역별 대기·결과 | 조회/저장 상태와 실패 대상 | 허용된 재시도 | `Skeleton`, `Button`과 지속 상태 문장. 닫히는 알림으로 저장 실패를 대체하지 않음 |

채널 선택은 접근 가능한 단일 선택의 한정 예외로 브라우저 `select`를 사용한다.
설치된 `Picker`의 `ScrollRadio`는 항목별 키보드 선택과 선택 상태의 접근성 연결을 제공하지 않으므로 그대로 채택하지 않는다.
채널 ID를 값으로 유지하고 이름을 라벨로 표시한다. 미설정 옵션은 정책이 허용할 때만 포함한다.
`Dialog`는 저장 성공 전 자동으로 닫지 않는다. `primaryButton.disabled` 등 실제 버튼 옵션으로 중복 요청을 막는다.
배경 비활성화·접근 가능한 대화상자 이름·포커스 이동/복귀는 공통 오버레이 계약으로 보완한다. 공개 API에 없는 prop을 가정하지 않는다.

### 흐름·상태

| 상황 | 표시·조작 흐름 |
| --- | --- |
| 접근·현재값 확인 | 권한 검증 후 조회. 대기 중 기본값을 저장값처럼 보여 주거나 변경을 허용하지 않음 |
| 설정 편집 | 저장값을 편집값으로 복사 → 입력 변경 → 폼 끝 저장. 변경 취소는 마지막 확인된 저장값 복원 |
| 설정 저장 성공 | 서버 확정값을 새 기준으로 반영. 폼의 결과 영역 한 곳에 완료 피드백 제공 |
| 설정 검증 실패 | 입력 가까이에 오류를 연결하고 편집값 유지. 채널 조회 실패는 미설정과 구분 |
| 권한 변경 | 대상 행 버튼 → 대상·변경 내용 확인 → 요청 → 성공 시 Dialog 닫고 해당 행 갱신 |
| 권한 변경 실패 | Dialog 안에서 실패 이유와 현재 권한 유지. 성공한 것처럼 목록 권한을 먼저 바꾸지 않음 |
| 응답 유실·다른 관리자 변경 | 실제 저장 상태 확인 전 반복 요청하지 않음. 새 값 확인 후 사용자가 변경을 재검토 |
| 작업 중 권한 회수 | 추가 요청을 차단하고 공통 접근 정책 적용. 이전 데이터·메뉴를 변경 권한의 근거로 사용하지 않음 |
| 멤버 없음·조회 실패 | 빈 결과와 실패를 분리. 멤버 초대·등록 기능을 대신 추가하지 않음 |

### 미정 정책의 배치 영향

| 미정 항목 | 확정 후 조정할 부분 |
| --- | --- |
| 최초 관리자·위임·자신/마지막 관리자 보호 | 행별 변경 가능 여부와 Dialog의 검증·설명. 모든 멤버에게 버튼을 무조건 활성화하지 않음 |
| 편집할 설정과 채널 게시 기능 | 실제 폼의 존재·라벨·선택지. 스키마 전체를 설정 메뉴로 만들지 않음 |
| 채널 미설정·삭제·봇 권한 상실 | 미설정 선택 허용과 오류 복구. 임의 대체 채널로 저장하지 않음 |
| 설정 적용 시점·진행 중 내전에 미치는 영향 | 저장 전에 필요한 영향 설명. 기존 게시물 전체 갱신을 기본 동작으로 가정하지 않음 |
| 멤버 규모·조회 방식 | 필요한 경우에만 탐색 도구 추가. 검색·페이지 이동·일괄 권한 변경을 지금 확정하지 않음 |

## STDF 확인 범위

설치 버전 `stdf@3.0.0`의 선언과 `Button`, `Dialog`, `List`, `Skeleton`, `Picker`, `ScrollRadio`, `Popup` 소스를 확인했다.
실제 사용 후보는 `Button`·`Dialog`·`Skeleton`이며, 목록·선택의 예외는 위의 확인된 구조와 키보드 요구에 한정한다.
`Table`·`Select`·`Drawer`라는 STDF 컴포넌트가 있다고 가정하지 않는다. 검증되지 않은 옵션이나 자동 접근성 동작을 약속하지 않는다.
