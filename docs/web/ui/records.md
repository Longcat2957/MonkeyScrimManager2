# 경기 기록·전적·통계 UI 구성안

상태: 컴포넌트 책임과 배치를 정하는 설계 초안. UI 코드·스타일·API를 구현하지 않는다.
업무 범위는 [기록 페이지 명세](../pages/records.md), 공통 셸·토큰·상태 처리는 [UI 구성 계획](../ui-plan.md)을 따른다.
아래 지표와 필터는 첫 화면 구성을 위한 **추천안**이며, 기존 정책으로 확정된 사항과 구분한다.

## 공통 구성 기준

- 네 경로 모두 `GuildHeader` → 본문 → 푸터 순서다. `GuildHeader`가 전역 헤더 전체를 대체하며 별도 길드 메뉴 줄은 없다.
- 로고·서버 선택·개인 메뉴는 헤더 내부에서 재사용한다. 헤더는 한 종류만 렌더링하고, 고정도 해당 헤더 한 곳에만 적용한다.
- Match 상세는 내전 레이아웃의 자식이 아니다. 요약·팀 편성·대진 메뉴를 이 페이지에 복제하지 않는다.
- 페이지 제목과 현재 조회 범위를 먼저 읽고, 바로 아래에서 검색·내용 선택을 수행한다. 별도의 사이드바나 하단 탭은 두지 않는다.
- 목록·수치 묶음은 제목·간격·얇은 경계선으로 구분한다. 빈 상태·작은 수치마다 큰 Card를 만들지 않는다.
- 완료·취소·보류는 텍스트로 구분한다. 색은 보조 신호이며, 점수의 크기만으로 승자를 추정하지 않는다.
- 필요한 데이터를 페이지에서 준비해 서비스 컴포넌트에 전달한다. 아래 컴포넌트가 목 데이터 위치나 조회 API를 직접 결정하지 않는다.

| 공통 책임 | 입력·행동 | 구성과 재사용 범위 |
| --- | --- | --- |
| `MatchList` | 권한 처리된 시리즈 요약·개별 URL을 받아 시리즈 탐색 | 서버 홈과 경기 목록에서 재사용. 검색·페이지 이동은 부모 책임 |
| `ParticipantIdentity` | 당시 표시명·허용된 이미지·선택적 사용자 URL | 모집 명단·성적표의 공통 식별 표시. 이미지와 이름을 한 링크로 묶거나 정적 표시 |
| `RecordScopeControl` | 기간·시즌 등 실제 제공하는 범위 옵션과 선택값, 변경 행동 | 개인·서버 통계에서 범위 선택 책임이 같을 때 재사용. 다른 필터를 한 만능 폼으로 합치지 않음 |
| `TaskDialog` | 제목·본문·요청 상태·닫기 가능 여부와 제출/닫기 의도 | 모집·계정 연결·ROFL이 공유하는 Popup 기반 작업 패널. 포커스·배경 차단·닫기 규칙은 이 공통 책임에 모음 |
| 작업별 상태 영역 | 현재 작업 상태·사유·가능한 복구 행동 | 공통 상태 규칙을 적용하되 문맥별 문구와 복구 책임은 해당 작업이 보유 |

설치 STDF의 List·Cell·Avatar는 내부에 button을 사용한다. 링크를 감싸거나 행 안에 여러 행동을 넣지 않는다.
따라서 `MatchList`는 의미 있는 `ul/li`와 한 개의 `a`, `ParticipantIdentity`는 정적 이미지·텍스트와 선택적 `a`를 사용한다.
이는 같은 기능을 다시 구현하는 선택이 아니라, 설치 버전에서 링크 의미와 중첩 조작 방지를 충족하기 위한 예외다.
상태·기간·시즌의 단일 선택은 라벨을 연결한 native select를 사용한다. 설치 Picker의 키보드 선택·선택 상태 전달 한계에 따른 예외이며 별도 선택 Popup을 추가하지 않는다.

## 1. `/g/[guildId]/matches` — 경기 목록

### 목표·우선순위

1. 찾는 시리즈를 검색하고 두 팀·점수·상태를 비교한다.
2. 한 시리즈를 선택해 상세 결과로 이동한다.
3. 검색 조건과 목록 위치를 유지해 여러 기록을 이어서 탐색한다.

첫 검색 추천은 내전명·팀명 검색과 상태 필터다. 참가자 신상 검색은 공개 정책 합의 전 범위에 넣지 않는다.

### 데스크톱 배치

```text
경기 기록
검색어 Input ───────────── 상태 select                  조회 Button
조회 결과 수·현재 범위
──────────────────────────────────────────────────────────────
내전·시각     팀 A       점수       팀 B       BO·상태      ↗
다음 시리즈 …                    MatchList
──────────────────────────────────────────────────────────────
                        Pagination
```

- 시리즈 한 행 전체가 하나의 링크다. 팀명·점수·화살표를 같은 목적지의 독립 링크로 만들지 않는다.
- 내전명은 목록의 구분 정보로 표시한다. 별도 내전 탐색이 필요하면 상세에서 소속 내전을 한 번 연결한다.
- 필터 영역은 목록 위 한 곳에 둔다. 결과 없음 영역에 두 번째 검색·조건 초기화 조작을 추가하지 않는다.

### 모바일 배치

- 검색어가 첫 줄을 채우고, 다음 줄에 상태 선택과 조회를 배치한다. 조작 순서는 데스크톱과 같다.
- 같은 `MatchList` 행을 두 줄로 재배치한다. 첫 줄은 두 팀·점수, 둘째 줄은 내전·시각·상태다.
- 긴 팀명은 줄바꿈한다. 점수를 화면 밖으로 밀거나 팀명을 의미 없이 잘라내지 않는다.
- Pagination은 목록 끝 한 곳에 두고 최대 노출 페이지 수를 줄인다. 무한 스크롤과 동시 제공하지 않는다.

### 컴포넌트 책임

| 서비스 컴포넌트 | 책임·입력 | 행동 | STDF 조합·재사용 |
| --- | --- | --- | --- |
| `MatchSearch` | 검색 초안·적용 조건·필터 옵션·조회 중 여부 | 조회 실행, 조건 편집 | Input + Button + native select 예외. 경기 목록 전용 |
| `MatchList` | 시리즈 요약·상태·허용 URL | 단일 시리즈 링크 이동 | 의미 있는 목록·링크 예외. 서버 홈과 공용 |
| 페이지 이동 영역 | 전체 건수·현재 페이지·페이지 크기 | 페이지 변경 | Pagination 직접 사용. 불필요한 서비스 래퍼 없음 |

### 흐름·상태

| 상황 | 화면과 다음 행동 |
| --- | --- |
| 최초 조회 | 목록 모양의 Skeleton. 조회 결과 수를 0으로 먼저 표시하지 않음 |
| 검색 | 입력 후 조회 또는 Enter로 같은 요청 실행. 조합 중인 한국어 입력을 먼저 제출하지 않음 |
| 조건 변경·페이지 이동 중 | 필터 유지, 결과 영역에 Loading과 적용 중 상태. 이전 결과의 조건을 혼동하지 않게 구분 |
| 기록 자체 없음·검색 결과 없음 | 목록 자리에 각각 한 문장. 필터·조회는 기존 위치에 유지 |
| 목록 조회 실패 | 목록 영역의 사유와 재시도 한 곳. 서버 접근 자체 실패는 공통 오류 화면 |
| 상세에서 돌아옴 | 적용 조건·페이지·행 위치 복원. 상단에 동일 목록으로 가는 추가 버튼을 두지 않음 |

### 미정 정책의 배치 영향

- 검색 대상·상태 옵션·정렬·페이지 크기는 미정이다. 검색 행과 목록·페이지 이동의 위치는 유지한다.
- 추천 방식은 페이지 번호 탐색이다. 총량 조회가 불가능한 계약을 채택하면 하단 탐색 영역만 재설계한다.
- 실제 경기 시각 미확인 시 업로드 시각을 경기 시각처럼 쓰지 않는다. 시각 종류에 맞는 라벨을 해당 행에서 한 번 제공한다.

## 2. `/g/[guildId]/matches/[matchId]` — 시리즈·Game 결과

### 목표·우선순위

1. 두 팀의 시리즈 점수와 정상 종료·중도 종료 여부를 확인한다.
2. Game을 골라 실제 출전자·성적·최종 세팅을 읽는다.
3. 권한 보유자는 ROFL을 제출하고 자동 등록 결과 또는 예외를 확인한다.

### 데스크톱 배치

```text
소속 내전 링크 · 시리즈 이름                       ROFL 등록 Button
팀 A                       1 : 0                       팀 B
BO·시리즈 상태
───────────────────────────────────────────────────────────────
GameSelection: 1경기 | 2경기 | …
선택한 경기 결과 · 승리 진영 · 경기 길이
┌─ 기본 성적표: 본문 2/3 ──────────┬─ 상세 성적: 본문 1/3 ──────┐
│ 팀·진영·결과                    │ 선택한 참가자               │
│ 참가자 / K·D·A / CS / 상세     │ 전투·경제·시야 수치         │
│ 다른 팀·진영·결과              │ 최종 아이템·주문·룬         │
└─────────────────────────────────┴────────────────────────────┘
하드 피어리스 사용 이력: 적용 시 해당 Match의 이전 경기 기록
```

- 소속 내전 링크는 Match에서 내전 문맥을 되찾는 한 곳이다. 길드 메뉴의 경기 기록 링크를 본문에 복제하지 않는다.
- 기본 성적표는 한 개의 의미 있는 table로 만들고 팀별 행 그룹과 헤더를 구분한다. 표 전체를 버튼으로 만들지 않는다.
- 첫 추천 열은 참가자·챔피언·확인된 포지션, K/D/A 원수치, CS, 상세 행동이다. 복잡한 파생 지표는 기본 열에서 제외한다.
- CS 합계는 미니언·정글 CS가 모두 확인된 경우만 계산한다. 일부 값이 없으면 합계 미확인으로 표현한다.
- 상세 영역에는 기본 표의 K/D/A·CS를 반복하지 않고 추가 수치와 최종 세팅만 둔다. 선택 전에는 상세 볼 참가자를 선택하라는 한 문장만 표시한다.
- 피어리스 안내는 적용되는 시리즈에서만 결과 아래에 둔다. Game 탭이나 업로드 안내에 같은 사용 목록을 반복하지 않는다.

### 모바일 배치

- 제목 → 시리즈 점수 → 업로드 진입 → Game 선택 → 선택 결과 → 성적표 순서다. 업로드 진입은 재배치하며 복제하지 않는다.
- Game 선택은 STDF의 가로 overflow로 처리한다. 화면에 들어오지 않는 항목이 있음을 보이고 키보드 포커스 항목도 확인 가능하게 한다.
- 성적표는 같은 데이터·한 개의 표를 유지한다. 참가자 셀의 이미지·이름·챔피언을 줄바꿈하고 추가 수치는 상세 영역으로 분리한다.
- 작은 폭에서 표가 넘치면 이름 있는 표 영역 안에서만 가로 탐색한다. 페이지 전체를 가로 스크롤하게 만들지 않는다.
- 상세 영역은 선택한 참가자의 기본 행 바로 다음에 한 번 표시하는 흐름으로 바꾼다. 데스크톱 오른쪽 상세와 동시에 조작할 수 없게 한다.
- 상세 선택·닫기 후 해당 행과 포커스를 유지한다. 모바일에서도 표 아래 끝까지 내려가서 선택 결과를 찾아야 하는 구조는 피한다.

### 컴포넌트 책임

| 서비스 컴포넌트 | 책임·입력 | 행동 | STDF 조합·재사용 |
| --- | --- | --- | --- |
| `MatchSummary` | 두 팀·완료 Game 점수·BO·시리즈 상태·내전 URL | 소속 내전 이동 | 정적 제목·점수·상태와 단일 링크. 상세 전용 |
| `GameSelection` | Game 목록·유효한 선택 ID | Game 선택, URL 쿼리 동기화 | Tabs/Tab의 내용 선택. 라우트 메뉴로 사용하지 않음 |
| `GameScoreboard` | 팀별 실제 출전 기록·열람 허용 사용자 URL | 사용자 전적 링크, 별도 상세 선택 | semantic table + ParticipantIdentity + Button. 상세 전용 |
| `ParticipantGameDetail` | 선택 출전자의 추가 통계·세팅·누락 여부 | 상세 닫기 | 정의 목록·이미지 + Button. 데스크톱/모바일 공용 책임 |
| `RoflUpload` | 대상 시리즈·등록 가능 범위·처리 상태 | 파일 선택·등록·복구·닫기 | TaskDialog(Popup) + Button + Loading, native file input 예외 |
| 피어리스 이력 영역 | 적용 여부·이전 Game의 검증된 사용 챔피언 | 이력 읽기 | 정적 목록. 존재만으로 별도 서비스 래퍼를 만들지 않음 |

`ParticipantIdentity`의 사용자 전적 이동과 상세 성적 선택은 다른 행동이다. 이름은 링크, 상세는 설명된 Button으로 분리한다.
같은 사용자가 한 Game에서 여러 표현에 등장해도 전적 링크는 기본 성적표의 식별 표시 한 곳에만 둔다.

### 흐름·상태

#### 결과 조회

- 유효한 Game 선택은 `?game=<gameId>`와 동기화한다. 새 Game 선택 시 이전 참가자 상세 선택은 해제한다.
- 추천 기본 선택은 결과가 있는 Game 중 순번이 가장 큰 경기이며, 결과가 없으면 가장 앞 순번이다. 잘못된 쿼리는 선택 오류와 유효 Game 선택 줄을 남기고 사용자가 선택하게 한다. 이는 정책 확정 전 구현 조건인 제안이다.
- 조회 실패는 결과 영역에서 재시도한다. 시리즈 요약까지 읽을 수 없는 경우 공통 오류 화면으로 전환한다.
- Game이 없으면 선택 탭·빈 성적표를 생성하지 않는다. 결과 없는 Game에는 결과 대기 상태만 표시하며 승패를 입력하는 조작은 추가하지 않는다.
- 부분 통계·아이콘 매핑 실패는 해당 셀·항목에서 미확인으로 표시한다. 알려진 성적까지 모두 숨기지 않는다.
- MMR 보류는 결과 등록 실패와 구분해 해당 경기 결과 상태에 한 번 표시한다. 업로드를 다시 하라는 일반 해결책을 붙이지 않는다.

#### ROFL 모달 배치와 처리

```text
ROFL 등록
대상 시리즈·등록할 경기 문맥
ROFL 파일 [운영체제 파일 선택]   선택한 파일명
입력 또는 처리 상태: 필요한 원인·결과 한 곳
                                      닫기   등록
```

- 이 페이지의 업로드 Button 하나로 공통 `TaskDialog`를 연다. 데스크톱은 읽기 폭을 제한한 중앙 패널, 모바일은 좌우 여백과 세로 스크롤을 갖춘 같은 패널이다.
- `TaskDialog`가 Popup의 `children`으로 제목·본문·하단 작업을 조립한다. ROFL은 파일 입력·검증 상태와 제출/닫기 의도를 전달하며, 별도 모달 래퍼를 만들지 않는다.
- 제출과 닫기는 하단 Button 두 개만 둔다. Popup의 `maskClosable=false`로 마스크 클릭 닫기를 끄며, 제목 옆 X를 중복 제공하지 않는다.
- 미제출 파일을 잃는 닫기는 `TaskDialog`의 공통 미저장 처리 규칙을 적용한다. 닫기가 완료되면 선택 파일을 해제한다.
- 모달 안의 파일 선택은 라벨을 연결한 native file input 한 곳이다. 별도 드롭존·중복 파일 선택 Button은 첫 범위에 넣지 않는다.
- 배경 조작 차단·초기 포커스·포커스 유지·Escape·닫은 뒤 업로드 Button 복귀는 `TaskDialog`의 공통 책임이다. ROFL 작업에서 같은 처리를 별도로 구현하지 않는다.
- 작은 화면에서는 본문을 스크롤해 파일 오류·등록 결과와 행동을 모두 읽는다. 별도 고정 하단 업로드 바를 만들지 않는다.

| 단계 | 파일·행동 상태 | 피드백과 다음 행동 |
| --- | --- | --- |
| 열기·파일 미선택 | 제출 비활성, 파일 선택 가능 | 대상 경기 문맥을 표시. 조회 중인 Game을 등록 대상으로 암묵 적용하지 않음 |
| 파일 선택 | 제출 가능 여부 검증 | 파일명·검증 오류를 선택 영역에 표시. 수정하면 오류 재검증 |
| 전송·검증·저장 | 제출·파일 교체 비활성 | Loading과 현재 확인 가능한 단계. 측정하지 않은 진행률 표시 금지 |
| 저장 성공 | 제출·닫기를 결과 확인 하나로 교체 | 모달 상태 영역에 등록된 경기 표시. 결과 확인으로 닫고 해당 Game을 선택하는 안을 추천 |
| 파싱·연결·충돌 실패 | 원인에 따라 재선택 또는 재시도 | 상태 영역에 원인·가능한 복구 행동 한 곳. 승인 대기나 수동 승패 입력으로 우회하지 않음 |
| 동일 결과가 이미 있음 | 새 Game 생성하지 않음 | 권한이 허용된 기존 결과 확인으로 연결 |
| 응답 유실 | 자동 재전송하지 않음 | 등록 상태 확인 행동으로 저장 여부부터 확인 |

성공 뒤 배경 결과를 갱신하며, 같은 성공 문구를 Toast·본문 알림·모달에 동시에 띄우지 않는다.
처리 중 닫기를 허용하는 안을 추천한다. 닫아도 작업은 취소하지 않고 기존 진입을 등록 상태 확인으로 전환한다.
진행 상태는 모달을 열면 모달 안에서, 닫으면 기존 진입 영역에서 한 번 표시한다. 재진입 시 같은 작업 상태를 복원해야 한다.
이 흐름은 서버의 작업 상태 확인 계약이 선행 조건이다. 별도 취소 버튼이나 확인되지 않은 전송 취소 기능을 가정하지 않는다.

### 미정 정책의 배치 영향

- 업로드 권한·허용 시점은 업로드 Button의 노출/비활성 이유를 바꾼다. 진입 위치는 그대로 유지한다.
- Game 순번·신규 생성·정정 대상 결정 정책에 따라 모달의 대상 문맥 영역에 선택이 추가될 수 있다. 이 경우 파일 선택보다 먼저 둔다.
- 처리 중 닫기·이탈·취소 정책, 성공 후 선택 방식은 미정이다. 정상 ROFL에 사람의 승인 단계를 추가하지 않는다.
- 중도 종료·취소 운영 조작의 소유 페이지는 미정이다. 이 배치에는 임시 관리 버튼이나 점수 편집을 넣지 않는다.
- 상세 지표·MMR 노출 범위는 정책과 데이터 검증에 따라 좁힐 수 있다. 단위 미검증 CC·사망 시간은 추천 상세에서 제외한다.

## 3. `/g/[guildId]/players/[userId]` — 사용자 전적

### 목표·우선순위

1. 누구의 어느 서버 기록인지 확인하고 누적 출전·승패를 읽는다.
2. 필요한 범위를 선택하고 실제 출전 Game으로 이동한다.
3. 제공 정책이 허용하면 시즌·포지션별 MMR을 확인한다. Riot 티어와 같은 지표로 보이지 않게 분리한다.

### 데스크톱 배치

```text
ParticipantIdentity: 사용자 이름·허용된 표시 정보
조회 범위 select
출전 Game 수       승 / 패       승률
───────────────────────────────────────────────────────────
포지션별 MMR: TOP | JUNGLE | MID | BOT | SUPPORT (제공 시)
───────────────────────────────────────────────────────────
출전 기록: 시리즈·경기 순번 / 사용 챔피언 / 승패 / 시각
Pagination
```

- 추천 핵심 지표는 실제 출전 Game 수·승패·승률이다. 신청한 내전 수와 출전 경기 수를 섞지 않는다.
- 수치는 하나의 정의 목록으로 읽는다. 지표 하나마다 카드나 중복 설명을 만들지 않는다.
- 포지션별 MMR은 별도 한 영역이며 시즌을 그 영역에서 식별한다. 누적 전적 범위와 MMR 시즌이 다르면 각각 명시한다.
- 출전 기록은 특정 Game으로 연결한다. 같은 시리즈에 여러 출전이 있어도 각 Game이라는 다른 대상임을 경기 순번으로 구분한다.

### 모바일 배치

- 식별 정보·범위 선택·기본 수치·MMR·출전 목록 순서를 유지한다.
- 기본 수치는 줄바꿈 가능한 묶음, 포지션별 MMR은 5개 행으로 재배치한다. 같은 값을 모바일용 카드에 추가 복제하지 않는다.
- 출전 행은 상대·승패를 첫 줄, 시리즈·경기 순번·챔피언·시각을 다음 줄로 배치한다. 행의 링크는 한 개다.

### 컴포넌트 책임

| 서비스 컴포넌트 | 책임·입력 | 행동 | STDF 조합·재사용 |
| --- | --- | --- | --- |
| `ParticipantIdentity` | 공개 처리된 사용자 표시 정보 | 이 페이지에서는 정적 표시 | 모집·경기 표와 공용. 자기 페이지 링크 없음 |
| `RecordScopeControl` | 사용 가능한 범위·현재 선택 | 범위 변경 | 라벨을 연결한 native select 예외. 서버 통계와 공용 |
| 누적 수치 영역 | 대상 Game·승패·집계 기준 | 읽기 | 의미 있는 정의 목록. 단순 수치용 래퍼 불필요 |
| `PositionMmrSummary` | 시즌·5포지션 값·반영 상태 | 읽기 | 정의 목록. 독립 책임으로 분리하되 재사용을 가정하지 않음 |
| `PlayerGameList` | 사용자 실제 출전 요약·Game URL | 해당 Game으로 이동 | 의미 있는 목록·단일 링크 예외. MatchList와 대상이 달라 별도 책임 |
| 페이지 이동 영역 | 출전 목록 페이지 정보 | 페이지 변경 | Pagination 직접 사용 |

### 흐름·상태

- 범위를 바꾸면 기본 수치와 출전 목록에 같은 범위를 적용한다. 요청 중에는 변경 대상 영역만 갱신 중으로 표시한다.
- 기록 없음은 0승 0패와 미확인 수치를 구분한다. 승률 분모가 0이면 비율을 계산하지 않는다.
- 비공개·접근 제한은 공개 정책에 맞는 공통 응답으로 처리한다. 빈 전적이라는 거짓 결과로 대체하지 않는다.
- MMR 미적용·보류·초기값을 구분한다. 다른 기록은 보여주면서 MMR 영역만 처리 상태를 표시할 수 있다.
- 계정 연결이나 이름 변경으로 과거 결과를 다시 합산하지 않는다. 사용자 연결이 없는 경기 행은 임의 프로필로 링크하지 않는다.

### 미정 정책의 배치 영향

- 대표 지표·범위·승률 분모는 추천안이며 확정이 필요하다. 지표 영역과 출전 탐색 위치는 유지한다.
- MMR 공개가 허용되지 않으면 해당 영역을 제거하고 출전 목록을 바로 잇는다. 가려진 빈 카드로 남기지 않는다.
- 계정 설정·공개 범위 변경은 `/me`의 책임이다. 사용자 전적에는 본인용 설정 메뉴를 반복하지 않는다.

## 4. `/g/[guildId]/stats` — 서버 통계

### 목표·우선순위

1. 선택한 서버의 집계 범위를 파악한다.
2. 검증된 결과로 계산한 규모·경기 길이·참여 정도를 읽는다.
3. 제공 범위가 정해진 세부 집계를 확인한다. 첫 구성에 개인 순위 경쟁을 전제로 넣지 않는다.

### 데스크톱 배치

```text
서버 통계                                  조회 범위 select
완료 Game 수      확인된 출전자 수      평균 경기 길이
집계에 사용한 표본·누락 여부 (필요할 때)
────────────────────────────────────────────────────────────
세부 집계: 포지션별 / 챔피언별 중 합의한 항목
분류 이름                    경기 수·선정 지표
다음 분류 …
```

- 추천 핵심 수치는 완료 Game 수·확인된 출전자 수·평균 경기 길이다. 출전자 수는 식별 가능한 사용자 수와 미연결 기록을 구분한다.
- 평균 경기 길이는 확인된 Game만 분모에 포함하며 누락 여부를 같은 영역에서 설명한다.
- 첫 화면은 수치와 비교 가능한 표 중심으로 잡는다. 차트·랭킹·장식 배너를 빈 공간을 채우는 용도로 추가하지 않는다.
- 세부 집계는 표의 같은 열을 비교하도록 구성한다. 지표 설명은 해당 열 또는 분모 설명 한 곳에 둔다.

### 모바일 배치

- 제목 다음에 범위 선택, 수치 묶음, 세부 표 순으로 쌓는다.
- 기본 수치와 세부 집계의 같은 값을 여러 카드로 반복하지 않는다. 긴 분류명은 줄바꿈하고 숫자는 열 정렬을 유지한다.
- 제공하는 세부 집계 종류가 여러 개면 내용 선택 Tabs를 표 위 한 곳에 둔다. 종류가 하나면 탭을 만들지 않는다.

### 컴포넌트 책임

| 서비스 컴포넌트 | 책임·입력 | 행동 | STDF 조합·재사용 |
| --- | --- | --- | --- |
| `RecordScopeControl` | 허용된 범위 옵션·선택값 | 범위 변경 | 라벨을 연결한 native select 예외. 사용자 전적과 공용 |
| 서버 집계 요약 | 지표·분모·표본·누락 여부 | 읽기 | 정의 목록. 페이지 내 역할로 유지 |
| `GuildStatBreakdown` | 제공하기로 한 집계 종류·열 정의·행 | 집계 내용 선택 | 선택이 필요하면 Tabs, 비교는 semantic table 예외 |
| 작업 상태 영역 | 집계 시점·반영 지연·오류 | 필요 시 재시도 | Loading + 문장 + Button. 집계 영역 소유 |

### 흐름·상태

- 범위 변경 → 조회 중 → 같은 범위의 요약·세부 집계를 반영한다. 이전 수치의 조회 범위를 조용히 바꾸지 않는다.
- 경기 자체 없음과 선택 범위 없음은 집계 영역에서 구분한다. 빈 상태에 가짜 그래프·0으로 채운 비교표를 만들지 않는다.
- 집계 실패는 해당 영역에 사유와 재시도를 제공하고, 이미 확인한 다른 집계가 있으면 보존한다.
- 갱신 지연·항목 누락은 실제 0과 다르다. 정상 ROFL 결과와 MMR 지표의 반영 시점도 혼용하지 않는다.
- 사용자별 집계가 나중에 합의되면 해당 행의 식별 표시를 단일 프로필 링크로 사용한다. 현재 계획에 빈 순위표를 선행 추가하지 않는다.

### 미정 정책의 배치 영향

- 핵심 지표·세부 분류·최소 표본·기간·시즌 관계·집계 갱신 주기는 미정이다. 먼저 합의한 지표만 같은 자리에서 제공한다.
- 개인 순위·식별 정보 공개는 별도 결정이다. 익명 집계가 가능하다는 이유로 사용자 행이나 외부 검색 링크를 추가하지 않는다.
- 지표가 한 종류로 좁혀지면 선택 Tabs를 없애고 표를 직접 표시한다. 기능이 없는 선택지를 남기지 않는다.

## STDF 3.0.0 확인 사항

STDF 스킬의 컴포넌트 색인·상세 문서와 설치된 `apps/web/node_modules/stdf`의 선언·Svelte 소스를 확인했다.
아래는 구현 단계에서 지킬 실제 계약이며, 접근성 보완이 이미 구현됐다는 의미가 아니다.

| 대상 | 확인한 계약·설계 영향 |
| --- | --- |
| Button | `disabled`, `loading`, `type`, `onclick` 제공. 설치 소스의 `disabledLoading` 기본값은 true이며 스킬 API 표의 false와 다름 |
| Input | 검색 입력 사용 가능. file/date 타입을 제공하지 않으므로 ROFL 선택은 native input 사용. 필드 이름·오류와 실제 입력의 접근 가능한 연결은 구현 시 확인 |
| Picker/ScrollRadio | 설치 소스의 선택 항목은 스크롤 기반 div이며 항목별 키보드 선택·선택 상태의 접근성 연결이 없음. 상태·기간·시즌 단일 선택은 native select로 제한해 대체 |
| Pagination | `total`, `pageSize`, `current`, `maxShowPage`, `onchange` 제공. `onnext/onpre`와 onchange를 모두 조회에 연결해 이중 요청하지 않음 |
| Tabs/Tab | `active`·선택 콜백·overflow 제공. 내부는 button이며 ARIA tab 역할·선택 속성·방향키 처리가 없음. 이름 있는 버튼 그룹, 선택 상태가 읽히는 label, Tab/Shift+Tab·Enter/Space 조작으로 계획 |
| TabContent | 숨긴 내용이 조작되지 않도록 선택 결과만 렌더링하는 방식 우선. 이동 효과로 다른 Game 결과를 화면 밖에 남기는 방식은 피함 |
| Popup | `visible`, `position`, `size`, `maskClosable`, `children`, `onclose` 제공. 공통 TaskDialog가 제목·입력·작업을 조립하고 ROFL은 업무별 내용과 상태를 전달 |
| TaskDialog 접근성 | 설치 Popup에 dialog 역할·초기 포커스·포커스 가두기·Escape 처리 보장이 없음. 공통 TaskDialog가 보완하고 배경 조작 차단·복귀까지 검증 |
| Skeleton/Loading | 각각 첫 조회의 형태 예고와 작업 처리 중 표시에 사용. Loading만으로 상태 문구나 완료 결과를 대신하지 않음 |
| List/Cell/Avatar | 내부 button 때문에 링크·복합 조작의 컨테이너로 사용하지 않음. 정적 이미지·단일 링크 목록 예외를 공통 셸 계획과 공유 |
| Table·FileUpload | 설치 export에 없음. 의미 있는 table과 native file input을 필요한 범위에만 사용 |

Pagination의 내부 이동 이름 등 설치 컴포넌트의 접근 가능한 이름·선택 상태·키보드 동작은 한국어 화면에서 확인한다.
공식 props가 없는 기능을 임의 속성으로 문서화하거나, 컴포넌트 사용만으로 접근성 검토를 끝내지 않는다.
