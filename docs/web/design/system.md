# 디자인 시스템 — Arena Console (다크 우선)

개정: 2026-10-29. 대상: `apps/web`의 모든 서비스 화면.
구현 기준: `apps/web/src/lib/styles/tokens.css`(토큰) · `utilities.css`(화면 규칙). 화면 코드가 이 문서보다 우선한다.

## 1. 콘셉트

내전이 열리는 저녁, 운영자가 한 화면에서 모집·편성·대진·결과를 지휘하는 콘솔.
**다크를 기본**으로 하고 라이트는 같은 구조의 반전이다. 표면 단·타입 대비·행동 위계로 구분하고, 테두리만으로는 구분하지 않는다.

| 원칙 | 코드로의 규칙 |
| --- | --- |
| **지금 할 일이 먼저** | 화면당 대표 블록 1개(히어로)와 주 행동 1개(`.btn--primary`) |
| **숫자가 주인공** | 수치는 tabular, 스코어·인원·지표만 Jersey 10 |
| **면으로 층을 만든다** | 표면 4단(bg→panel→panel-2/inset) + 1px 선. 그림자 남발 금지 |
| **구성 요소마다 다른 모양** | 상태=글자+마커, 경기=3열 스코어 행, 지표=인셋 웰, 목록=2줄 행, 강조=비대칭 히어로 |
| **STDF는 상호작용에** | Button/Input/Steps/ActionSheet/Accordion/Popup/Skeleton 등. 표·라벨·상태는 우리 규칙 |

## 2. 색

## 3. 표면과 대비

- 표면은 4단(`bg`→`panel`→`panel-2`→`inset`)만 쓴다. 카드 안에 카드를 넣지 않는다.
- 구분선은 **구역 경계와 행 사이**에만. 패널 안에서 테두리를 다시 그리지 않는다.
- 히어로만 `--line-strong` + 상단 2px 시안 그라디언트로 강조한다.

## 4. 타입

| 역할 | 크기/무게 | 클래스 |
| --- | --- | --- |
| 페이지 제목 | 24px / 800 | `.page-title` |
| 히어로 제목 | 22px / 800 | `.hero-title` |
| 소제목·행 제목 | 14–15px / 700 | `.row-title` |
| 본문 | 13–14px / 400 | `text-[13px]` · `.text-mut` |
| 보조 | 11.5–12.5px | `text-faint` |

한국어는 `word-break: keep-all`로 단어 중간 줄바꿈을 막는다.

## 5. 화면 규칙 (클래스)

| 클래스 | 쓰는 곳 | 규칙 |
| --- | --- | --- |
| `.shell` | 헤더·레이·본문·푸터 | 같은 좌우 기준선(최대 76.25rem) |
| `.region` + `.lbl` + `.count` | 구역 라벨 | 패널 **밖 왼쪽**에 세로로 쌓는다(라벨 위, 건수 아래). 오른쪽 끝에 작은 글자를 두지 않는다 |
| `.hero` / `.hero-main` / `.hero-score` | 대표 블록 | 비대칭 2단. 우측은 인원·미터·주 행동 |
| `.panel` | 묶음 | 1px 선 + 표면 한 단, 모서리 2px |
| `.row` + `.row-title` / `.row-meta` / `.row-num` / `.row-side` | 목록 행 | 3열(내용·숫자·상태), 행 사이 선만 |
| `.match-row` + `.team` / `.scorebox` / `.match-info` | 경기 행 | 4열(팀·스코어·팀·정보). 목록 행과 다른 구조로 구분 |
| `.stats` / `.stat` | 지표 | 1px 간격 인셋 웰 + Jersey 숫자 |
| `.state` + `--live` / `--wait` / `--done` / `--danger` | 상태 | 채운 마커=지금 진행/완료, 빈 마커=기다림/취소 |
| `.btn` / `--primary` / `--danger` / `--text` | 버튼 | 3종 + 텍스트. 테두리 버튼(STDF `fill="line"`)은 쓰지 않는다 |
| `.field` | native select·number·datetime | 44px, 인셋 배경 |
| `.chip` | 필터·선택 | 라디오는 `sr-only`, 칩이 조작 모양 |
| `.data-table` | 표 | 헤더 10.5px 대문자, 행 헤어라인, 64rem 미만은 라벨 스택 |

## 6. 상태 톤 (단일 출처: `lib/components/ui/status.ts`)

- `live`: 모집 중·편성 완료·진행 중·선발·입찰 중
- `wait`: 편성 중·대기·예정·결과 대기·유찰·중도 종료
- `done`: 종료·기록됨·철회·낙찰·경매 완료
- `danger`: 취소·제외·경매 취소

색은 보조 신호이며 문구가 항상 함께 읽힌다. 표시용 상태 라벨은 `StatusState`(native span)다.

## 7. STDF 사용

- 상호작용: `Button`·`Input`·`Popup`(래퍼 `TaskDialog` 안에서만)·`Steps`·`ActionSheet`·`Accordion`·`Skeleton`·`Pagination`·`Badge`·`Progress`
- 래퍼를 만드는 경우: 설치판에 포커스 트랩·Escape·dialog 의미가 없는 Popup 계열만(`TaskDialog`)
- 쓰지 않는 경우: `Tag`(항상 role=button)는 표시용에 쓰지 않고 `StatusState`로 대체. `Cell`은 행 전체가 버튼이라 내부 조작을 넣을 수 없어 설정 행에는 쓰지 않는다.

## 8. 화면 책임 (단일 책임)

- 한 화면은 한 가지 일만 맡는다. **다른 화면이 담당하는 데이터·요약을 다시 보여주지 않는다.**
- 예: 서버 홈은 "지금 진행 중인 내전"만 보여준다. 완료 경기·참여자 집계는 통계 화면, 전체 기록은 경기 기록 화면이 맡는다.
- 같은 값이 한 화면에 두 번 나오지 않는다. 히어로가 `선발 7 / 10`을 보여주면 참가자 구역에서는 `신청 9 / 12`처럼 다른 사실만 표시한다.
- 요약이 필요하면 화면 안에 복제하지 않고, 그 일을 맡은 화면으로 이동한다(레이·목록 링크).

## 9. 반응형·접근성

- 64rem 미만: 히어로·행·경기 행이 세로로 쌓이고, 표는 라벨 스택으로 바뀐다.
- 터치 목표 44px 이상(`.btn` 40px + 패딩, `.chip` 36px은 밀집 구역에서만).
- 포커스 링은 `--focus-ring` 2px, 모든 조작에 유지한다.
- 모바일과 데스크톱에 같은 조작을 동시에 렌더하지 않는다(ActionSheet 하나만 둔다).
