# 기록 페이지

코드 대조일: 2026-11-05. 모두 서버 범위 헤더를 쓴다. 실제 서버의 경기·개인 전적·통계를 DB에서 공개 조회한다. 개발 샘플 서버만 목 데이터를 사용하며 ROFL 결과는 확정 라인업·계정·포지션·팀·중복·순서를 검증해 자동 등록한다.

## 현재 데이터 연결 범위

| 화면 | 데이터 출처와 저장 범위 |
| --- | --- |
| 경기 목록·상세 | `server/matches/queries.ts`가 서버 범위의 Match·Game·채택 ROFL·실출전 데이터를 조회 |
| ROFL 업로드 | 관리자·확정 출전자가 등록. 결과·실사용 계정·MMR·대진·게시 작업을 같은 DB 트랜잭션으로 저장. 원본은 보관하지 않음 |
| 사용자 전적·서버 통계 | `server/records/queries.ts`가 현재 활성 시즌의 완료 Game과 당시 실출전을 조회. 취소 내전·대진 제외, 중도 종료 기록 보존, 현재 계정 소유자 변경과 무관한 과거 귀속 유지 |
| MMR | 현재 시즌의 유효 반영을 읽고 확인된 사용자의 5포지션을 표시. 미반영 포지션은 초기 1500. 실제 ROFL 결과 등록과 같은 트랜잭션에서 반영하고 안전한 마지막 결과만 역분개 |
| 업적·MVP·ACE·평점 | 합의된 평가 기준이 없어 실제 서버에서는 만들지 않음. 개발 샘플에만 가상 지표 표시 |
| 이름·이미지 | 실제 Data Dragon 카탈로그를 사용하고 실패 시 텍스트·빈 이미지 대체 |

[ROFL 적재 모델](../../rofl-import.md)에 자동 계정 귀속·등록·정정 계약을 정리했다.

## 표시 규칙

- 누락된 수치·시각·포지션은 nullable로 유지하고 수치는 `-`로 표시한다. 통계는 지표마다 유효한 표본만 같은 분자·분모에 포함하며 팀 합계에 필요한 출전 기록이 부족하면 합계도 null이다. 업로드 시각·희망 포지션·목 평점으로 보충하지 않는다.
- 실제 경기 시각을 모르면 세트 머리에서는 날짜를 생략하고, 목록에서는 `날짜 미확인`/`미확인`을 표시한다. 업로드 시각으로 대신하지 않는다.
- 단위가 검증되지 않은 원값(CC 시간·사망 시간 등)은 표시하지 않는다.
- 아이템·주문·룬은 "최종 세팅"이다. 구매 순서로 보이게 나열하지 않는다.
- Riot ID를 가리는 개인별 공개 설정은 없다. 일반 서버 열람과 함께 비로그인·비소속자에게도 공개한다.
- 사용자 전적 내역은 "승"/"패" `StatusTag`, 세트 진영 머리는 "승리"/"패배" 텍스트, 정상 종료 시리즈는 승리 팀 이름으로 결과를 표시한다. 통계·개인 전적의 횟수 표시는 현재 화면의 `게임` 문구를 유지한다.
- Match의 A/B 팀은 시리즈 내 고정 구분이고, 세트마다의 블루/레드 진영과 다르다. 세트 화면에는 진영을, 시리즈 점수에는 팀 이름을 쓴다.

## `/g/[guildId]/matches` — 경기 기록

**목적** 서버의 시리즈를 찾아 상세로 들어간다. 특정 내전의 경기 흐름은 그 내전의 대진 페이지가 담당한다.

**데이터**

```ts
{
  live: MatchListItem[],        // 진행 중·대기, 현재 조회 상한 100개
  done: MatchListItem[],        // 종료·중도 종료·취소. 20개씩
  doneTotal, page, pageSize, q, empty
}
// MatchListItem = { id, scrimTitle, teamA, teamB, scoreA, scoreB, bestOf, status, playedAt: string | null }
```

**화면** (상태별 목록 두 개)

```text
[h1] 경기 기록                                         [Input search: 내전·팀 이름]

┌ 진행 중 ──────────────────────────────────────────────────────────── 1경기 ┐
│ 경기                              형식   스코어   결과          날짜        │
│ 포로팀 vs 칼날부리팀               BO3    1 : 1   [진행 중]     10/30(금) › │
│ 금요일 칼바람 내전                                                          │
└─────────────────────────────────────────────────────────────────────────────┘
┌ 종료 ────────────────────────────────────────────────────────────── 26경기 ┐
│ 돌거북팀 vs 바위게팀               BO3    1 : 2   🏆 바위게팀   10/24(토) › │
│ 포로팀 vs 칼날부리팀               BO3    1 : 0   [중도 종료]   10/17(토) › │
│ …                                                                           │
│                               [PageNav]                                     │
└─────────────────────────────────────────────────────────────────────────────┘
모바일: 행마다 [팀 vs 팀 / 내전 · BO · 날짜 | 스코어] 다음 줄에 결과
```

| 영역 | 사용 | 동작 |
| --- | --- | --- |
| 검색 | `<form role="search">` + `Input type="search" clear` | Enter·지우기 → `?q=`(내전·팀 이름, 최대 50자, 대소문자 무시 부분 일치). 두 목록에 함께 적용하고 page 초기화. 폼에 `nonSubmitButtons`. 참가자 검색은 없음 |
| 목록 | `MatchTable` (`section`·`ul`·CSS grid, 머리 줄 제목·개수, 열 제목은 `md` 이상, 행 전체가 `/matches/[id]` 링크) | 진행 중 목록은 경기가 있을 때만. 결과 열: 정상 종료는 트로피 + 승리 팀, 그 외는 상태 `Tag`. 점수는 DB에 저장된 Match 결과. 개발 샘플에만 고정 점수 예시가 있음 |
| 페이지 | `PageNav` (종료 표 아래) | `?page=`. 종료 표에만 적용 |

서버 홈의 최근 경기는 그대로 `MatchListRow`를 쓴다.

**상태** 기록 없음 "아직 기록된 경기가 없어요"(검색·목록 없음) / 종료 목록의 검색 결과 없음: "'{q}'에 맞는 경기가 없어요" / 끝난 경기 없음 "아직 끝난 경기가 없어요". 검색·쪽 이동 중에는 제목에 `Loading`, 이전 결과에 흐림 효과를 쓴다.

현재 정렬은 `playedAt` 내림차순이며 날짜 미확인은 뒤로 간다. 취소·중도 종료도 종료 목록에 포함한다. `page`는 기본 1, 음수는 1 이상으로 보정하지만 마지막 쪽을 넘는 값은 보정하지 않는다.

**미구현·미결정** 기간·시즌 필터. 현재 UI에는 검색·종료 목록 쪽 이동 이외 필터가 없다.

## `/g/[guildId]/matches/[matchId]` — 경기 상세

**목적** 시리즈 점수와 세트별 결과·개인 성적을 본다. 확정 라인업의 ROFL을 등록하고 마지막 결과를 안전하게 취소한다.

**권한** 조회는 활성 서버의 경기를 누구나 읽는다. 업로드는 관리자 또는 확정된 경기 출전자에게 허용하며 실제 POST에서도 현재 권한을 다시 검사한다. 라인업 확정·해제와 마지막 결과 취소는 관리자만 가능하다. 개발 샘플의 업로드만 목 경기 존재·진행 중 상태를 검사한다.

**근거** `samples/매치 결과 참고자료.png`의 구성(어두운 세트 머리 + 진영별 표)을 서비스 토큰으로 옮긴다.

**데이터** (`lib/features/matches/types.ts`의 `MatchDetail`·`GameDetail`·`GamePlayer`)

```ts
{
  match: { id, scrim: { id, title }, teamA, teamB, scoreA, scoreB, bestOf, status, hardFearless,
           games: { id, order, winner: 'a' | 'b' | null }[] },
  game: {                                   // ?game으로 고른 세트, 없거나 잘못되면 마지막 세트, 기록 없으면 null
    id, order, durationSec, playedAt: string | null, patch, mmrStatus, splashUrl,
    sides: { side: 'blue' | 'red', slot: 'a' | 'b', teamName, win,
             players: { userId, displayName, riotId, champion, level, kills, deaths, assists,
                        cs, damage, damageTaken, gold, visionScore, wardsPlaced, wardsKilled, controlWards,
                        heal, shield, largestKillingSpree, multiKills,
                        items: (LoadoutIcon | null)[7], spells, keystone, secondaryStyle,
                        score, badge: 'mvp' | 'ace' | null, fearlessViolation }[] }[]
  } | null,
  usedChampions: { a: ChampionRef[], b: ChampionRef[] } | null,   // 하드 피어리스 진행 중만
  operation: MatchOperationContext | null, // 경기 전체 라인업·팀별 선수·다음 세트·revision·조작 권한
  can: { upload: boolean }
}
```

아이템·주문·룬 이름과 아이콘은 서버가 최신 Data Dragon `ko_KR` 카탈로그로 채운다(`loadoutResolver`). 경기의 과거 패치와 버전을 맞추지는 않는다. 찾지 못한 ID는 아이콘 없이 숫자 ID로 표시하며, ID 자체가 없으면 빈 칸을 유지한다.

**화면** 아래는 실제 서버의 진행 중 경기 예시다. 개발 샘플의 가상 MVP·평점은 포함하지 않는다.

```text
[h1] 포로팀 vs 칼날부리팀                                    [ROFL 업로드: 진행 중이며 확정 라인업·권한이 있을 때]
10월 정기 내전 · BO3 · 하드 피어리스  [상태]                ← 내전 이름은 /scrims/[id] 링크
┌ 포로팀  1 : 1  칼날부리팀 ┐                              ← 시리즈 점수
[출전 라인업 · 확정] 팀별 다섯 포지션                       ← 경기 전체에서 재사용
[Tab] 1세트 | 2세트                                        ← 세트가 2개 이상일 때만
[마지막 세트 취소]                                         ← 관리자·안전한 취소 조건·마지막 세트 선택 시
┌ GameHero (어두운 카드) ─────────────────────────────────────┐
│ 레드 · 칼날부리팀 승리                                      │
│ 25 : 42   ← 진영별 킬(블루·레드 색)                          │
│ 31분 3초 · 패치 16.21                                      │
└────────────────────────────────────────────────────────────┘
┌ 블루 · 포로팀 패배  60,700 골드                         25 K · 42 D · 26 A ┐
│ 선수(챔피언·레벨·주문·룬·이름·배지) | KDA | 딜량·받은 피해 | 시야 | CS | 아이템 | 상세 │
└────────────────────────────────────────────────────────────────────────────┘
┌ 레드 · 칼날부리팀 승리 … ┐
[h2] 다음 세트에서 쓸 수 없는 챔피언                        ← 하드 피어리스 진행 중만
```

| 영역 | 사용 | 동작 |
| --- | --- | --- |
| 시리즈 머리 | `h1`, 메타 한 줄(내전 링크), `StatusTag`, 점수 상자 | 점수는 DB에 저장된 Match 결과이며 개발 샘플만 고정 예시를 사용. 정상 종료만 승자 표시 |
| 출전 라인업 | `MatchLineupBoard` | 실제 경기의 대기·진행 중 상태에 팀별 5포지션 표시. 수동은 확정 편성에서 자동 준비하고 경매는 경기별 한 번 확정. 결과 이력이 있으면 확정 해제 불가 |
| ROFL 업로드 | `Button fill="base"` → `RoflUploadDialog` | `can.upload`일 때만. 남은 세트가 없으면 비활성 |
| 세트 선택 | `Tab` (`N세트`) | `?game=<id>`로 이동 |
| 세트 머리 | `GameHero` | 이긴 진영·팀, 진영별 킬, 확인된 날짜·시간·패치. MMR 미반영 자료에는 대기 `StatusTag`를 표시할 수 있지만 정상 ROFL 등록은 MMR까지 함께 저장. MVP 카드는 개발 샘플만 표시 |
| 진영 표 | `GameTeamTable` (`<table>` + `caption`) | 진영색 머리에 결과·총 골드·K/D/A. 열: 선수, 평점(`sm` 이상), KDA(비율), 딜량·받은 피해 막대(두 진영 최대값 기준)·시야(`lg` 이상), CS·최종 아이템(`md` 이상), `상세`. 아이템 7칸은 `xl` 미만에서 4칸씩 두 줄. `sm` 미만은 선수·KDA·상세만 남고 주문·룬 아이콘도 숨김 |
| 평점·배지 | 평점 열, MVP(이긴 팀 1위)·ACE(진 팀 1위) | 실제 서버에서는 평점·배지가 null이다. 개발 샘플의 **임시 성과 점수**: (K+A)/max(1,D) + 킬 관여×4 + 팀 내 피해 비중×6. 소수 둘째 자리까지 표시하며 진영별 최고 점수 동점자 모두 배지를 받을 수 있다. 세트 머리는 첫 MVP 한 명만 표시 |
| 피어리스 | 챔피언 옆 `StatusTag warning "피어리스"`, 하단 사용 챔피언 목록 | 같은 팀의 앞 세트 실출전자가 사용한 챔피언. 예정 로스터를 넣지 않으며 위반을 이유로 등록을 막지 않는 정책이다 |
| 행 상세 | `GamePlayerDialog` (`Popup` 데스크톱 오른쪽, 모바일 아래) | 주문·룬·아이템 이름, 피해·골드·CS·시야·회복·보호막·연속 킬·다중 킬 |

### ROFL 업로드 팝업

실제 서버에서는 다음 세트의 파일 하나와 그 세트의 블루 팀을 지정한다. 확정 라인업은 모든 세트에서 재사용한다. 입력창을 연 시점의 경기 revision·라인업·세트 번호를 전송한다.

```text
[h2] ROFL 업로드
[이번 세트의 블루 팀]
[ROFL 선택: 1개 · 파일당 64MB]
[ImageList: 실제 서버에서는 한 파일]
  ┌───────────────────────────────┐
  │ KR-7312345678.rofl  12.4MB    │
  └───────────────────────────────┘
                                         [닫기] [업로드]
```

| 단계 | 처리 |
| --- | --- |
| 파일 선택 | `ImageList`(`columns=3`, `maxSize=64`MB, `max`=실제 서버 1개, 개발 샘플 남은 세트 수) + 숨긴 `<input type="file" accept=".rofl">`. `onclickUpload`로 입력을 열고 `addFiles()`로 넘긴다. 실제 서버와 빈 선택 칸은 전체 폭으로 표시하고 개발 샘플의 다중 파일만 3열로 표시 |
| 업로드 | 실제 서버는 `?/upload` action으로 다음 세트 파일 하나를 전송. 개발 샘플만 다중 파일 순차 전송. 항목 `status="uploading"`, `업로드` 버튼 `loading`, 닫기 비활성 |
| 성공 | 항목 `status="success"`, `message`에 기록된 세트 번호를 저장. `닫기` 버튼·Escape의 `close()`를 거치면 `invalidateAll()` 후 마지막으로 기록된 세트 탭 선택 |
| 실패 | 항목 `status="error"`, `message`에 검증 이유를 표시. 일반 실패는 같은 `업로드` 버튼으로 재시도하며 개발 샘플의 순차 전송도 첫 실패에서 멈춤. 충돌·응답 유실은 재전송 비활성 |
| 응답 없음 | 항목 오류 "기록 여부를 확인하지 못했어요". `close()` 경로로 닫으면 재조회해 실제 반영을 확인 |

파일명·크기·처리 상태·성공/실패 문구와 선택 해제를 `itemChild` 안에 표시한다. 마스크·Escape·닫기 버튼은 모두 같은 초기화·재조회 경로를 사용한다. 응답 유실·409 충돌 뒤에는 재전송을 멈추고 닫을 때 최신 상태를 확인한다.

| 서버 결과 | 항목 메시지 |
| --- | --- |
| 손상·미지원 형식 | 실제 서버는 파서 검증 문구(예: ROFL 파일 헤더가 올바르지 않습니다.), 개발 샘플은 읽을 수 없는 ROFL 파일이에요 |
| 중복 결과 | 실제 서버는 같은 성공 요청의 재시도에는 기존 성공을 반환한다. 취소 파일은 같은 경기·세트·라인업의 최신 revision에서 복구할 수 있고 다른 문맥에서는 충돌한다. 개발 샘플은 이미 {N}세트로 기록된 파일이에요 |
| 결과 충돌·불완전 | 실제 서버는 출전자·팀·포지션·승패 등 실패한 검증의 이유를 반환. 개발 샘플은 결과를 확인할 수 없어 기록하지 않았어요 |
| 진행 상태·세트·라인업 변경 | 실제 서버는 현재 요청과 다른 운영 상태를 충돌로 거절. 개발 샘플은 지금은 이 경기에 업로드할 수 없어요 |
| 파일 누락·잘못된 확장자 | ROFL 파일을 골라 주세요 |
| 64MiB 초과 | 파일이 너무 커요 |
| 경기 없음 | 경기를 찾을 수 없어요 |

개발 샘플에서 파서 결과가 `consistent`인 파일은 검토·승인 단계 없이 목 저장소에 바로 기록한다. 승패 수동 입력은 없다. 운영 경로는 실제 권한·계정·라인업을 검증하며 개발 샘플의 단순 등록과 구분한다. 원본 파일은 보관하지 않는다.

**상태**

| 상황 | 처리 |
| --- | --- |
| 세트 없음 | 탭 대신 "아직 기록된 세트가 없어요" |
| `?game`이 잘못됨 | 기본 세트 선택(쿼리 무시) |
| 일부 수치·이미지 누락 | nullable 수치는 `-`, 챔피언은 이름 일부·장비는 ID/빈 칸으로 대체. 실제 수치·팀 합계는 누락을 0으로 채우지 않음 |
| 사용자 연결 없는 플레이어 | `GameTeamTable`에서 이름을 정적 텍스트로 표시하고 사용자 전적 링크를 만들지 않음 |
| 중도 종료(예: 5전 3선승 1:1) | 지금까지의 세트·점수를 그대로 보여 주고 승자 표시·업로드 버튼 없음. 중도 종료는 이 화면이 아니라 내전 요약 운영 메뉴에서 내전 단위로 한다 |

**목 기록 규칙과 한계** 다음 세트 번호는 현재 세트 수 + 1이며, 한 팀이 BO 과반을 이기면 경기만 `completed`로 바꾼다. 업로드한 세트의 실제 경기 시각은 null이다. 중복은 해당 경기 안의 `gameLengthMs + 참가자 챔피언 순서` 문자열로 검사하며 파일 해시나 서버 전체 중복 검사는 아니다. 블루 진영의 A/B 팀 연결도 세트 순번 홀짝으로 가정한다. 실제 계정↔팀원 연결과 진영 매핑, MMR 계산·통계 갱신·대진 자동 진출 연결은 없다. `mmrStatus`는 진행 중 경기의 마지막 세트만 `pending`, 나머지는 `applied`로 만드는 목 표시다.

**라인업·정정** 라인업 편집은 같은 팀 안에서 드래그 또는 선수 선택 후 자리 선택으로 배치·교환하며, 모든 포지션이 채워지면 한 번 확정한다. 진출 팀의 직전 확정 포지션은 다음 경기에도 복사하고 경매의 다음 경기는 복사한 초안을 확정한다. `마지막 세트 취소`는 이후 MMR 변경·후속 경기 작업이 없을 때만 허용한다. 취소 이력은 보존하며 새 결과를 같은 세트 번호로 등록해 정정한다. 같은 파일도 같은 경기·세트·라인업의 최신 revision에서 다시 올려 복구하거나 블루 팀을 정정할 수 있다. 복구는 기존 출전자·계정 근거를 유지한 새 Game으로 기록하며 다른 경기·세트에 재사용할 수 없다.

**미결정** MVP·ACE·종합 평점 정책. 개발 샘플의 가상 지표는 운영 결과에 적용하지 않는다.

## `/g/[guildId]/players/[userId]` — 사용자 전적

**목적** 한 사용자의 서버 전적을 본다. 완료 Game의 당시 출전 사용자 ID로 기록을 합산하므로 해당 서버의 여러 Riot 계정 기록이 함께 조회되고, 현재 소유자 변경으로 과거 기록이 이전되지 않는다.

**근거** `samples/개별 전적 참고자료.png`의 머리(업적 배지·승패)·최근 10게임·핵심 지표(상위 %)·레이더·챔피언 성적·듀오 구성을 따른다. 등급(A·B 등)과 오브젝트·NJ Score처럼 정의가 없는 지표는 두지 않는다.

**권한** 활성 서버의 현재 연결 사용자 또는 당시 참가 기록이 있는 사용자를 누구나 조회한다. 개인별 공개 설정은 없다.

**데이터** (`lib/features/players/`의 `PlayerGame`·`summarize`·`topPercents`·`championRecords`·`duoRecords`, `achievements.ts`)

  badges: { id, emoji, title }[],                                       // 실제 서버는 빈 배열. 개발 샘플만 업적 표시

| 포지션 필터 | `Tab` (라벨에 게임 수) | `?position=`. 게임이 있는 포지션만 제공하고 그 외 값은 전체로 읽는다. 핵심 지표·상위 %·레이더·챔피언·최근 게임에 적용하고 `page`를 초기화 |

| MMR | `<table>` | 포지션·MMR·게임 |
| 듀오 | `DuoList` | 함께한 게임 수와 승률, 사용자 전적 링크. 함께 3게임 이상인 사람 중 높은/낮은 승률 순으로 각각 최대 2명, 두 목록에 중복 없음. 없으면 "세 게임 이상 함께한 사람이 없어요" |

머리의 전체 승패·최근 10게임, MMR, 듀오는 포지션 필터와 무관하다. 실제 서버에서는 업적 배지를 숨긴다. 경기 시각이 확인되지 않은 기록이 섞이면 최근 10게임과 연승·연패를 표시하지 않고 내역의 날짜는 미확인으로 남긴다. 챔피언은 게임 수 내림차순, 같으면 승률 내림차순이다. 상위 %는 같은 포지션 범위에서 4게임 이상인 사용자(본인 포함)를 비교해 `ceil((앞선 사람 수 + 1) / 비교 인원 × 100)`으로 계산하며 동점은 같은 값이다. 게임이 없으면 지표 대신 빈 안내, 본인이 4게임 미만이면 상위 %와 레이더를 숨긴다.

**현재 한계·미결정** MMR 게임 수는 유효 원장 반영 기준이므로 전체 전적 수와 다를 수 있다. 상위 %는 지표별 유효 값이 있는 사용자만 비교하며 누락 지표는 레이더에 넣지 않는다. 기본 집계는 MSM1과 같은 현재 활성 시즌이다. 과거 시즌 선택 UI와 MSM1에 없는 운영 업적은 후속 범위다. 탈퇴·계정 연결 변경 후에도 당시 기록의 귀속을 유지한다.

## `/g/[guildId]/stats` — 서버 통계

**목적** 서버 전체 누적 지표와 사용자별 순위를 본다.

**근거** `samples/서버통계부분.png`·`samples/업적리스트.png`의 지표 카드·업적 캐러셀·업적별 순위·리더보드 배지 구성을 따른다. 기간·시즌 선택과 OPS·등급·유틸 열은 현재 없다.

**화면** 실제 서버는 아래 구성 중 업적·업적별 순위·최근 10게임 업적 필터를 숨긴다.

```text
[h1] 통계
[Grids 6열(모바일 2)] StatTile(아이콘): 총 게임 | 참가자 | 평균 게임 시간 | 분당 킬 | 평균 KDA | 사용한 챔피언
[Tab] 전체 | 탑 | 정글 | 미드 | 원딜 | 서폿                ← 업적·리더보드·챔피언에 적용
[h2] 업적                      최근 10게임만 [Switch]  [업적별 순위]
   ‹  [앞 업적(흐림)]  [ 1위 카드: 얼굴·이모지·업적명·설명·이름·값 ]  [다음 업적(흐림)]  ›
   ● ● ━ ● ● …                                         ← 업적 바로가기 점
   4게임 이상 뛴 사람부터 집계해요
[h2] 리더보드        최소 게임 [Stepper]  13명 / 18명
<table> 순위 | 사용자 [업적 배지] | 게임 | KDA | 승률 | 킬 관여 | CS/분 | 피해/분 | 시야   ← 열 머리로 정렬, 20명씩, 1~3위 행 바탕 구분
[h2] 챔피언
<table> 챔피언 | 픽 | 승률 | KDA     ← 픽 많은 순, 5픽 미만은 승률 `-`, 15개씩 PageNav
```

| 영역 | 사용 | 동작 |
| --- | --- | --- |
| 핵심 지표 | `Grids` + `StatTile` | 실제 완료 Game 수를 세며 출전자 수를 10으로 나누지 않는다. 시간·킬이 확인된 게임만 해당 지표에 포함한다. 상단 지표는 모든 필터와 무관한 서버 전체 값 |
| 포지션 | `Tab` | `?position=` |
| 업적 | `AchievementCarousel` | 업적 16종(`ACHIEVEMENTS`, 임시). 4게임 이상인 사람 중 1위를 한 장씩. 이전·다음 `Button`, 점 버튼, 터치 밀기. `?recent=1`은 포지션 필터 적용 후 사용자별 최근 10게임을 집계하며 리더보드의 1위 배지도 같은 결과 사용 |
| 업적별 순위 | `AchievementRankingDialog` (`Popup`) | 업적 칩(`aria-pressed`)으로 골라 상위 10명. 고른 업적은 캐러셀과 같이 움직인다 |
| 리더보드 | `LeaderboardTable` | `?min=` 기본 5, 1~50으로 제한. 수치는 선택 포지션의 전체 게임이며 최근 10게임 스위치와 무관. 기본 KDA 내림차순, 열 머리 버튼으로 정렬(`aria-sort`), 같은 열 재선택은 방향 전환. 정렬·20명씩 쪽 이동은 로컬 상태. `md` 미만은 순위·사용자·KDA·승률, `sm` 미만은 업적 배지와 K/D/A·승패 보조 줄도 숨김. 게임·킬 관여는 `md` 이상, CS/분·피해/분·시야는 `lg` 이상 |
| 챔피언 | `<table>` + 챔피언 아이콘, `PageNav` | 포지션만 적용하고 최근 10게임·최소 게임 필터는 적용하지 않음. 픽 수 내림차순, 동점이면 승률 내림차순. 15개씩 로컬 쪽 이동, 5픽 미만 승률은 `-` |

쿼리에는 `position`·`recent`·`min`만 저장한다. 잘못된 포지션은 전체, `recent`는 정확히 `1`일 때만 켜진다. 리더보드 쪽은 행 데이터 변경·정렬 시 1로 돌아가고, 챔피언 쪽·선택 업적도 서버 필터 값이 갱신되면 처음으로 돌아간다. 업적은 지표 동점이면 게임 수 많은 순으로 정렬하고 첫 사용자 한 명에게 배지를 부여한다. 양옆 업적 미리보기는 `aria-hidden`·`inert` 장식이며 활성 카드만 사용자 전적 링크를 가진다.

**상태** 완료 Game이 없으면 "아직 기록된 게임이 없어요" (지표 0 대신). 업적·리더보드 표본 없음: "{N}게임 이상 뛴 사람이 없어요". 필터 이동 중에는 업적·리더보드·챔피언 영역의 이전 결과를 흐리게 표시한다.

**현재 한계·미결정** 실제 서버는 업적 캐러셀·업적별 순위·최근 10게임 업적 필터를 숨긴다. `평균 KDA`는 K/D/A가 함께 확인된 표본의 (킬+어시스트)/max(1,데스)다. 현재 활성 시즌을 기본 집계하며 과거 시즌 선택·실시간 갱신과 새 업적 정책은 후속 작업이다. 위 업적 UI 설명은 개발 샘플의 구성이다.
