# 기록 페이지

활성 서버의 경기·전적·통계는 공개다. 프로필과 Riot ID는 [본인 공개 설정](global.md#me--내-정보)을 각각 따른다. 과거 기록은 당시 실출전자에게 귀속된다. 탈퇴하거나 연결 계정 소유자가 바뀌어도 기록을 다른 사람에게 옮기지 않는다.

## 표시 규칙

- 시리즈의 고정 A/B 팀과 세트별 블루/레드 진영은 다르다. 시리즈 점수에는 팀 이름을, 세트 결과에는 실제 진영을 쓴다.
- 확인할 수 없는 수치·시각·포지션을 0, 업로드 시각, 희망 포지션으로 보충하지 않는다. 합계·평균은 해당 지표의 유효 표본으로만 계산한다. 단위가 검증되지 않은 수치는 표시하지 않는다.
- 아이템·룬·주문은 구매 순서가 아니라 최종 세팅이다. Data Dragon에서 찾을 수 없는 ID는 임의의 이름이나 이미지로 바꾸지 않는다.
- 실제 서버는 합의되지 않은 업적·MVP·ACE·종합 평점을 표시하지 않는다. 개발 샘플 수치나 공식을 운영 평가 기준으로 사용하지 않는다.

## `/g/[guildId]/matches` — 경기 기록

내전 또는 팀 이름(최대 50자), 경기일, 시즌을 입력하고 `조회`로 함께 적용하거나 조건을 초기화한다. 참가자 검색은 제공하지 않는다. 경기 목록의 기본값은 **전체 시즌**이다. 한국 시각 기준 시작일·종료일을 모두 포함하며, 기간을 지정하면 실제 경기일이 확인된 경기만 조회한다. 뒤집히거나 잘못된 날짜는 결과 없음이 아니라 수정할 입력 오류다.

넓은 화면에서는 조회 조건과 경기 목록을 나란히 두고 좁은 화면에서는 조건을 목록 위에 둔다. 경기마다 내전·일자·양 팀 점수·상태를 한 행에서 확인한다.

진행·대기와 종료(중도 종료·취소 포함) 목록을 구분하며, 각 경기에서 시리즈 상세로 이동한다. 종료 목록만 20개씩 나눈다. 확인된 첫 세트 시작 시각의 최신순이며 미확인 경기일은 뒤에 둔다. 빈 서버·필터 결과 없음·범위 밖 페이지를 구분하고 조건을 바꿀 수 있게 한다.

## `/g/[guildId]/matches/[matchId]` — 경기 상세

시리즈 점수와 세트 선택 아래에서 양 진영의 선수 성적을 비교한다. 확정 라인업으로 확인된 포지션끼리 맞추고, 포지션을 모르면 기록 순서를 보존한다.

- 누구나 시리즈 점수·세트·진영별 선수 성적과 선수 상세를 조회한다. `game`을 생략하거나 없는 세트를 지정하면 기록된 마지막 세트를 보여 준다. 시리즈 승자 표시는 정상 종료에만 사용한다.
- 관리자는 양 팀의 5포지션 라인업을 경기 전체에 한 번 확정한다. 수동 편성의 확정 포지션을 재사용하고, 경매는 경기별로 배치·교환 후 확정한다. 드래그 또는 선수 선택 후 자리를 지정한다. 진출 팀의 직전 포지션은 다음 경기 초안에 반영한다. 결과 이력이 있으면 확정을 풀 수 없다.
- 진행 중에는 점수판 곁에 다음 세트의 예정 진영을 표시하고, 좁은 화면에서는 점수판 바로 아래에 둔다. 운영자가 `진영 설정`을 열 때만 입력과 저장 버튼을 보인다. 선택은 해당 경기·세트에만 적용하며 다음 세트에 자동으로 복사하거나 교대하지 않는다.
- 하드 피어리스에서는 양 팀이 이전 유효 세트에서 실제 사용한 챔피언을 안내한다. 취소 기록과 예정 로스터는 제외한다. 위반 자체가 ROFL 등록을 막지는 않는다.

### ROFL 업로드 팝업

1. 관리자 또는 확정 출전자가 진행 중 경기에서 다음 세트의 `.rofl` 파일 하나(최대 64MiB)를 선택한다. 예정 진영을 기본값으로 보여 주며, 정한 적이 없으면 어느 팀도 선택하지 않는다. 실제 블루 팀이 다르면 바꾸고 양 팀 진영을 직접 확인한다. 파일·진영 또는 대상이 바뀌면 확인도 다시 받는다.
2. 서버는 요청자의 권한, 경기 revision, 확정 라인업, 다음 세트 번호, 실제 출전·팀·포지션·승패와 중복을 검증한다. 성공하면 세트·실사용 계정·MMR·승자 진출과 Discord 게시 예약을 함께 저장한다. 정상 결과는 수동 승인하지 않고 원본 파일도 보관하지 않는다.
3. 실패 사유는 선택 파일 옆에 표시한다. 충돌·응답 유실이면 같은 파일을 자동 재전송하지 않고 창을 닫아 최신 경기 상태를 확인한다. 개발 샘플만 여러 파일을 순서대로 처리한다. 실제 계정 귀속·MMR·진영 검증을 대체하지 않는다.

**정정:** 관리자만 마지막 유효 세트를 취소할 수 있다. 이후 MMR 변경·후속 경기 작업이 역분개를 막으면 이유를 안내한다. 취소 이력은 보존하고 올바른 결과를 같은 세트 번호에 다시 등록한다. **취소한 동일 파일은 같은 경기·세트·확정 라인업과 원래 블루 팀에서만 복구한다.** 다른 진영으로 바꿔 기존 선수 귀속을 덮어쓸 수 없다. 상세 계약은 [ROFL 적재 모델](../../rofl-import.md)을 따른다.

## 개인 전적·서버 통계의 시즌 선택

서버 순위·개인 전적·통계는 활성 시즌이 기본이며, 종료 시즌을 선택하면 그 시즌만 읽는다. 전체 시즌을 합산하지 않는다. 활성 시즌이 없어도 과거 시즌을 선택할 수 있다. 개인 전적 링크는 선택 시즌을 유지한다. 취소 결과는 제외하고 중도 종료 전의 정상 세트는 보존한다.

## `/g/[guildId]/players/[userId]` — 사용자 전적

시즌 전체 승패·MMR과 포지션 필터를 적용하는 분석 영역을 분리한다. 분석 영역에서는 지표와 백분위를 비교한 뒤 게임별 기록과 챔피언 성적을 확인한다.

- 선택 시즌의 승패·5포지션 MMR·듀오를 확인한다. 시즌과 사용자가 확인됐지만 유효 MMR 반영이 없는 포지션은 1500이다. 원장 게임 수는 전적 게임 수와 다를 수 있다.
- 포지션을 바꾸면 핵심·세부 지표, 비교 백분위, 챔피언별 성적과 게임 기록이 바뀐다. 시즌 전체 승패·MMR·듀오는 바뀌지 않는다. 같은 포지션 범위에 4게임 이상인 사용자만 백분위를 비교하며 지표가 없으면 레이더 축을 만들지 않는다. 경기일 미확인 기록이 섞이면 최근 10게임과 연속 승패는 추정하지 않는다.
- 챔피언 목록을 펼치거나 접고, 게임 기록은 10개씩 조회해 세트 상세로 이동한다. 듀오는 함께 3게임 이상 한 사람 중 승률 상·하위 각 최대 2명이며 한 사람을 양쪽에 반복하지 않는다.

## `/g/[guildId]/stats` — 서버 통계

시즌 요약 아래에 선수 리더보드를 두고 업적·챔피언 기록과 함께 살핀다. 좁은 화면에서는 표 안에서 가로로 스크롤하고 링크로 하단 기록에 바로 이동한다.

- 핵심 지표는 선택 시즌의 완료 세트를 센다. 경기 시간·분당 킬 등은 필요한 값이 있는 세트만 계산한다. 포지션·최소 게임 필터는 시즌 전체 요약을 바꾸지 않는다.
- 포지션과 최소 게임 수(기본 5, 범위 1~50)를 골라 리더보드를 비교한다. KDA·승률·게임·킬 관여·CS/분·피해/분·시야 열로 정렬하고 20명씩 본다. 챔피언 표에는 포지션만 적용하며, 픽 수·승률 순으로 15개씩 보고 5픽 미만 승률은 표시하지 않는다.
- `새로고침`과 자동 갱신 중지는 별도 조작이다. 같은 조건은 30초 간격으로 갱신하고 정렬·쪽을 보존한다. 탭을 숨기거나 오프라인이면 진행 요청을 중단한다. 실패하면 마지막 결과를 유지하고 재시도 간격을 늘린다. 시즌에 기록이 없으면 0으로 채운 지표 대신 빈 안내와 시즌 선택을 제공한다.
- 업적 선택과 업적별 순위, 최근 10게임 업적 필터는 기준이 정해지기 전까지 개발 샘플에서만 제공한다.
