# 기록 페이지

코드 대조일: 2026-11-03. 모두 서버 범위 헤더를 쓴다. 현재 기록 화면은 개발 모드 목 데이터로 제공하며 운영 모드에서는 404다. 실제 인증·서버 열람 권한·DB 기록 조회는 연결하지 않았다.

## 현재 데이터 연결 범위

| 화면 | 데이터 출처와 저장 범위 |
| --- | --- |
| 경기 목록·상세 | `lib/mocks/matches.ts`의 메모리 저장소. 초기 게임은 `fixtures/rofl-sample.json`을 변형한 데이터이며, 목록 검증용 일부 경기는 게임 없이 고정 점수만 보유 |
| ROFL 업로드 | 실제 `projectRoflGame` 파서로 읽고 일관된 결과만 같은 메모리 저장소에 추가. 원본 파일은 보관하지 않으며 서버 재시작 시 추가 기록 초기화 |
| 사용자 전적·서버 통계·홈 업적 | `lib/mocks/players.ts`가 순위 목 데이터에서 고정 시드로 합성한 사용자 게임. 경기 상세 저장소와 별개여서 ROFL 업로드를 반영하지 않음 |
| MMR | `lib/mocks/ranking.ts`의 목 수치. 경기 상세의 반영 대기 표시는 계산 작업 상태가 아니라 목 상태 |
| 이름·이미지 | 실제 Data Dragon 카탈로그를 사용하고 실패 시 텍스트·빈 이미지 대체 |

[ROFL 적재 모델](../../rofl-import.md)의 영구 저장·참가자 연결·검증 계약과 현재 목 UI는 구분한다.

## 표시 규칙

- nullable 개인 수치는 `-`로 표시한다. 현재 경기 목 변환은 K/D/A·다중 킬 누락을 0으로 채우고 팀 골드 합계에서도 null을 0으로 취급한다. 모든 누락값을 구분해 표시하는 구현은 아니다.
- 실제 경기 시각을 모르면 게임 머리에서는 날짜를 생략하고, 목록에서는 `날짜 미확인`/`미확인`을 표시한다. 업로드 시각으로 대신하지 않는다.
- 단위가 검증되지 않은 원값(CC 시간·사망 시간 등)은 표시하지 않는다.
- 아이템·주문·룬은 "최종 세팅"이다. 구매 순서로 보이게 나열하지 않는다.
- Riot ID를 가리는 개인별 공개 설정은 없다. 현재 목 서버 접근 범위에서 표시하며 실제 열람 정책 연결은 남아 있다.
- 사용자 최근 게임은 "승"/"패" `StatusTag`, 게임 진영 머리는 "승리"/"패배" 텍스트, 정상 종료 시리즈는 승리 팀 이름으로 결과를 표시한다.
- Match의 A/B 팀은 시리즈 내 고정 구분이고, 게임마다의 블루/레드 진영과 다르다. 게임 화면에는 진영을, 시리즈 점수에는 팀 이름을 쓴다.

## `/g/[guildId]/matches` — 경기 기록

**목적** 서버의 시리즈를 찾아 상세로 들어간다. 특정 내전의 경기 흐름은 그 내전의 대진 페이지가 담당한다.

**데이터**

```ts
{
  live: MatchListItem[],        // 진행 중·대기, 현재 조회 상한 100개
  done: MatchListItem[],        // 종료·중도 종료·취소. 20개씩
  doneTotal, page, pageSize, q, empty
}
// MatchListItem = { id, scrimTitle, teamA, teamB, scoreA, scoreB, bestOf, status, playedAt: string | null }
```

**화면** (상태별 목록 두 개)

```text
[h1] 경기 기록                                         [Input search: 내전·팀 이름]

┌ 진행 중 ──────────────────────────────────────────────────────────── 1경기 ┐
│ 경기                              형식   스코어   결과          날짜        │
│ 포로팀 vs 칼날부리팀               BO3    1 : 1   [진행 중]     10/30(금) › │
│ 금요일 칼바람 내전                                                          │
└─────────────────────────────────────────────────────────────────────────────┘
┌ 종료 ────────────────────────────────────────────────────────────── 26경기 ┐
│ 돌거북팀 vs 바위게팀               BO3    1 : 2   🏆 바위게팀   10/24(토) › │
│ 포로팀 vs 칼날부리팀               BO3    1 : 0   [중도 종료]   10/17(토) › │
│ …                                                                           │
│                               [PageNav]                                     │
└─────────────────────────────────────────────────────────────────────────────┘
모바일: 행마다 [팀 vs 팀 / 내전 · BO · 날짜 | 스코어] 다음 줄에 결과
```

| 영역 | 사용 | 동작 |
| --- | --- | --- |
| 검색 | `<form role="search">` + `Input type="search" clear` | Enter·지우기 → `?q=`(내전·팀 이름, 최대 50자, 대소문자 무시 부분 일치). 두 목록에 함께 적용하고 page 초기화. 폼에 `nonSubmitButtons`. 참가자 검색은 없음 |
| 목록 | `MatchTable` (`section`·`ul`·CSS grid, 머리 줄 제목·개수, 열 제목은 `md` 이상, 행 전체가 `/matches/[id]` 링크) | 진행 중 목록은 경기가 있을 때만. 결과 열: 정상 종료는 트로피 + 승리 팀, 그 외는 상태 `Tag`. 점수는 기록된 게임 집계이며 일부 목 경기는 고정 점수 |
| 페이지 | `PageNav` (종료 표 아래) | `?page=`. 종료 표에만 적용 |

서버 홈의 최근 경기는 그대로 `MatchListRow`를 쓴다.

**상태** 기록 없음 "아직 기록된 경기가 없어요"(검색·목록 없음) / 종료 목록의 검색 결과 없음: "'{q}'에 맞는 경기가 없어요" / 끝난 경기 없음 "아직 끝난 경기가 없어요". 검색·쪽 이동 중에는 제목에 `Loading`, 이전 결과에 흐림 효과를 쓴다.

현재 정렬은 `playedAt` 내림차순이며 날짜 미확인은 뒤로 간다. 취소·중도 종료도 종료 목록에 포함한다. `page`는 기본 1, 음수는 1 이상으로 보정하지만 마지막 쪽을 넘는 값은 보정하지 않는다.

**미구현·미결정** DB 조회·실제 열람 권한, 기간 필터·운영 정렬 정책, 비멤버 열람 범위. 현재 UI에는 검색·종료 목록 쪽 이동 이외 필터가 없다.

## `/g/[guildId]/matches/[matchId]` — 경기 상세

**목적** 시리즈 점수와 게임별 결과·개인 성적을 보고, 권한이 있으면 ROFL을 올려 결과를 기록한다.

**권한** 현재 `load`와 업로드 action은 개발 모드만 허용한다. `can.upload`는 경기 상태가 `in_progress`일 때만 true이며 실제 운영자·참가자 권한 검사는 없다. 업로드 action은 목 경기 존재·진행 중 상태를 검사한다.

**근거** `samples/매치 결과 참고자료.png`의 구성(어두운 게임 머리 + 진영별 표)을 서비스 토큰으로 옮긴다.

**데이터** (`lib/features/matches/types.ts`의 `MatchDetail`·`GameDetail`·`GamePlayer`)

```ts
{
  match: { id, scrim: { id, title }, teamA, teamB, scoreA, scoreB, bestOf, status, hardFearless,
           games: { id, order, winner: 'a' | 'b' | null }[] },
  game: {                                   // ?game으로 고른 게임, 없거나 잘못되면 마지막 게임, 기록 없으면 null
    id, order, durationSec, playedAt: string | null, patch, mmrStatus, splashUrl,
    sides: { side: 'blue' | 'red', slot: 'a' | 'b', teamName, win,
             players: { userId, displayName, riotId, champion, level, kills, deaths, assists,
                        cs, damage, damageTaken, gold, visionScore, wardsPlaced, wardsKilled, controlWards,
                        heal, shield, largestKillingSpree, multiKills,
                        items: (LoadoutIcon | null)[7], spells, keystone, secondaryStyle,
                        score, badge: 'mvp' | 'ace' | null, fearlessViolation }[] }[]
  } | null,
  usedChampions: { a: ChampionRef[], b: ChampionRef[] } | null,   // 하드 피어리스 진행 중만
  can: { upload: boolean }
}
```

아이템·주문·룬 이름과 아이콘은 서버가 최신 Data Dragon `ko_KR` 카탈로그로 채운다(`loadoutResolver`). 경기의 과거 패치와 버전을 맞추지는 않는다. 찾지 못한 ID는 아이콘 없이 숫자 ID로 표시하며, ID 자체가 없으면 빈 칸을 유지한다.

**화면**

```text
[h1] 포로팀 vs 칼날부리팀                                    [ROFL 업로드: 진행 중만]
10월 정기 내전 · BO3 · 하드 피어리스  [상태]                ← 내전 이름은 /scrims/[id] 링크
┌ 포로팀  2 : 1  칼날부리팀 ┐                                          ← 시리즈 점수, 진 팀은 흐리게
[Tab] 1게임 | 2게임 | 3게임                                  ← 게임이 2개 이상일 때만
┌ GameHero (항상 어두운 카드, MVP 챔피언 스플래시) ───────────────────────┐
│ (레드 · 칼날부리팀 승리) [MMR 반영 대기]                      ┌ MVP ─────────┐ │
│ 25 : 42   ← 진영별 킬(블루·레드 색)                    │ 홍길동 자야 … │ │
│ 2026년 10월 24일 · 31분 3초 · 패치 16.21               └──────────────┘ │
└───────────────────────────────────────────────────────────────────────────┘
┌ 블루 · 포로팀 패배  60,700 골드                         25 K · 42 D · 26 A ┐
│ 선수(챔피언·레벨·주문·룬·이름·배지) | KDA | 딜량·받은 피해 | 시야 | CS | 아이템 | 상세 │
└────────────────────────────────────────────────────────────────────────────┘
┌ 레드 · 칼날부리팀 승리 … ┐
[h2] 다음 게임에서 쓸 수 없는 챔피언                        ← 하드 피어리스 진행 중만
```

| 영역 | 사용 | 동작 |
| --- | --- | --- |
| 시리즈 머리 | `h1`, 메타 한 줄(내전 링크), `StatusTag`, 점수 상자 | 점수는 기록된 게임 집계 또는 목 고정 점수. 정상 종료만 승자 표시 |
| ROFL 업로드 | `Button fill="base"` → `RoflUploadDialog` | `can.upload`일 때만. 남은 게임이 없으면 비활성 |
| 게임 선택 | `Tab` (`N게임`) | `?game=<id>`로 이동 |
| 게임 머리 | `GameHero` | 이긴 진영·팀, 진영별 킬, 날짜·시간·패치, MMR 대기 `StatusTag`, MVP 카드 |
| 진영 표 | `GameTeamTable` (`<table>` + `caption`) | 진영색 머리에 결과·총 골드·K/D/A. 열: 선수, 평점(`sm` 이상), KDA(비율), 딜량·받은 피해 막대(두 진영 최대값 기준)·시야(`lg` 이상), CS·최종 아이템(`md` 이상), `상세`. 아이템 7칸은 `xl` 미만에서 4칸씩 두 줄. `sm` 미만은 선수·KDA·상세만 남고 주문·룬 아이콘도 숨김 |
| 평점·배지 | 평점 열, MVP(이긴 팀 1위)·ACE(진 팀 1위) | **임시 성과 점수**: (K+A)/max(1,D) + 킬 관여×4 + 팀 내 피해 비중×6. 소수 둘째 자리까지 표시하며 진영별 최고 점수 동점자 모두 배지를 받을 수 있다. 게임 머리는 첫 MVP 한 명만 표시 |
| 피어리스 | 챔피언 옆 `StatusTag warning "피어리스"`, 하단 사용 챔피언 목록 | 같은 팀이 앞 게임에서 쓴 챔피언. 업로드를 막지 않는다 |
| 행 상세 | `GamePlayerDialog` (`Popup` 데스크톱 오른쪽, 모바일 아래) | 주문·룬·아이템 이름, 피해·골드·CS·시야·회복·보호막·연속 킬·다중 킬 |

### ROFL 업로드 팝업

```text
[h2] ROFL 업로드
[ROFL 선택: 최대 남은 게임 수 · 파일당 64MB]
[ImageList: 선택 뒤 3열]
  ┌───────────────────────────────┐
  │ KR-7312345678.rofl  12.4MB    │
  │ KR-7312345990.rofl  11.8MB    │
  └───────────────────────────────┘
                                         [닫기] [업로드]
```

| 단계 | 처리 |
| --- | --- |
| 파일 선택 | `ImageList`(`columns=3`, `maxSize=64`MB, `max`=남은 게임 수) + 숨긴 `<input type="file" accept=".rofl">`. `onclickUpload`로 입력을 열고 `addFiles()`로 넘긴다. 비어 있으면 선택 칸을 전체 폭으로 표시 |
| 업로드 | `?/upload` action으로 파일마다 순차 전송, 항목 `status="uploading"`. `업로드` 버튼 `loading`, 닫기 비활성 |
| 성공 | 항목 `status="success"`, `message`에 기록된 게임 번호를 저장. `닫기` 버튼·Escape의 `close()`를 거치면 `invalidateAll()` 후 마지막으로 기록된 게임 탭 선택 |
| 실패 | 항목 `status="error"`, `message`에 아래 문구를 저장. 다른 파일은 계속 진행. 전체 `업로드` 버튼을 다시 누르면 성공하지 않은 항목들을 재전송 |
| 응답 없음 | 항목 오류 "기록 여부를 확인하지 못했어요". `close()` 경로로 닫으면 재조회해 실제 반영을 확인 |

**현재 렌더링 한계** 설치된 STDF 3.0.0의 `ImageList`는 `itemChild`가 있으면 기본 항목 분기의 `statusChild`·재시도·삭제 UI를 렌더링하지 않는다. 현재 팝업은 `itemChild`로 파일명·크기를 그리므로 파일별 업로드 상태·성공·실패·재시도 버튼은 눈에 보이지 않는다. 결과 문구는 별도 `sr-only`/`aria-live` 목록에만 전달된다. 아래 메시지는 현재 action·항목 데이터의 결과이며 시각적 상태 표시 완료를 뜻하지 않는다.

또한 `Popup` 마스크로 닫기는 `open` 바인딩만 바꾸고 내부 `close()`를 호출하지 않는다. 업로드 후 마스크로 닫으면 재조회·게임 선택·파일 초기화 경로가 실행되지 않는다.

| 서버 결과 | 항목 메시지 |
| --- | --- |
| 손상·미지원 형식 | 읽을 수 없는 ROFL 파일이에요 |
| 같은 경기에서 중복 서명 발견 | 이미 {N}게임으로 기록된 파일이에요 |
| 결과 충돌·불완전 | 결과를 확인할 수 없어 기록하지 않았어요 |
| 진행 중이 아닌 경기 | 지금은 이 경기에 업로드할 수 없어요 |
| 파일 누락·잘못된 확장자 | ROFL 파일을 골라 주세요 |
| 64MiB 초과 | 파일이 너무 커요 |
| 경기 없음 | 경기를 찾을 수 없어요 |

파서 결과가 `consistent`인 파일은 검토·승인 단계 없이 목 저장소에 바로 기록한다. 승패 수동 입력은 없다. 참가자 연결 실패·실제 권한 상실 검증은 아직 없어 그 결과를 현재 동작으로 안내하지 않는다. 원본 파일은 보관하지 않는다.

**상태**

| 상황 | 처리 |
| --- | --- |
| 게임 없음 | 탭 대신 "아직 기록된 게임이 없어요" |
| `?game`이 잘못됨 | 기본 게임 선택(쿼리 무시) |
| 일부 수치·이미지 누락 | nullable 수치는 `-`, 챔피언은 이름 일부·장비는 ID/빈 칸으로 대체. K/D/A·팀 합계의 목 예외는 위 표시 규칙 참조 |
| 사용자 연결 없는 플레이어 | `GameTeamTable`에서 이름을 정적 텍스트로 표시하고 사용자 전적 링크를 만들지 않음 |
| 중도 종료(예: 5전 3선승 1:1) | 지금까지의 게임·점수를 그대로 보여 주고 승자 표시·업로드 버튼 없음. 중도 종료는 이 화면이 아니라 내전 요약 운영 메뉴에서 내전 단위로 한다 |

**목 기록 규칙과 한계** 다음 게임 번호는 현재 게임 수 + 1이며, 한 팀이 BO 과반을 이기면 경기만 `completed`로 바꾼다. 업로드한 게임의 실제 경기 시각은 null이다. 중복은 해당 경기 안의 `gameLengthMs + 참가자 챔피언 순서` 문자열로 검사하며 파일 해시나 서버 전체 중복 검사는 아니다. 블루 진영의 A/B 팀 연결도 게임 순번 홀짝으로 가정한다. 실제 계정↔팀원 연결과 진영 매핑, MMR 계산·통계 갱신·대진 자동 진출 연결은 없다. `mmrStatus`는 진행 중 경기의 마지막 게임만 `pending`, 나머지는 `applied`로 만드는 목 표시다.

**미구현·미결정** 실제 업로드 권한·참가자 연결·영구 저장·동시 등록 검증, 시각적 업로드 피드백·닫기 경로 보완, MVP·ACE 정책, 기존 결과 정정·재분석과 예외 연결 해결 담당. 현재 클라이언트는 남은 게임 수만 선택하게 하지만 action에는 별도 게임 수 상한 검사가 없다.

## `/g/[guildId]/players/[userId]` — 사용자 전적

**목적** 한 사용자의 서버 전적을 보는 화면이다. 현재는 사용자별 합성 게임을 집계하며 여러 Riot 계정의 실제 저장 기록 합산은 연결되지 않았다.

**근거** `samples/개별 전적 참고자료.png`의 머리(업적 배지·승패)·최근 10게임·핵심 지표(상위 %)·레이더·챔피언 성적·듀오 구성을 따른다. 등급(A·B 등)과 오브젝트·NJ Score처럼 정의가 없는 지표는 두지 않는다.

**권한** 개발 모드와 목 서버·사용자 존재를 확인한다. 실제 서버 열람 권한 검사는 미구현이며 개인별 공개 설정은 없다.

**데이터** (`lib/features/players/`의 `PlayerGame`·`summarize`·`topPercents`·`championRecords`·`duoRecords`, `achievements.ts`)

| 포지션 필터 | `Tab` (라벨에 게임 수) | `?position=`. 게임이 있는 포지션만 제공하고 그 외 값은 전체로 읽는다. 핵심 지표·상위 %·레이더·챔피언·최근 게임에 적용하고 `page`를 초기화 |
| 머리 | 업적 배지(`title` + `sr-only` 이름), 승·패·게임 | 배지는 통계 화면과 같은 업적 기준(4게임 이상) |

| 플레이 성향 | `RadarChart` | 전투(KDA)·성장(분당 골드)·시야·생존(데스 적은 순)·챔프 폭·킬 관여의 상위 %를 0~1로 그린다. 꼭짓점에 `title`, 축 목록은 `sr-only`. `percents`가 없으면 숨김 |
| 챔피언별 성적 | 카드 목록, 상위 5개에 순위 배지 | 6개까지 보이고 `챔피언 N개 모두 보기`/`접기`. 포지션을 바꾸면 다시 접는다 |

머리의 전체 승패·업적 배지·최근 10게임, MMR, 듀오는 포지션 필터와 무관하다. 챔피언은 게임 수 내림차순, 같으면 승률 내림차순이다. 상위 %는 같은 포지션 범위에서 4게임 이상인 사용자(본인 포함)를 비교해 `ceil((앞선 사람 수 + 1) / 비교 인원 × 100)`으로 계산하며 동점은 같은 값이다. 게임이 없으면 지표 대신 빈 안내, 본인이 4게임 미만이면 상위 %와 레이더를 숨긴다.

**현재 한계·미결정** `riotIds`는 `/me`·서버 관리의 계정 저장소와 연결되지 않는다. MMR의 게임 수와 합성 전적의 게임 수는 다를 수 있다(합성은 포지션당 최대 30게임). 합성 최근 게임의 링크는 몇 개의 목 경기 ID를 재사용하므로 링크된 상세가 그 사용자의 수치와 일치하지 않는다. 기본 집계 기간·시즌·탈퇴자 처리와 운영 지표 정책은 미결정이다.

## `/g/[guildId]/stats` — 서버 통계

**목적** 서버 전체 누적 지표와 사용자별 순위를 본다.

**근거** `samples/서버통계부분.png`·`samples/업적리스트.png`의 지표 카드·업적 캐러셀·업적별 순위·리더보드 배지 구성을 따른다. 기간·시즌 선택과 OPS·등급·유틸 열은 현재 없다.

**화면**

```text
[h1] 통계
[Grids 6열(모바일 2)] StatTile(아이콘): 총 게임 | 참가자 | 평균 게임 시간 | 분당 킬 | 평균 KDA | 사용한 챔피언
[Tab] 전체 | 탑 | 정글 | 미드 | 원딜 | 서폿                ← 업적·리더보드·챔피언에 적용
[h2] 업적                      최근 10게임만 [Switch]  [업적별 순위]
   ‹  [앞 업적(흐림)]  [ 1위 카드: 얼굴·이모지·업적명·설명·이름·값 ]  [다음 업적(흐림)]  ›
   ● ● ━ ● ● …                                         ← 업적 바로가기 점
   4게임 이상 뛴 사람부터 집계해요

<table> 챔피언 | 픽 | 승률 | KDA     ← 픽 많은 순, 5픽 미만은 승률 `-`, 15개씩 PageNav
```

| 영역 | 사용 | 동작 |
| --- | --- | --- |
| 핵심 지표 | `Grids` + `StatTile` | 게임 수는 사용자 게임 수 ÷ 10을 반올림하고, 분당 킬은 전체 킬 ÷ (사용자 게임 시간 합 ÷ 10). 상단 지표는 모든 필터와 무관한 서버 전체 값 |
| 포지션 | `Tab` | `?position=` |
| 업적 | `AchievementCarousel` | 업적 16종(`ACHIEVEMENTS`, 임시). 4게임 이상인 사람 중 1위를 한 장씩. 이전·다음 `Button`, 점 버튼, 터치 밀기. `?recent=1`은 포지션 필터 적용 후 사용자별 최근 10게임을 집계하며 리더보드의 1위 배지도 같은 결과 사용 |
| 업적별 순위 | `AchievementRankingDialog` (`Popup`) | 업적 칩(`aria-pressed`)으로 골라 상위 10명. 고른 업적은 캐러셀과 같이 움직인다 |
| 리더보드 | `LeaderboardTable` | `?min=` 기본 5, 1~50으로 제한. 수치는 선택 포지션의 전체 게임이며 최근 10게임 스위치와 무관. 기본 KDA 내림차순, 열 머리 버튼으로 정렬(`aria-sort`), 같은 열 재선택은 방향 전환. 정렬·20명씩 쪽 이동은 로컬 상태. `md` 미만은 순위·사용자·KDA·승률, `sm` 미만은 업적 배지와 K/D/A·승패 보조 줄도 숨김. 게임·킬 관여는 `md` 이상, CS/분·피해/분·시야는 `lg` 이상 |
| 챔피언 | `<table>` + 챔피언 아이콘, `PageNav` | 포지션만 적용하고 최근 10게임·최소 게임 필터는 적용하지 않음. 픽 수 내림차순, 동점이면 승률 내림차순. 15개씩 로컬 쪽 이동, 5픽 미만 승률은 `-` |

쿼리에는 `position`·`recent`·`min`만 저장한다. 잘못된 포지션은 전체, `recent`는 정확히 `1`일 때만 켜진다. 리더보드 쪽은 행 데이터 변경·정렬 시 1로 돌아가고, 챔피언 쪽·선택 업적도 서버 필터 값이 갱신되면 처음으로 돌아간다. 업적은 지표 동점이면 게임 수 많은 순으로 정렬하고 첫 사용자 한 명에게 배지를 부여한다. 양옆 업적 미리보기는 `aria-hidden`·`inert` 장식이며 활성 카드만 사용자 전적 링크를 가진다.

**상태** 현재 `devGuild001` 이외 목 서버는 "아직 기록된 게임이 없어요" (지표 0 대신). 업적·리더보드 표본 없음: "{N}게임 이상 뛴 사람이 없어요". 필터 이동 중에는 업적·리더보드·챔피언 영역의 이전 결과를 흐리게 표시한다.

**현재 한계·미결정** 수치는 독립 합성 데이터여서 실제 경기 ID를 기준으로 중복 제거한 게임 수가 아니며 ROFL 등록과 연동되지 않는다. `평균 KDA`는 개별 KDA 평균이 아니라 전체 (킬+어시스트)/max(1,데스)다. 실제 DB 집계·기간·시즌·갱신 방식 및 지표·업적 정책은 미결정이다.
