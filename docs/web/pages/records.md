# 기록 페이지

코드 대조일: 2026-11-16. 상단 서버 메뉴를 유지하고 경기 상세에는 소속 내전의 공통 머리·메뉴도 표시한다. 실제 서버의 경기·개인 전적·통계를 DB에서 공개 조회한다. 개발 샘플 서버만 목 데이터를 사용하며 ROFL 결과는 확정 라인업·계정·포지션·팀·중복·순서를 검증해 자동 등록한다.

## 현재 데이터 연결 범위

| 화면 | 데이터 출처와 저장 범위 |
| --- | --- |
| 경기 목록·상세 | `server/matches/queries.ts`가 서버 범위의 Match·Game·채택 ROFL·실출전 데이터를 조회 |
| ROFL 업로드 | 관리자·확정 출전자가 등록. 결과·실사용 계정·MMR·대진·게시 작업을 같은 DB 트랜잭션으로 저장. 원본은 보관하지 않음 |
| 사용자 전적·서버 통계 | `server/records/queries.ts`가 선택 시즌의 완료 Game과 당시 실출전을 조회. 생략하면 활성 시즌. 취소 내전·대진 제외, 중도 종료 기록 보존, 현재 계정 소유자 변경과 무관한 과거 귀속 유지 |
| MMR | 선택 시즌의 유효 반영을 읽고 확인된 사용자의 5포지션을 표시. 선택 시즌의 미반영 포지션은 초기 1500. 실제 ROFL 결과 등록과 같은 트랜잭션에서 반영하고 안전한 마지막 결과만 역분개 |
| 업적·MVP·ACE·평점 | 합의된 평가 기준이 없어 실제 서버에서는 만들지 않음. 개발 샘플에만 가상 지표 표시 |
| 이름·이미지 | 실제 Data Dragon 카탈로그를 사용하고 실패 시 텍스트·빈 이미지 대체 |

[ROFL 적재 모델](../../rofl-import.md)에 자동 계정 귀속·등록·정정 계약을 정리했다.

### 개인 전적·서버 통계의 시즌 선택

`server/records/seasons.ts`가 MSM1의 같은 서버 시즌 선택 규칙을 준용한다. `?season=<uuid>`가 없으면 활성 시즌만 읽고, 명시하면 해당 서버의 종료 시즌을 포함해 그 시즌만 읽는다. 전체 시즌 합산은 제공하지 않는다. 잘못된 UUID(빈 값 포함)는 400, 다른 서버 또는 없는 시즌은 404다. 활성 시즌이 없고 선택도 없으면 기록은 비어 있고 `selectedSeasonId`는 `null`이다.

두 페이지의 loader는 빈 상태에도 아래 형식을 반환한다(`lib/features/seasons.ts`). 시즌은 활성 시즌 먼저, 시작 시각·ID 내림차순이다.

```ts
type RecordSeasonSelection = {
    seasons: { id: string; name: string; startedAt: string; endedAt: string | null }[];
    selectedSeasonId: string | null;
};
```

`SeasonSelector`는 여러 시즌이 있거나 아직 선택되지 않은 종료 시즌이 있으면 조회할 시즌 메뉴를 제공한다. 유일한 시즌을 이미 조회 중이면 정적 시즌 이름을 표시한다. 시즌 변경은 `page`·`offset`만 제거하고 기존 포지션·최소 게임·최근 기록 등 다른 쿼리를 보존한다. 순위·리더보드·듀오에서 사용자 전적으로 이동할 때 선택 시즌을 유지한다. 기록 없는 시즌에서도 선택기를 유지해 다른 시즌으로 이동할 수 있다. 개발 샘플에는 실제 시즌 이력이 없어 `seasons: []`, `selectedSeasonId: null`을 반환하며 과거 UUID나 수치를 만들지 않는다. 경기 목록은 아래 별도 계약대로 전체 시즌이 기본이며 검색·기간·시즌을 조회 버튼에서 함께 적용한다.

## 표시 규칙

- 누락된 수치·시각·포지션은 nullable로 유지하고 수치는 `-`로 표시한다. 통계는 지표마다 유효한 표본만 같은 분자·분모에 포함하며 팀 합계에 필요한 출전 기록이 부족하면 합계도 null이다. 업로드 시각·희망 포지션·목 평점으로 보충하지 않는다.
- 실제 경기 시각을 모르면 세트 머리에서는 날짜를 생략하고, 목록에서는 `날짜 미확인`을 표시한다. 업로드 시각으로 대신하지 않는다.
- 단위가 검증되지 않은 원값(CC 시간·사망 시간 등)은 표시하지 않는다.
- 아이템·주문·룬은 "최종 세팅"이다. 구매 순서로 보이게 나열하지 않는다.
- 일반 서버는 공개 열람하되 이름·아바타·Discord ID와 Riot ID는 본인의 독립 공개 설정을 따른다. 비공개·탈퇴 사용자의 과거 기록은 별도 공개 UUID로 연결하고 이전 스냅샷으로 개인정보를 되살리지 않는다. [내 정보](global.md#me--내-정보)를 따른다.
- 사용자 전적 내역은 "승"/"패" `StatusTag`, 세트 진영 머리는 "승리"/"패배" 텍스트, 정상 종료 시리즈는 승리 팀 이름으로 결과를 표시한다. 통계·개인 전적의 횟수 표시는 현재 화면의 `게임` 문구를 유지한다.
- Match의 A/B 팀은 시리즈 내 고정 구분이고, 세트마다의 블루/레드 진영과 다르다. 세트 화면에는 진영을, 시리즈 점수에는 팀 이름을 쓴다.

## `/g/[guildId]/matches` — 경기 기록

**목적** 서버의 시리즈를 찾아 상세로 들어간다. 특정 내전의 경기 흐름은 그 내전의 대진 페이지가 담당한다.

**데이터**

```ts
{
  live: MatchListItem[],        // 진행 중·대기, 현재 조회 상한 100개
  done: MatchListItem[],        // 종료·중도 종료·취소. 20개씩
  doneTotal, page, pageSize, q, empty,
  from, to, seasons, selectedSeasonId, filterError
}
// MatchListItem = { id, scrimTitle, teamA, teamB, scoreA, scoreB, bestOf, status, playedAt: string | null }
```

**화면** (상태별 목록 두 개)

```text
[h1] 경기 기록
[검색] [경기일: 시작일 / 종료일] [시즌: 전체 시즌 또는 선택] [조회] [초기화]
기간을 지정하면 날짜가 확인된 경기만 보여요.

┌ 진행 중 ──────────────────────────────────────────────────────────── 1경기 ┐
│ 경기                              형식   스코어   결과          날짜        │
│ 포로팀 vs 칼날부리팀               BO3    1 : 1   [진행 중]     10/30(금) › │
│ 금요일 칼바람 내전                                                          │
└─────────────────────────────────────────────────────────────────────────────┘
┌ 종료 ────────────────────────────────────────────────────────────── 26경기 ┐
│ 돌거북팀 vs 바위게팀               BO3    1 : 2   🏆 바위게팀   10/24(토) › │
│ 포로팀 vs 칼날부리팀               BO3    1 : 0   [중도 종료]   10/17(토) › │
│ …                                                                           │
│                               [PageNav]                                     │
└─────────────────────────────────────────────────────────────────────────────┘
모바일: 행마다 [팀 vs 팀 / 내전 · BO · 날짜 | 스코어] 다음 줄에 결과
```

| 영역 | 사용 | 동작 |
| --- | --- | --- |
| 복합 필터 | `MatchFilters`의 `<search><form method="GET">`, STDF Input/Button·SeasonSelector, native date input | 검색·기간·시즌은 초안으로 편집하고 조회/Enter에서 한 번에 적용한다. 지우기는 검색 초안만 비우며 초기화는4조건 전체를 지우고 조회한다. 검색은 내전/팀 이름 부분 일치50자, 참가자 검색은 없음. 적용은 page만 초기화하고 다른 query를 보존한다 |
| 목록 | `MatchTable` (`section`·`ul`·CSS grid, 머리 줄 제목·개수, 열 제목은 `md` 이상, 행 전체가 `/matches/[id]` 링크) | 진행 중 목록은 경기가 있을 때만. 결과 열: 정상 종료는 트로피 + 승리 팀, 그 외는 상태 `Tag`. 점수는 DB에 저장된 Match 결과. 개발 샘플에만 고정 점수 예시가 있음 |
| 페이지 | `PageNav` (종료 표 아래) | `?page=`. 종료 표에만 적용 |

서버 홈의 최근 경기는 그대로 `MatchListRow`를 쓴다.

**상태** 서버 전체 기록 없음은 "아직 기록된 경기가 없어요"다. 필터0결과에도 폼을 유지하고 "조건에 맞는 경기가 없어요"로 구분한다. 잘못된 기간은 role=alert와 날짜 입력에서 고치며 조회하지 않은 결과/빈 상태는 표시하지 않는다. 순서가 뒤집힌 날짜는 client에서 조회 전 차단하고 종료일에 포커스를 둔다. 조회 중 단일 요청과 이전 결과의 aria-busy/흐림을 유지한다. 범위 밖 쪽은 별도 안내와 기존 PageNav로 돌아가며 총1쪽이면 첫 페이지 복구 버튼 한 곳만 제공한다.

현재 정렬은 표시값인 `playedAt`(완료 Game.startedAt 중 최소 실제 시각) 내림차순·null 마지막·Match ID 동률 순서다. DB·목·정렬·기간·쪽에 같은 의미를 사용한다. 취소·중도 종료도 종료 목록에 포함한다. `page`는 기본1이며 상한100000, 마지막 쪽을 넘는 값은 보정하지 않는다.

**기간·시즌** `from`/`to`는 엄격한 YYYY-MM-DD이고 한국 시각의 시작일0시 이상·종료일 다음날0시 미만이다. 두 목록에 동일 적용하며 기간을 지정하면 표시일null인 경기는 제외한다. 업로드/생성 시각으로 보충하지 않는다. 시즌 생략은 전체 시즌이며 명시하면 같은 서버 시즌만 허용한다. 개인 전적/통계의 기본 활성 시즌과 다르다. 날짜 오류는200+filterError·안전한 요청값을 반환하고 기록 조회를 생략해 수정할 수 있게 한다. 명시 빈/잘못된 시즌은400, 다른 서버/없는 시즌은404다.

목 경기에는 실제 시즌 귀속이 없어 기존 seasons:[]를 보존하며 임의 fixture시즌을 만들지 않는다. 실제2시즌·ROFL·명시 날짜/null의 검증은 [후속 작업표](../../remaining-implementation.md)를 따른다.

## `/g/[guildId]/matches/[matchId]` — 경기 상세

**목적** 시리즈 점수와 세트별 결과·개인 성적을 본다. 확정 라인업의 ROFL을 등록하고 마지막 결과를 안전하게 취소한다.

**권한** 조회는 활성 서버의 경기를 누구나 읽는다. 업로드는 관리자 또는 확정된 경기 출전자에게 허용하며 실제 POST에서도 현재 권한을 다시 검사한다. 라인업 확정·해제와 마지막 결과 취소는 관리자만 가능하다. 개발 샘플의 업로드만 목 경기 존재·진행 중 상태를 검사한다.

**근거** `samples/매치 결과 참고자료.png`의 구성(어두운 세트 머리 + 진영별 표)을 서비스 토큰으로 옮긴다.

**데이터** (`lib/features/matches/types.ts`의 `MatchDetail`·`GameDetail`·`GamePlayer`)

```ts
{
  match: { id, scrim: { id, title }, teamA, teamB, scoreA, scoreB, bestOf, status, hardFearless,
           games: { id, order, winner: 'a' | 'b' | null }[] },
  game: {                                   // ?game으로 고른 세트, 없거나 잘못되면 마지막 세트, 기록 없으면 null
    id, order, durationSec, playedAt: string | null, patch, mmrStatus, splashUrl,
    sides: { side: 'blue' | 'red', slot: 'a' | 'b', teamName, win,
             players: { userId, displayName, riotId, champion, level, kills, deaths, assists,
                        cs, damage, damageTaken, gold, visionScore, wardsPlaced, wardsKilled, controlWards,
                        heal, shield, largestKillingSpree, multiKills,
                        items: (LoadoutIcon | null)[7], spells, keystone, secondaryStyle,
                        score, badge: 'mvp' | 'ace' | null, fearlessViolation }[] }[]
  } | null,
  usedChampions: ChampionRef[] | null,   // 하드 피어리스 진행 중 양 팀 공통 목록
  operation: MatchOperationContext | null, // 경기 전체 라인업·팀별 선수·다음 세트·revision·조작 권한
  can: { upload: boolean }
}
```

아이템·주문·룬 이름과 아이콘은 서버가 최신 Data Dragon `ko_KR` 카탈로그로 채운다(`loadoutResolver`). 경기의 과거 패치와 버전을 맞추지는 않는다. 찾지 못한 ID는 아이콘 없이 숫자 ID로 표시하며, ID 자체가 없으면 빈 칸을 유지한다.

**화면** 아래는 실제 서버의 진행 중 경기 예시다. 개발 샘플의 가상 MVP·평점은 포함하지 않는다.

| 영역 | 사용 | 동작 |
| --- | --- | --- |
| 시리즈 머리 | 내전 공통 `h1`·메뉴 아래 팀 이름·점수를 합친 `h2`, BO 방식, `StatusTag` | 점수는 DB에 저장된 Match 결과이며 개발 샘플만 고정 예시를 사용. 정상 종료만 승자 표시. 상태 배지의 조상에 opacity를 적용하지 않음 |

| ROFL 업로드 | `Button fill="base"` → `RoflUploadDialog` | `can.upload`일 때만. 남은 세트가 없으면 비활성 |
| 세트 선택 | `Tab` (`N세트`) | `?game=<id>`로 이동. 이전 세트를 유지하면서 aria-busy와 로딩 안내 제공 |
| 세트 머리 | `GameHero` | 이긴 진영·팀, 진영별 킬, 확인된 날짜·시간·패치. MMR 미반영 자료에는 대기 `StatusTag`를 표시할 수 있지만 정상 ROFL 등록은 MMR까지 함께 저장. MVP 카드는 개발 샘플만 표시 |
| 진영 표 | `GameTeamTable` (`<table>` + `caption`) | 진영색 머리에 결과·총 골드·K/D/A. 열: 선수, 평점(`sm` 이상), KDA(비율), 딜량·받은 피해 막대(두 진영 최대값 기준)·시야(`lg` 이상), CS·최종 아이템(`md` 이상), `상세`. 아이템 7칸은 `xl` 미만에서 4칸씩 두 줄. `sm` 미만은 선수·KDA·상세만 남고 주문·룬 아이콘도 숨김 |
| 평점·배지 | 평점 열, MVP(이긴 팀 1위)·ACE(진 팀 1위) | 실제 서버에서는 평점·배지가 null이다. 개발 샘플의 **임시 성과 점수**: (K+A)/max(1,D) + 킬 관여×4 + 팀 내 피해 비중×6. 소수 둘째 자리까지 표시하며 진영별 최고 점수 동점자 모두 배지를 받을 수 있다. 세트 머리는 첫 MVP 한 명만 표시 |
| 피어리스 | 챔피언 옆 `StatusTag warning "피어리스"`, 하단 양 팀 공통 사용 챔피언 목록 | 같은 경기의 앞선 유효 세트에서 양 팀 실출전자가 사용한 챔피언. 진영 변경과 무관하게 적용하고 취소한 세트·예정 로스터는 제외한다. 중복 챔피언은 한 번만 표시하며 위반을 이유로 등록을 막지 않는다 |
| 행 상세 | `GamePlayerDialog` (`Popup` 데스크톱 오른쪽, 모바일 아래) | 주문·룬·아이템 이름, 피해·골드·CS·시야·회복·보호막·연속 킬·다중 킬. 상세·닫기는 44px이고 열린 동안 Popup 위치를 유지 |

### ROFL 업로드 팝업

실제 서버에서는 다음 세트의 파일 하나와 그 세트의 블루 팀을 지정한다. 블루·레드 팀 이름을 확인하는 체크는 기본 해제이며, 파일·진영·경기/세트 변경과 팝업 닫기에서 초기화한다. 서버도 명시적 확인값 `true`를 검사한다. 취소한 동일 파일은 기존에 저장한 블루 팀으로만 복구할 수 있고 진영을 바꿔 선수 귀속을 덮어쓰지 않는다. 확정 라인업은 모든 세트에서 재사용한다. 입력창을 연 시점의 경기 revision·라인업·세트 번호를 전송한다.

```text
[h2] ROFL 업로드
[이번 세트의 블루 팀]
[블루·레드 팀 확인 체크]
[ROFL 선택: 1개 · 파일당 64MB]
[ImageList: 실제 서버에서는 한 파일]
  ┌───────────────────────────────┐
  │ KR-7312345678.rofl  12.4MB    │
  └───────────────────────────────┘
                                         [닫기] [업로드]
```

| 단계 | 처리 |
| --- | --- |
| 파일 선택 | `ImageList`(`columns=3`, `maxSize=64`MB, `max`=실제 서버 1개, 개발 샘플 남은 세트 수) + 숨긴 `<input type="file" accept=".rofl">`. `onclickUpload`로 입력을 열고 `addFiles()`로 넘긴다. 실제 서버와 빈 선택 칸은 전체 폭으로 표시하고 개발 샘플의 다중 파일만 3열로 표시 |
| 업로드 | 실제 서버는 `?/upload` action으로 다음 세트 파일 하나를 전송. 개발 샘플만 다중 파일 순차 전송. 항목 `status="uploading"`, `업로드` 버튼 `loading`, 닫기 비활성. 함수 가드와 finally로 동시 업로드 방지 |
| 성공 | 항목 `status="success"`, `message`에 기록된 세트 번호를 저장. `닫기` 버튼·Escape의 `close()`를 거치면 `invalidateAll()` 후 마지막으로 기록된 세트 탭 선택 |
| 실패 | 항목 `status="error"`, `message`에 검증 이유를 표시. 일반 실패는 선택 파일을 보존하고 같은 `업로드` 버튼으로 재시도하며 개발 샘플의 순차 전송도 첫 실패에서 멈춤. 충돌·응답 유실은 재전송 비활성 |
| 응답 없음 | 항목 오류 "기록 여부를 확인하지 못했어요". `close()` 경로로 닫으면 재조회해 실제 반영을 확인 |

파일명·크기·처리 상태·성공/실패 문구와 선택 해제를 `itemChild` 안에 표시한다. 마스크·Escape·닫기 버튼은 모두 같은 초기화·재조회 경로를 사용한다. 응답 유실·409 충돌 뒤에는 재전송을 멈추고 닫을 때 최신 상태를 확인한다.

| 서버 결과 | 항목 메시지 |
| --- | --- |
| 손상·미지원 형식 | 실제 서버는 파서 검증 문구(예: ROFL 파일 헤더가 올바르지 않습니다.), 개발 샘플은 읽을 수 없는 ROFL 파일이에요 |
| 중복 결과 | 실제 서버는 같은 성공 요청의 재시도에는 기존 성공을 반환한다. 취소 파일은 같은 경기·세트·라인업의 최신 revision에서 복구할 수 있고 다른 문맥에서는 충돌한다. 개발 샘플은 이미 {N}세트로 기록된 파일이에요 |
| 결과 충돌·불완전 | 실제 서버는 출전자·팀·포지션·승패 등 실패한 검증의 이유를 반환. 개발 샘플은 결과를 확인할 수 없어 기록하지 않았어요 |
| 진행 상태·세트·라인업 변경 | 실제 서버는 현재 요청과 다른 운영 상태를 충돌로 거절. 개발 샘플은 지금은 이 경기에 업로드할 수 없어요 |
| 파일 누락·잘못된 확장자 | ROFL 파일을 골라 주세요 |
| 64MiB 초과 | 파일이 너무 커요 |
| 경기 없음 | 경기를 찾을 수 없어요 |

개발 샘플에서 파서 결과가 `consistent`인 파일은 검토·승인 단계 없이 목 저장소에 바로 기록한다. 승패 수동 입력은 없다. 운영 경로는 실제 권한·계정·라인업을 검증하며 개발 샘플의 단순 등록과 구분한다. 원본 파일은 보관하지 않는다.

**상태**

| 상황 | 처리 |
| --- | --- |
| 세트 없음 | 탭 대신 "아직 기록된 세트가 없어요" |
| `?game`이 잘못됨 | 기본 세트 선택(쿼리 무시) |
| 일부 수치·이미지 누락 | nullable 수치는 `-`, 챔피언은 이름 일부·장비는 ID/빈 칸으로 대체. 실제 수치·팀 합계는 누락을 0으로 채우지 않음 |
| 사용자 연결 없는 플레이어 | `GameTeamTable`에서 이름을 정적 텍스트로 표시하고 사용자 전적 링크를 만들지 않음 |
| 중도 종료(예: 5전 3선승 1:1) | 지금까지의 세트·점수를 그대로 보여 주고 승자 표시·업로드 버튼 없음. 중도 종료는 이 화면이 아니라 내전 요약 운영 메뉴에서 내전 단위로 한다 |

**목 기록 규칙과 한계** 다음 세트 번호는 현재 세트 수 + 1이며, 한 팀이 BO 과반을 이기면 경기만 `completed`로 바꾼다. 업로드한 세트의 실제 경기 시각은 null이다. 중복은 해당 경기 안의 `gameLengthMs + 참가자 챔피언 순서` 문자열로 검사하며 파일 해시나 서버 전체 중복 검사는 아니다. 블루 진영의 A/B 팀 연결도 세트 순번 홀짝으로 가정한다. 실제 계정↔팀원 연결과 진영 매핑, MMR 계산·통계 갱신·대진 자동 진출 연결은 없다. `mmrStatus`는 진행 중 경기의 마지막 세트만 `pending`, 나머지는 `applied`로 만드는 목 표시다.

**라인업·정정** 라인업 편집은 같은 팀 안에서 드래그 또는 선수 선택 후 자리 선택으로 배치·교환하며, 모든 포지션이 채워지면 한 번 확정한다. 진출 팀의 직전 확정 포지션은 다음 경기에도 복사하고 경매의 다음 경기는 복사한 초안을 확정한다. `마지막 세트 취소`는 이후 MMR 변경·후속 경기 작업이 없을 때만 허용한다. 취소 이력은 보존하며 새 결과를 같은 세트 번호로 등록해 정정한다. 같은 파일도 같은 경기·세트·라인업의 최신 revision에서 다시 올려 복구하거나 블루 팀을 정정할 수 있다. 복구는 기존 출전자·계정 근거를 유지한 새 Game으로 기록하며 다른 경기·세트에 재사용할 수 없다.

**미결정** MVP·ACE·종합 평점 정책. 개발 샘플의 가상 지표는 운영 결과에 적용하지 않는다.

## `/g/[guildId]/players/[userId]` — 사용자 전적

**목적** 한 사용자의 선택 시즌 서버 전적을 본다. 완료 Game의 당시 출전 사용자 ID로 기록을 합산하므로 해당 서버의 여러 Riot 계정 기록이 함께 조회되고, 현재 소유자 변경으로 과거 기록이 이전되지 않는다.

**근거** `samples/개별 전적 참고자료.png`의 머리(업적 배지·승패)·최근 10게임·핵심 지표(상위 %)·레이더·챔피언 성적·듀오 구성을 따른다. 등급(A·B 등)과 오브젝트·NJ Score처럼 정의가 없는 지표는 두지 않는다.

**권한** 활성 서버의 현재 연결 사용자 또는 당시 참가 기록이 있는 사용자를 누구나 조회한다. 개인별 공개 설정은 없다.

**데이터** (`lib/features/players/`의 `PlayerGame`·`summarize`·`topPercents`·`championRecords`·`duoRecords`, `achievements.ts`)

```ts

  selectedSeasonId: string | null,

  badges: { id, emoji, title }[],                                       // 실제 서버는 빈 배열. 개발 샘플만 업적 표시
```

| 영역 | 사용 | 동작 |
| --- | --- | --- |
| 시즌 | `SeasonSelector` | 머리에서 `?season=` 선택. MMR·전적·비교 표본 전체를 같은 시즌으로 읽고, 포지션 필터와 별개로 유지 |
| 최근 10게임 | 정적 챔피언 아이콘(승패 테두리 + `sr-only` 결과) | 결과 요약이며, 상세 이동은 아래 기록 행에서 제공 |
| 포지션 필터 | `Tab` (라벨에 게임 수) | `?position=`. 게임이 있는 포지션만 제공하고 그 외 값은 전체로 읽는다. 핵심 지표·상위 %·레이더·챔피언·최근 게임에 적용하고 `page`를 초기화 |
| 머리 | 업적 배지(`title` + `sr-only` 이름), 승·패·게임 | 배지는 통계 화면과 같은 업적 기준(4게임 이상) |
| 핵심 지표 | `Grids` + 중립 `StatTile` (3/2열), `AccessibleAccordion` | 승률·KDA·킬 관여·분당 CS·분당 피해량·게임당 시야 6개를 먼저 표시. 최장 연승·최장 연패·평균 K/D/A·최다 킬·챔피언 폭·분당 골드·분당 받은 피해 9개는 세부 지표에서 펼침. 모든 기존 수치·계산·상위 %(연패는 없음)를 유지 |
| 플레이 성향 | `RadarChart` | 전투(KDA)·성장(분당 골드)·시야·생존(데스 적은 순)·챔프 폭·킬 관여의 상위 %를 0~1로 그린다. 기존 상위 % 값은 각 축 이름 아래에도 보이고, figcaption에서 바깥쪽일수록 서버 내 순위가 높음을 설명한다. 꼭짓점 `title`·`sr-only` 축별 목록도 유지. `percents`가 없으면 숨김 |
| 챔피언별 성적 | 카드 목록, 상위 5개에 순위 배지 | 6개까지 보이고 `챔피언 N개 모두 보기`/`접기`. 포지션을 바꾸면 다시 접는다 |
| 최근 게임 | `CellGroup` + `LinkCell` | 챔피언·포지션 아이콘, K/D/A·CS, 내전·날짜, `detailChild`에 승/패 `StatusTag`. 10개씩 `PageNav`. 같은 목적지 URL이 반복되면 첫 기록만 링크, 나머지는 같은 내용을 가진 정적 LinkCell. 범위를 벗어난 쪽은 빈 안내와 기존 쪽 이동 제공 |
| MMR | `<table>` | 포지션·MMR·게임. 핵심 지표 다음 DOM 영역으로 한 번 표시하며 데스크톱에서는 지표 옆 첫 행에 배치 |
| 듀오 | `DuoList` | 함께한 게임 수와 승률, 사용자 전적 링크. 함께 3게임 이상인 사람 중 높은/낮은 승률 순으로 각각 최대 2명, 두 목록에 중복 없음. 없으면 "세 게임 이상 함께한 사람이 없어요" |

머리의 전체 승패·최근 10게임, MMR, 듀오는 선택 시즌 안에서 포지션 필터와 무관하다. 필터·쪽 이동 중에는 이전 기록을 유지하고 aria-busy·로딩 안내를 제공한다. 주요 이름과 Riot ID는 긴 문자열도 줄바꿈한다. 실제 서버에서는 업적 배지를 숨긴다. 경기 시각이 확인되지 않은 기록이 섞이면 최근 10게임과 연승·연패를 표시하지 않고 내역의 날짜는 미확인으로 남긴다. 챔피언은 게임 수 내림차순, 같으면 승률 내림차순이다. 상위 %는 같은 포지션 범위에서 4게임 이상인 사용자(본인 포함)를 비교해 `ceil((앞선 사람 수 + 1) / 비교 인원 × 100)`으로 계산하며 동점은 같은 값이다. 게임이 없으면 지표 대신 빈 안내, 본인이 4게임 미만이면 상위 %와 레이더를 숨긴다.

**현재 한계·미결정** MMR 게임 수는 유효 원장 반영 기준이므로 전체 전적 수와 다를 수 있다. 상위 %는 선택 시즌·포지션 안에서 지표별 유효 값이 있는 사용자만 비교하며 누락 지표는 레이더에 넣지 않는다. MSM1에 없는 운영 업적은 후속 범위다. 탈퇴·계정 연결 변경 후에도 당시 기록의 귀속을 유지한다.

## `/g/[guildId]/stats` — 서버 통계

**목적** 서버 전체 누적 지표와 사용자별 순위를 본다.

**근거** `samples/서버통계부분.png`·`samples/업적리스트.png`의 지표 카드·업적 캐러셀·업적별 순위·리더보드 배지 구성을 따른다. 시즌은 실제 서버 이력에서 선택하며 임의 기간 필터와 OPS·등급·유틸 열은 현재 없다.

**화면** 실제 서버는 아래 구성 중 업적·업적별 순위·최근 10게임 업적 필터를 숨긴다.

```text
[h1] 통계                                         [시즌: 선택한 시즌 ▾]
[자동 갱신 켜짐/꺼짐] [새로고침]   화면 갱신 HH:mm:ss · 30초 간격
[Grids 6열(모바일 2)] StatTile(아이콘): 총 게임 | 참가자 | 평균 게임 시간 | 분당 킬 | 평균 KDA | 사용한 챔피언
[Tab] 전체 | 탑 | 정글 | 미드 | 원딜 | 서폿                ← 업적·리더보드·챔피언에 적용
[h2] 업적                      최근 10게임만 [Switch]  [업적별 순위]
   [ 1위 카드: 얼굴·이모지·업적명·설명·이름·값 ]
   [이전]                 [다음]                         ← 내용 밖 조작
   ● ● ━ ● ● …                                         ← 업적 바로가기 점
   4게임 이상 뛴 사람부터 집계해요
[h2] 리더보드        최소 게임 [Stepper]  13명 / 18명
<table> 순위 | 사용자 [업적 배지] | KDA | 승률 | 게임 | 킬 관여 | CS/분 | 피해/분 | 시야   ← 열 머리로 정렬, 20명씩, 1~3위 행 바탕 구분
[h2] 챔피언
<table> 챔피언 | 픽 | 승률 | KDA     ← 픽 많은 순, 5픽 미만은 승률 `-`, 15개씩 PageNav
```

| 영역 | 사용 | 동작 |
| --- | --- | --- |
| 시즌 | `SeasonSelector` | 제목 옆에서 `?season=` 선택. 빈 상태에서도 `RecordSeasonSelection`을 반환하고 선택기를 유지 |
| 갱신 | `StatsRefreshControls` | 기본 자동 갱신, 중지 토글과 일회 새로고침은 별개 조작. 처리 중 수동 중복을 막으며 자동 토글로 진행 중 요청도 중단 가능. 갱신 시각은 한국 시간 |
| 핵심 지표 | `Grids` + `StatTile` | 선택 시즌의 실제 완료 Game 수를 세며 출전자 수를 10으로 나누지 않는다. 시간·킬이 확인된 게임만 해당 지표에 포함한다. 포지션·최근 기록·최소 게임 필터와 무관한 선택 시즌 전체 값 |
| 포지션 | `Tab` | `?position=` |
| 업적 | `AchievementCarousel` | 업적 16종(`ACHIEVEMENTS`, 임시). 4게임 이상인 사람 중 1위를 한 장씩. 자연 높이의 한 장과 카드 밖 이전·다음 `Button`, 44px 직접 선택 버튼, 단일 가로 터치. 세로·취소·멀티터치는 선택을 바꾸지 않는다. `?recent=1`은 포지션 필터 적용 후 사용자별 최근 10게임을 집계하며 리더보드의 1위 배지도 같은 결과 사용 |
| 업적별 순위 | `AchievementRankingDialog` (`Popup`) | 업적 칩(`aria-pressed`)으로 골라 상위 10명. 고른 업적은 캐러셀과 같이 움직인다. 열린 동안 Popup 위치를 고정하고 닫기는 44px |
| 리더보드 | `LeaderboardTable` | `?min=` 기본 5, 1~50으로 제한. 수치는 선택 포지션의 전체 게임이며 최근 10게임 스위치와 무관. 기본 KDA 내림차순, 열 머리 버튼으로 정렬(`aria-sort`), 같은 열 재선택은 방향 전환. 정렬·20명씩 쪽 이동은 로컬 상태. 모든 폭에서 일곱 수치를 유지한다. 좁으면 이름을 고정한 표를 이름 있는 키보드 스크롤 영역에서 가로 이동한다. 이름은 작은 얼굴 옆에서 자연 줄바꿈하고 프로필 링크는 최소 44px 높이. KDA·승률이 처음 보이며 정렬 버튼 44px·현재 열에만 aria-sort·정렬 변경 안내를 제공. `sm` 미만은 업적 배지와 K/D/A·승패 보조 줄만 생략 |
| 챔피언 | `<table>` + 챔피언 아이콘, `PageNav` | 포지션만 적용하고 최근 10게임·최소 게임 필터는 적용하지 않음. 픽 수 내림차순, 동점이면 승률 내림차순. 15개씩 로컬 쪽 이동, 5픽 미만 승률은 `-`. 표는 최소 20rem이며 숫자를 한 줄에 유지하고 더 좁은 폭에서는 이름 있는 키보드 가로 스크롤 영역으로 제공 |

쿼리에는 `season`·`position`·`recent`·`min`을 저장한다. 잘못된 포지션은 전체, `recent`는 정확히 `1`일 때만 켜진다. 같은 필터의 수치 갱신은 리더보드 정렬·쪽, 챔피언 쪽, 고른 업적 ID·열린 순위를 보존한다. 항목이 줄면 마지막 유효 쪽으로 보정하고, 업적이 없거나 전체 빈 상태면 순위를 닫는다. 필터가 바뀌면 쪽·선택 업적을 초기화하고, 정렬 조작은 리더보드 쪽을1로 돌린다. 업적은 지표 동점이면 게임 수 많은 순으로 정렬하고 첫 사용자 한 명에게 배지를 부여한다. 양옆 장식 미리보기는 제거했다. 캐러셀의 선수 이름은 정적이며 선수 이동은 페이지의 순위 목록과 순위 팝업에서 제공한다.

리더보드 정렬 머리는 포커스가 들어올 때 `scrollIntoView({block:'nearest', inline:'nearest', behavior:'instant'})`로 전체 버튼을 보이게 한다. 표 region의 scroll-padding은 고정 이름 열 9/14rem에 0.5rem 여백을 더한다. CSS 여백만으로 해결되지 않던 native Tab의 부분 가림을 보완하며, 클릭 정렬·프로필 이동·키보드와 수동 가로 스크롤을 유지한다.

**상태** 선택한 시즌에 완료 Game이 없으면 "이 시즌에는 기록된 게임이 없어요", 선택한 시즌도 없으면 "아직 기록된 게임이 없어요" (지표 0 대신). 업적·리더보드 표본 없음: "{N}게임 이상 뛴 사람이 없어요". 필터 이동 중에는 업적·리더보드·챔피언 영역의 이전 결과를 유지하고 흐림 효과·aria-busy로 알린다.

**현재 한계·미결정** 실제 서버는 업적 캐러셀·업적별 순위·최근 10게임 업적 필터를 숨긴다. `평균 KDA`는 K/D/A가 함께 확인된 표본의 (킬+어시스트)/max(1,데스)다. 활성 시즌을 기본으로 조회하며 과거 시즌은 선택한 경우에만 조회한다. 새 업적 정책은 사용자 보류다. 위 업적 UI 설명은 개발 샘플의 구성이다.

**통계 갱신 수명:** `/stats/live` GET은 초기 SSR과 같은 snapshot 서비스·공개 권한·시즌·개인정보 투영을 사용하며 `private, no-store`다. 완료 뒤30초에 다음 자동 조회를 예약하고 자동 요청만 `priority: low`를 쓴다. 숨긴 탭·offline·자동 중지·이동·해제는 요청을 취소하고 늦은 응답을 차단한다. 숨김/offline 복귀는 자동 상태일 때 다시 조회한다.15초 timeout이나 실패는 마지막 정상 화면을 유지하며60/120초 후 재시도하고 수동 새로고침으로도 복구할 수 있다. 무관 query/hash 및 상위 레이아웃 자료 병합은 최신 통계를 오래된 SSR로 되돌리지 않는다. 조용한 성공 시각은 live region에 넣지 않고 오류·offline·수동 성공만 한 곳에서 전달한다.
