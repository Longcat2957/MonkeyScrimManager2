상태: 프론트엔드 구현 전 요구사항 초안. 페이지 역할과 저장 계약은 기존 문서를 따르며,
아래 **상호작용 초안**은 이를 화면에서 다루기 위한 제안이다. **미결정** 항목을 이미 합의한 기능으로 간주하지 않는다.
공통 접근·상태·중복 방지 원칙은 [페이지 요구사항](../page-requirements.md)을 따른다.

근거: [라우트 설계](../routing.md), [프로젝트 목적](../../purpose.md),
[ROFL 적재 모델](../../rofl-import.md), [MMR 저장 계약](../../mmr.md),

스키마의 상태·필드가 존재한다는 사실만으로 화면 조작이나 운영 정책을 추가하지 않는다.

## `/g/[guildId]/matches` — 서버 경기 기록

### 역할

- **기존 합의:** 선택한 서버의 Match, 즉 두 팀의 시리즈를 검색하고 개별 기록으로 진입한다.
- 특정 내전의 대진 탐색은 해당 내전의 `/bracket`에서 담당한다.

### 접근 대상

- 서버 전체 기록을 탐색하는 열람 허용 사용자 대상이다.
- 공개 설정과 서버 접근 정책을 적용하며, 목록을 열 수 있다는 사실이 모든 참가자의 신상 열람 권한을 뜻하지 않는다.

### 필요한 정보

- Match 식별자, 소속 내전, 두 팀, BO 형식, 시리즈 상태와 완료된 Game 기준 점수.
- 조회 범위를 구분할 시각. 실제 경기 시각과 업로드 시각을 혼용하지 않는다.
- 목록 총량 또는 다음 결과 존재 여부 등 선택한 탐색 방식에 필요한 정보.
- 검색에 참가자 식별 정보를 사용한다면 해당 열람자의 검색·공개 권한도 함께 판단한다.

### 상호작용

| 조작 | 입력·조건 | 성공 결과 | 실패·제약 |
| --- | --- | --- | --- |
| 기록 검색·범위 변경 | 검색어 또는 확정한 필터 | 해당 서버 안의 조건 일치 Match 목록 | 이전 조건의 결과를 새 조건의 결과처럼 표시하지 않음 |
| 추가 결과 탐색 | 목록 뒤에 조회할 결과가 있음 | 같은 조건의 다음 결과 | 실패한 구간만 재시도하고 조건 유지 |
| Match 열기 | 목록의 특정 시리즈 선택 | `/g/[guildId]/matches/[matchId]` 진입 | 대상 소속·열람 권한 재검증 |

검색 조건과 목록 위치는 상세에서 돌아왔을 때 복원하는 것을 제안한다.
공통 길드 메뉴의 경기 기록 링크 외에 같은 목록으로 돌아오는 링크를 본문에 중복 배치하지 않는다.

### 상태별 처리

- 첫 조회 로딩, 검색 조건 변경 중, 정상 결과, 다음 결과 조회 중.
- 서버에 경기 기록이 전혀 없음과 조건에 맞는 결과가 없음을 구분한다.
- 조회 실패, 접근 제한, 존재하지 않는 서버를 빈 목록으로 숨기지 않는다.
- 미완료·중도 종료·취소 시리즈를 정상 종료 시리즈와 구분하고 미확정 승자를 만들지 않는다.

### 미결정 사항

- 검색 대상 필드, 상태·기간·내전 등 필터의 범위, 정렬 기준과 페이지 탐색 방식.
- 기본 조회 범위와 취소 시리즈 포함 여부, 검색 상태의 URL 표현.
- 비회원·서버 비소속자·탈퇴자의 목록 열람 범위와 개인 식별 정보 검색 제한.

## `/g/[guildId]/matches/[matchId]` — 시리즈·Game 결과

### 역할

- **기존 합의:** 시리즈 점수와 선택한 Game의 결과·통계를 한 페이지에서 조회하며 ROFL 업로드를 담당한다.
- Game 선택은 결과 조회다. 밴픽·픽 순서·경기 중 진행 입력이나 수동 승패 입력을 제공하지 않는다.

### 접근 대상

- 열람 허용 사용자와 결과 등록 권한을 가진 사용자를 구분한다. 업로드 가능 역할은 별도 결정 대상이다.
- 조회·업로드 모두 해당 서버·내전·Match와 현재 권한을 확인한다.

### 필요한 정보

- 시리즈의 소속 내전·두 팀·BO 형식·상태, 완료된 Game에서 집계한 점수와 정상 종료 시 승자.
- **데이터 계약:** Match의 두 팀 A/B는 시리즈 내 고정 구분이고, Game마다의 블루·레드 진영과 다르다.
- Game 목록과 순번, 결과 존재 여부, 선택한 Game의 진영·승패·경기 길이.
- 실제 출전자의 당시 표시 정보·사용 챔피언·포지션 연결과 ROFL에서 확인한 성적·최종 세팅.
- 실제 경기 시각이 확인되지 않으면 미확인으로 다루며 업로드 시각에서 역산하지 않는다.
- 현재 공개 설정을 적용한 Riot ID 표시 정보, 업로드 가능 여부와 불가 사유.
- 하드 피어리스 적용 시 해당 Match의 이전 Game에서 양 팀이 실제 사용한 챔피언.
- MMR을 함께 표시하는 범위에서는 결과 저장 여부와 별도로 반영 완료·보류 등 처리 상태.

### 상호작용

#### 결과 조회

| 조작 | 입력·조건 | 성공 결과 | 실패·제약 |
| --- | --- | --- | --- |
| Game 선택 | 해당 Match에 속한 `gameId` | 결과 영역과 `?game=<gameId>` 갱신 | 다른 Match의 Game이나 잘못된 ID를 조회하지 않음 |
| 앞뒤 이동·공유 URL 진입 | Game 쿼리가 있는 주소 | 같은 Game 선택 복원 | 기본 선택·잘못된 선택의 표시 방식은 미결정 |
| 참가자 전적 열기 | 당시 사용자 연결과 열람 권한이 존재 | 같은 서버의 `/players/[userId]` 진입 | 미연결 기록에 추정 사용자 링크를 만들지 않음 |
| 상세 성적 확인 | 해당 Game에서 확인 가능한 수치·세팅 | 선택한 참가자 또는 항목의 세부 정보 | 누락·매핑 실패를 0이나 임의 아이콘으로 대체하지 않음 |

성적 항목의 구체적인 노출 범위와 펼침 방식은 후속 설계에서 정한다.
총 CS·KDA 비율·분당 수치·팀 합계가 필요하면 누락값·0 나눗셈·집계 기준을 먼저 정한다.
단위가 검증되지 않은 CC·사망 시간 원값을 초·분당 지표로 표시하지 않는다.
최종 아이템·주문·룬은 최종 세팅이며 구매 순서·스킬 사용 이력으로 해석하지 않는다.

#### ROFL 업로드

**기존 합의:** 업로드 진입은 이 페이지 한 곳에 두고 모달로 처리한다.
파일 선택 → 서버의 권한·참가자 연결·중복·데이터 검증 → Game 저장·시리즈 집계를 기본 흐름으로 삼는다.
정상 파일마다 검토·승인을 요구하지 않는다.

| 단계 | 사용자의 조작·판단 | 필요한 결과 |
| --- | --- | --- |
| 모달 열기 | 대상 시리즈와 업로드 가능 여부 확인 | 현재 조회 중인 Game과 등록 대상이 같은지 명확히 구분 |
| 파일 선택·제출 | 로컬 ROFL 선택 후 등록 요청 | 파일 선택 오류를 제출 전 표시하되 서버 검증 유지 |
| 전송·검증·저장 | 처리 상태 확인 | 중복 제출 방지, 완료 전 성공으로 표시하지 않음 |
| 자동 등록 성공 | 기록 확인 | 저장된 Game·시리즈 점수 갱신, 등록 결과를 한 곳에서 안내 |
| 등록 실패·불확실 | 오류 원인과 실제 저장 여부 확인 | 허용된 복구 경로 제공, 무조건 재전송하지 않음 |

조회용 Game 탭을 바꾸는 행위만으로 업로드 대상을 암묵적으로 바꾸지 않는다.
Game 순번·새 Game 생성·기존 결과에 대한 업로드를 어떻게 지정할지는 미결정이며,
이 결정 전에는 다음 Game이나 기존 채택본 교체를 자동 선택하는 것으로 설계하지 않는다.

### 상태별 처리

#### 업로드 예외와 복구

| 상황 | 필요한 피드백과 처리 경계 |
| --- | --- |
| 파일 손상·미지원 형식·검증 오류 | 등록되지 않았음을 알리고 원인에 맞게 올바른 파일 선택 또는 지원 여부 확인 |
| 참가자·팀 연결 실패 | 실패 대상을 권한 범위 안에서 식별하고 결과 확정과 구분. 이름만으로 연결하거나 승패를 직접 입력해 우회하지 않음 |
| 결과 누락·충돌 | 자동 등록할 수 없는 근거를 표시. 정상 결과로 가장하거나 기존 결과를 자동 덮어쓰지 않음 |
| 동일 파일 재요청·동시 업로드 | 중복 Game·점수 증가 없이 서버 처리 결과 제시. 기존 기록을 보여줄 때도 접근 권한 적용 |
| 같은 경기로 보이는 다른 파일 | 파일 해시만으로 동일 경기 판정이 끝났다고 간주하지 않음. 판정·충돌 처리 정책 필요 |
| 응답 유실·연결 종료 | 저장 실패로 단정하지 않고 실제 등록 상태 확인 후 재시도 여부 결정 |
| 업로드 도중 권한·시리즈 상태 변경 | 서버의 최신 검증 결과 반영. 화면에 남은 이전 권한으로 계속 제출하지 않음 |
| 정상 기록의 MMR 보류 | 경기 결과는 보존하고 MMR 미반영을 구분. 결과 재업로드를 일반적인 해결책으로 안내하지 않음 |
| 하드 피어리스 위반 | 확인한 사용 이력을 근거로 안내하며 업로드·결과 등록은 차단하지 않음 |

원본 파일은 서비스가 보관하지 않는다. 재분석이 필요한 경우 파일 재업로드가 필요하며,
서비스에 저장한 원본 다운로드나 파일 없이 재분석하는 조작은 제공하지 않는다.
실패 작업의 보존·재개 방법, 예외 수정 담당자와 수정 장소는 아직 정하지 않았다.

#### 조회·처리 상태

- Match 로딩·조회 실패·접근 제한·다른 서버에 속한 Match·대상 없음.
- Game 없음, 선택한 Game에 결과 없음, 결과 정상 조회, 일부 통계·이미지 매핑 누락.
- 진행 중·정상 종료·중도 종료·취소 등 서버가 확정한 시리즈 상태. 점수가 앞서도 중도 종료 승자를 임의 생성하지 않는다.
- 업로드 모달의 미선택·입력 오류·처리 중·성공·예외·응답 불확실 상태.
- 정상 결과와 MMR 반영 지연은 구분한다. 사용자·포지션·처리 순서 확인이 필요한 MMR을 완료로 표시하지 않는다.

### 미결정 사항

- 업로드 권한과 허용 시점, 파일 크기·건수 제한, 처리 중 닫기·이탈·취소의 의미.
- Game 기본 선택과 유효하지 않은 `game` 쿼리 처리, 등록 성공 뒤 Game 선택 방식.
- Game 순번·진영·등록 대상을 확정하는 방법과 이미 등록된 결과의 정정·재분석 업무.
- Match 중도 종료·취소 등 운영 상태 변경의 조건·권한과 소유 페이지. 결과 상세에 조작을 추가할지는 아직 정하지 않는다.
- 예외 연결을 해결할 역할·경로, 응답 유실 시 상태 확인 수단. 새 API·라우트 추가를 이 문서에서 확정하지 않는다.
- 경기 결과에 노출할 상세 지표, 피어리스 이력·MMR 처리 상태의 표현 범위.

## `/g/[guildId]/players/[userId]` — 서버 내 사용자 전적

### 역할

- **기존 합의:** 특정 사용자가 해당 서버에서 쌓은 누적 전적을 조회한다. 계정 연결·개인 설정은 `/me`의 책임이다.
- `[userId]`는 Discord 사용자 ID인 `users.id`다. Riot 계정 ID·내전 참가 기록 ID를 받는 경로가 아니다.
- 해당 서버의 과거 `scrim_participants.user_id` 연결을 기준으로 여러 Riot 계정의 기록을 합산한다.
- 현재 계정 소유권·멤버십·표시 이름으로 과거 사용자를 다시 추정하지 않는다.
- 현재 파일 경로는 `[playerId]`이며 이름 변경은 별도 구현 작업이다. 여기서는 목표 경로만 문서화한다.

### 접근 대상

- 해당 사용자의 서버 내 전적을 열람할 수 있는 사용자 대상이다.
- 본인 여부·현재 서버 소속만으로 타인의 비공개 정보 열람 권한을 부여하지 않으며, 구체적인 접근 정책은 미결정이다.

### 필요한 정보

- 조회 대상 사용자와 서버, 허용된 표시 정보, 집계 대상 경기와 범위.
- 승패·참가 Game 등 누적 기록과 실제 출전한 개별 Game의 탐색 정보.
- MMR을 제공한다면 길드·시즌·사용자·포지션별 값과 해당 처리 상태. Riot 티어와 혼용하지 않는다.
- **데이터 계약:** 스키마는 설정 부재 시 비공개 기본값을 두고 과거 경기의 Riot ID에도 현재 공개 설정을 적용한다.
- 개인 공개 설정은 길드 내부 경기 기록 삭제·통계 제외 기능이 아니다. 외부 공개와 내부 열람의 구체적인 조합은 별도 결정한다.

| 누적 범위 변경 | 합의한 기간·시즌·포지션 등 | 표시한 범위의 집계와 경기 목록 갱신 | 전체 누적과 선택 범위 수치를 혼용하지 않음 |
| 출전 Game 열기 | 해당 사용자의 특정 출전 기록 | Match 상세와 해당 `?game=<gameId>`로 이동 | 열람 제한·삭제된 연결을 재검증 |
| 포지션별 MMR 확인 | MMR 공개·표시 범위가 허용됨 | 선택 시즌의 값과 반영 여부 확인 | 기록 없음·초기값·반영 보류를 같은 의미로 표현하지 않음 |

한 행에 해당 Game을 여는 링크를 여러 이름으로 반복하지 않는다.
MMR 상세 이력 탐색이나 외부 전적 검색 링크는 필드가 존재한다는 이유로 추가하지 않는다.

### 상태별 처리

- 조회 중, 정상 집계, 서버 내 출전 기록 없음, 선택 범위의 기록 없음, 조회 실패.
- 비공개·서버 접근 제한·존재하지 않는 사용자·삭제로 사용자 연결이 사라진 기록을 구분해 처리할 정책이 필요하다.
- 미연결·사용자 삭제 기록은 경기 결과에는 남지만 해당 사용자 누적에 추정 합산하지 않는다.
- MMR 적용 전·보류·과거 시즌 상태를 구분하며 미확인 포지션을 ROFL에서 추측하지 않는다.

### 미결정 사항

- 내부·외부 열람자별 프로필 공개 조건과 비공개 응답 방식, 탈퇴자 전적 접근 정책.
- 기본 집계 기간, 필터와 대표 지표, MMR·변동 이력·Riot ID의 노출 범위.
- 실제 사용자 식별이 사라진 과거 참가자의 표시 방식. 대체 사용자 URL을 임의로 만들지 않는다.

## `/g/[guildId]/stats` — 서버 누적 통계

### 역할

- **기존 합의:** 선택한 서버 전체의 누적 경기 통계를 조회한다.
- 한 사용자의 전적은 `/players/[userId]`, 개별 시리즈·Game 결과는 `/matches/[matchId]`가 담당한다.

### 접근 대상

- 해당 집계의 열람이 허용된 사용자 대상이다. 개인 순위나 식별 정보를 포함할지는 별도 정책을 따른다.

### 필요한 정보

- 집계 대상 서버·기간 또는 시즌, 대상 Game 수와 실제 반영 범위.
- 정상 기록된 결과와 검증된 통계에서 계산한 지표, 항목별 누락 데이터 여부.
- 집계가 결과 저장과 별도로 갱신되는 경우 갱신 시각·반영 지연 여부.
- 사용자 단위 집계를 제공한다면 과거 사용자 연결과 개인 공개 설정을 적용한 표시 정보.

### 상호작용

| 조작 | 입력·조건 | 성공 결과 | 실패·제약 |
| --- | --- | --- | --- |
| 집계 범위 변경 | 합의한 기간·시즌 등 | 같은 범위를 적용한 지표 갱신 | 집계 중 이전 결과를 현재 조건의 수치로 표시하지 않음 |
| 지표별 상세 확인 | 설명만으로 충분하지 않은 실제 세부 데이터가 있음 | 분모·집계 대상·세부값 확인 | 목적 없는 탭·설명 반복을 만들지 않음 |
| 개인 전적으로 이동 | 사용자별 집계가 제공되고 열람 가능 | 같은 서버의 `/players/[userId]` 진입 | 비공개 사용자의 정보가 링크·검색 결과로 노출되지 않음 |

### 상태별 처리

- 첫 집계 로딩, 조건 변경 중, 정상 결과, 경기 자체가 없음, 선택 범위가 비어 있음, 집계 실패.
- 데이터 누락·집계 지연·MMR 보류를 실제 0이나 완전 반영으로 표시하지 않는다.
- 일부 항목을 제공할 수 없을 때 확인 가능한 지표의 의미를 유지하고 없는 분석을 추정 생성하지 않는다.

### 미결정 사항

- 첫 제공 지표, 기간·시즌 필터, 기본 범위, 계산식·분모·최소 표본 수·정렬 기준.
- 사용자·챔피언·포지션별 분석이나 순위 제공 여부. 저장 가능한 모든 필드를 자동으로 화면에 넣지 않는다.
- 공개 설정과 식별 가능한 집계의 관계, 갱신 주기·지연 표시 기준, 이전 시즌 조회 범위.
