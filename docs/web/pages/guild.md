# 서버 페이지

코드 대조일: 2026-11-15. 서버 범위 헤더를 쓴다. `g/[guildId]/+layout.server.ts`는 활성 DB 서버를 공개 조회해 `guild: { id, name, isAdmin }`을 내려준다. 일반 읽기는 비로그인·비소속자도 허용하며 관리 화면·쓰기는 현재 권한을 별도로 확인한다. 명시적 개발 샘플 서버만 목 데이터를 사용한다. 관리 조작 표시의 신선도 제한은 [공통 상태 표현](../patterns.md#1-상태-표현)을 따른다.

## `/g/[guildId]` — 서버 홈

실제 DB를 읽는 **게임 대시보드**다. `routes/g/[guildId]/+page.server.ts`, `+page.svelte`, `ranking/+server.ts`가 담당한다. 내전·경기·선택 시즌 MMR 순위를 각 조회 모듈에서 읽는다. 홈 업적은 실제 서버에서는 아직 숨기고 개발 샘플에서만 표시한다. Data Dragon 이름·이미지는 실제 카탈로그를 사용한다.

**목적** 들어온 사람이 "내가 지금 할 일"(다음 내전·신청)을 바로 보고, 내전 현황·순위·최근 결과를 확인한 뒤 업적을 탐색한다.

**권한** 활성 서버를 누구나 조회한다. 서버가 없거나 비활성이면 404다.

**데이터** 서버 범위의 시즌 선택을 먼저 검증한 뒤, 영역마다 따로 조회해(`Promise.allSettled`) 한 영역 실패가 페이지 전체를 막지 않게 한다. 잘못된 명시 시즌은 페이지의 400/404로 처리한다.

```ts
{
  guild,
  seasons: { id, name, startedAt: string, endedAt: string | null }[], // RecordSeasonSelection
  selectedSeasonId: string | null,
  nextScrim: NextScrim | null,                     // { kind: 'mine' | 'open', scrim, hardFearless, artUrl }
  activeScrims: SectionResult<ScrimListItem[]>,    // nextScrim으로 보여 준 내전은 뺀다
  recentMatches: SectionResult<MatchListItem[]>,   // 실제 서버는 종료 경기 최근 5개
  ranking: SectionResult<GuildRanking | null>,     // 포지션별 첫 10명 + 내 기록. 시즌이 없으면 null
  achievements: (AchievementRanking & { splashUrl })[] // 서버 통계 업적과 같음. 실패하면 빈 배열(영역 숨김)
}
```

`nextScrim` 선정: 내가 참여하는 내전(선발 > 대기, 같으면 진행 중 > 예정 시각 오름차순)을 먼저, 없으면 내 선발·대기 신청이 없고 정원이 남은 모집을 예정 시각 순으로 고른다. 일정 미정은 뒤로 보낸다. 배경 아트는 전체 챔피언 중 무작위 Data Dragon 스플래시(`randomChampionSplash`).

내전 현황의 `진행 중`에는 `recruit`·`preparing`·`ready`·`in_progress`가 모두 포함되며 예정 시각 오름차순이다. 최근 경기는 종료 목록에서 실제 경기 시각 내림차순으로 최대 5개를 읽고 날짜 미확인은 뒤로 보낸다. 각 영역 결과를 모두 기다린 뒤 페이지 데이터를 반환하므로 초기 영역별 스트리밍·Skeleton은 없다.

**화면**

```text
[h1] {서버명}
┌ NextScrimHero (항상 어두운 카드, 챔피언 스플래시 배경) ─────────────────────────────┐
│ 내 다음 내전 [선발됨]                                                                │
│ 경매 내전                                                                            │
│ 11/2(월) 21:00 · 경매 · 4팀                                                          │
│ 시작까지 [3 일][06 시간][58 분][50 초]      ← 진행 중이면 LIVE · 지금 진행 중        │
│ (모집 중이면 신청 현황 Progress)                                                     │
│ [내전 보기 →]                               ← 미참가 모집은 "신청하러 가기", 진행 중은 "진행 상황 보기" │
└──────────────────────────────────────────────────────────────────────────────────────┘
lg: 2열 같은 폭
내전 현황 [진행 중 n | 최근 경기]  (ActivityBoard)    서버 순위 [시즌: 선택한 시즌 ▾]
                                                       [탑|정글|미드|원딜|서폿]  (RankingBoard)
                                                       카드 안 스크롤 + 더 불러오기, 내 순위 아래 고정
업적 (AchievementCarousel, 최대 48rem 한 장. 카드 밖 이전/다음·직접 선택)
모바일: hero → 내전 현황 → 서버 순위 → 업적
```

**구성**

| 영역 | 사용 | 메모 |
| --- | --- | --- |
| 다음 내전 | `NextScrimHero`: STDF `CountDown`·`Progress` + 링크 버튼 | 카운트다운은 브라우저에서 계산하고 내전 ID·일정이 바뀌면 재생성. 시작 시각은 메타 문구, 매초 표시는 `aria-hidden`. 만료 시 `onfinish`로 "예정 시각이 지났어요"를 표시하며 실제 모집·진행 상태는 바꾸지 않는다. 없으면 "지금 참가할 내전이 없어요" |
| 내전 현황 | `ActivityBoard`: `SelectionTabs`(`진행 중 n` · `최근 경기`) + `ScrimListRow` / `MatchListRow` | 한 카드에 두 목록을 탭으로. 처음 열 때 진행 중 목록이 비어 있으면 최근 경기 탭부터. hero의 내전은 진행 중 목록에서 제외("다른 진행 중인 내전이 없어요"). 탭 선택은 로컬 상태이며 URL에 넣지 않는다 |
| 업적 | `AchievementCarousel` (서버 통계와 같은 컴포넌트) | 서버 통계의 업적을 전체 포지션·전체 게임 기준으로 보여 준다. 집계 기준(`ACHIEVEMENT_MIN_GAMES`)도 같다. 필터·`업적별 순위`·집계 기준 안내는 서버 통계에만 둔다. 제목은 `h3`, 내용 길이에 맞춰 높이를 늘리며 1위 이름은 중복 선수 이동을 만들지 않는 정적 텍스트다. 카드 밖 44px 이전/다음·직접 선택, 현재 선택·결과 안내와 가로 단일 터치 탐색을 제공한다 |
| 서버 순위 | `RankingBoard`: `SeasonSelector` + `SelectionTabs` + `InfiniteScroll` + `LinkCell` | 선택 시즌의 포지션별 MMR. 1~3위 메달 색(`--color-medal-*`)과 숫자, 주 챔피언 아이콘, `n전 n승 · 승률`. 카드 안(최대 26rem)에서 스크롤하면 `GET /g/[guildId]/ranking?season=&position=&offset=`로 처음 선택한 시즌을 고정해 10명씩 조회한다. 다음 쪽에 기존 사용자가 겹치면 같은 시즌·포지션의 첫 쪽을 한 번 다시 받아 목록·본인 순위·추가 조회 여부를 교체하고 맨 위로 이동한다. 내 순위는 아직 불러오지 않은 구간에 있을 때만 카드 아래 고정. 선수 링크는 선택 시즌을 유지하며 포지션 선택은 로컬 상태 |

`전체 보기` 링크·모집 생성 버튼은 두지 않는다(헤더 메뉴와 내전 목록이 담당).

`?season=<uuid>`를 생략하면 활성 시즌, 명시하면 같은 서버의 해당 시즌만 순위에 적용한다. 종료 시즌도 조회할 수 있으며 전체 시즌 합산은 없다. 시즌 변경은 `page`·`offset`을 제거하고 다른 쿼리를 보존한다. `nextScrim`·`activeScrims`·`recentMatches` 등 운영 자료를 과거 시즌으로 바꾸지 않는다. 시즌 목록·빈 상태 계약은 [기록 페이지](records.md#개인-전적서버-통계의-시즌-선택)과 같고, 개발 샘플은 실제 시즌 이력을 만들지 않는다.

**상태**

| 상황 | 처리 |
| --- | --- |
| 예정 시각 경과 | 0으로 멈춘 "시작까지" 대신 경과 문구. 예정 시각만으로 상태 변경이나 자동 시작을 하지 않음 |
| 참가할 내전 없음 | hero가 빈 안내. 내전 현황의 초기 탭은 hero 유무가 아니라 진행 중 목록이 비었는지로 결정 |
| 경기 기록·순위 없음 | 탭 안 빈 문구 / 순위는 `SectionState empty` |
| 내전 현황·최근 경기·순위 조회 실패 | 해당 영역만 `SectionState error` + `다시 시도`(`invalidate('app:guild-home')`) |
| 다음 내전·업적 조회 실패 | 다음 내전은 없음으로 처리하고, 업적은 영역을 숨김. 이 두 영역에는 오류·재시도 UI가 없음 |
| 순위 추가 조회·중복 후 첫 쪽 재조회 실패 | 기존 목록을 유지하고 목록 끝에 "불러오지 못했어요. 눌러서 다시 시도해 주세요". 자동 재시도 없이 사용자가 다시 시도 |
| Data Dragon 조회 실패 | 아트·아이콘 없이 표시(배경색, 이름 첫 글자) |

개발 모드 확인: `devGuild002`는 빈 서버, `?preview=error`는 최근 경기 조회 실패.

**현재 한계·미결정** hero는 내전 요약 링크이며 바로 신청하지 않는다. `ranking` GET은 활성 서버를 공개 조회하고 잘못된 포지션·범위 밖 offset·잘못된 시즌 UUID는 400, 다른 서버 또는 없는 시즌은 404다. 시즌을 생략했는데 활성 시즌이 없으면 404이며 명시한 빈 시즌은 빈 `RankingPage`다. 순위는 현재 활성 멤버이면서 선택 시즌·포지션 유효 반영이 1게임 이상인 사용자만 포함하고 실제 최다 사용 챔피언을 표시하며 새 ROFL 결과의 MMR을 자동 반영한다. 시즌 전환은 봇 `/시즌` 또는 서버 관리의 시즌 탭을 사용하며 같은 전환 서비스를 공유한다. 홈 업적은 기준 확정 전 보류다.

순위는 요청 시점의 값을 읽으며 여러 쪽의 동일 시점 스냅샷은 제공하지 않는다. 중복 없이 발생한 순위 변동은 다음 전체 조회 때 반영한다. 서버·선택 시즌 또는 첫 쪽 데이터가 바뀌거나 화면을 떠나면 진행 중 요청을 취소하고 이전 응답은 적용하지 않는다.

## `/g/[guildId]/admin` — 서버 관리

**목적** 서버 관리자가 멤버의 Riot 계정 연결과 Discord 연동(운영자 역할, 모집·엔트리·결과 채널)을 관리하고 변경 이력을 확인하고 시즌을 전환한다. Riot 계정 연결은 사용자가 직접 하지 않고 여기서 운영자가 지정한다.

**권한** 실제 세션의 현재 Discord 관리자 권한을 `load`와 모든 action에서 확인한다. 헤더 `관리` 메뉴도 관리자에게만 렌더링한다. 비로그인은 401, 소속이 없거나 대상이 사라지면 404, 소속은 있으나 권한이 없으면 403이다.

서버 관리자는 웹에서 한 명씩 지정하지 않는다. **Discord 실효 서버 관리 권한 또는 설정한 운영자 역할**로 관리자 여부를 계산한다. 소유자·ADMINISTRATOR·MANAGE_GUILD와 역할·timeout을 실제 REST 응답으로 검사하며 서비스 운영자 권한으로 우회하지 않는다.

멤버 목록은 `/초기설정`의 일반 멤버 전체 등록·로그인·참가로 연결된 DB 멤버십이다. 이름은 서버 별명 → Discord 전역 표시 이름 → 사용자명 순으로 표시하며 마지막 동기화 값을 사용한다. 검색은 서버 표시 이름과 사용자명에 적용한다. 조작할 실행자·대상은 매번 실제 소속을 확인한다. Riot API로 식별자·이름·LoL 플랫폼을 조회하고 서버별 연결을 저장한다. 이 조회는 계정 소유권 인증이 아니다.

**데이터**

```ts
{
  tab: 'members' | 'discord' | 'audit' | 'seasons',                         // ?tab=, 기본 members
  members: { userId, displayName, isAdmin, riotAccounts: RiotAccount[] }[],   // 서비스에 연결된 멤버만. 계정은 대표 먼저
  adminCount: number,
  discord: {                                                    // 멤버 탭에서는 불러오지 않아 null
    roles: { id, name }[],                                      // 실제 역할의 위치·이름 순
    channels: { id, name, category, botCanPost }[],
    settings: { operatorRoleId, recruitmentChannelId, entryChannelId, resultChannelId },   // 각각 null 가능
    actorRoleIds: string[] | null                               // 내 역할. 서버 관리 권한이 있으면 null(제한 없음)
  } | null,
  audit: { entries: GuildAuditEntry[], total: number } | null, // 변경 이력 탭에서만 조회
  seasons: GuildSeasonOverview | null // 시즌 탭만 현재/지난 시즌 조회
}
```

| 영역 | 사용 | 동작 |
| --- | --- | --- |
| 탭 | `SelectionTabs` (`role="group"` 래퍼, 선택 버튼 `aria-pressed`, 영역 제목은 `sr-only` `h2`) | `?tab=discord`, `audit`, `seasons`. 기본은 멤버이며 탭을 바꾸면 기존 쿼리를 모두 지운다 |
| 멤버 검색 | `<form role="search">` + `Input type="search"` | Enter·지우기로 `?q=` 갱신, 50자 제한. 이름 부분 일치, 대소문자 무시. 검색 변경 시 page 초기화. 폼에 `nonSubmitButtons`·`inputLabel`, 이동 중 `aria-busy` |
| 멤버 행 | `<li>`: 사진·이름·`관리자` `StatusTag`·대표 Riot ID(`외 n`) + `Riot 계정` 버튼 | 관리자 여부는 표시만 한다. 긴 이름·Riot ID는 줄바꿈하고 계정 버튼은 최소 44px 높이를 유지한다 |
| Riot 계정 | `Button fill="lineLight"` → `MemberRiotAccountsDialog`(`Popup`) | 연결된 계정 목록(대표 `Tag`, `대표로`·`해제`(→ `confirm`)) + `Input title="연결할 Riot ID"` → `조회` → 찾은 계정 확인 → `연결`. 첫 계정은 대표가 된다. 진행 중 내전에 쓰인 계정은 `해제` 비활성 + 이유. action: `lookup`·`link`·`primary`·`unlink`(대상 `userId`는 이 서버 멤버만) |
| Discord 연동 항목 | `DiscordSettingRow`: 현재 값 `Button` → `ActionMenu`(데스크톱 팝오버, 모바일 시트) | 고르면 메뉴를 닫고 바로 저장(action `discord`, `key`·`value`). 맨 앞은 `설정 안 함`, 현재 값은 `현재 설정`으로 비활성. 값 버튼은 최소 44px 높이이며 항목 이름·현재 값으로 접근 가능한 이름을 제공한다 |
| 변경 이력 | `GuildAuditHistory`의 순서 목록·`time`, `PageNav` | 계정 연결·해제·대표 변경·Discord 설정 변경을 최신 시각/ID순20개씩 조회. 대상·담당자·변경 전후를 표시하고 같은 값 반복·실패는 기록하지 않음. 빈 이력과 범위 밖 쪽을 구분 |

감사 원장은 실제 변경과 같은 DB 트랜잭션에 저장한다. 권한 없는 사용자의 SSR·부분 데이터에 이력을 전달하지 않는다. 사용자·Riot 이름 스냅샷을 새로 복제하지 않으며 사용자/계정 참조에서 현재 표시 이름을 읽는다. 원장에는 세션·토큰·PUUID·요청/오류 원문을 저장하지 않는다. 개발 샘플도 해당 프로세스에서 성공한 조작만 가변 이력으로 보여 준다. [구현·검증 진행](../../remaining-implementation.md)을 따른다.

선택지 규칙(서버도 같은 규칙으로 검사):

- **운영자 역할**: 바꾼 뒤에도 내가 관리자로 남아야 한다. 서버 관리 권한이 없으면 내가 가진 역할만 고를 수 있고 `설정 안 함`도 고를 수 없다(비활성 + 이유).
- **채널**: 봇이 글을 쓸 수 없는 채널은 비활성 + "봇이 글을 쓸 수 없어요".

멤버 초대·추방·Discord 역할 부여는 제공하지 않는다(Discord에서 한다).

**action의 검증 범위** `discord`는 현재 관리자·역할/채널 존재·변경 후 자기 관리 권한·봇 게시 가능 권한을 검사하고 설정을 원자적으로 저장한다. 계정 action은 현재 관리자와 대상의 소속을 확인한다. `lookup`·`link`는 실제 Riot 조회와 실행자별 분당 10회 제한을 사용한다. `link`는 연결 직전 재조회하고 서버별 첫 계정을 대표로 지정한다. 같은 서버의 다른 사용자 연결은 거절하지만 다른 서버 연결은 독립적이다. 대표 해제 시 연결 시각·ID 순으로 다음 대표를 정한다. 사용자·계정·활성 내전을 잠그고 같은 서버의 활성 신청 계정 해제를 차단한다.

**상태**

목 조회 오류는 `없는계정#KR1`, `조회제한#KR1`, `충돌계정#KR1`로 확인한다. 이미 연결된 Riot ID도 같은 충돌 문구를 반환한다. 이 예시는 개발 샘플에 한정한다. 실제 `inActiveScrim`은 같은 서버의 활성 신청을 조회한 값이며 해제 트랜잭션에서 다시 검사한다.

모집·엔트리·경기 라인업·ROFL 결과 게시, 운영자 요청 참가 안내 DM·개인 신청 interaction·Gateway 동기화는 [봇](../../bot.md)에 연결했다. 채널 미설정이나 게시 실패가 웹 저장을 취소하지 않으며 이후 채널 설정·게시 복구로 처리한다. 현재 멤버 목록은 서비스에 연결된 사용자만 포함한다. 실제 Discord 등록·발송 검증 완료를 뜻하지 않는다.

**시즌** `GuildSeasonManagement`는 현재 이름/시작 시각 → 시즌 전환 폼 → 종료된 시즌 목록 순서다. 이름은 trim 후1~100자이고 같은 이름 재사용을 막지 않는다. 확인창에서 실제 현재/새 이름을 확인하며 취소는0POST, 처리 중 중복을 막고 실패 때 입력을 보존한다.409는 `app:guild-seasons`만 다시 읽어 바뀐 현재를 확인한 뒤 재동의하게 한다. 결과 불명/성공 뒤 갱신 실패는 추가 전송을 막고 새로고침으로 현재를 확인한다. 정상 성공은 새현재/지난목록 갱신·한 번의 status·이름 입력 포커스로 마친다.

`rotateSeason` action은 `{name,expectedCurrentSeasonId,confirm:true}`를 받고 웹에 가짜 Discord receipt를 만들지 않는다. 서버/현재 시즌 잠금·CAS·기존 내전/MMR 보존은 봇과 같은 서비스다. 과거 결과는 이전 시즌에 남고 새 모집부터 신규 시즌이며 기본 MMR1500이다. GET은 초기 시즌/점수를 만들지 않고 활성 없으면 기존 초기 설정 안내/전환 비활성·409를 유지한다. 개발 목도 실제 시즌 자료가 없어 current:null/completed:[]다. 변경 코드·검증은 [후속 기록](../../ui-review/backlog.md#5-웹-시즌-관리)을 따른다.

별도 계정 소유권 인증은 현재 범위에 없으며 관리자 지정 방식과 구분한다.
