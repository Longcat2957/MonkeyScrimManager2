# 전역 페이지 역할·상호작용

상태: 구현 전 설계 초안. 표기와 공통 상태 처리는 [페이지 명세](../page-requirements.md)를 따른다.
공통 헤더·푸터의 동작은 상위 문서에서 정의하며 각 페이지 본문에 중복하지 않는다.

## 1. `/` — 서비스 홈

### 역할

Monkeybot이 내전 모집·참가자 관리·팀 편성·대진과 ROFL 결과 기록을 돕는 서비스임을 이해하는 진입점이다.
서버 진입은 공통 헤더의 서버 선택기가 담당한다는 점은 [기존 합의](../routing.md)다.

### 접근 대상

- 방문자와 로그인 사용자 모두를 대상으로 하는 소개 페이지다.
- 특정 서버의 멤버십이나 관리 권한을 요구하지 않는다.

### 필요한 정보

서비스 용도와 이용 흐름을 이해하는 데 필요한 설명만 제공한다. 서버별 진행 내전·전적은 서버 홈이 담당한다.
개발 모드에서 제공하는 임시 바로가기는 서비스 기능이나 추천 목록으로 취급하지 않는다.

### 상호작용

| 행동 | 입력·조건 | 결과 |
| --- | --- | --- |
| 이용 시작 | 공통 헤더에서 인증·서버 선택 | 해당 서버 홈으로 이동. 본문에 로그인·서버 선택·동일 목적지의 시작 버튼을 반복하지 않음 |

### 상태별 처리

| 상태 | 처리 |
| --- | --- |
| 비로그인·로그인 | 같은 소개를 제공하고 인증 상태는 공통 헤더에서 처리 |
| 서버 목록 없음·실패 | 서버 선택기의 공통 상태 사용. 본문에 오류 안내 중복 금지 |
| 개발 모드 | 페이지 바로가기와 개발 도구를 구분. 실제 공통 메뉴가 제공하게 되는 동일 목적지는 중복 제거 |
| 운영 모드 | 개발 도구·임시 ID·개발 바로가기 미노출 |

### 미결정 사항

최종 소개 문구와 공개할 기능 범위. 계정 가입·서버 등록·봇 초대의 별도 행동은 합의 전 추가하지 않는다.

## 2. `/me` — 내 정보

### 역할

본인의 Riot 계정 연결과 개인 설정·공개 범위를 관리한다. 서버별 누적 전적과 내전별 참가 정보 편집은 각각의 페이지가 담당한다.

### 접근 대상

로그인한 본인만 조회·변경한다. 다른 사용자의 ID를 입력해 편집하는 페이지가 아니며, 서비스 운영자의 대리 편집도 가정하지 않는다.

### 필요한 정보

| 정보 | 범위·근거 |
| --- | --- |
| 본인 식별 정보 | Discord 표시 이름·아바타 등 현재 로그인 대상을 구분할 정보. 서비스에서 Discord 프로필 자체를 편집하지 않음 |
| 연결한 Riot 계정 | 계정별 식별 정보·조회 상태. 한 사용자에게 여러 계정을 연결할 수 있다는 [데이터 계약](../../../apps/web/src/lib/server/db/schema.ts)을 따름 |
| 공개 설정 | 프로필 공개·Riot ID 표시·외부 전적 검색 허용의 저장값과 실제 적용 범위 |
| 개인 선호 후보 | 포지션별 선호 챔피언의 저장 구조가 있음. 참가 신청에서 실제로 사용할 범위를 먼저 정한 후 제공 |

공개 설정 미생성 시 기본값은 비공개이며, 과거 경기의 Riot ID 표시에도 현재 설정을 적용하는 것이 데이터 계약이다.
비공개 설정은 길드 내부 기록 삭제나 통계 제외를 의미하지 않는다. 대상별 실제 열람 권한은 공통 미결정 정책을 따른다.

### 상호작용

| 행동 | 입력·조건 | 결과 |
| --- | --- | --- |
| Riot 계정 조회 | Riot ID의 이름·태그 입력 | 식별된 계정을 확인. 조회 성공을 소유권 검증·연결 완료로 표시하지 않음 |
| Riot 계정 연결 | 확인한 대상, 별도 합의할 소유권·연결 정책 충족 | 서버 저장 성공 후 본인의 연결 목록 갱신. 다른 사용자 연결을 임의로 가져오지 않음 |
| 연결 해제 검토 | 연결된 계정 선택, 진행 중 참가에 미치는 영향 확인 | 해제 허용 정책 확정 후 제공할 행동. 현재 연결을 해제해도 과거 참가 기록의 귀속을 재해석하지 않음 |
| 공개 범위 변경 | 각 설정의 공개 대상과 영향을 확인하고 저장 | 저장된 범위를 이후 조회에 적용. 제공되지 않는 기능의 설정을 작동하는 것처럼 노출하지 않음 |
| 개인 선호 변경 검토 | 선호 기능을 채택하는 경우 포지션별 챔피언 선택 | 저장 후 사용하는 참가 흐름에 반영. 이번 문서만으로 자동 팀 편성·자동 참가 기능을 만들지 않음 |

화면 모드와 로그아웃은 공통 헤더에서만 제공한다. 계정 연결 해제와 서비스 계정 삭제는 다른 작업이다.

### 상태별 처리

| 상태 | 처리 |
| --- | --- |
| 비로그인·세션 만료 | 개인정보 반환을 중단하고 공통 인증 진입 사용. 저장 성공으로 처리하지 않음 |
| 로딩·연결 계정 없음 | 조회 중과 미연결을 구분. 계정 추가 동작은 한 곳에만 둠 |
| 계정 없음·입력 오류 | Riot ID 입력 위치에서 수정 안내 |
| 외부 조회 제한·실패 | 기존 연결 정보를 유지하고 조회 실패를 구분. 반복 제출 방지 |
| 이미 연결됨·다른 사용자와 충돌 | 현재 연결 상태를 알리고 임의 덮어쓰기 금지. 다른 사용자의 비공개 정보는 노출하지 않음 |
| 저장 중·실패·동시 변경 | 공통 변경 처리 적용. 공개 범위는 저장 확인 전 완료로 표시하지 않음 |

### 미결정 사항

- Riot 계정 소유권 확인 방법, 연결 해제·이전과 진행 중 내전의 관계.
- 공개 설정별 정확한 대상·효과, 외부 전적 검색 기능의 범위. 저장 열만 있는 기능은 설정 UI로 확정하지 않는다.
- 선호 챔피언의 실제 사용처·선택 개수·저장 방식. 일반 개인 설정을 임의로 늘리지 않는다.
- 탈퇴·삭제·데이터 요청 기능의 제공 경로와 정책. DB의 삭제 참조 규칙만으로 삭제 버튼을 만들지 않는다.

## 3. `/docs` — 이용 문서

### 역할

이용자가 모집 참여·팀 편성·대진 확인·ROFL 등록 등 필요한 절차와 실패 시 할 일을 찾아 읽는다.
개발 문서나 API 명세를 제품 이용 안내로 그대로 노출하지 않는다.

### 접근 대상

방문자 포함 공개 열람을 초안으로 둔다. 관리 업무 안내를 공개할지는 내용 확정 시 판단한다.

### 필요한 정보

실제 제공되는 업무별 절차, 사전 조건, 사용자 스스로 해결할 수 있는 오류와 필요한 다음 행동.
아직 구현하지 않은 기능을 이미 사용할 수 있는 것처럼 안내하지 않는다.

### 상호작용

| 행동 | 입력·조건 | 결과 |
| --- | --- | --- |
| 주제 탐색 | 필요한 업무 선택 | 같은 문서의 해당 절차로 이동. 별도 하위 라우트·검색 기능은 현재 범위에 포함하지 않음 |
| 이용 방법 확인 | 절차·예외 안내 읽기 | 실제 작업은 해당 업무 페이지에서 수행. 공통 메뉴와 같은 목적지 링크를 반복하지 않음 |

### 상태별 처리

초기에는 준비된 내용만 제공한다. 내용 미작성·문서 조회 실패를 구분하고, 존재하지 않는 도움말 링크를 만들지 않는다.
키보드로 주제를 탐색할 수 있어야 한다. 전체 페이지 오류는 공통 오류 처리를 따른다.

### 미결정 사항

첫 공개에 포함할 문서 주제·순서와 문의/예외 처리의 실제 경로. 문의 수단이 정해지기 전 임의 연락처를 넣지 않는다.

## 4. `/terms` — 이용약관

### 역할

서비스 이용 조건의 적용 내용을 확인하는 열람 페이지다. 이번 작업은 약관 본문 작성이나 법적 요건 확정을 포함하지 않는다.

### 접근 대상

로그인 여부와 관계없이 열람할 수 있도록 한다.

### 필요한 정보

확정된 약관 본문과 적용일. 정책 내용을 승인·확정한 주체가 제공한 값을 사용하며 임의 날짜·조항을 생성하지 않는다.

### 상호작용

확정된 본문을 읽는다. 길이에 따라 본문 목차 이동을 제공할 수 있다. 로그인·가입 시 동의 처리 기능을 이 열람 페이지에 가정하지 않는다.

### 상태별 처리

본문 준비 전에는 약관 제공 완료로 취급하지 않는다. 본문 조회 실패와 미작성 상태를 구분하고, 실제 발행본이 있을 때만 적용일을 표시한다.

### 미결정 사항

약관 본문·적용일·개정 이력 제공 범위와 별도 동의가 필요한 흐름. 현재는 추가 라우트를 만들지 않는다.

## 5. `/privacy` — 개인정보 처리방침

### 역할

서비스에서 개인정보를 어떻게 처리하는지 확인한다. 개인의 공개 범위를 바꾸는 행동은 `/me`가 담당한다.

### 접근 대상

로그인 여부와 관계없이 열람할 수 있도록 한다.

### 필요한 정보

실제 수집·이용·보관·삭제 처리와 일치하는 확정된 방침 본문, 적용일과 요청 경로.
원본 ROFL 미보관 등 [프로젝트의 보존 원칙](../../purpose.md#6-데이터-보존-원칙)과 모순되지 않아야 한다.
여기서는 방침의 법적 내용이나 보관 기간을 새로 정하지 않는다.

### 상호작용

확정된 본문과 필요한 요청 절차를 읽는다. 요청 수단은 실제로 정해진 경우에만 제공한다.
개인 메뉴와 같은 `/me` 이동을 본문에서 중복 제공하거나 공개 설정을 이곳에서 편집하지 않는다.

### 상태별 처리

본문 준비 전·조회 실패를 구분한다. 이용자가 읽어야 할 방침은 로그인이나 서버 선택 실패 때문에 접근이 막히지 않아야 한다.

### 미결정 사항

방침 본문·적용일·개정 이력, 개인정보 관련 요청 담당과 처리 경로.

## 6. `/backoffice` — 서비스 전체 관리

### 역할

서비스 전체 운영자의 전용 영역이다. 세부 메뉴는 업무 범위를 정한 뒤 구성한다는 것이 [기존 합의](../routing.md)다.
현재 제목만 있는 상태에서 사용자 제재·데이터 수정·통계 대시보드 같은 기능을 자동으로 추가하지 않는다.

### 접근 대상

`users.isServiceAdmin`이 허용하는 서비스 운영자. 길드 관리 권한만으로 접근하지 못하며, 직접 URL 접근도 검사해야 한다.

### 필요한 정보

현재 사용자의 서비스 운영 권한과 확정된 운영 업무가 요구하는 정보. 업무를 정하기 전 전체 사용자·서버 데이터를 조회할 필요는 없다.

### 상호작용

공통 개인 메뉴에서 진입한다. 그 외 변경 작업은 업무·대상·권한·복구 기준을 정한 다음 이 명세에 추가한다.
길드별 설정을 같은 기능으로 다시 만들지 않는다.

### 상태별 처리

| 상태 | 처리 |
| --- | --- |
| 비로그인·권한 확인 중 | 운영 데이터 조회·조작을 먼저 허용하지 않음 |
| 권한 없음·회수 | 공통 접근 오류 처리. 길드 관리 권한을 대체 근거로 사용하지 않음 |
| 업무 미정 | 문서상 미구현 범위로 유지. 제품 화면에 임시 통계·가짜 작업·개발 설명을 채우지 않음 |
| 조회 실패 | 확정된 운영 업무가 생기면 해당 데이터의 실패·복구 상태 추가 |

### 미결정 사항

첫 운영 업무, 필요한 조회·변경 대상, 서비스 운영 권한의 부여·회수 경로, 변경 이력과 복구 요구.
길드 관리와의 분담을 먼저 정하고 세부 메뉴·경로는 그 후 결정한다.

## 7. `/dev/components` — 개발 작업 공간

### 역할

개발자가 컴포넌트를 시험할 작업 공간. [현재 합의](../routing.md#개발용-페이지)는 제목만 있는 빈 페이지이며 이번에 예제를 추가하지 않는다.

### 접근 대상

개발 모드에서만 접근한다. 운영 배포에서는 직접 URL 접근에도 404를 반환한다.

### 필요한 정보

현재는 제목 외 업무 데이터가 없다. 후속 구현에서 필요해진 사례만 추가하며 실제 개인정보를 샘플로 사용하지 않는다.

### 상호작용

홈의 개발 도구에서 진입한다. 테스트할 구체적 기능이 정해지면 해당 상태와 조작을 추가한다.

### 상태별 처리

개발 모드의 빈 공간과 운영 모드의 404를 구분한다. 후속 예제는 정상·로딩·빈 데이터·오류·비활성을 필요한 범위에서 재현한다.

### 미결정 사항

시험할 컴포넌트·상태 목록. 페이지 내부 목 데이터의 산재를 피하고 후속 데이터는 기존 목 데이터 규칙을 따른다.

## 8. `/dev/error` — 공통 오류 미리보기

### 역할

실제 공통 오류 화면을 확인한다. 제품 업무나 별도의 오류 UI를 만드는 페이지가 아니다.

### 접근 대상

개발 모드에서만 접근한다. 운영에서는 쿼리 값과 관계없이 404를 반환한다.

### 필요한 정보

URL의 `status` 값. 현재 구현과 합의에서 `403`, `404`, `500`만 지원하며 기본값과 그 외 값은 `404`다.

### 상호작용

| 행동 | 입력·조건 | 결과 |
| --- | --- | --- |
| 오류 상태 확인 | `/dev/error`, `?status=403`, `?status=500` 직접 진입 | 해당 공통 오류 화면 표시 |
| 5xx 새로고침 확인 | 500 미리보기 | 같은 요청을 다시 실행하므로 미리보기는 500 유지 |

### 상태별 처리

403·404에서는 새로고침 버튼을 제공하지 않는다. 500에서는 제공한다. 지원하지 않는 값은 404로 처리한다.

### 미결정 사항

현재 범위에서는 없음. 별도 오류 상태 선택 UI는 요구하지 않는다.
