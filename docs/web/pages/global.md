# 전역 페이지

코드 대조일: 2026-11-03. 모두 전역 범위 헤더를 쓴다([routing.md 3절](../routing.md#3-헤더)). 이 문서는 현재 구현을 기록하며, 실제 인증·저장소 연결 여부를 화면 구현과 구분한다.

## `/` — 서비스 소개

**목적** 처음 온 사람이 Monkeybot의 이용 흐름을 읽는다. 헤더의 서버 선택으로 실제 서버 화면에 진입하고, 개발 모드에는 별도 샘플 바로가기가 있다.

**권한** 누구나.

**화면**

```text
[h1] 디스코드 내전, 모집부터 전적까지
[p]  한 문단 소개

[Steps vertical] 모집 ─ 팀 편성 ─ 대진 ─ ROFL 기록   ← 각 단계 desc 한 줄, max-w-xl

(dev) ── 개발 바로가기 ───────────────────
[a 링크 격자: 경로 이름 + 경로]
[a 링크 격자: 컴포넌트 테스트 · 에러 페이지]
```

**구성**

| 영역 | 사용 | 메모 |
| --- | --- | --- |
| 소개 | `h1`, `p` | 워드마크를 본문에 다시 크게 쓰지 않는다(헤더에 있음) |
| 흐름 | `Steps vertical` | 진행 상태가 아닌 설명이다. 회색 '예정' 모양은 대비가 낮아 모든 단계를 완료 모양(테마색, 번호 막대)으로 그린다. 가로 `Steps`는 desc를 그리지 않으므로 화면 폭과 관계없이 세로. 클릭 동작 없음 |
| 개발 바로가기 | 링크 격자(이름 + 경로) | `dev`에서만. 헤더 메뉴로 갈 수 있는 경로도 임시 ID가 필요하므로 유지 |

본문에 `시작하기`·`로그인`·`서버 선택` 버튼은 없다. 서버 선택과 Discord 로그인·로그아웃은 헤더가 담당한다.

**구현 범위** 소개·이용 흐름은 정적 콘텐츠다. 개발 바로가기는 `dev`에서만 렌더링하며 수동 편성·경매·대진 운영·결과에 각각 해당 단계의 목 내전 ID를 사용한다. 로그인·서버 선택의 실제 연결 상태는 [routing.md](../routing.md)를 따른다. 봇 초대·서버 등록 진입은 없다.

## `/me` — 내 정보

**목적** 내 Discord 계정과 서버별로 나에게 연결된 Riot 계정 확인. Riot 계정 연결·해제·대표 지정은 서버 운영자가 [서버 관리](guild.md#gguildidadmin--서버-관리)에서 한다. 별도 공개 범위 설정은 두지 않으며 서버 전적·Riot ID는 공개 열람 정책을 따른다.

**권한** 실제 세션의 본인만 조회한다. 비로그인 요청은 401이며 다른 사용자 ID를 받아 조회하지 않는다.

**구현 범위** `guild_riot_accounts`와 Riot 계정 식별자를 읽어 서버별로 묶는다. 서버 관리에서 저장한 연결·대표 계정이 반영된다. 개발 모드의 `?mock=1&preview=empty`만 목의 빈 상태를 재현한다.

**데이터**

```ts
{
  me: { userId, displayName, avatarUrl },
  groups: { guildId, guildName, riotAccounts: { id, gameName, tagLine, region, isPrimary }[] }[] // 서버마다 대표 먼저
}
```

**화면** (한 열, `max-w-2xl`)

```text
[h1] 내 정보

  [img] 표시이름              Discord 계정        ← 정적 행

[h2] Riot 계정
서버별로 연결한 계정을 표시하고 해당 서버 내전의 신청 계정으로 사용한다.
[h3] {서버명}
[ul]
  Hide on bush  #KR1 · KR 서버        [대표]
  원숭이부캐    #KR2 · KR 서버
(없음) 연결된 Riot 계정이 없어요
```

**구성** 쓰기 action이 없다. 본인 식별과 계정 목록 모두 동작이 없으므로 `Cell`(버튼) 대신 같은 모양의 정적 목록을 쓴다. 화면 모드와 로그아웃은 헤더에서 제공한다.

**미구현·미결정** 탈퇴·데이터 삭제 경로. 선호 챔피언과 개인별 공개 설정 UI는 없다.

## `/docs` — 이용 문서

**목적** 모집 참여·팀 편성·대진 확인·ROFL 업로드 방법과 실패 시 할 일을 찾아 읽는다.

**권한** 누구나.

**화면** (`max-w-3xl`)

```text
[h1] 이용 안내
[nav 목차]  모집 참여 · 팀 편성 · 대진 · 되돌리기·중도 종료 · ROFL 업로드 · 자주 묻는 질문     ← 같은 문서 앵커 링크
[h2] 모집 참여 …
[h2] ROFL 업로드 …
[h2] 자주 묻는 질문
[Accordion] 질문 → 답
```

**구성** 본문은 네이티브 문서 요소(`.doc`), 목차는 `<nav><a href="#…">`, FAQ만 `Accordion`.
현재 주제: 모집 참여(신청 즉시 선발·대기, Riot 계정은 운영자가 연결), 팀 편성(요약의 편성 방식에서 수동·경매 선택·변경, 자동 팀 이름, 경매 입찰가 ±10·±50), 대진(2·3·4팀 틀, 끝난 내전은 결과 메뉴), 되돌리기·중도 종료(운영 메뉴 + 편성 화면의 방식 다시 고르기·팀장 다시 정하기), ROFL 업로드, FAQ 5개(기록 실패·중복 파일·직접 입력 불가·피어리스·대기 상태).

본문과 FAQ는 `+page.svelte`에 있는 정적 안내이며 검색·문의 접수 기능은 없다. 모집·편성·대진 조작은 실제 DB에 연결했다. ROFL 안내는 목표 흐름이며 운영 업로드는 참가자 귀속·진영·순서 검증 전까지 비활성이다. 실제 경계는 [내전 페이지](scrims.md)와 [기록 페이지](records.md)를 따른다. 현재 FAQ의 "파일 칸에 이유가 표시돼요" 문구는 업로드 팝업의 시각적 상태 미표시 문제와 일치하지 않는다([현재 렌더링 한계](records.md#rofl-업로드-팝업)).

**미결정** 첫 공개 주제, 문의 경로.

## `/terms`, `/privacy` — 약관·개인정보 처리방침

**목적** 확정된 정책 본문 열람.

**권한** 누구나. 로그인·서버 오류와 무관하게 열려야 한다.

**화면** 현재는 `h1`과 "준비 중이에요." 한 문단만 있다. 적용일·조항·개정 이력은 없다. `max-w-3xl`. `/docs`와 세 페이지가 `layout.css`의 `.doc` 컴포넌트 클래스 하나로 제목·문단·목록 간격을 공유한다. 별도 래퍼 컴포넌트는 없다.

본문이 확정되기 전에는 "준비 중이에요" 한 줄만 두고 적용일을 쓰지 않는다. 개인정보 처리방침 본문은 원본 ROFL 미보관 등 [데이터 보존 원칙](../../purpose.md#6-데이터-보존-원칙)과 일치해야 한다.

**미결정** 본문·적용일·개정 이력, 개인정보 요청 경로.

## `/backoffice` — 서비스 운영

**목적** 서비스 운영자 업무. 지금은 서비스 상태 확인 하나다.

**권한** 실제 세션의 `isServiceAdmin`을 `load`에서 검사한다. 서버 관리자 권한으로 대체하지 않는다. 비로그인은 401, 권한이 없으면 403이다. 개발 모드의 명시적 `mock=1` 미리보기는 별도다.

**데이터** `load`가 `checkServices()`(`lib/server/status.ts`) 결과를 스트리밍한다. 화면에 들어오면 목 상태가 아니라 환경 변수의 DB·봇 주소에 실제 요청한다. 두 확인을 병렬로 실행하고 항목마다 3초에서 기다리기를 종료한다. 판정은 `lib/features/backoffice/status.ts`가 한다.

| 항목 | 확인 방법 | 정상 | 지연 | 중단 | 설정 안 됨 |
| --- | --- | --- | --- | --- | --- |
| 데이터베이스 | `select 1` | 500ms 이하 | 500ms 초과 | 실패·시간 초과 | `DATABASE_URL` 비어 있음 |
| Discord 봇 | `BOT_STATUS_URL` GET (봇의 `BOT_STATUS_PORT`, 127.0.0.1 전용) | 게이트웨이·내부 API 정상(최근 30초), 지연 미측정 또는 1000ms 이하 | 지연 1000ms 초과 | 응답 없음·읽을 수 없음·게이트웨이/내부 API 미연결 | `BOT_STATUS_URL` 비어 있음 |

**화면**

```text
백오피스
서비스 상태                         14:02:31 확인 [다시 확인]
┌──────────────────────────────────────────────────────────┐
│ 데이터베이스   [정상]                          응답 4ms │
│ Discord 봇     [중단]                 연결하지 못했어요 │
└──────────────────────────────────────────────────────────┘
```

- 정상이면 측정값(응답 시간, 봇이 들어간 서버 수·Discord 지연), 아니면 확인할 내용을 쓴다.
- 다시 확인은 제목 옆 버튼 하나로 `invalidate('app:service-status')`를 호출한다. 자동 새로 고침은 없다. 확인 시각은 한국 시간으로 표시한다.
- 모바일에서는 측정값·문제를 이름 아래 줄로 내린다.

**상태** 확인 중: Skeleton. 확인 자체가 실패: 오류 문구(다시 확인은 같은 버튼). 빈 상태 없음.

**미결정** 운영자 지정·회수 방법, 그 밖의 운영 업무.

## `/dev/components` — 컴포넌트 검증

**목적** STDF와 서비스 공통 컴포넌트를 실제 페이지에 쓰기 전에 상태별로 확인한다.

**권한** `dev`에서만. 운영 404.

**화면** `ScrimSummary`, 내전 상태 `StatusTag`, `LinkCell` 2종, `SectionState`(로딩·빈·오류), `Button`(기본·보조·위험·로딩·비활성), 입력 팝업·확인 창, `.rofl`용 `ImageList` 영역이 있다. 요약·상태 데이터는 `lib/mocks/component-demo/`에서 받는다.

입력 팝업은 빈 제목 오류를 보여 주고 유효한 제목이면 닫고 성공 toast를 띄운다. 실제 모집 저장은 없다. `confirm` 결과는 확인함/취소함으로 표시한다. `overlay` attachment의 포커스·Escape·배경 inert와 `Popup`의 데스크톱 중앙/모바일 아래 배치를 확인할 수 있다.

**현재 한계** `ActionPopover` 전용 데모는 없다. 이 화면의 `ImageList`에는 파일 입력과 `onclickUpload`가 연결돼 있지 않아 선택·전송 흐름 전체를 검증할 수 없다. 실제 파일 선택·전송 연결과 현재 상태 표시의 한계는 경기 상세의 [ROFL 업로드 팝업](records.md#rofl-업로드-팝업)을 따른다.

## `/dev/error`, `+error.svelte` — 오류 화면

구현됨. `큰 상태 코드` → `h1 제목` → `한 줄 설명` → (5xx만) `Button fill="lineLight"` `다시 시도`.

`/dev/error?status=403|404|500`으로 확인하며 기본값과 허용되지 않은 값은 404다. 운영 모드의 `/dev/error`도 404다. 다시 시도는 전체 페이지를 새로고침한다. 오류 페이지에는 `noindex` 메타가 있고, 401을 포함해 403·404 이외 상태는 아래 기본 문구를 쓴다.

| 코드 | 제목 | 설명 |
| --- | --- | --- |
| 403 | 접근 권한이 없어요 | 운영자에게 이용 권한을 요청해 주세요. |
| 404 | 페이지를 찾을 수 없어요 | 주소가 올바른지 확인해 주세요. |
| 그 외 | 페이지를 불러오지 못했어요 | 잠시 후 다시 시도해 주세요. |
