# 전역 페이지

## `/` — 서버 선택

로그인하지 않았으면 본문의 `Discord로 로그인`에서 시작한다. 소속된 활성 서버가 있는 실제 세션은 첫 서버 홈으로 이동한다. 목록을 표시할 때는 서버 이름으로 들어가며, 조회 실패는 재시도, 소속 서버 없음은 운영자에게 확인하라는 안내를 제공한다. 공개 링크 열람에는 로그인이 필요 없다. 봇 초대나 서버 등록 화면은 아니다.

## `/me` — 내 정보

본인 세션만 접근한다(비로그인 401). Discord 프로필을 확인하고, 서버별 Riot 계정과 대표 여부를 조회한다. 연결·대표 변경·해제는 [서버 관리](guild.md)에서 한다. 계정 연결은 참가 신청의 필수 조건이 아니다.

| 조작 | 정책 |
| --- | --- |
| 선호 챔피언 검색·선택·순서 변경·저장 | 포지션마다 중복 없이 최대 10개를 저장한다. 다른 포지션으로 이동해도 미저장 초안을 유지한다. 실제 카탈로그에 없는 기존 ID는 같은 포지션에서 보존·제거할 수 있지만 새로 추가할 수 없다. 빈 목록으로 해제할 수 있다. 프로필을 공개한 활성 사용자만 경매 후보로서 선호 챔피언이 표시된다. |
| 프로필·Riot ID 공개 설정 | 두 설정은 독립적이다. 프로필 비공개 시 공개 DTO에서 이름·아바타·Discord ID를 가리고 별도 공개 UUID로 과거 전적을 연결한다. 이는 완전한 익명화가 아니다. 기존 비공개 Discord ID 경로의 예외는 본인과 현재 서버 관리자뿐이다. |
| 서비스 탈퇴 | 활성 내전에 신청·출전 중이거나 서비스 운영자이면 거절한다. 성공하면 본인 세션·소속·서버별 계정 연결·선호를 정리하고 이름·아바타를 지운다. 경기·MMR 원장과 기존 출전 귀속은 보존하며 타인의 계정 연결은 바꾸지 않는다. 명시적으로 다시 로그인하면 복귀하며 비공개 설정을 유지한다. |

저장 결과가 불명확하면 초안을 잃거나 같은 변경을 다시 보내지 않도록 현재 목록을 다시 읽는다. [기록과 개인정보](../../purpose.md#기록과-개인정보)가 공개 화면에도 적용된다.

## `/docs`, `/terms`, `/privacy` — 안내와 정책

`/docs`는 참가 신청, 수동 편성·경매, 대진, 중도 종료·되돌리기, ROFL 업로드와 실패 복구 방법을 제공한다. 서비스 사용자는 공통 푸터의 `문의` 이메일 링크를 사용한다. 별도 접수·처리 이력 기능은 없다.

약관과 개인정보 처리방침은 누구나 볼 수 있지만 법적 본문·시행일·개정 이력·개인정보 요청 절차는 확정되지 않았다. 승인 전에는 준비 중 안내만 표시한다.

## `/backoffice` — 서비스 운영

- 서비스 운영자만 접근한다(비로그인 401, 권한 없음 403). 서버 관리 권한은 대체 수단이 아니다. DB와 봇의 상태·확인 시각을 읽고 `다시 확인`으로 새 값을 요청한다. 오프라인이면 기존 정보와 연결 안내를 유지한다.
- 로그인 이력이 있는 Discord 사용자 ID를 지정해 서비스 운영 권한을 주거나 해제한다. 동명이인을 ID로 구분하고 확인 후 변경한다. 최초 운영자는 [배포 안내](../../deployment.md)의 CLI로 지정한다. 마지막 운영자는 해제할 수 없다. 자기 권한을 해제하면 `/me`로 이동한다.
- 변경 이력에는 성공한 실제 변경만 남는다. 실패와 중복 변경은 이력을 만들지 않는다. 최신순 20개씩 조회하며 개발용 미리보기 변경은 실제 권한에 반영하지 않는다.

## `/dev/*`와 공통 오류 화면

`/dev/components`에는 공통 컨트롤·상태 예시와 개발 샘플 업무 화면으로 가는 링크가 있다. `/dev/error?status=403|404|500`은 지정한 오류 화면을 재현한다. 둘 다 운영에서는 404다.

공통 오류 페이지는 401·403·404의 원인을 구분하고 검색 색인을 막는다. 5xx일 때만 다시 시도할 수 있다.
