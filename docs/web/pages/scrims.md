# 내전 페이지

확인일: 2026-11-15. 새 전체 취소의 구현·최종 통합검증을 완료했다. 대상: `apps/web/src/routes/g/[guildId]/scrims/**`와 내전·편성·대진 컴포넌트의 현재 구현.
목록은 서버 범위 헤더, `[scrimId]` 하위는 내전 범위 헤더를 쓴다.

## 현재 구현 범위

- 실제 서버의 목록·상세·수동 편성·경매·대진·결과를 DB에서 공개 조회한다. 개발 모드의 명시적 샘플 서버만 `lib/mocks/`의 메모리 데이터를 사용한다.
- 모집 생성·신청·선발·철회·설정과 편성·경매·대진·진행 변경은 업무 함수와 DB 트랜잭션에 연결했다. 실행자는 세션에서만 가져오며 조작 전에 현재 Discord 소속·관리 권한을 확인한다. Riot 계정은 선택 사항이며 계정 없이도 신청할 수 있다. 계정을 지정하면 해당 서버에서 본인에게 연결된 계정인지 검사한다.
- 관리 변경은 내전 행 잠금·`expectedRevision`과 서버/내전 소속·상태를 검사한다. 오래된 화면의 제출은 409로 거절하고 다시 읽는다. 생성의 요청 ID와 신청·계정 중복 제약을 검증한다.
- 참가자 MMR과 편성 참고 전적은 내전에 고정된 시즌 값을 사용한다. 시즌·사용자 귀속이 확정됐으면 미반영 포지션 MMR은 1500, 시즌·사용자가 미확정이면 null이다. 시너지·상대 전적과 경매 후보의 내전 전적·주력 챔피언은 유효 ROFL 실출전에서 조회하며, 선호 챔피언은 본인이 저장한 공개 설정만 표시하고 외부 Riot 전적 등 미제공 자료를 목 값으로 채우지 않는다. Data Dragon 이름·이미지는 실제 카탈로그를 사용한다.
- 내전 시작은 양 팀이 정해진 실제 Match를 생성한다. 수동 편성의 확정 포지션은 경기 전체 라인업에 자동 적용한다. ROFL 등록은 세트 결과·MMR·다음 대진 진출과 게시 예약을 함께 저장하고 최종 대진 종료 시 내전도 자동 완료한다. 서비스 목표인 자동 기록은 [purpose.md](../../purpose.md#51-운영-범위와-rofl-기반-전적-등록)를 따른다.

주요 데이터 형식은 `lib/features/scrims/types.ts`, `formation.ts`, `bracket.ts`, 설정·경로 규칙은 `settings.ts`, `paths.ts`에 있다. 컴포넌트는 전달받은 데이터와 현재 페이지의 action을 사용한다.

폼 없는 조작은 `postAction()`으로 action을 호출한다. 성공과 409 충돌이면 `invalidateAll()`로 데이터를 갱신하고, action 실패는 반환 문구를 `toast.error`로 알린다. 네트워크 예외는 입력 화면을 보존하고 저장 결과를 확인할 수 없다는 문구를 알린다. 성공 후 갱신 실패도 구분하며 자동 재전송은 하지 않는다. 신청·설정 팝업은 별도의 `enhance` 처리로 필드/폼 오류를 표시한다.

## 운영 규칙

| 항목 | 현재 동작 |
| --- | --- |
| 정원 | 팀 수 2~4, 팀당 5명, 추가 신청 정원 0~10명. 실출전 정원 = 팀 수 × 5, 전체 신청 정원 = 실출전 + 추가 신청 정원 |
| 새 신청 | 선발 자리가 남으면 `selected`, 찼으면 `standby`. 활성 신청의 사용자·지정한 Riot 계정 중복과 전체 신청 정원 초과를 거절. 계정 없는 참가자 여러 명은 서로 다른 신청으로 처리 |
| 철회·제외 | 활성 신청을 `withdrawn`·`excluded`로 남김. 빈 선발 자리는 신청 시각이 빠른 대기자부터 채움 |
| 수동 대기 전환 | 그 작업 직후에는 자동 선발을 하지 않음. 이후 철회·제외·모집 설정 저장 때는 같은 대기자가 다시 자동 선발될 수 있음 |
| 모집 마감 | 선발 수가 실출전 정원과 같아야 함. 편성 방식 선택은 마감 조건이 아님 |
| 편성 방식 | 운영자가 모집 중·편성 중 요약에서 수동 편성 또는 경매 선택. 방식을 바꾸면 활성 편성·경매를 초기화하고 이력을 보존 |
| 팀 이름 | 팀 순서대로 `포로팀`, `칼날부리팀`, `돌거북팀`, `바위게팀`. 이름 변경 조작 없음 |
| 경매 | 현재 후보 한 명. 팀장 포함 팀당 5명. 0점 낙찰과 가격 없는 수동 배치를 구분. 되돌린 기록은 `voided`로 남김 |
| 중도 종료 | 편성 중·대진 준비·진행 중에 가능. 중단한 실제 경기는 `ended_early`이며 완료 세트의 현재 점수 우세 팀만 승자로 표시하고 동점은 미확정. 완료 경기·Game·MMR·라인업은 유지 |
| 내전 전체 취소 | 진행 중에만 새 결과 취소 경로 제공. 후속 대진부터 현재 결과·MMR을 같은 트랜잭션에서 역분개. 타 내전·관리 보정 이후 원장은 넘지 않음. 원본 이력 보존·현재 대진 분리, 완료·중도 종료는 대상 제외 |

요약의 운영 줄에서 제공하는 단계 동작은 다음과 같다.

| 내전 상태 | 다음 단계 | 되돌리기 |
| --- | --- | --- |
| `recruit` | `모집 마감`: 선발 정원을 채우면 `preparing` | 없음 |
| `preparing` | 방식 미정이면 다음 단계 버튼 없음. 방식이 있으면 `대진 준비로`가 팀 편성 확정 안내와 함께 비활성. 수동 확정 또는 경매 전원 배치가 자동으로 `ready`로 변경 | `모집 다시 열기`: 편성 초기화·경매 이력 무효화, 선택한 방식 유지 |
| `ready` | `내전 시작`: 대진 확정 후 `in_progress` | `팀 편성 다시 하기`: 대진 삭제, 수동 확정 해제 또는 완료 경매를 진행 중으로 변경 |
| `in_progress` | `내전 종료`: 대진의 모든 경기가 완료돼야 `completed` | `대진 준비로 되돌리기`: 대진에 진행 흔적이 없을 때만 가능 |
| `completed` | 없음 | `진행 중으로 되돌리기` |
| `ended_early` | 없음 | 중도 종료 전 편성·대진 준비·진행 단계로 복귀. 중단한 Match만 이전 대기/진행 상태로 복원. 과거 복원 근거 없는 중도 종료는 기존 진행 재개 유지 |
| `cancelled` | 없음 | `내전 취소 복구`: 미시작 취소는 저장한 원래 단계·경매 상태 복귀. 진행 중 전체 취소는 배치 근거로 `preparing`, 취소 결과/MMR은 재개하지 않음. 근거 없음·현재 결과 존재·경매 근거 불일치는 이유와 함께 차단 |

현재 편성의 실제 Game이 있으면 대진 준비로 되돌릴 수 없다. 미시작 취소는 참가자·배정·대진·포인트·후보·행위를 보존하고 내전/경매 상태만 바꾼다. 진행 중 취소는 결과 수량과 MMR 역분개, 이력 보존, 복구 시 편성 준비 복귀와 결과/MMR 미재개를 확인한 뒤 실행한다. 복구는 참가자를 유지하며 수동 배정은 재사용하고 경매는 팀장·시작 포인트를 남긴 setup부터 다시 편성한다. 취소 배치에 연결된 과거 Match만 현재 편성 검사에서 분리한다. 원본 Match·라인업·Game·ROFL·출전·원장과 이전 대진은 보존한다. 기존 중도 종료는 기록·MMR을 유지하는 별도 동작이며 완료·중도 종료 내전에는 전체 취소를 노출하지 않는다. [전체 취소 근거](../../../artifacts/ui-review/next/cancellation.md)·[최종 검증 상태](../../ui-review/next.md)를 따른다.

취소된 내전의 공개 대진은 “내전이 취소되어 표시할 대진이 없어요.”를 표시하며 편집 동작을 제공하지 않는다. 결과 경로 `/result`에 접근하면 기존 정책대로 `/bracket`으로 307 이동한다.

## `/g/[guildId]/scrims` — 내전 목록

**목적** 내전을 찾아 열거나 새 모집을 만든다.

**권한** 활성 서버는 누구나 조회한다. `can.createScrim = guild.isAdmin`일 때 생성 버튼을 표시하며 `create` action은 현재 Discord 관리자 권한을 검사한다.

**데이터** `ScrimListItem[]`, `total`, `page`, `pageSize: 20`, `statusFilter`, 필터별 `counts`, `can.createScrim`.
목록 항목에는 제목·상태·일정·편성 방식·팀 수·신청 수/정원·내 신청 상태·활성 참가자 미리보기가 있다.

```text
[h1] 내전                                               [모집 만들기]
[Tab] 전체 n | 모집 중 n | 진행 중 n | 종료 n
───────────────────────────────────────────────────────────────────
[날짜] 내전 제목                 [참가자 얼굴, 데스크톱] [상태]
       요일·시각 · 편성 방식 · 신청/정원 또는 팀 수        내 신청
…
[PageNav]
```

| 영역 | 컴포넌트·동작 |
| --- | --- |
| 모집 만들기 | `Button` → `ScrimSettingsDialog`. 성공하면 새 내전 요약으로 이동 |
| 상태 필터 | `SelectionTabs`. `all`, `recruit`, `active`(편성 중·대진 준비·진행 중), `done`(종료·중도 종료·취소). `?status=` 변경 시 `page` 제거 |
| 목록 | `CellGroup` + `ScrimListRow`. 행 전체가 내전 요약 링크. `DateBadge`, 상태 태그, 선발/대기인 내 신청 표시 |
| 부제 | 일정이 있으면 요일·시각, 방식이 정해졌으면 모집 중에도 방식 표시. 모집 중은 신청 수/전체 정원, 그 뒤는 팀 수 |
| 참가자 미리보기 | 데스크톱만 `AvatarStack`: 선발 우선 최대 5명과 남은 수 |
| 페이지 | `PageNav`, 20개씩. `?page=`, 첫 페이지는 쿼리 생략 |

정렬은 다가오는 일정 오름차순 → 지난 일정 내림차순 → 일정 미정 생성 최신순이다. 알 수 없는 상태 필터는 `all`, 페이지는 최소 1로 읽는다. 필터/페이지 이동 중 기존 결과를 유지하면서 `aria-busy`·`Loading`을 표시한다.

**상태** 서버 전체가 비었으면 `아직 내전이 없어요`를 표시하고 필터·목록·페이지 이동을 숨긴다. 생성 권한이 있으면 생성 버튼은 남는다. 필터 또는 페이지 결과가 비었으면 `조건에 맞는 내전이 없어요`를 표시한다.

### 모집 생성·설정 수정 팝업

`ScrimSettingsDialog`는 생성과 요약의 설정 수정이 공유한다. 데스크톱은 중앙, 모바일은 아래쪽 `Popup`이며 열린 동안 위치를 유지해 폭 전환에도 입력 트리를 하나만 렌더링한다. 필드 영역만 스크롤하고 하단 버튼은 바깥에 유지한다.

| 필드 | 컴포넌트·현재 검증 |
| --- | --- |
| 제목 | `Input`, 필수, 공백 제거 후 1~50자 |
| 날짜 | 읽기 전용 `Input` → 입력 아래 `Calendar mode="single" popup={null} height={32}`. height는 뷰포트 높이의 백분율이며 현재 월부터 6개월 뒤 월까지 제공. 날짜 이름·선택 상태를 보완하고 빈 칸은 조작에서 제외. 선택 뒤 시각 입력에 포커스 |
| 시각 | `Input inputmode="numeric"`, `HH:mm` 형식 |
| 일정 | 날짜와 시각을 함께 입력하거나 모두 비움. 비우면 미정. 입력은 `+09:00`, 표시는 `Asia/Seoul` |
| 팀 수 | `Stepper`, 2~4, 기본 2. `stepperLabels("팀 수")`와 공개 크기 옵션으로 목적 있는 증감 이름·44px 조작 영역 제공 |
| 추가 신청 정원 | `Stepper`, 0~10, 기본 2. 별도 목적의 증감 이름·44px 조작 영역, 계산된 실출전·최대 신청 인원 한 줄 표시 |
| 하드 피어리스 | `SwitchCell`, 생성 기본 꺼짐 |

편성 방식은 팝업에서 받지 않고 요약에서 선택한다. 수정 가능한 필드는 모집 중 전체, 편성 중·대진 준비는 제목/일정/하드 피어리스, 진행 중은 제목/일정이며 끝난 내전에는 설정 수정 메뉴가 없다. action은 현재 단계의 수정 가능 필드를 검사한다. 선발 수보다 실출전 정원, 활성 신청 수보다 전체 정원을 작게 줄이면 409를 반환한다.

변경한 팝업을 닫을 때 폐기 확인을 받는다. 저장 중 필드·중복 제출·닫기를 막고, 필드 오류는 `inputFeedback`으로 연결해 첫 실제 입력으로 포커스를 옮기며 기타 오류는 팝업 안에서 알린다. 실패 시 입력을 보존하고 저장 후 화면 갱신 실패는 저장 완료와 새로고침 필요를 구분한다. 서버는 UI 외부 요청에도 실제 달력 날짜·입력 범위·정원 축소를 검사한다.

## `[scrimId]` 공통 — `ScrimSummary`

`[scrimId]/+layout.server.ts`와 경기 상세 loader가 DB `ScrimContext`를 준비한다. 모든 내전 작업판과 경기 상세는 같은 `ScrimSummary`로 제목 `h1`·상태·일정·팀 수·하드 피어리스를 표시하고, 운영자에게는 선택한 편성 방식도 표시한다. 배경 아트와 별도 단계 막대는 사용하지 않는다.

내전 메뉴는 `모집·참가자`·`팀 편성`·`대진·경기`·`결과` 순서를 유지한다. 아직 선택하지 않은 팀 편성과 아직 없는 결과는 비활성으로 두며, 종료된 내전은 결과 메뉴로 이동한다. 상단 서버 메뉴는 내전 안에서도 바뀌지 않는다.

## `/g/[guildId]/scrims/[scrimId]` — 요약

**목적** 참가자가 신청을 관리하고 운영자가 참가자 선발·편성 방식·내전 단계를 관리한다. 모집 마감 성공 뒤 선택한 편성 방식의 작업판으로 이동하며, 경기 시작은 대진 화면에서 처리한다.

**데이터** `scrim`, `participants: ScrimParticipant[]`, 상태별 인원과 두 정원의 `counts`, `me`, `settings`, `editable`, `finished`, `can`.
`me`는 세션 본인의 활성 신청·이전 신청의 희망 포지션과 해당 서버에 연결된 Riot 계정/대표 계정 ID를 담는다. `can`은 신청 가능 여부·차단 이유, 신청 수정·운영·선발 권한, 다음 단계·되돌리기·복구·중도 종료 정보를 담는다. `cancelGameCount`는 관리자 진행 중 내전의 현재 완료 결과 수량(0 포함), `cancelledGameCount`는 관리자 취소 배치의 역분개 수량이며 그 외 상태·공개/비관리자 조회는 null이다.

```text
ScrimSummary
운영자: 운영 → 내 신청·편성 방식 → 참가자
참가자: 내 신청 → 참가자
비로그인 열람자: 참가자

┌ 운영     다음 단계가 막힌 이유                      [⋯] [다음 단계] ┐
└───────────────────────────────────────────────────────────────────┘

└───────────────────────────────────────────────────────────────────┘
┌ 참가자  신청 n/정원명 · 선발 n/실출전명 [참가자 추가] [선발 관리] ┐
```

**권한·구성**

역할과 관계없이 본인 신청 영역을 참가자 목록 위에 둔다. 편성 방식 선택과 공통 머리의 방식 표시는 운영자에게만 제공하고, 일반 참가자에게는 참가 현황과 확정 편성 결과를 공개한다. `ParticipantBoard`는 한 번만 렌더링하며 시각·DOM·키보드 순서는 같다.

| 영역 | 컴포넌트·동작 |
| --- | --- |
| 내 신청 | `MyRegistrationBar`. `me`가 있고 내전이 끝나지 않았을 때 표시. 활성 신청이 있으면 상태·계정·포지션, 없으면 신청 버튼 또는 차단 이유 |

| 철회 | `confirm` → `withdraw`. 신청 이력은 보존하며 참가자 목록에는 사람마다 최신 상태만 표시한다. 마지막 상태가 철회·제외이면 전용 탭에서 확인하고, 모집 중 조건을 만족하면 다시 신청 가능 |

| 참가자 머리 | 신청 수/전체 정원. 운영자에게 선발 수/실출전 정원도 표시. 선발 관리는 모집 중 운영자만 가능 |

**상태**

- 신청 불가 이유는 모집 마감, 연결 계정 없음, 정원 마감이다. 비로그인 상태에서는 내 신청 줄 자체를 렌더링하지 않는다.
- 신청 성공은 팝업을 닫고 신청 줄을 갱신한다. 오류는 팝업에 표시하며 409이면 정원 데이터를 재조회한다. 신청 팝업도 열린 동안 위치를 유지하고 제출 중 필드·닫기·중복 제출을 막는다. 포지션 오류는 그룹과 실제 버튼에 연결하고 첫 선택 버튼으로 이동하며 입력은 실패 뒤에도 보존한다.
- 참가자 전체 없음은 `아직 신청한 사람이 없어요`, 필터 결과 없음은 `해당하는 참가자가 없어요`다.
- 종료·중도 종료는 내 신청 줄을 숨기고 운영자의 되돌리기를 남긴다. 취소는 내 신청 줄을 숨기고 참가자 패널과 운영자의 취소 복구 메뉴를 남긴다. 근거 없는 과거 취소의 복구 메뉴는 이유를 설명하고 비활성이다.

## `/g/[guildId]/scrims/[scrimId]/manual` — 수동 편성

**목적** 선발 참가자를 팀·포지션에 배정하고 확정한다.

**권한** `can.edit = canManage && status === 'preparing' && !formation.confirmed`. 선택 방식이 수동이 아니면 실제 방식의 작업판 또는 방식 미정인 요약으로 307 이동한다.

**데이터** `formation`은 팀 목록, `FormationPlayer[]`, 참가 기록 ID → `teamId:position`인 `assignments`, `confirmed`, 참가자 쌍별 `pairs`를 담는다. 모집 중에는 `formation: null`이다. 실제 서버의 `getManualFormation()`은 같은 서버·내전 고정 `mmrSeasonId`의 완료 세트에서 채택 ROFL의 실제 출전자 쌍을 집계한다. 취소한 세트·경기·내전은 제외하고 중도 종료의 정상 기록은 유지한다. 사용자 귀속은 당시 참가 기록을 따르며 현재 Riot 계정 소유자·희망 포지션으로 과거 기록을 바꾸지 않는다.

`pairs`의 `together`는 포지션과 무관하게 실제 같은 팀이었던 세트 수·승수다. `againstByLane`은 실제 상대 팀에서 같은 포지션으로 맞붙은 세트 수·승수를 포지션별로 담고, 현재 배정 자리의 포지션으로 조회한다. 해당 포지션에 기록이 없으면 다른 포지션의 합계로 대체하지 않는다. 수동·경매 모두 같은 BO 경기 모델의 유효 실출전을 사용하며 편성 방식으로 과거 기록을 제외하지 않는다.

**화면** `ManualFormationBoard`는 도구 줄·선택 안내 → 미배정 목록 → 팀 자리 순서다. 좁은 화면은 팀 한 열, `sm` 이상 두 열이며 고정 최소 폭이나 가로 스크롤을 요구하지 않는다. 상세는 `lg` 이상 2팀에서 `[팀 시너지 | 팀 | 라인 상대 전적 | 팀 | 팀 시너지]`, 3~4팀은 시너지/팀 묶음을 두 개씩 배치한다. 그 미만에서는 시너지를 각 팀 아래에, 2팀 상대 전적은 팀 영역 뒤에 압축 표시한다.

| 영역 | 컴포넌트·동작 |
| --- | --- |
| 도구 줄 | 배치/전체 수·상세 토글. 미배정 수는 미배정 목록 머리에만 표시. 편집자는 `방식 다시 고르기`, `초기화`, 편성 확정. 2팀은 경기 방식 선택과 `편성 확정·경기 시작` |
| 팀 자리 | `FormationTeamCard`: 포지션 아이콘, 얼굴·이름, 해당 포지션 MMR. 희망 밖 포지션이면 `희망 외`. 중요한 MMR·희망 외 표시는 좁은 자리에서 줄바꿈하며 생략하지 않는다. 선택 대상/읽기 전용에는 빈 해제 열을 예약하지 않음. 팀 이름으로만 구분하며 편성 단계에서 진영을 표시하지 않음. 평균 MMR은 상세를 켰을 때만 표시 |
| 배치·교환 | 참가자를 끌어 자리에 놓거나, 참가자 버튼 선택 후 자리를 누름. 선택한 이름과 다음 배치 행동은 작업판 안내 한 곳에서 알리며, 선택 중에는 기존 안내가 공유 헤더 아래 고정된다. 다른 사람이 있으면 원래 자리와 교환하고 원래 자리가 없으면 상대를 미배정으로 돌림 |
| 배정 해제 | 자리의 `×` 또는 미배정 목록으로 끌어 놓기. STDF Button의 실제 버튼 영역도 최소 44×44px로 확보 |
| 선택 해제 | 같은 참가자 재선택, `Escape`, `선택 취소` |
| 미배정 | `FormationPool`: 희망 포지션과 희망 포지션 중 최고 MMR. 전원 배정이면 완료 문구. 확정 전에는 열람자에게도 표시 |
| 상세 | `FormationSynergyRail`: 현재 탑-정글·정글-미드·원딜-서폿으로 배정된 사용자 쌍의 실제 동팀 전적. 2팀은 `FormationHeadToHead`에서 현재 라인에 해당하는 실제 동포지션 맞대결도 표시. 조회할 쌍·포지션의 유효 기록이 없으면 `기록 없음`/`맞대결 없음` |
| 초기화 | 확인 후 모두 미배정 |
| 방식 다시 고르기 | `ChangeMethodButton`: 확인 후 방식·편성 기록을 지우고 요약으로 이동 |
| 편성 확정 | 전원 배정·저장 완료 후 활성. 2팀은 경기 방식을 고른 뒤 `편성 확정·경기 시작`으로 확정·대진·출전 명단·시작을 한 트랜잭션에서 처리하고 경기 상세로 이동. 3·4팀은 확정 후 대진으로 이동 |

배치는 응답 전에 화면을 먼저 바꾸고 연속 배치를 큐에 넣어 순차 전송한다. 실패하면 남은 큐를 버리고 서버 데이터로 돌아가 오류를 알린다. 배정 요청이 남아 있으면 초기화·확정·방식 변경을 막고, 초기화·확정 중에는 선택·배치·드래그도 막는다. `aria-busy`·로딩으로 진행 상태를 표시한다. 확정 후에는 참가자 배치 조작과 미배정 목록이 사라지지만 상세는 계속 열 수 있다. 수정하려면 요약 운영 메뉴의 `팀 편성 다시 하기`를 사용한다.

**상태** 모집 중에는 `모집이 마감되면 선발된 참가자로 팀을 편성할 수 있어요`를 표시한다. 목 초기 편성은 일부 참가자 6명을 미리 배치하며, 이미 대진 준비 이후인 내전은 전원 배정·확정 상태로 만든다.

배치 진행 수는 작업판 머리, 미배정 수는 미배정 목록 머리에서만 표시한다. 빈 미배정 영역은 편집 중 배치 해제 드롭 대상으로 유지하며 읽기 전용에서는 숨긴다.

시즌·사용자 귀속·해당 쌍의 유효 기록이 없으면 빈 자료를 표시한다. 조회 실패는 기존 페이지 오류 경로로 전달하며 빈 기록이나 개발 샘플로 숨기지 않는다. 결과 저장은 업로드에서 지정한 해당 세트의 블루 팀을 사용한다.

## `/g/[guildId]/scrims/[scrimId]/auction` — 경매

**목적** 팀장·포인트를 정하고 후보를 낙찰·유찰·수동 배치해 팀을 완성한다.

**권한** 선택 방식이 경매가 아니면 실제 방식의 작업판 또는 요약으로 307 이동한다. 조작은 현재 관리자이며 내전 상태가 `preparing`일 때만 허용한다. 각 action은 경매의 `setup`·`in_progress` 상태와 revision을 추가로 검사한다.

**데이터** `AuctionView`의 상태, 선발 참가자, 팀장·시작/남은 포인트·팀원, 현재 후보 `openLot`, 대기열 `queue`, 유찰자 `unsold`, 기록 `history`, 현재 후보 전적 `openProfile`. 모집 중에는 `auction: null`이다.

### 준비 (`setup`)

`AuctionSetupBoard`는 넓은 화면에서 왼쪽 검색 가능한 팀장 후보 목록과 오른쪽 팀 설정 패널을 붙이고, 좁은 화면에서는 세로로 쌓는다. 공통 머리에 준비 상태·방식 변경, 작업 줄에 저장·시작과 막힌 이유를 두고 그 아래 후보·팀 설정을 표시한다. 팀 설정은 DOM에서도 후보 목록 뒤다.

- 참가자를 누르는 순서대로 비어 있는 첫 팀의 팀장이 되며 다시 누르면 해제된다. 모든 팀장이 정해졌으면 다른 후보는 비활성이다.
- 팀 카드에는 시작 포인트와 팀장을 표시한다. 시작 포인트 기본값은 1000이며 서버는 1 이상의 안전한 정수를 받는다.
- 설정 저장은 변경이 있고 포인트가 유효할 때 가능하다. 팀장을 일부만 정한 설정도 저장할 수 있다.
- 모든 팀장 지정·유효 포인트·저장 완료 후 `경매 시작`이 활성화된다. 확인 후 팀장을 제외한 참가자를 무작위 대기열에 넣고 경매 상태를 진행 중으로 바꾼다. 현재 후보는 `다음 후보`로 별도 선택한다.
- 열람자는 후보 검색·선택과 저장/시작 조작 없이 팀 설정만 본다. 검색 결과가 없으면 빈 결과 문구를 표시한다.

모든 팀이 5명이 되면 경매는 완료, 내전은 대진 준비가 되고 마지막 배정을 실행한 운영자는 대진으로 이동한다. 요약에서 `팀 편성 다시 하기`를 실행하면 경매 진행 중으로 돌아가 기록 되돌리기·초기화·팀장 다시 정하기를 사용할 수 있다.

**상태** 모집 중에는 경매 준비 안내, 현재 후보 없음은 역할에 맞는 후보 대기 안내를 표시한다. 완료 경매는 상태·팀 카드·경매 이야기·기록만 표시한다. 미시작 내전 취소는 경매 상태만 취소하고 영입·후보·행위를 보존하며 복구 시 이전 상태로 돌아간다. 진행 중 내전 전체 취소는 이전 영입·행위를 무효 이력으로 보존하고, 복구하면 팀장·시작 포인트를 유지한 setup에서 다시 시작한다.

**후보 전적 상태** 실제 프로필은 같은 서버·내전 고정 시즌의 채택 ROFL 실출전을 당시 사용자에게 귀속해 조회한다. 취소한 세트·경기·내전은 제외하고 중도 종료의 정상 기록은 유지한다. 해당 시즌 전적이 0건이면 상세에 `이 내전과 같은 시즌의 기록이 없어요.`를 표시하며 조회 실패는 기존 페이지 오류로 전달한다. 챔피언 이름·이미지는 Data Dragon 카탈로그로 해석하고 미확인 포지션·시각을 희망 포지션이나 업로드 시각으로 대체하지 않는다. 실제 시각은 내림차순·null 마지막으로 정렬하되 시각 미확인 기록이 하나라도 있으면 `최근 게임` 대신 `게임 기록`으로 표시하고 최근 흐름 막대를 숨긴다. 선호 챔피언·외부 Riot 요약을 내전 기록에서 합성하지 않는다.

**되돌리기 경계** 신규 `auction_actions` 원장에 기록된 직전 작업만 한 번 되돌린다. 과거 원장 없는 행위는 lot로 추정하지 않는다. 초기화·재설정·방식 변경·모집 재개는 이전 행위의 복원 경계를 끊지만 기록은 보존한다. 되돌리기 불가 상태여도 유효 영입이 남아 있으면 경매 초기화는 가능하다. 팀 편성 완료 뒤 직접 되돌리기는 기존처럼 요약에서 팀 편성 단계로 돌아온 후 사용한다.

## `/g/[guildId]/scrims/[scrimId]/bracket` · `/g/[guildId]/scrims/[scrimId]/result` — 대진·결과

**목적** 확정된 팀을 대진 자리에 배치하고 확정한 뒤 점수·승자를 조회한다.

**경로·권한** 대진·결과 경로가 내전 상태와 맞지 않으면 종료·중도 종료는 `/result`, 나머지는 `/bracket`으로 307 이동한다. 정상 종료한 내전의 현재 대진이 완료된 한 경기라면 `/result`에서 해당 경기 상세로 307 이동한다. 여러 경기·중도 종료는 전체 대진 결과를 유지한다. `/result`에는 편집 action이 없다. 두 경로 모두 `BracketBoard`를 사용하되 본문 제목은 대진에서 `대진`, 결과에서 `대진 결과` 또는 `중도 종료 결과`다. 브라우저 제목도 경로의 목적을 구분한다.
`can.edit`는 운영자 + 대진 준비 + 미확정, `can.unlock`은 운영자 + 대진 준비 + 확정이다.

**데이터** `BracketView`의 팀/팀원, 경기 목록, 라운드별 `bestOf`, 확정 여부, 편집/확정 해제 권한. 각 경기에는 직접 배치 `seat` 또는 이전 경기 승자 `from`, 팀 ID, 점수·상태·승자, 경기 상세용 `matchId`가 있다. 팀 편성 전은 `bracket: null`이다.

| 팀 수 | 틀 | 초기 경기 방식 |
| --- | --- | --- |
| 2팀 | 결승 한 경기 | 3전 2선승 |
| 3팀 | 준결승 한 경기 + 결승 직행 자리 | 준결승 3전 2선승, 결승 5전 3선승 |
| 4팀 | 준결승 A·B + 결승 | 준결승 3전 2선승, 결승 5전 3선승 |

`bracketTemplate()`이 틀을 만들며 결승 직행은 자동 승리/점수가 아닌 운영자가 정하는 시드다. `resolveWinners()`는 `completed` 경기의 승자만 다음 자리에 올린다.

**화면** 도구 줄 아래 `[팀 풀 | 준결승 | 결승]`. 팀 풀은 편집 중에만 표시하고 `lg` 미만은 위로 쌓는다. 라운드 열은 `md` 미만에서 세로로 쌓는다.

| 영역 | 컴포넌트·동작 |
| --- | --- |
| 도구 줄 | 편집 중 배치 수. `초기화`는 확인 후 배치만 지우고 경기 방식 유지. 전원 배치 시 `대진 확정·내전 시작` 활성. 확인과 시작을 같은 트랜잭션으로 처리하며 대진 전체가 한 경기이면 상세로 이동 |
| 기존 확정 대진 | 시작 전 데이터는 대진 화면에서 `내전 시작` 제공. 한 경기면 상세로 이동 |
| 다시 편성 | 확정 뒤 시작 전 운영자에게 표시. 별도 확인 없이 확정만 해제하고 배치 유지 |
| 팀 풀·배치 자리 | `BracketTeamContent`: 팀명·팀원 이름, `sm` 이상 얼굴 묶음. 팀을 선택하거나 끌어 배치. 기존 팀을 옮기면 원래 자리를 비우고 도착 자리에 있던 팀은 풀로 반환 |
| 배치 해제 | 자리의 `×` 또는 팀 풀로 끌어 놓기 |
| 선택 해제 | 같은 팀 재선택, `Escape`, `선택 취소` |
| 경기 방식 | `BracketFormatControl`의 `Radio`: 준결승/결승 각각 단판·3전 2선승·5전 3선승. 확정 후에는 텍스트만 표시 |
| 경기 표시 | `BracketMatchBox`: 확정/열람 시 팀명·점수·승자. 대기·취소는 점수 `–`, 진행 중은 경고 테두리. 대기 외 상태 태그 표시. `matchId`가 있을 때만 경기 상세 링크 |

작업 중 로딩과 `aria-busy`를 표시하고 관련 선택·배치·해제·확정의 중복 실행을 막는다. 선택한 팀 이름과 놓을 자리 안내는 작업판 한 곳에서 제공한다. 배치는 서버 응답 후 갱신한다. HTML 드래그 외에 버튼 선택·배치를 지원한다.

**상태** 팀 미확정이면 `팀 편성이 끝나면 대진을 만들 수 있어요`. 대진 생성 전 중도 종료 결과는 이미 종료됐다는 별도 안내를 쓴다. 대진 준비 첫 진입은 빈 틀과 팀 풀, 모두 배치하면 풀에 완료 문구를 표시한다. 중도 종료는 실제 완료 세트의 현재 점수 우세 팀만 경기 승자로 표시하고 동점은 null이다. 결승이 진행되지 않았으면 준결승 우세로 새 결승 경기나 우승팀을 만들지 않는다.

**연결 범위** 실제 대진 배치·확정은 DB에 저장하고 내전 시작 시 양 팀이 정해진 Match를 생성한다. 점수·완료 결과는 저장된 경기 자료를 읽는다. ROFL 등록 시 점수·승자를 갱신하고 다음 대진으로 자동 진출시킨다. 개발 샘플만 고정 `RESULTS`를 사용한다. 밴픽·픽 순서·경기 중 진행 입력은 이 화면의 기능이 아니다.

ROFL 결과 등록·자동 대진 진출·MMR 반영과 실제 후보 상세 전적·시너지·동포지션 상대 전적은 현재 업무 흐름에 연결되어 있다. 경매 열람자의 제한적 자동 조회를 제공하며 WebSocket 구독·서버 입찰·서버 타이머는 없다. 개발 샘플의 고정 점수·가상 전적은 운영 데이터로 사용하지 않는다. 경매의 현재 후보 수동 배치는 드래그 외에도 후보 선택 후 팀의 배치 버튼으로 실행할 수 있다. 기존 실행은 [운영 후속 기록](../../ui-review/operations.md), 새 전체 취소·운영 제한의 최종 통합검증은 [새 후속 기록](../../ui-review/next.md)을 따른다.
