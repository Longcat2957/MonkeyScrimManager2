# 내전 페이지

활성 서버의 내전은 공개 조회한다. 참가 신청은 본인 소속, 운영은 현재 서버 관리 권한이 필요하다. 저장 시 서버·내전·단계·revision을 다시 검사한다. 오래된 화면은 409로 거절하고 최신 상태를 읽는다. 샘플 서버의 메모리 상태는 실제 내전·계정·점수에 반영되지 않는다.

## 내전 목록과 모집 설정

`/g/[guildId]/scrims`에서 전체·모집 중·진행 중·종료 필터를 고르고 20개씩 조회한다. 각 쪽에서 모집 중인 내전을 먼저 제시하고 나머지는 월별로 묶는다. 진행 중 필터는 편성·대진 준비·진행을, 종료 필터는 정상 종료·중도 종료를 포함한다. 취소된 내전은 기본 목록과 건수에서 제외하며, `취소된 내전 포함`을 선택하면 전체·종료 필터에 포함한다. 내전 제목을 선택하면 요약으로 들어간다.

운영자는 `모집 만들기`에서 제목(앞뒤 공백 제거 후 1~50자), 일정, 팀 수, 추가 신청 정원, 하드 피어리스를 정한다. 날짜와 시각은 함께 입력하거나 모두 비우며 한국 시각 기준이다. 팀 수는 2팀(10명) 또는 4팀(20명) 중 고르며, 추가 신청은 0~10명이다. 기본은 2팀·추가 2명·피어리스 꺼짐이다. 편성 방식은 별도로 요약에서 선택한다.

웹과 Discord 모두 새 모집 창을 연 시각의 30분 뒤를 한국 시각으로 채운다. 운영자가 바꾼 시각이나 명시적으로 비운 일정은 오류 후 다시 열어도 유지한다. 기존 내전의 미정 일정을 임의로 채우지 않는다.

모집 중에는 전체 설정, 편성·대진 준비 중에는 제목·일정·하드 피어리스, 진행 중에는 제목·일정만 수정한다. 끝난 내전은 수정할 수 없다. 실출전·전체 정원을 현재 선발·활성 신청보다 줄일 수 없다. 변경한 초안을 닫을 때는 폐기를 확인한다.

## 내전 요약과 참가자

`/g/[guildId]/scrims/[scrimId]`의 제목·일정·상태 아래에 모집·팀 편성·대진·결과 경로를 둔다. 편성 방식과 운영 조작은 관리자에게만 제공한다. 포지션 분포는 **선발된** 참가자의 첫 희망과 나머지 희망을 따로 세어 팀 수와 비교한다. 이는 확정 출전 포지션이 아니다.

| 조작 | 조건과 결과 |
| --- | --- |
| 신청·수정·철회 | 소속 멤버는 모집 중 한 번에 신청한다. 대표 등 연결된 계정을 사용할 수 있고 계정 없이도 신청할 수 있다. 이전 희망 포지션이 없으면 다섯 포지션 전체로 신청한다. 수정 시 계정 없이 참가하거나 연결 계정과 하나 이상의 희망 포지션을 고른다. 철회는 확인 후 처리한다. |
| 선발·대기 | 일반 신청은 실출전 자리가 남으면 선발, 아니면 대기다. 전체 정원 초과와 활성 사용자·지정 계정 중복은 거절한다. Discord에서 합류 시각을 지정하면 대기 명단에 들어가고, 모집 중 그 시각 이후 빈 선발 자리로 이동한다. 만석이면 빈자리가 날 때까지 대기한다. 그 외 대기는 운영자 수동 배정만 허용한다. |
| 참가자 관리 | 평소 명부는 선발·대기만 표시하며 철회·제외는 해당 필터에서 확인한다. 한 사람의 최신 상태만 센다. 모집 중 운영자는 활성 참가자를 골라 선발·대기·제외를 일괄 적용한다. 제외는 확인하고 실패하면 선택을 유지한다. |
| 참가자 추가·안내 | 운영자가 서버 별명·사용자명을 검색해 여러 멤버를 추가한다. 실제 소속·봇 제외·중복·정원을 다시 확인하며 실패 대상만 재시도한다. 편성·대진 준비·진행 중에는 선발자에게 안내 DM을 요청하고 대기·완료·실패·전달 확인 필요 건수를 본다. 이미 요청한 대상은 중복 예약하지 않는다. |
| 편성 방식 | 운영자가 모집·편성 단계에서 수동 또는 경매를 고른다. 방식 변경·다시 고르기는 기존 편성 효과를 초기화하지만 이력은 남긴다. 팀 이름은 순서대로 포로팀·칼날부리팀·돌거북팀·바위게팀이며 직접 변경하지 않는다. |

## 단계 진행과 복구

| 단계 | 진행 | 되돌리기 |
| --- | --- | --- |
| 모집 | 선발 수가 실출전 정원과 같을 때 마감. 방식 미정이어도 마감 가능 | — |
| 편성 | 수동 확정 또는 경매 전원 배치 후 대진 준비 | 모집을 다시 열면 방식은 유지하고 기존 편성 효과는 초기화 |
| 대진 준비 | 양 팀이 정해진 대진을 확정하고 시작하면 실제 경기 생성 | 경기 생성 전에는 확정 여부와 관계없이 대진을 해제하고 수동 편성 또는 경매를 재개. 기존 선수 배정·경매 영입·잔액 보존 |
| 진행 | ROFL 결과로 승자 진출. 최종 대진이 종료되면 내전 자동 완료 | 진행 흔적이 없을 때만 대진 준비로 복귀 |
| 정상 종료 | 결과 열람 | 진행 중으로 되돌리기 |

**중도 종료:** 편성·대진 준비·진행 단계에서 가능하다. 완료 세트·MMR·라인업은 보존한다. 중단한 경기의 실제 점수 우세 팀만 승자로 표시하고 동점은 미확정이다. 열리지 않은 결승이나 우승팀을 만들지 않는다. 재개하면 원래 단계로 돌아가 중단한 경기만 복원한다.

**내전 취소:** 시작 전 취소는 참가자·배정·대진·경매 포인트와 이력을 보존한다. 복구하면 저장된 원래 단계로 돌아간다. 진행 중 전체 취소는 영향받을 결과 수와 MMR 역분개를 확인한 뒤, 후속 대진부터 한 트랜잭션에서 취소한다. 다른 내전이나 관리자 보정 이후의 원장을 넘어서 역분개하지 않는다. 원본 경기·결과·원장은 삭제하지 않는다.

진행 중 전체 취소를 복구하면 참가자를 유지하고 **편성 준비**로 돌아간다. 수동 배정은 재사용하며 경매는 팀장·시작 포인트만 남은 준비 상태로 돌아간다. 취소한 결과와 MMR은 다시 적용하지 않는다. 근거가 없거나 현재 결과와 충돌하면 복구를 막는다. 완료·중도 종료한 내전에는 전체 취소를 제공하지 않는다.

## 수동 편성 (`manual`)

- 운영자는 편성 단계에서 선발자를 끌거나 선택 후 팀의 포지션 자리를 눌러 배치한다. 이미 선수가 있으면 자리를 바꾸거나 밀려난 선수를 미배정으로 돌린다. 자리 해제·선택 취소·전체 초기화·방식 다시 고르기를 제공한다. 저장 중 확정하거나 다른 방식으로 바꿀 수 없다. 연속 배치가 실패하면 남은 요청을 버리고 저장된 배치로 돌아간다.
- 자리에는 해당 포지션 MMR과 희망 외 여부를 표시한다. 상세를 열면 현재 조합의 동팀 전적과 2팀의 같은 포지션 맞대결을 본다. 현재 계정 소유자나 희망 포지션을 과거 실출전으로 대체하지 않는다.
- 상단에는 배치 인원과 상세 보기만 둔다. 참가자와 팀 자리를 먼저 보고 작업판 아래에서 배정을 초기화하거나 편성을 확정한다. 2팀도 경기 방식을 지정한 뒤 편성만 확정한다. 1세트 진영 선택과 경기 시작은 대진 화면에서 별도로 진행한다. 열람자에게는 편집 조작을 표시하지 않는다.

## 경매 (`auction`)

1. **준비:** 선발자 중 팀장을 고르고 팀별 시작 포인트를 설정한다(기본 1000, 양의 안전한 정수). 팀장 일부만 정해도 설정 저장은 가능하다. 호명 순위는 같은 서버의 모든 시즌에 걸친 평균 낙찰가 기준이다. 취소되지 않은 내전의 완료된 경매에서 무효화되지 않은 1P 이상 낙찰만 건수와 평균에 포함한다. 0P 낙찰과 수동 배치는 영입 기록에는 남지만 가격 표본에서 제외한다. 가격 이력이 없는 후보는 최하위로 취급하며 동률 후보의 호명 확률은 같다.
   `핀볼 추첨`의 첫 단계에서 이번 추첨에서 제외할 참가자를 선택한다. 수동 팀장은 처음부터 대상이 아니며, 체크한 참가자는 내전과 경매에는 그대로 남는다. 남은 참가자가 뽑을 팀장 수 이상이어야 `추첨 시작`으로 레이스에 진입한다. 결과창에서 다시 뽑으면 같은 제외 목록을 수정할 수 있고, 창을 닫으면 제외 목록은 초기화된다.
   공동 관전 화면에서 구슬은 이름표와 번호로 구분한다. 구슬마다 중반 코스의 무작위 지점에서 같은 세기의 자동 부스트를 한 번 사용한다. 부스트 중에도 구슬·지형과 충돌한다. `자동 중계`는 출발 무리, 접전, 후미권, 결승을 비춘다. `중계 카메라`에서 참가자를 고르면 그 구슬을 따라가며, 미니맵 테두리는 실제 화면 범위를 나타낸다. 관전 방식, `결과 바로 보기`, 동작 줄이기 설정은 도착 순위에 영향을 주지 않는다.
   팀장은 마지막에 도착한 참가자 중에서 뽑는다. 10명이 두 자리를 추첨하면 1~8번째 도착자는 제외하고 9번째와 10번째 도착자를 차례로 배정한다. 수동 팀장 한 명을 남긴 경우에는 추첨 참가자 중 맨 마지막 한 명만 선발한다. 20인전·재추첨도 추첨 대상 팀 수만큼 마지막 도착자를 선발한다.
   `팀장 배정`은 실제 결승선 통과 순서로 초안에 반영한다. 결과창에서 `다시 추첨`하거나 배정 후 `설정 저장` 전에 다시 뽑을 수 있다. 재추첨 대상은 빈 팀과 이전 추첨으로 채운 팀뿐이다. 수동 팀장과 시작 포인트는 유지하며, 새 결과를 배정하지 않고 닫으면 기존 초안도 그대로다. 저장한 팀장은 직접 해제해야 다시 추첨할 수 있다.
2. **후보:** 팀장을 제외한 후보 수 `N`은 10인 내전에서 8명, 20인 내전에서 16명이다. 평균 낙찰가 순위 `r`인 후보가 `s`번째로 호명될 확률은 `(1 + 0.44 × (N+1−2r) × (N+1−2s) / (N−1)²) / N`이다(순위와 순번은 1부터, 동률은 공동 구간의 평균 순위). 단독 1위의 첫 호명 확률은 각각 18%, 9%이며, 최하위도 각각 7%, 3.5%로 첫 후보가 될 수 있다. `다음 후보`는 저장된 순서에서 한 명만 공개한다. 대기 명단은 호명 순서와 무관한 이름순이다. 후보 상세에서 내전 고정 시즌의 실출전·주력 챔피언·포지션별 MMR과 공개된 선호 챔피언을 구분한다. 시각이 불확실하면 최근 순서를 주장하지 않으며 외부 Riot 전적을 만들어 내지 않는다.
3. **낙찰·배치:** 운영자는 팀당 5명과 잔여 포인트 범위 내에서 0 이상의 정수로 낙찰하거나 유찰한다. 가격 없는 수동 배치는 0점 낙찰과 다르다. 후보 목록의 대기자는 추첨 없이 빈자리가 있는 팀에 바로 배치할 수 있다. 다른 후보의 입찰이 진행 중이어도 그 입찰은 유지한다. 현재 후보는 팀으로 끌거나 목록의 팀 버튼으로 배치한다. 유찰자는 현재 후보가 없을 때 배치하거나 다시 올린다.
4. **조정 시간:** 진행자가 입찰가를 바꾸면 현재 후보 카드 상단의 10초 타이머가 다시 시작한다. 카드 배경은 고정하고 막대와 남은 초로 시간을 표시한다. 동작 줄이기 설정에서는 빛 효과 없이 초 단위로 갱신한다. 시간이 끝나도 자동 낙찰·유찰하지 않는다. 열람자는 서버 입찰을 하지 않으며 진행자 입력을 자동 동기화하지 않는다.
5. **되돌리기:** 직전 추첨·낙찰·유찰·수동 배치·유찰자 복귀 중 원장에 있는 한 작업만 되돌린다. 대기자의 수동 배치를 되돌리면 원래 추첨 순서로 복원한다. 연속 되감기나 과거 기록 추정은 없다. 초기화·팀장 재설정·방식 변경·모집 재개는 복원 경계를 끊지만 무효 처리한 이력은 남긴다.
6. **완료:** 모든 팀이 5명이면 대진 준비로 이동한다. 팀 편성을 다시 열면 직전 작업 되돌리기·초기화·팀장 재설정이 가능하다. 수정할 필요가 없으면 `경매 편성 확정`으로 같은 팀과 낙찰 기록을 유지한 채 대진으로 돌아간다.

`상세 보기`를 열면 첫 줄에 호명과 같은 기준으로 집계한 역대 평균 낙찰가와 유상 낙찰 횟수를 표시한다. 기록이 없으면 `유상 낙찰 기록 없음`으로 표시한다. 앞면에는 가격 정보를 표시하지 않는다. 이어서 시즌의 포지션별 MMR·출전 수, 실제 사용 챔피언, 직접 등록한 선호 챔피언, 경기 기록을 확인할 수 있다.

모집 마감 시 선발자의 신청 계정(미지정이면 같은 서버의 대표 계정)을 확인한다. 솔로/듀오 랭크의 현재 티어·단계·LP와 시즌 중 서비스가 관측한 최고값은 내전 MMR이 아니다. 관측 전 기록이나 관측 사이의 승급은 최고값에 포함되지 않는다. 최근 챔피언은 솔로/듀오 랭크 최대 20경기에서 사용 횟수가 많은 3개이며, 동률이면 더 최근에 사용한 챔피언이 먼저다. 일반·자유 랭크·내전 경기로 표본을 채우지 않는다.

앞면에는 Discord 아바타 옆에 이름·포지션을 묶는다. 솔로랭크는 `현재 티어`와 `최고 티어`를 나란히 표시한다. 최고 티어는 해당 시즌에 관측한 값이며, 없으면 `기록 없음`으로 표시한다. 카드에는 조회 시각을 표시하지 않는다. 그 아래 한 줄에서 MMR·시즌 전적·승률을 비교하며, 승패를 함께 쓰는 시즌 전적에 가장 넓은 열을 배정한다. 시즌 기록이 없으면 MMR만 표시한다. 데스크톱에서는 기록이 있을 때만 주력 챔피언을 최대 3명 표시한다. 모바일에서는 요약만 고정한다. 상세 버튼을 누르면 80ms 후 회전을 시작하고 카드가 옆면에 도달하면 내용을 바꾼다. 동작 줄이기 설정에서는 지연·회전·모서리 호버 효과를 생략한다.

`상세 보기`와 `상세 접기`는 카드 아래 조작 줄 왼쪽의 고스트 버튼이고, 운영자의 `유찰`은 오른쪽에 둔다. 첫 호명 전에도 작업판과 입찰 줄의 자리를 유지하고 입찰은 후보를 뽑은 뒤에만 활성화한다. 뒷면은 앞면과 같은 자리를 써서 전환 중에도 조작 줄·입찰란·푸터가 밀리지 않는다.

열람자의 준비·진행 화면은 기본 5초마다 갱신한다. 조회 실패 시 마지막 정상 자료를 유지하고 재시도 간격을 최대 30초까지 늘린다. 숨긴 탭·오프라인에서는 갱신을 멈춘다. 열람자는 자동 갱신을 끄거나 한 번만 새로고침할 수 있다. 진행자의 미확정 입력은 자동 조회로 바꾸지 않는다.

진행자도 현재 후보의 Riot 조회가 대기 중인 동안에는 해당 후보의 외부 전적만 갱신한다. 입찰 입력·열린 상세·다른 후보에 대한 조작은 변경하지 않는다.

## 대진·결과 (`bracket`, `result`)

대진은 참가 팀, 라운드별 배치, 확정 조작 순으로 읽는다. 결과는 편집 화면을 재사용하지 않고 종료 상태와 실제 경기 목록을 보여 준다. 완료된 결승에서만 우승팀을 표시한다.

- 2팀은 결승 하나, 4팀은 준결승 두 경기와 결승을 사용한다. 기본 방식은 2팀 결승·4팀 준결승 BO3, 4팀 결승 BO5다.
- 운영자는 팀을 끌거나 선택 후 자리에 놓고, 다시 빼거나 초기화한다. 초기화는 배치만 지우며 경기 방식은 유지한다. 라운드별 단판·BO3·BO5를 정한다. 준결승 승자로 양 팀이 정해지는 결승은 경기 상세에서 진영을 선택한다.
- 경매에서 블루·레드 자리에 배치하면 해당 경기의 1세트 진영이 정해진다. 같은 경기의 반대 자리로 옮기면 두 팀을 교환한다. 대진 확정 후 시작 전에는 같은 경기 안에서만 교환할 수 있다. 수동 대진에서는 양 팀을 배치한 뒤 블루 팀을 별도로 고른다.
- 실제 경기 링크에서 라인업·세트를 확인하고 [ROFL을 등록](records.md#rofl-업로드-팝업)한다. 정상 완료 승자만 다음 경기에 올라간다. 밴픽·게임 중 진행·승패를 직접 입력하지 않는다. 결과 화면은 읽기 전용이며, 정상 종료한 단일 경기는 경기 상세로 이동한다. 취소된 내전에는 편집할 대진을 표시하지 않는다.
