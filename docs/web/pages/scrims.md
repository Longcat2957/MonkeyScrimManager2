# 내전 페이지

활성 서버의 내전은 공개 조회한다. 참가 신청은 본인 소속, 운영은 현재 서버 관리 권한이 필요하다. 저장 시 서버·내전·단계·revision을 다시 검사한다. 오래된 화면은 409로 거절하고 최신 상태를 읽는다. 샘플 서버의 메모리 상태는 실제 내전·계정·점수에 반영되지 않는다.

## 내전 목록과 모집 설정

`/g/[guildId]/scrims`에서 전체·모집 중·진행 중·종료 필터를 고르고 20개씩 조회한다. 각 쪽에서 모집 중인 내전을 먼저 제시하고 나머지는 월별로 묶는다. 진행 중 필터는 편성·대진 준비·진행을, 종료 필터는 정상 종료·중도 종료·취소를 포함한다. 내전 제목을 선택하면 요약으로 들어간다.

운영자는 `모집 만들기`에서 제목(앞뒤 공백 제거 후 1~50자), 일정, 팀 수, 추가 신청 정원, 하드 피어리스를 정한다. 날짜와 시각은 함께 입력하거나 모두 비우며 한국 시각 기준이다. 팀 수는 2팀(10명) 또는 4팀(20명) 중 고르며, 추가 신청은 0~10명이다. 기본은 2팀·추가 2명·피어리스 꺼짐이다. 편성 방식은 별도로 요약에서 선택한다.

모집 중에는 전체 설정, 편성·대진 준비 중에는 제목·일정·하드 피어리스, 진행 중에는 제목·일정만 수정한다. 끝난 내전은 수정할 수 없다. 실출전·전체 정원을 현재 선발·활성 신청보다 줄일 수 없다. 변경한 초안을 닫을 때는 폐기를 확인한다.

## 내전 요약과 참가자

`/g/[guildId]/scrims/[scrimId]`의 제목·일정·상태 아래에 모집·팀 편성·대진·결과 경로를 둔다. 편성 방식과 운영 조작은 관리자에게만 제공한다. 포지션 분포는 **선발된** 참가자의 첫 희망과 나머지 희망을 따로 세어 팀 수와 비교한다. 이는 확정 출전 포지션이 아니다.

| 조작 | 조건과 결과 |
| --- | --- |
| 신청·수정·철회 | 소속 멤버는 모집 중 한 번에 신청한다. 대표 등 연결된 계정을 사용할 수 있고 계정 없이도 신청할 수 있다. 이전 희망 포지션이 없으면 다섯 포지션 전체로 신청한다. 수정 시 계정 없이 참가하거나 연결 계정과 하나 이상의 희망 포지션을 고른다. 철회는 확인 후 처리한다. |
| 선발·대기 | 실출전 정원이 남으면 선발, 찼으면 대기다. 전체 정원을 초과하거나 이미 활성인 사용자·지정 계정이 중복되면 거절한다. 철회·제외 후 빈 선발 자리는 신청 시각이 빠른 대기자부터 채운다. 수동 대기 전환 직후에는 자동 재선발하지 않는다. |
| 참가자 관리 | 평소 명부는 선발·대기만 표시하며 철회·제외는 해당 필터에서 확인한다. 한 사람의 최신 상태만 센다. 모집 중 운영자는 활성 참가자를 골라 선발·대기·제외를 일괄 적용한다. 제외는 확인하고 실패하면 선택을 유지한다. |
| 참가자 추가·안내 | 운영자가 서버 별명·사용자명을 검색해 여러 멤버를 추가한다. 실제 소속·봇 제외·중복·정원을 다시 확인하며 실패 대상만 재시도한다. 편성·대진 준비·진행 중에는 선발자에게 안내 DM을 요청하고 대기·완료·실패·전달 확인 필요 건수를 본다. 이미 요청한 대상은 중복 예약하지 않는다. |
| 편성 방식 | 운영자가 모집·편성 단계에서 수동 또는 경매를 고른다. 방식 변경·다시 고르기는 기존 편성 효과를 초기화하지만 이력은 남긴다. 팀 이름은 순서대로 포로팀·칼날부리팀·돌거북팀·바위게팀이며 직접 변경하지 않는다. |

## 단계 진행과 복구

| 단계 | 진행 | 되돌리기 |
| --- | --- | --- |
| 모집 | 선발 수가 실출전 정원과 같을 때 마감. 방식 미정이어도 마감 가능 | — |
| 편성 | 수동 확정 또는 경매 전원 배치 후 대진 준비 | 모집을 다시 열면 방식은 유지하고 기존 편성 효과는 초기화 |
| 대진 준비 | 양 팀이 정해진 대진을 확정하고 시작하면 실제 경기 생성 | 팀 편성 다시 하기. 기존 대진 해제, 수동 편성 또는 경매 재개 |
| 진행 | ROFL 결과로 승자 진출. 최종 대진이 종료되면 내전 자동 완료 | 진행 흔적이 없을 때만 대진 준비로 복귀 |
| 정상 종료 | 결과 열람 | 진행 중으로 되돌리기 |

**중도 종료:** 편성·대진 준비·진행 단계에서 가능하다. 완료 세트·MMR·라인업은 보존한다. 중단한 경기의 실제 점수 우세 팀만 승자로 표시하고 동점은 미확정이다. 열리지 않은 결승이나 우승팀을 만들지 않는다. 재개하면 원래 단계로 돌아가 중단한 경기만 복원한다.

**내전 취소:** 시작 전 취소는 참가자·배정·대진·경매 포인트와 이력을 보존한다. 복구하면 저장된 원래 단계로 돌아간다. 진행 중 전체 취소는 영향받을 결과 수와 MMR 역분개를 확인한 뒤, 후속 대진부터 한 트랜잭션에서 취소한다. 다른 내전이나 관리자 보정 이후의 원장을 넘어서 역분개하지 않는다. 원본 경기·결과·원장은 삭제하지 않는다.

진행 중 전체 취소를 복구하면 참가자를 유지하고 **편성 준비**로 돌아간다. 수동 배정은 재사용하며 경매는 팀장·시작 포인트만 남은 준비 상태로 돌아간다. 취소한 결과와 MMR은 다시 적용하지 않는다. 근거가 없거나 현재 결과와 충돌하면 복구를 막는다. 완료·중도 종료한 내전에는 전체 취소를 제공하지 않는다.

## 수동 편성 (`manual`)

- 운영자는 편성 단계에서 선발자를 끌거나 선택 후 팀의 포지션 자리를 눌러 배치한다. 이미 선수가 있으면 자리를 바꾸거나 밀려난 선수를 미배정으로 돌린다. 자리 해제·선택 취소·전체 초기화·방식 다시 고르기를 제공한다. 저장 중 확정하거나 다른 방식으로 바꿀 수 없다. 연속 배치가 실패하면 남은 요청을 버리고 저장된 배치로 돌아간다.
- 자리에는 해당 포지션 MMR과 희망 외 여부를 표시한다. 상세를 열면 현재 조합의 동팀 전적과 2팀의 같은 포지션 맞대결을 본다. 현재 계정 소유자나 희망 포지션을 과거 실출전으로 대체하지 않는다.
- 상단에는 배치 인원과 상세 보기만 둔다. 참가자와 팀 자리를 먼저 보고, 작업판 아래에서 배정을 초기화하거나 편성을 확정한다. 2팀은 이곳에서 경기 방식과 1세트 블루 팀을 골라 바로 시작한다. 3·4팀은 편성 확정 후 대진 작업으로 이동한다. 열람자에게는 편집 조작을 표시하지 않는다.

## 경매 (`auction`)

1. **준비:** 선발자 중 팀장을 고르고 팀별 시작 포인트를 설정한다(기본 1000, 양의 안전한 정수). 팀장 일부만 정해도 설정 저장은 가능하다. 시작 시 팀장을 제외한 후보를 호명 기준가 내림차순으로 정렬한다. 서버 관리자가 지정한 보정가가 있으면 이를 우선한다. 없으면 같은 서버의 실제 평균 낙찰가를 쓰고, 낙찰 이력도 없으면 멤버의 경매 초기값을 쓴다. 세 값이 모두 없으면 뒤에 두며 동률은 무작위로 나눈다. 실제 평균은 시즌과 무관하게 취소되지 않은 내전의 완료된 경매에서 유효한 1P 이상 낙찰만 집계한다. 초기값·보정가 변경은 다음 경매 시작·초기화부터 적용하며 낙찰 통계에는 포함하지 않는다.
2. **후보:** 10인 내전은 2명씩, 20인 내전은 4명씩 네 그룹을 만든다. 호명 기준가가 높은 그룹부터 호명하되 각 그룹 안의 순서는 무작위다. 기존 15인 내전만 종전의 전체 무작위 호명을 유지한다. `다음 후보`는 저장된 순서에서 한 명만 공개한다. 대기 명단은 호명 순서와 무관한 이름순이다. 후보 상세에서 내전 고정 시즌의 실출전·주력 챔피언·포지션별 MMR과 공개된 선호 챔피언을 구분한다. 시각이 불확실하면 최근 순서를 주장하지 않으며 외부 Riot 전적을 만들어 내지 않는다.
3. **낙찰·배치:** 운영자는 팀당 5명과 잔여 포인트 범위 내에서 0 이상의 정수로 낙찰하거나 유찰한다. 가격 없는 수동 배치는 0점 낙찰과 다르다. 드래그 외에 후보 목록의 팀 버튼으로도 배치한다. 현재 후보가 없으면 유찰자를 배치하거나 다시 올린다.
   경매 가격 통계는 완료된 경매에서 무효화되지 않은 1P 이상 낙찰만 집계한다. 0P 낙찰은 영입 이력에 남기되 통계의 낙찰 건수와 평균가 계산에서 제외한다.
4. **조정 시간:** 진행자가 입찰가를 바꾸면 현재 후보 카드 상단의 10초 타이머가 다시 시작한다. 카드 배경은 고정하고 막대와 남은 초로 시간을 표시한다. 동작 줄이기 설정에서는 빛 효과 없이 초 단위로 갱신한다. 시간이 끝나도 자동 낙찰·유찰하지 않는다. 열람자는 서버 입찰을 하지 않으며 진행자 입력을 자동 동기화하지 않는다.
5. **되돌리기:** 직전 추첨·낙찰·유찰·현재 후보 수동 배치·유찰자 수동 배치·유찰자 복귀 중 원장에 있는 한 작업만 되돌린다. 연속 되감기나 과거 기록 추정은 없다. 초기화·팀장 재설정·방식 변경·모집 재개는 복원 경계를 끊지만 무효 처리한 이력은 남긴다.
6. **완료:** 모든 팀이 5명이면 대진 준비로 이동한다. 팀 편성을 다시 열어야 직전 작업 되돌리기·초기화·팀장 재설정을 할 수 있다.

열람자는 편성 중 준비·진행 화면을 5초 간격으로 읽으며 자동 중지와 일회 새로고침을 사용할 수 있다. 숨긴 탭·오프라인에서는 중단하고 실패 시 마지막 정상 자료를 유지한다. 진행자의 미확정 입력은 자동 조회로 바꾸지 않는다.

## 대진·결과 (`bracket`, `result`)

대진은 참가 팀, 라운드별 배치, 확정 조작 순으로 읽는다. 결과는 편집 화면을 재사용하지 않고 종료 상태와 실제 경기 목록을 보여 준다. 완료된 결승에서만 우승팀을 표시한다.

- 2팀은 결승 하나, 3팀은 준결승 하나와 운영자가 지정하는 결승 직행 시드, 4팀은 준결승 두 경기와 결승을 사용한다. 직행에는 승리·점수를 부여하지 않는다. 초기 방식은 2팀 결승·준결승 BO3, 3·4팀 결승 BO5다.
- 운영자는 팀을 끌거나 선택 후 자리에 놓고, 다시 빼거나 초기화한다. 초기화는 배치만 지우며 경기 방식은 유지한다. 라운드별 단판·BO3·BO5를 정한다. 3팀 결승 직행은 진영을 정하지 않으며, 나중에 양 팀이 정해지는 결승은 경기 상세에서 선택한다.
- 경매에서 블루·레드 자리에 배치하면 해당 경기의 1세트 진영이 정해진다. 같은 경기의 반대 자리로 옮기면 두 팀을 교환한다. 대진 확정 후 시작 전에는 같은 경기 안에서만 교환할 수 있다. 수동 대진에서는 양 팀을 배치한 뒤 블루 팀을 별도로 고른다.
- 실제 경기 링크에서 라인업·세트를 확인하고 [ROFL을 등록](records.md#rofl-업로드-팝업)한다. 정상 완료 승자만 다음 경기에 올라간다. 밴픽·게임 중 진행·승패를 직접 입력하지 않는다. 결과 화면은 읽기 전용이며, 정상 종료한 단일 경기는 경기 상세로 이동한다. 취소된 내전에는 편집할 대진을 표시하지 않는다.
