# MSM2 프론트엔드 배치·컴포넌트 계획

> **대체됨:** 이 문서의 배치안은 [프론트엔드 디자인 전면 재작성 계획](design/README.md)으로 대체되었다.
> 실제 구현은 `docs/web/design/`의 시스템·구조·컴포넌트·페이지 문서를 따른다. 이 문서는 배치 근거의 역사 기록으로만 유지한다.

작성일: 2026-10-29

상태: 글로 작성한 UI/UX 설계안. 화면·컴포넌트·CSS·API를 구현하는 단계가 아니다.

## 1. 설계 범위와 결정의 성격

[페이지 요구사항](page-requirements.md)이 정한 업무를 실제 화면의 읽기 순서, 조작 위치, 컴포넌트 책임으로 옮긴다.
아래 배치도는 구현 코드가 아니라 화면을 위에서 아래로 읽는 순서다. 컴포넌트 이름도 설계상 이름이며 파일 생성 지시가 아니다.

- **사용자 확정:** 일반 페이지의 기존 헤더 전체를 서버·내전용 헤더로 교체한다. 기존 헤더 아래에 내비게이션을 덧붙이지 않는다.
- **이번 배치안:** 헤더별 구성, 본문 열 수, 주요 행동 위치, 모바일 전환, STDF 조합을 구체적으로 제안한다.
- **업무 정책 미정:** 권한 부여, 경매 규칙, 계정 소유권, 공개 범위, 결과 정정 등은 기존 요구사항의 미결정 상태를 유지한다. 배치도가 그 기능의 승인이나 출시를 뜻하지 않는다.

색상 장식보다 현재 대상·상태·다음 행동을 빨리 파악하는 것을 우선한다.
한 화면에서 이미 설명한 사실을 요약 카드·배지·도움말로 다시 반복하지 않는다.

## 3. 헤더와 레이아웃의 소유 구조

```text
RootLayout
├─ 한국어 STDF 설정 + 기존 전역 테마
├─ 본문 바로가기
├─ HeaderOutlet: GlobalHeader / GuildHeader / ScrimHeader 중 하나
├─ MainFrame
│  ├─ 전역 페이지 본문
│  └─ GuildLayout: 검증된 서버 문맥 + 하위 콘텐츠
│     ├─ 서버 홈·목록·기록·통계·관리 본문
│     └─ ScrimLayout: 내전 문맥
│        ├─ ScrimContext: 제목·상태·예정 시각 한 번
│        └─ 요약 / 팀 편성 / 대진 중 현재 페이지 본문
└─ AppFooter: 서비스 표시 정보 + 문서·정책 링크
```

| 소유 위치 | 책임 | 경계 |
| --- | --- | --- |
| 루트 레이아웃 | 하나의 헤더 선택 영역, 본문 틀, 푸터, 한국어·테마 기본값 | 세 헤더를 동시에 마운트하고 CSS로 감추는 방식은 사용하지 않음 |
| 길드 레이아웃 | 현재 서버·열람/관리 가능 범위 준비, 서버 헤더 문맥 제공 | 본문 앞에 두 번째 헤더·서버 메뉴를 만들지 않음 |
| 내전 레이아웃 | 현재 내전·하위 목적지 준비, 내전 헤더 문맥 제공, `ScrimContext` | 서버 헤더와 내전 헤더가 누적되지 않음 |
| 페이지 | 본문의 조립과 작업 상태 연결 | 로고·로그인·서버 선택·공통 목적지 링크를 복제하지 않음 |

루트는 현재 라우트에서 준비된 가장 구체적인 **검증된 문맥**으로 헤더를 선택한다.
길드 안에서는 `GuildHeader`, 내전 상세 하위에서는 이를 `ScrimHeader`로 교체한다.
이는 라우트 데이터와 헤더 표시 책임의 계약이며, 전역 이벤트 버스나 각 페이지의 DOM 이동을 요구하지 않는다.
`Match` 상세는 내전 레이아웃의 자식이 아니므로 `GuildHeader`를 사용한다.
`GlobalHeader`는 현재 `AppHeader`의 전역 역할을 가리키는 설계명이며 이번 문서는 파일 이름 변경을 요구하지 않는다.

### 3.1. 넓은 화면의 헤더

| 헤더 | 왼쪽 → 오른쪽 구성 | 이동 메뉴 |
| --- | --- | --- |
| `GlobalHeader` | 브랜드 홈 링크 → 서버 선택 → 여유 공간 → 화면 모드 → 개인 메뉴/로그인 | 본문 업무와 무관한 홈·GitHub 메뉴를 두지 않음 |
| `GuildHeader` | 작은 브랜드 홈 링크 → 서버 선택 → 서버 업무 메뉴 → 화면 모드 → 개인 메뉴 | 서버 홈·내전·경기 기록·통계·관리 |
| `ScrimHeader` | 작은 브랜드 홈 링크 → 서버 선택 → 서버 메뉴 열기 → 내전 업무 메뉴 → 화면 모드 → 개인 메뉴 | 요약·팀 편성·대진. 서버 업무는 서버 메뉴 안에서만 제공 |

각 헤더는 STDF `NavBar`의 좌측·제목·우측 사용자 영역을 사용해 조립한다.
사용자 영역으로 대체하여 기본 뒤로가기·제목이 추가로 남지 않게 한다.
내비게이션 자체는 의미 있는 링크 목록이며, 이름만 비슷한 STDF `Tabs`를 라우트 링크 대신 사용하지 않는다.
긴 내전 이름과 상태는 본문의 `ScrimContext`가 표시하므로 헤더에 같은 제목을 다시 쓰지 않는다.

`ScrimHeader`의 서버 메뉴는 서버 홈·내전 목록·경기 기록·통계·관리를 제공한다.
요약·팀 편성·대진 링크는 그 메뉴에 넣지 않아 같은 대상의 조작이 겹치지 않는다.
팀 편성 링크는 `/teams` 공통 진입점 하나로 유지하고 `/teams/manual`·`/teams/auction`에서도 활성 상태로 표시한다.
개인 메뉴는 `/me`, 권한이 있는 경우 `/backoffice`, 로그아웃만 담당한다.
정책 링크는 푸터에만 둔다. 서버 선택기의 현재 서버는 표시 항목으로 두며 서버 홈 링크와 중복시키지 않는다.

### 3.2. 좁은 화면의 헤더

```text
[브랜드 홈 아이콘] [현재 서버 / 서버 선택] [메뉴]
메뉴를 연 경우: 현재 문맥의 이동 → 상위 서버 이동(내전만) → 개인 작업 → 화면 모드
```

- 1024px 미만에서는 펼쳐진 내비게이션·화면 모드·개인 메뉴를 단일 메뉴 패널로 옮긴다. 데스크톱판은 조작·포커스 대상에서 제외한다.
- 서버 선택은 헤더의 한 지점에 유지하고 메뉴 패널에 다시 넣지 않는다. 긴 이름은 줄임 표시하되 선택 패널에서는 전체 이름을 읽을 수 있다.
- 내전에서는 요약·팀 편성·대진을 먼저, 서버 전체 이동을 다음 그룹으로 둔다. 로그인 상태와 관리 권한에 따라 실제 가능한 항목만 제공한다.
- 하나의 패널만 열린다. 서버 선택 패널과 메뉴를 겹쳐 띄우지 않는다. 메뉴에서 이동하면 닫고 새 페이지 제목으로 읽기 맥락을 넘긴다.
- 헤더만 고정한다. 본문 상단에 또 다른 고정 메뉴, 하단 탭, 동일 작업의 플로팅 버튼은 두지 않는다.

### 3.3. 헤더 공통 조각

| 구성 | 입력·책임 | 사용할 기반 |
| --- | --- | --- |
| `BrandHomeLink` | 홈 링크 한 개, 화면 크기에 따른 이미지·워드마크 표현 | 의미 있는 링크·이미지, 기존 `font-brand` |
| `GuildSwitcher` | 접근 가능한 서버·선택값·로딩/오류. 선택은 해당 서버 홈 이동 | `Button` → `Popup`, 이름 있는 링크 목록 |
| `AccountMenu` | 본인·운영자 권한·로그아웃 상태 | `Button` → `Popup`, 링크와 로그아웃 `Button` |
| `AppearanceControl` | 현재 화면 모드와 변경 | 현재 상태와 다음 동작을 알 수 있는 `Button` |
| `ContextNavigation` | 길드/내전 목적지와 현재 경로 | `nav`·링크, 현재 위치 표시. 목적지 데이터만 공유 |

모바일은 동일한 목적지 데이터를 메뉴 패널에서 사용한다. 각 헤더 전체를 하나의 거대한 조건부 컴포넌트로 만들거나
STDF 컴포넌트마다 래퍼를 만드는 방식 대신, 세 헤더의 실제 공통 책임만 위 조각으로 공유한다.
서버 선택·개인 메뉴·모바일 메뉴의 Popup에도 아래의 이름·포커스·배경 차단 규칙을 동일하게 적용한다.

## 4. 본문 배치와 시각적 기준

| 기준 | 이번 배치안 |
| --- | --- |
| 기본 틀 | 기존 본문 최대 84rem·중앙 정렬·푸터 폭을 유지. 헤더는 기존 최대 96rem·64px 높이를 출발점으로 함 |
| 넓은 작업 화면 | 목록·대진·편성·결과는 본문 폭 사용. 두 열이 필요하면 1024px 이상에서만 배치 |
| 읽기·설정 화면 | 문서 약 48rem, 내 정보 약 44rem의 읽기 폭. 임의 카드로 나머지 공간을 채우지 않음 |
| 여백 | 바깥 16~40px, 영역 사이 24~32px, 입력·관련 정보 사이 8~16px를 공통 토큰으로 관리 |
| 표면 | 문서·목록은 제목과 구분선 중심. 독립 편집·업무 단위에만 `Card`, 그림자는 기본적으로 제거 |
| 색상·글꼴 | 기존 Slate 라이트/다크, Noto Sans KR, 브랜드의 Jersey 10을 유지. 색상만으로 승패·권한·진행 상태를 구분하지 않음 |
| 주 행동 | 작업 영역당 대표 제출 한 곳. 보기 전용 화면에는 행동이 없어도 됨. 본문 위·아래에 같은 저장을 반복하지 않음 |
| 좁은 화면 | 제목 → 핵심 상태 → 현재 사용자 행동 → 상세 정보 순서. 의미가 이어지는 입력은 한 열로 배치 |

값은 STDF 공개 옵션과 전역 토큰으로 적용할 설계 기준이다. 픽셀별 컴포넌트 CSS를 문서에서 요구하지 않는다.
본문에 과도한 스크롤 컨테이너를 중첩하지 않고, 긴 페이지는 문서 스크롤을 기본으로 한다.
데이터 표처럼 필요한 영역만 가로 스크롤을 허용하며, 작은 화면에서 핵심 정보와 작업이 가려지지 않게 대안을 둔다.

## 5. 서비스 컴포넌트의 경계

| 구성 | 사용 위치 | 전달받는 정보·알리는 행동 | 분리 이유 |
| --- | --- | --- | --- |
| `ScrimContext` | 내전 요약·팀 편성·대진 | 내전 이름·상태·예정 시각. 조회 전용 | 내전 식별과 정보 중복 방지 |
| `ScrimList` | 서버 홈·내전 목록 | 접근 허용된 요약 항목. 각 내전으로 이동 | 같은 내전 탐색 단위 재사용. 검색·페이지 조회는 부모 책임 |
| `MatchList` | 서버 홈·경기 목록 | 접근 허용된 시리즈·점수·상태. Match로 이동 | 같은 시리즈 탐색 단위 재사용 |
| `ParticipantIdentity` | 신청 명단·팀·결과·관리 명단 | 표시명·허용된 계정 표시·선택적 사용자 링크 | 과거 사용자 연결·공개 범위와 단일 프로필 링크 표현 |
| `TaskDialog` | 모집 생성·계정 연결·ROFL·서비스 입력 패널 | 제목·본문·요청 상태·닫기 가능 여부, 제출/닫기 의도 | STDF `Popup`에 서비스 공통 포커스·배경 차단·작업 중 닫기 규칙을 묶음 |
| `DocumentPage` | 이용 문서·약관·처리방침 | 확정된 제목·적용일·목차·본문 | 문서 읽기 폭과 제목 계층·본문 이동의 공유 |

`TaskDialog`는 업무 데이터나 API를 알지 않는다. 단순 확인은 STDF `Dialog`를 직접 사용하고 같은 포커스 규칙을 적용한다.
입력 부품·버튼·카드 전체를 `AppInput`·`AppButton`처럼 일괄 포장하지 않는다.
이름·책임만 단순한 지역 구획은 페이지 안에서 조립하고, 자체 상호작용 또는 실제 재사용이 있을 때 분리한다.

페이지 로딩 계층은 데이터·접근 가능 작업·공개 범위를 준비한다. 구성 컴포넌트는 전달받은 데이터와 상태를 표현하고
선택·저장·파일 제출 같은 의도를 부모에게 알린다. 컴포넌트가 특정 API 주소나 목 데이터 경로를 직접 조회하지 않는다.

## 6. 상태에 따른 배치 변화

| 상태 | 위치·구성 | 조작 규칙 |
| --- | --- | --- |
| 최초 로딩 | 실제 콘텐츠 자리에 `Skeleton`, 영역의 읽기 상태 설명 한 곳 | 빈 데이터 안내와 동시 표시하지 않음 |
| 조건 변경·부분 갱신 | 해당 목록/결과의 제목 근처 작은 `Loading` | 이전 결과를 새 조건 결과로 표시하지 않음. 이미 입력한 조건 유지 |
| 데이터 없음 | 기존 결과 자리의 짧은 문장 | 생성·검색이 이미 있으면 빈 상태에 같은 버튼 추가 금지 |
| 일부 실패 | 실패한 영역의 문장과 재시도 `Button` | 정상 콘텐츠 유지. 헤더·본문·토스트에 같은 오류 반복 금지 |
| 입력 오류 | 해당 입력의 오류와 첫 실패 입력으로 포커스 | 색상·별표만으로 처리하지 않음. 저장은 하나의 제출 경로 |
| 요청 처리 중 | 원래 제출 `Button`의 `Loading`과 필요한 단계명 | 중복 요청 차단. 진짜 전송량을 모르면 퍼센트를 표시하지 않음 |
| 성공 | 저장한 값·새 상태 반영, 작업 결과 위치 한 곳 | 완료 토스트·상단 안내·본문 메시지를 중복하지 않음 |
| 권한/상태에 따른 제한 | 할 수 있는 읽기는 유지. 차단된 현재 작업 위치에 이유 | 권한 없는 조작은 숨김. 준비 부족으로 잠시 불가한 행동만 이유와 함께 비활성 |
| 충돌·응답 불확실 | 원래 작업 영역에 저장 상태 확인 결과 | 입력 자동 덮어쓰기와 무조건 재전송 금지 |

STDF `Alert`는 떠 있는 알림이므로 지속 오류 영역에 사용하지 않는다.
결과가 화면에 남는 업무에는 전역 토스트를 기본으로 추가하지 않는다.
403·404·5xx는 공통 오류 본문을 사용하고 5xx만 재시도한다. 검증된 길드 문맥이 없으면 `GlobalHeader`로 안전하게 복귀한다.

## 7. 패널·입력·접근성

- 간단한 선택은 한 패널 안에서 끝낸다. 긴 폼은 상단 제목·본문 입력·하단 작업 순서이며, 넓은 화면에서 가운데, 좁은 화면에서 화면 폭을 쓰는 같은 `Popup`을 재배치한다.
- 패널은 화면 높이를 넘기지 않고 내부 본문이 스크롤된다. 가상 키보드와 안전 영역 때문에 제출·닫기가 가려지지 않아야 한다.
- 닫기 기능은 하나의 컨트롤만 둔다. 제목의 닫기와 하단 취소를 동시에 만들지 않는다. Escape·배경 클릭은 같은 닫기 정책을 따르며 입력을 잃을 때만 확인한다.
- 취소하면 원래 진입으로 포커스를 돌린다. 성공으로 진입 버튼이 없어지면 새 상태의 대응 조작으로, 페이지가 이동하면 목적지 제목으로 옮긴다. 사라진 요소에 복귀하려 하지 않는다.
- STDF `Popup`·`Dialog`가 포커스 제한·복귀·Escape·배경 비활성화·대화상자 이름을 모두 제공한다고 가정하지 않는다. 공통 상호작용 보완은 실제 입력 작업을 구현하기 전에 준비한다.
- 배경을 비활성화할 때 열린 패널 자신이나 그 조상을 함께 비활성화하지 않는다. 중첩 선택기가 필요하면 최상위 패널만 조작하고, 닫을 때 바로 아래 작업으로 복귀해야 한다.
- `Input`의 실제 제목·라벨 구조를 사용한다. Form의 필수 표시는 검증이 아니며 서버 결과·오류 연결·한글 조합 중 Enter 처리를 별도로 확인한다.
- 링크는 새 탭·복사·브라우저 앞뒤 이동이 가능한 링크로 유지한다. 선택 상태·버튼 이름·입력 라벨을 지원하지 않는 API를 문서에 있다고 가정하지 않는다.
- 모든 작업은 키보드로 완료할 수 있어야 한다. 드래그·스와이프·색·툴팁만으로 필수 정보나 조작을 전달하지 않는다.
- 동작 없는 프로필 사진을 버튼으로 만들지 않는다. 아이콘 전용 조작은 읽을 수 있는 이름을 제공하고 작은 터치 대상을 피한다.
- 기본 조작 높이는 약 44px를 목표로 한다. 큰 글자와 320px 폭에서도 행동이 잘리거나 겹치지 않아야 한다. 모션 감소 설정을 존중한다.
