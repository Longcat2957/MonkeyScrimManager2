# 시즌 칭호 15종: 확정 명세와 구현 계획

**상태: 명칭·지표 확정, 운영 미구현.** 시즌 칭호는 같은 서버·같은 시즌의 1위 기록이다. 영구 해금하는 배지가 아니며, 새 결과나 정정으로 보유자가 바뀐다. 아래 번호는 이 문서의 시즌 칭호 순서이며 한 세트·Bo3 단발 업적의 번호와 무관하다. 단발 업적, MVP/ACE, 종합 평점은 이번 구현 대상이 아니다.

### 공통 판정

- 기본은 활성 시즌, 과거 시즌 선택 시 그 시즌만 사용한다. 귀속은 내전의 `mmrSeasonId` 기준이다. 업로드 시각·경기일·현재 Riot 계정 연결·모집 명단으로 추정하지 않는다.
- 표본 기준은 해당 칭호에서 **분자와 분모를 모두 계산할 수 있는** 세트/시리즈 수다. 누락을 0으로 채우지 않고, 실제 기록된 0은 보존한다. 분모가 0이거나 시간이 없으면 해당 비율에서만 제외한다. 분당 값은 세트별 분당 값의 평균이 아니다.
- 팀 지분과 킬 관여율의 팀 합계는 해당 세트 같은 진영의 실제 5명에게 필요한 값이 모두 있을 때만 계산한다. `가성비 킹`은 다섯 포지션별 순위이며 한 선수가 여러 포지션에서 보유할 수 있다. 예: 피해 지분 30%, 골드 지분 20%면 그 세트는 +10%p다.
- 원래 값으로 비교하고 표시할 때만 반올림한다. 공동 1위는 모두 보유자이며 표본 수·이름·조회 순서로 승자를 가르지 않는다. `원챔`에서 한 선수의 최다승 챔피언이 여럿이어도 같은 칭호를 중복 부여하지 않는다. 자격자가 없으면 해당 칭호에는 보유자가 없다.
- 시즌·서버가 같으면 어느 화면에서도 보유자가 같다. 통계의 포지션·최소 게임·최근 10게임, 개인 전적의 포지션·쪽 번호는 시즌 칭호 계산을 바꾸지 않는다.

## 구현 계획

1. **기록 읽기: 기존 시즌 전적 조회에서 한 번만 준비한다.** [전적 조회](../apps/web/src/lib/server/records/queries.ts)의 `recordsInTransaction`은 서버·시즌을 제한하고 취소된 내전·경기를 제외한다. `completed` 세트에 채택된 ROFL과 일치하는 실제 출전자만 사용한다. 중도 종료 전에 정상 등록된 세트는 1~13번에 남긴다. 기존 조회에서 읽은 `stats`의 `wardsKilled`, `healOnTeammates`, `damageShieldedOnTeammates`와 양 팀별 피해·골드 합계를 서버 내부 집계에 연결한다. 받은 피해는 `damageTaken`, 포지션은 `gameParticipants.position`, 챔피언은 저장된 실제 픽을 사용한다. [ROFL V1 저장 계약](../apps/web/src/lib/server/rofl/import-model.ts)에 모두 있으므로 원본 재파싱·재업로드·마이그레이션은 필요 없다.
2. **시리즈는 세트와 따로 센다.** 조회가 이미 조인하는 `matches`에서 BO 형식·상태·고정 팀·승자를 가져온다. [경기 기록](../apps/web/src/lib/server/matches/queries.ts)의 정상 종료 판정(확정 승자와 유효 세트 점수 일치)을 재사용한다. 14·15번만 `bestOf = 3`으로 제한한다. `matchId`로 묶고 취소되지 않은 `gameNumber`로 순서와 1:1을 확인한다. 블루/레드가 아니라 서비스 팀으로 각 세트 승자를 맞춘다. 14번은 3세트 승리 실출전자에게, 15번은 실제 출전한 사용자마다 `(matchId, 사용자)`당 한 번만 승패를 반영한다. 부전승·몰수처럼 유효 ROFL 점수로 완결되지 않은 경기는 포함하지 않는다.
3. **집계·공동 순위: 임시 업적 계산기를 교체한다.** [현재 계산기](../apps/web/src/lib/features/players/achievements.ts)는 전체 4게임 컷, 요약값 정렬, `entries[0]` 단독 배지를 사용한다. 칭호의 고정 ID와 표시 문구를 분리하고, 서버에서 선수별 유효 표본·합계·챔피언별 승수·승리 포지션을 누적한다. 전체 `PlayerSummary` 하나로 포지션별 지분이나 시리즈 승률을 역산하지 않는다. 점수·표본 수/단위·공동 순위·필요한 경우 포지션/챔피언을 결과로 전달한다. 상위 목록을 자르기 **전에** 모든 보유자를 정한다. 공동 1위가 10명을 넘어도 홈·개인 배지에서 누락하지 않는다.
4. **세 화면을 같은 결과로 전환한다.** [통계 스냅샷](../apps/web/src/lib/server/stats/snapshot.ts)은 `scoped` 리더보드와 별도로 선택 시즌 전체를 집계한다. 최초 SSR과 기존 `stats/live`가 같은 결과를 반환하게 하고 응답 타입·클라이언트 검증기도 함께 바꾼다. [서버 홈](../apps/web/src/routes/g/%5BguildId%5D/+page.server.ts)의 `devGuild001` 전용 로더에는 선택 시즌을 연결한다. 다음 내전·현황에는 시즌 필터를 적용하지 않는다. [개인 전적](../apps/web/src/routes/g/%5BguildId%5D/players/%5BuserId%5D/+page.server.ts)은 동일한 보유자 목록에서 해당 선수 배지만 꺼낸다. 기존 백분위용 4게임 기준은 유지한다. 개발 샘플도 동일 계산기를 쓰고, 없는 필드를 만들어 수상자를 채우지 않는다.
5. **기존 카드·순위창·배지의 단독 1위 전제를 제거한다.** 카드와 순위창에는 공동 1위 여부·값·표본 단위(세트/시리즈)를 전달한다. `가성비 킹`은 포지션을 구분하고, 공통 ‘최소 4게임’ 안내와 최근 10게임 업적 필터는 제거한다. 통계 리더보드 필터는 유지한다. 빈 시즌/자격자 없음은 오류와 구분하고, 조회 실패를 샘플 데이터로 대체하지 않는다. 서버 내부에서만 실출전자별로 집계한 뒤 기존 `readPublicIdentities`와 공개 표시 이름·링크 정책을 적용한다. 비공개·탈퇴자의 Discord ID, 실명성 표시 이름, Riot ID가 공개 응답에 새지 않게 한다.
6. **조회 시 계산으로 시작한다.** 결과 등록·취소·재등록 시 별도 수상 테이블을 쓰지 않고 다음 조회에서 같은 유효 기록으로 다시 계산한다. 같은 요청에서 칭호마다 DB를 재조회하거나 화면별로 승자를 다시 고르지 않는다. 기존 업로드·정정 트랜잭션, MMR, 외부 API는 변경하지 않는다. 시즌 전체 조회 비용은 실제 규모에 가까운 시즌에서 30초 통계 갱신 기준으로 측정한 뒤 별도 최적화 여부를 판단한다.

## 검증과 운영 반영 순서

| 단계 | 통과 기준 |
| --- | --- |
| 순수 집계 | 15종 각각에 보유자와 비보유자가 갈리는 입력을 둔다. 9/10 유효 세트, 9승+1패와 10승, 횟수 0/1, Bo3 4/5경기를 구별한다. 시간 가중, 팀원 한 명의 누락, 실제 0, 포지션 교차, 동일 챔피언 반복 승리, 반올림 동점처럼 보이는 다른 값과 진짜 공동 1위를 검증한다. |
| DB 통합 | [통계 스냅샷 테스트](../apps/web/tests/api/hard/db/stats-snapshot.test.ts)에 서버·시즌 격리, 익명 공개값, 채택된 ROFL만 반영하는 사례를 추가한다. 2:0/2:1, 진영 변경, Bo5 3세트 제외, 취소 후 다른 결과 재등록, 미완결 시리즈에서 유효 세트만 남는 사례로 세트·시리즈 분모를 대조한다. |
| 화면·갱신 | 같은 시즌의 홈 카드·통계 순위창·개인 배지와 [통계 실시간 응답](../apps/web/tests/api/hard/http/stats-live.test.ts)의 보유자가 일치해야 한다. 시즌 변경은 반영하고 리더보드 필터는 무시한다. 긴 칭호명, 공동 보유자 11명 이상, 빈 시즌, 비공개 사용자, 모바일·키보드 조작을 확인한다. |
| 운영 공개 | 선택 시즌 샘플의 원시 합계와 수상자를 대조한 후 세 화면의 개발 전용 제한을 함께 교체한다. 다른 미확정 업적은 공개하지 않는다. 운영 반영 후 기존 기록에도 재업로드 없이 표시되고, 정정 뒤 다음 조회에 보유자가 바뀌는 것이 완료 조건이다. |
