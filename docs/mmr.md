# MMR 저장 계약

이번 단계는 [DB 스키마](../apps/web/src/lib/server/db/schema.ts)에 MMR 저장 구조를 추가한다.
계산 함수, 결과 등록과의 트랜잭션, 서비스 레이어·API, 마이그레이션 생성·적용은 아직 구현하지 않는다.
아래 계산·반영 절차는 후속 구현에서 지킬 계약이며 현재 실행되는 기능을 뜻하지 않는다.

## 계산 기준

- MMR의 단위는 **길드 + 시즌 + Discord 사용자 + 포지션**이다. 한 사용자가 연결한 여러 Riot 계정은 같은 사용자 MMR을 사용한다.
- 탑·정글·미드·바텀·서포터 값을 각각 관리한다. 초기값은 포지션마다 `1500`, Elo의 K 값은 `32`다.
- 같은 포지션의 상대를 기준으로 `예상 승률 = 1 / (1 + 10^((상대 MMR - 본인 MMR) / 400))`, `변동량 = 32 × (실제 승패 - 예상 승률)`을 적용한다. 실제 승패는 승리 `1`, 패배 `0`이며 양쪽 모두 해당 Game 반영 전 값을 사용한다.
- 일반·경매 내전 모두 **완료된 Game 한 판마다** 반영한다. Match나 Scrim의 종료를 기다리지 않으며, 중도 종료 전에 정상 기록한 Game도 대상이다.
- 계산값은 소수로 보존하고 임의 반올림하지 않는다. Riot 티어·외부 전적을 초기 MMR로 변환하지 않는다.
- 시즌이 바뀌면 새 시즌에서 시작한다. 이전 시즌의 값과 이력은 보존하며, 종료된 시즌의 기록을 새 시즌으로 옮겨 계산하지 않는다.

기본값·공식·반영 단위는 MSM1의 `apps/api/src/domain/elo.rs`와 일반·경매 Game 등록 구현에서 확인했다.
MSM1의 데이터 이관·관리 도구 전체를 계승하는 것은 아니다.

## 저장 구조

| 스키마 객체 | 책임 |
| --- | --- |
| `mmrSeasons` | 길드별 MMR 시즌과 시작·종료 시각 |
| `userPositionMmr` | 사용자·시즌·포지션별 현재값과 변경 순서 |
| `gameMmrApplications` | 한 Game에서 어떤 채택 ROFL 결과를 MMR에 반영했는지 식별하는 처리 단위 |
| `mmrLedgerEntries` | 변경 전·후 점수, 참가자와 반영 회차, 변경 순서와 역분개 근거 |

증감은 `afterMmr - beforeMmr`로 계산하며 별도 열에 중복 저장하지 않는다.
같은 반영 회차의 포지션별 원장으로 당시 상대의 MMR을 확인할 수 있다.
시즌·사용자·포지션은 점수 행의 식별 기준이므로 이력이 생긴 뒤 다른 대상으로 바꾸지 않는다.

현재 길드 멤버십과 Riot 계정 소유자는 과거 MMR의 소유 기준이 아니다.
길드 탈퇴·재가입이나 Riot 계정 연결 변경으로 이미 반영한 사용자와 상대를 다시 해석하지 않는다.
사용자 삭제 정책은 스키마의 참조 규칙을 따르며, 현재 멤버십을 삭제하는 동작에 원장이 연쇄 삭제되지 않도록 한다.

## 반영 대상과 보류

모집에서 최종 선정되어 실제 Game에 출전한 사용자만 반영한다. 대기·제외 인원은 참가 신청 기록이 있어도 MMR이 변하지 않는다.
반영 전에 양 팀의 사용자 연결, 진영, 다섯 포지션의 대응과 승패를 확인한다.
MMR을 계산하기 위해 ROFL에 없는 포지션을 추측하지 않는다. 사전에 확정한 팀 편성을 근거로 삼을 수 있는 경우에도
실제 출전과의 대응을 검증한 뒤 `gameParticipants.position`에 기록한 값을 사용한다.

사용자나 포지션을 확인하지 못한 정상 ROFL은 경기 결과를 먼저 보존하고 MMR 처리를 보류한다.
MMR 계산을 위해 정상 결과 등록을 막거나 대기 인원을 임의 출전자로 채우지 않는다.
보류·재처리와 실패 복구를 실행하는 서비스 로직은 후속 작업이다.

## 중복 반영과 정정

Game의 현재 채택본과 MMR에 사용한 ROFL 근거를 구분한다. 처리 단위와 사용자별 변경 순서를 이용해
동일 결과의 재요청이 중복으로 점수를 올리지 않게 하고, 현재값 갱신과 원장 기록을 원자적으로 처리해야 한다.
반영 당시의 근거는 이후 채택본이 바뀌어도 보존한다. `gameParticipants`를 재작성하는 작업이 MMR 이력을 지우면 안 된다.

게임 반영의 취소·정정은 원장을 삭제하거나 기존 값을 덮어쓰는 대신 원본 반영을 가리키는 역분개로 남긴다.
운영자의 수동 점수 조정은 별도 `adjustment` 행에 사유와 전후 점수를 남긴다.
Elo는 앞선 결과에 영향을 받으므로 과거 Game의 delta만 현재 점수에서 빼는 방식은 올바른 재계산이 아니다.
늦게 들어온 결과나 과거 결과 정정은 관련 후속 반영을 시간순으로 확인하고, 필요한 역순 취소·재계산·순차 재반영 절차를 거쳐야 한다.
경기 시각을 확정할 수 없을 때 업로드 순서를 실제 경기 순서라고 가정하지 않는다.
처리 순서를 확정하거나 안전하게 복구할 수 없다면 결과는 보존하고 MMR 처리를 보류한다.

이 절차의 구현과 동시성·중복 요청 검증은 서비스 레이어를 작성할 때 진행한다.
