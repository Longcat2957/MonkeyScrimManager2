# MMR 저장 계약

업무 규칙은 MSM1 커밋 `d60df685e48c180b236342eae81b389ae87e38bf`의
`services/series/mmr.py`, `repositories/series/mmr.py`, `services/auctions/games.py`를 준용한다.
[MMR 서비스](../apps/web/src/lib/server/mmr/)는 [DB 스키마](database-erd.md)의 점수·반영 회차·원장을 사용해 ROFL 결과를 반영하고, 마지막 세트 또는 진행 중 내전의 결과를 역분개한다.

## 계산 기준

- 단위는 **길드 + 내전에 고정된 시즌 + Discord 사용자 + 포지션**이다. 같은 사용자의 여러 Riot 계정은 같은 점수를 쓴다.
- 초기값은 포지션마다 **1500**, Elo의 K는 **32**다. 시즌·사용자가 확정된 조회에서 미반영 포지션도 초기값을 표시하며 조회 중 점수 행을 생성하지 않는다.
- 같은 포지션 상대에 대해 `expected = 1 / (1 + 10^((opponent - current) / 400))`, `delta = 32 × (won - expected)`를 적용한다. 승리는 1, 패배는 0이다.
- 양쪽 모두 해당 Game 반영 전 점수로 계산하며 소수 값을 보존한다. Riot 티어를 초기 MMR로 환산하지 않는다.
- 일반·경매 모두 **Game 한 판마다** 반영한다. 정상 기록 후 중도 종료해도 이미 반영한 Game을 취소하지 않는다.
- 활성 시즌에서만 모집을 생성하고 그 시즌을 고정한다. 봇의 초기화는 첫 시즌을 준비하거나 기존 활성 시즌을 재사용하며, 종료한 시즌을 임의로 재개하지 않는다.

## 시즌 전환

웹 서버 관리와 봇의 [시즌 명령](bot.md#시즌-조회와-전환)은 [공통 시즌 서비스](../apps/web/src/lib/server/guild/seasons.ts)를 사용한다. MSM1의 [시즌 전환](https://github.com/Longcat2957/MonkeyScrimManager/blob/d60df685e48c180b236342eae81b389ae87e38bf/apps/api-python/src/monkeybot_api/services/guilds/seasons.py)처럼 현재 시즌 종료와 새 시즌 생성을 같은 트랜잭션에서 처리한다.

- 현재 실효 관리자 권한을 검사하고, 새 이름은 trim 후 1~100자, `confirm=true`와 선택한 `expectedCurrentSeasonId`를 요구한다. 현재 시즌이 바뀌었으면 409이며 다른 시즌을 자동으로 선택해 재시도하지 않는다.
- 길드·현재 시즌 잠금으로 최초 준비와 전환을 직렬화한다. interaction receipt는 실행자·선택 시즌·새 이름·결과를 함께 보존하며 같은 요청의 재전송은 새 시즌을 중복 생성하지 않는다.
- 진행 중인 내전도 이미 고정된 시즌을 유지하고, 이후 정상 결과와 정정은 그 시즌의 MMR·원장을 사용한다. 전환 후 새 모집은 새 활성 시즌에 고정한다.
- 이전 MMR 행이나 원장을 새 시즌으로 복제·이동하지 않는다. 새 시즌의 미반영 포지션은 기존 1500 규칙을 적용하며 조회로 점수 행을 생성하지 않는다.
- 웹 개인 전적·통계·홈 순위에서 `?season=<UUID>`를 생략하면 활성 시즌을 조회한다. 명시한 시즌이 없거나 다른 서버 소속이면 404다. 시즌 변경은 `position`·`min`·`recent`·`q`를 보존하고 `page`·`offset`을 초기화한다. 홈의 모집·진행 내전·최근 경기와 편성의 고정 시즌은 바뀌지 않는다.

## 결과 입력과 운영 문맥

ROFL은 최종 결과 입력을 대체한다. Match·다음 Game 번호·확정 출전 라인업은 서비스의 문맥이다.
양 팀의 5명·5포지션과 사용자 유일성을 확정하고, ROFL 참가자·사용 계정·팀이 그 라인업과 대응하는지 검증한다.
MMR은 그렇게 보존된 `gameParticipants.position`을 사용한다. 희망 포지션을 실제 출전으로 자동 복사하지 않는다.

수동 편성은 이미 확정한 포지션을 경기 생성 시 복사하고, 경매는 경기 전체의 라인업을 한 번 확정한다.
진출한 팀의 확정 포지션도 다음 경기로 복사하며, 같은 경기의 다음 Game마다 라인업을 다시 확정하지 않는다.
[ROFL 자동 귀속 규칙](rofl-import.md#자동-귀속과-경기-운영)에 따라 실사용 계정을 출전자와 연결한다. 첫 결과에서 새로 확인한 서버별 연결도 결과와 함께 저장하며, 기존 소유자·대표 계정·과거 MMR 귀속은 덮어쓰지 않는다.

Game과 점수 처리 순서는 MSM1처럼 서비스의 등록 순서·Match revision으로 관리한다.
실제 경기 시각은 별도의 사실이므로 확인되지 않으면 null을 유지하고 업로드 시각으로 만들지 않는다.

## 저장 구조와 원자성

| 객체 | 책임 |
| --- | --- |
| `mmrSeasons` | 길드별 시즌과 시작·종료 |
| `userPositionMmr` | 사용자·시즌·포지션의 현재 점수와 revision |
| `gameMmrApplications` | Game의 특정 채택 ROFL을 반영한 회차·역분개 상태 |
| `mmrLedgerEntries` | 변경 전후 점수·참가자·반영 회차·역분개 근거 |

원장의 차이는 `afterMmr - beforeMmr`다. 점수 행의 시즌·사용자·포지션을 과거 이력이 생긴 뒤 다른 대상으로 바꾸지 않는다.
길드 탈퇴나 현재 계정 연결 변경으로 과거 점수의 사용자 귀속을 다시 해석하지 않는다.

정상 경로는 **ROFL 선별 자료·Game·실출전·MMR 원장·현재 점수·경기 종료·대진 진출·게시 예약을 한 트랜잭션에서 처리**한다.
내부 MMR 함수는 최상위 결과 서비스가 전달한 Transaction을 사용하며 독립 커밋하지 않는다.
결과 잠금은 시즌 → 내전 → 경기 → Game → 정렬한 점수 행 순서다. 업로드가 필요한 사용자·계정 키·서버 연결 잠금은 그보다 먼저 잡는다.
기존 계정의 식별 키는 `KEY SHARE`로 보호해 계정 관리의 표시 정보 수정과 충돌하지 않는다. Riot 호출·파일 파싱은 잠금 밖에서 끝낸다.
현재 채택본·완료 상태·10명/5포지션·기존 반영을 잠금 안에서 다시 검사한다. 동일 활성 반영의 재요청은 추가 원장을 만들지 않는다.

연결 실패나 DB 오류는 전체를 롤백한다. Game만 성공시키거나 결과 커밋 후 별도 MMR 처리를 기본 경로로 두지 않는다.

## 마지막 Game의 안전한 역분개

MSM1처럼 **마지막 확정 Game**만 정정 대상으로 한다. 다음 조건을 모두 확인한다.

1. 해당 Game의 유효 반영 회차와 10개 원장이 일치한다.
2. 각 현재 점수가 대상 반영의 after와 일치하고, 현재 revision·점수가 최신 원장과 연속되며 아직 유효한 후속 경기 반영·관리 보정이 없다. 이미 취소한 후속 정·역분개 쌍은 이력으로 보존하며 순서대로 이전 Game까지 되돌릴 수 있다.
3. 최상위 결과 서비스가 다음 경기의 관리자 수정·라인업 확정·결과 등 후속 작업을 검사한다. 자동 생성만 된 수동 다음 경기나 미확정 경매 초안은 안전하게 제거할 수 있다.
4. 원장을 삭제하지 않고 원본을 가리키는 `game_reversal`을 추가해 before 값으로 복원한다.
5. 반영 회차의 역분개 표시, 기존 Game의 `cancelled` 전환, 등록 이력의 취소 표시, 경기·대진 복원과 게시 예약은 같은 트랜잭션에서 완료한다. 같은 파일 또는 다른 결과의 파일은 같은 Game 번호의 별도 행으로 등록한다.

안전 조건이 맞지 않으면 409로 거절한다. 과거 delta만 현재 점수에서 빼거나 후속 전체를 자동 재계산하지 않는다.
이전 원장과 ROFL 근거는 보존한다. 광범위한 재계산·수동 점수 관리 API는 MSM1 준용의 기본 범위에 추가하지 않는다.

내전 중도 종료는 편성·대진 준비·진행 단계의 유효 Game과 MMR을 보존한다. 경기의 현재 점수 우세 팀은 종료 표시로만 사용하고 동점은 승자를 만들지 않으며 새 Game·MMR을 합성하지 않는다.

같은 ROFL로 마지막 세트의 진영 선택을 정정하거나 실수 취소를 복구하려면 동일 Match·세트·확정 라인업의 최신 revision으로 다시 제출한다. 원본 ROFL 선별 자료와 당시 사용 계정·출전자·포지션은 재사용하고 새 Game·반영 회차·원장을 생성한다. 기존 Game·등록 이력·정분개·역분개는 유지하며, 계정 API를 다시 조회해 과거 귀속을 바꾸지 않는다. 오래된 요청과 다른 슬롯 재사용, 다른 바이트의 동일 결과는 차단한다. 자세한 조건은 [ROFL 결과 정정](rofl-import.md#자동-귀속과-경기-운영)을 따른다.


## 진행 중 내전 전체 취소

MSM1 pin의 [경매 전체 취소](https://github.com/Longcat2957/MonkeyScrimManager/blob/d60df685e48c180b236342eae81b389ae87e38bf/apps/api-python/src/monkeybot_api/services/auctions/cancellation.py#L53)와 [마감된 모집 복구](https://github.com/Longcat2957/MonkeyScrimManager/blob/d60df685e48c180b236342eae81b389ae87e38bf/apps/api-python/src/monkeybot_api/services/auctions/recruitments.py#L349)를 통합 Scrim 모델에 대응했다. 기존 미시작 취소의 정확한 복구는 유지하며 새 전체 취소는 `in_progress`에만 적용한다. 완료·중도 종료 내전에는 확대하지 않는다.

- 고정 시즌 → 내전 → 후속 대진 Match → Game → 점수 순서로 잠근다. 후속 대진·같은 경기의 뒤 세트·같은 점수의 나중 반영부터 기존 `reverseGameMmr`를 **하나의 트랜잭션** 안에서 호출한다. 마지막 세트 취소 서비스를 반복 호출하지 않는다.
- 현재값·revision·원장·채택 ROFL 영수증·10명 실출전을 검증한다. 타 내전의 유효 후속 반영과 점수가 같은 관리 보정도 넘지 않는다. 최신 세트를 먼저 역분개했더라도 앞선 결과에서 실패하면 모든 변경을 롤백한다.
- `scrim_cancellations` 배치와 `Match.cancellationBatchId`에 이전 운영 문맥·대진·라인업·결과 수량을 남긴다. Game·출전·ROFL·원장·Match·라인업의 원본 행과 FK는 보존하며 현재 대진만 분리한다.
- 복구는 참가자를 유지한 `preparing`이다. 취소한 결과·MMR을 재적용하지 않는다. 수동 배정은 유지하고, 경매는 팀장·시작 포인트를 보존한 `setup`으로 돌아가 영입을 다시 진행한다. 근거 없는 과거 취소와 경매 취소 근거 불일치는 복구하지 않는다.
