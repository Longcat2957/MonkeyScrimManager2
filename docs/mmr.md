# MMR 저장 계약

업무 규칙은 MSM1 커밋 `d60df685e48c180b236342eae81b389ae87e38bf`의
`services/series/mmr.py`, `repositories/series/mmr.py`, `services/auctions/games.py`를 준용한다.
현재 [40개 테이블 스키마](database-erd.md)의 점수·반영 회차·원장을 사용한다. [내부 반영·역분개 서비스](../apps/web/src/lib/server/mmr/README.md)는 운영 ROFL 저장·마지막 결과 취소 흐름에 연결되어 있다.

## 계산 기준

- 단위는 **길드 + 내전에 고정된 시즌 + Discord 사용자 + 포지션**이다. 같은 사용자의 여러 Riot 계정은 같은 점수를 쓴다.
- 초기값은 포지션마다 **1500**, Elo의 K는 **32**다. 시즌·사용자가 확정된 조회에서 미반영 포지션도 초기값을 표시하며 조회 중 점수 행을 생성하지 않는다.
- 같은 포지션 상대에 대해 `expected = 1 / (1 + 10^((opponent - current) / 400))`, `delta = 32 × (won - expected)`를 적용한다. 승리는 1, 패배는 0이다.
- 양쪽 모두 해당 Game 반영 전 점수로 계산하며 소수 값을 보존한다. Riot 티어를 초기 MMR로 환산하지 않는다.
- 일반·경매 모두 **Game 한 판마다** 반영한다. 정상 기록 후 중도 종료해도 이미 반영한 Game을 취소하지 않는다.
- 활성 시즌에서만 모집을 생성하고 그 시즌을 고정한다. 봇의 초기화는 첫 시즌을 준비하거나 기존 활성 시즌을 재사용하며, 종료한 시즌을 임의로 재개하지 않는다.

현재 시즌 종료·다음 시즌 생성·전환을 수행하는 운영 서비스와 화면은 없다. 시즌 테이블과 첫 시즌 준비가 구현된 상태이며, 전적·순위의 과거 시즌 선택도 후속 범위다.

## 결과 입력과 운영 문맥

ROFL은 최종 결과 입력을 대체한다. Match·다음 Game 번호·확정 출전 라인업은 서비스의 문맥이다.
양 팀의 5명·5포지션과 사용자 유일성을 확정하고, ROFL 참가자·사용 계정·팀이 그 라인업과 대응하는지 검증한다.
MMR은 그렇게 보존된 `gameParticipants.position`을 사용한다. 희망 포지션을 실제 출전으로 자동 복사하지 않는다.

수동 편성은 이미 확정한 포지션을 경기 생성 시 복사하고, 경매는 경기 전체의 라인업을 한 번 확정한다.
진출한 팀의 확정 포지션도 다음 경기로 복사하며, 같은 경기의 다음 Game마다 라인업을 다시 확정하지 않는다.
실제 Riot 계정과 파일의 명시적 `TEAM_POSITION`을 대조해 출전자를 자동 연결한다. 미연결 부계정은 팀·포지션 근거가
충분할 때 당시 사용 계정으로만 기록하고 서버 계정 연결은 바꾸지 않는다. 포지션이 없는 기존 연결 계정은 검증된 사용자와 확정 포지션을 사용한다.

Game과 점수 처리 순서는 MSM1처럼 서비스의 등록 순서·Match revision으로 관리한다.
실제 경기 시각은 별도의 사실이므로 확인되지 않으면 null을 유지하고 업로드 시각으로 만들지 않는다.

## 저장 구조와 원자성

| 객체 | 책임 |
| --- | --- |
| `mmrSeasons` | 길드별 시즌과 시작·종료 |
| `userPositionMmr` | 사용자·시즌·포지션의 현재 점수와 revision |
| `gameMmrApplications` | Game의 특정 채택 ROFL을 반영한 회차·역분개 상태 |
| `mmrLedgerEntries` | 변경 전후 점수·참가자·반영 회차·역분개 근거 |

원장의 차이는 `afterMmr - beforeMmr`다. 점수 행의 시즌·사용자·포지션을 과거 이력이 생긴 뒤 다른 대상으로 바꾸지 않는다.
길드 탈퇴나 현재 계정 연결 변경으로 과거 점수의 사용자 귀속을 다시 해석하지 않는다.

정상 경로는 **ROFL 선별 자료·Game·실출전·MMR 원장·현재 점수·경기 종료·대진 진출·게시 예약을 한 트랜잭션에서 처리**한다.
내부 MMR 함수는 최상위 결과 서비스가 전달한 Transaction을 사용하며 독립 커밋하지 않는다.
결과 잠금은 시즌 → 내전 → 경기 → Game → 정렬한 점수 행 순서다. 업로드가 필요한 사용자·계정 키·서버 연결 잠금은 그보다 먼저 잡는다.
기존 계정의 식별 키는 `KEY SHARE`로 보호해 계정 관리의 표시 정보 수정과 충돌하지 않는다. Riot 호출·파일 파싱은 잠금 밖에서 끝낸다.
현재 채택본·완료 상태·10명/5포지션·기존 반영을 잠금 안에서 다시 검사한다. 동일 활성 반영의 재요청은 추가 원장을 만들지 않는다.

연결 실패나 DB 오류는 전체를 롤백한다. Game만 성공시키거나 결과 커밋 후 별도 MMR 처리를 기본 경로로 두지 않는다.

## 마지막 Game의 안전한 역분개

MSM1처럼 **마지막 확정 Game**만 정정 대상으로 한다. 다음 조건을 모두 확인한다.

1. 해당 Game의 유효 반영 회차와 10개 원장이 일치한다.
2. 각 현재 점수가 대상 반영의 after와 일치하고, 현재 revision·점수가 최신 원장과 연속되며 아직 유효한 후속 경기 반영·관리 보정이 없다. 이미 취소한 후속 정·역분개 쌍은 이력으로 보존하며 순서대로 이전 Game까지 되돌릴 수 있다.
3. 최상위 결과 서비스가 다음 경기의 관리자 수정·라인업 확정·결과 등 후속 작업을 검사한다. 자동 생성만 된 수동 다음 경기나 미확정 경매 초안은 안전하게 제거할 수 있다.
4. 원장을 삭제하지 않고 원본을 가리키는 `game_reversal`을 추가해 before 값으로 복원한다.
5. 반영 회차의 역분개 표시, 기존 Game의 `cancelled` 전환, 등록 이력의 취소 표시, 경기·대진 복원과 게시 예약은 같은 트랜잭션에서 완료한다. 같은 파일 또는 다른 결과의 파일은 같은 Game 번호의 별도 행으로 등록한다.

안전 조건이 맞지 않으면 409로 거절한다. 과거 delta만 현재 점수에서 빼거나 후속 전체를 자동 재계산하지 않는다.
이전 원장과 ROFL 근거는 보존한다. 광범위한 재계산·수동 점수 관리 API는 MSM1 준용의 기본 범위에 추가하지 않는다.

같은 ROFL로 진영 선택을 정정하거나 실수 취소를 복구하려면 동일 Match·세트·확정 라인업의 최신 revision으로 다시 제출한다. 원본 ROFL 선별 자료와 당시 사용 계정·출전자·포지션은 재사용하고 새 Game·반영 회차·원장을 생성한다. 기존 Game·등록 이력·정분개·역분개는 유지하며, 계정 API를 다시 조회해 과거 귀속을 바꾸지 않는다. 오래된 요청과 다른 슬롯 재사용, 다른 바이트의 동일 결과는 차단한다. 자세한 조건은 [ROFL 결과 정정](rofl-import.md#자동-귀속과-경기-운영)을 따른다.
