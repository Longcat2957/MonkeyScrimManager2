# Data4 디자인 적용 재점검

**핵심 개선은 실제 화면에 반영됐다. 서버 홈은 충분, 내전·경기 목록은 적절한 기존 구조 유지와 필요한 보완으로 충분, 통계는 부분이다.** 모든 화면을 같은 정도로 시각 재설계했다고 설명하면 과장이다. 통계의 모바일 이름 식별성은 실제로 남은 대가다.

대상은 푸시된 `897eddf`의 `/g/devGuild001`, `/scrims`, `/matches`, `/stats`다. 새 Playwright MCP 격리 탭에서1440×1000·390×844와 primary/dark16조건을 촬영하고 실제 이미지를 읽었다. 원래 primary BEFORE8장, 새 기본16장, 가로 스크롤2장을 비교했다. 헤더·본문·푸터를 함께 봤다. source·API 쓰기는 하지 않았다. 동작 통과는 보조 증거이며 디자인 판단의 충분조건으로 쓰지 않았다.

## Impeccable 목표별 판단

이 표는 명령 호출 횟수가 아닌 실제 결과를 평가한다. 호출하지 않은 기능까지 적용했다고 간주하지 않는다.

| 관점 | 달성 | 실제 근거 |
| --- | --- | --- |
| layout | 충분 / 통계는 부분 | 홈에서 운영 현황이 업적보다 먼저 읽힌다. 두 목록은 이미 적절한 순서를 유지했다. 통계는 모바일 비교 영역의 이름/수치 폭 배분에 보완 여지가 있다. |
| distill | 충분 | 복제·흐림 업적 장식과 KPI 레이블을 되풀이한 설명이 없어졌다. 내전 상태와 내 참가 상태는 서로 다른 판단 정보라 유지한 것이 적절하다. |
| typeset | 부분 | 제목·수치·보조 정보와 검색 레이블이 구분되고 어두운 테마도 읽힌다. 통계의72px 이름 텍스트 영역에서는 식별 문구가 말줄임된다. |
| quieter | 충분 | 홈의 운영 정보와 업적이 경쟁하던 순서가 바뀌고 캐러셀 glow/양옆 흐림을 정리했다. 통계의 여섯 색 KPI가 동등한 무게를 갖는 구조는 유지돼 완전히 조용한 데이터 화면은 아니다. 이는 기존 시각 의도를 유지한 선택으로 구분한다. |
| colorize | 충분 | 어두운 히어로의 참가 상태, 기본/다크 상태 문구, 보조 정보가 실제 이미지에서 읽히며 진영·승패·상태 의미가 보존된다. 이번 재점검에서 새 대비 수치나 개선율은 측정하지 않았다. |
| adapt | 부분 | 모든 일곱 지표가 모바일에서도 비교 가능하고 가로 스크롤 중 사용자 열이 남는다. 반면 같은 화면에서 사람 이름을 덜 읽게 된 대가는 남았다. |
| onboard | 부분 / 적용 증거 제한 | 내전 보기·모집 만들기·검색이라는 첫 행동은 명확하다. 현재 샘플은 이미 선발된 사용자 맥락이며, 이 화면만으로 새 방문자 온보딩이 새로 완성됐다고 결론 내릴 수 없다. |
| polish | 부분 | 버튼·필터·검색·표의 공통 표현과 테마는 일관된다. 통계 이름의 과한 말줄임과 서버 순위 하단의 부분 행 노출은 남은 마감 문제다. |

## 남은 질적 약점

### D-DATA-01 · P2 · 통계 모바일 이름 식별성

실제390px, 양 테마에서 세 이름을 확인했다. BEFORE PNG의 같은 행에서는 세 이름이 온전히 보인다. AFTER는 부모 사용자 열이 고정되고 이름 텍스트에72px만 남아 말줄임된다.

| 이름 | clientWidth / scrollWidth | 전체 접근성 이름 | 화면 안에서의 전체 이름 확인 |
| --- | --- | --- | --- |
| 원딜은억울해 | 72 / 77px | `link "원딜은억울해"` | span·상위 링크에 title이 없고 CSS 말줄임. 선수 페이지로 이동하면 확인 가능. |
| 와드박는기계 | 72 / 77px | `link "와드박는기계"` | 동일. |
| 서폿장인 몽키 | 72 / 81px | `link "서폿장인 몽키"` | 동일. |

문자열·접근성 이름·이동 목적지는 보존됐으므로 데이터 손실이나 작동 불가 결함은 아니다. 그러나 시각 사용자에게는 표 안에서 누구의 수치인지 인식하는 비용이 늘었다. 특히 비슷한 접두어 이름은 비교가 어려워질 수 있다.7개 정렬이 정상이라는 사실로 이 대가를 상쇄했다고 볼 수 없다.

후속 판단 기준: 고정 사용자 열·모든 지표를 유지하면서 보통 길이 이름을 한 번에 구분할 수 있게 할 것. 두 줄 이름 허용 등 제한된 배치를 검토할 수 있으나 이번 재점검에서는 구현하지 않았다. 이름을 더 줄이거나 중요한 수치를 숨기는 것을 자동 해법으로 제시하지 않는다.

### D-DATA-02 · P3 · 서버 순위 영역의 끝이 행 중간에서 끊김

새 기본 모바일·데스크톱 이미지에서6번째 행의 얼굴/일부 정보가 하단에서 잘린다. 실제 순위 영역은 높이416px이고 정글 순위 내용은797px이며6번째 행이 경계를 가로지른다. BEFORE에도 있던 표현이므로 새 회귀는 아니다. 아래 순위가 있다는 단서는 되지만 표 하단 마감이 깔끔하지 않고 내부 스크롤을 알아채야 한다. 기능을 막지는 않으며 bounded list 의도를 존중하되 향후 polish 대상으로 판단할 여지가 있다.

### 우선순위 판단을 유보한 항목 · 통계의 비교 시작점

개발 샘플 모바일에서는6개 KPI와 업적을 지나 리더보드 제목이 문서 y1016에 나온다. 서버 전체 수치를 훑기에는 시작점이 좋지만 사람을 비교하려는 사용자에게는 첫 비교 도달이 늦다. 다만 [제품 문서](../../../docs/web/pages/records.md)는 실제 서버에서 업적 영역을 숨긴다고 명시한다. 따라서 이 샘플 배치를 실제 서버의 작업 방해로 일반화하거나 근거 없이 모든 통계 화면의 순서를 다시 바꿔야 한다고 판단하지 않는다.

## 보조 동작 검증

새16조건은HTTP200, 페이지 가로 넘침0, pageerror0, 콘솔 오류0이었다.7개 지표를 양방향·양 테마·양 폭으로56회 정렬해 표시 수치 순서와 단일 aria-sort를 확인했다. 모바일 이름 고정·키보드 가로 스크롤, 포지션6필터·내전4필터, 경기 검색/빈 결과/지우기, 홈 최근 경기·정글 순위 전환과 캐러셀 다음/이전도 확인했다. 쓰기 요청은 없었다.

이 결과는 조작이 살아 있다는 보조 근거다. 디자인 충분 판정은 앞의 실제 전후 정보 위계·배치·읽기 품질에 근거했다. 메타데이터의 attrs-only 이름 휴리스틱이 최근10게임 Switch를 잡았지만 실제 wrapping label로 접근성 이름이 제공돼 결함으로 세지 않았다.

구조화된 결과·전체 이미지 해시·실제 읽기 목록은 [data.json](data/data.json)에 있다. 새로운 detector 실행, 앱 소스 수정, 제품 데이터 변경은 하지 않았다.
