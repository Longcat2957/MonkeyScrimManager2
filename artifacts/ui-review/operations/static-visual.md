# 기본 화면 전후 이미지와 경매 갱신 읽기 검토

2026-11-15. 루트가 Playwright MCP로 촬영한 기본 페이지의 수정 전 12장과 최종 수정 후 12장, 총 **24장 모두 `view_image`로 직접 읽었다.** 대상은 경매 준비·모집 중 요약·진행 중 요약의 3개 URL, 1440×1000·390×844, primary/dark다. PNG는 페이지 전체 캡처라 실제 이미지 높이는 뷰포트보다 길 수 있다. 각 파일의 실제 크기·SHA-256·URL·뷰포트·직접 읽기 여부는 [static-visual.json](static-visual.json)에 기록했다.

수정 전은 이번 루트 UI 변경 이전에 촬영했지만 동시에 백엔드 개발이 진행 중이었다. **`521e763`만 실행한 순수 기준 이미지라고 단정하지 않는다.** 최종 수정 후는 루트가 같은 URL·뷰포트·파일에서 새 context, 초기 테마 복원, 제목 표시·폰트 준비·600ms·2RAF 정착을 확인한 파일이다. 원본 촬영 목록 [before](before/captures.json)·[after](after/captures.json)는 수정하지 않았다. [동적 운영 상태 16장](lifecycle.md)의 증거와 중복하지 않는다.

공통 헤더·본문·푸터를 함께 읽었다. 모바일 헤더는 로고·서버 선택·로그인·메뉴를 좁은 폭에 배치하고 데스크톱 내비게이션을 동시에 펼쳐 두지 않는다. 페이지 아래의 서비스 표기·문서·약관·개인정보 링크가 남아 있다. 이 이미지 범위에서 새 레이아웃·위계·반응형 회귀는 확인하지 않았다.

새 취소 복구·중도 종료 메뉴와 갱신 실패/재시도는 기본 사진에서 열린 상태가 아니다. 해당 조작의 성공·권한·키보드·상태 처리를 정적 사진만으로 증명하지 않으며 [lifecycle](lifecycle.md)과 루트 경매 운영 브라우저 기록을 함께 사용한다. 후보 목록의 모든 항목 도달·실제 터치·스크린리더·색상 대비 수치·성능 수치는 이 정적 검토에서 새로 측정하지 않았다.

## 경매 자동 갱신 소스 검토

검토 대상은 [auction/+page.svelte](../../../apps/web/src/routes/g/[guildId]/scrims/[scrimId]/auction/+page.svelte), [live/+server.ts](../../../apps/web/src/routes/g/[guildId]/scrims/[scrimId]/auction/live/+server.ts), [auction-live.ts](../../../apps/web/src/lib/features/scrims/auction-live.ts)다. 보조 근거로 실제 공개 조회 함수·GET 권한 갱신 hook·기존 경매 브라우저 테스트와 설치된 SvelteKit의 `invalidateAll()` 구현을 확인했다. 제품 코드는 수정하지 않았다.

| 항목 | 확인한 구현 | 판단 |
| --- | --- | --- |
| 정리·요청 중복 | effect 정리에서 `stopped`, timer 해제, 진행 요청 abort, visibility/online/offline listener 제거. `request`가 있으면 추가 갱신을 시작하지 않음 | 페이지 이탈·문맥 재설정 뒤 같은 timer/listener가 계속 누적되는 명백한 경로는 확인하지 않음 |
| 늦은 응답 | 응답 뒤 stopped·AbortSignal·현재 pathname 확인. 내전 ID·auction 필드 확인. 단일 요청으로 응답 순서 역전 제한 | 이탈·중단한 조회가 현재 화면을 다시 덮는 명백한 경로는 확인하지 않음 |
| 권한·캐시 | live는 기존 guild/Scrim 공개 조회를 재사용하고 실제 GET hook의 권한 갱신을 거친다. `private, no-store`. 운영자는 자동 조회 대상에서 제외되며 편성 중 열람자만 갱신. 문맥 키는 revision만 제외하고 단계·설정·권한 변화는 상위 load 재조회 | 새 쓰기 권한을 공개 endpoint에 부여하거나 오래된 관리자 UI를 snapshot만으로 유지하는 경로는 확인하지 않음 |
| 실패·재개 | 마지막 snapshot을 먼저 비우지 않고 실패 안내를 표시. 15초 timeout과 5~30초 backoff, 수동 갱신·자동 갱신 토글. 숨김/offline에서 정지·abort하고 복귀 시 재조회 | 실패를 빈 경매나 목 값으로 대체하지 않음. 자동 갱신과 한 번 새로고침은 서로 다른 조작이며 각 작업판에서 snippet을 한 번 렌더링 |

이 읽기 검토에서 근거를 갖고 새 결함으로 확정한 항목은 **0개**다. 상위 문맥이 달라진 직후 `invalidateAll()` 자체의 라우터/로드 실패를 별도로 주입해 재현하지는 않았다. 그 경로의 동작까지 이번 정적 검토의 실행 검증으로 표시하지 않는다. 기존 브라우저 테스트의 실행 결과는 루트 최종 gate를 따른다.

Impeccable의 `audit`·`critique` 관점으로 기존 작업판의 상태·계층·중복 조작·좁은 화면을 재검토했다. 새 스타일·예외 무시·취향 변경은 적용하지 않았다. 최종 프로덕션 build와 전체 회귀 완료는 루트의 별도 기록을 따른다.
