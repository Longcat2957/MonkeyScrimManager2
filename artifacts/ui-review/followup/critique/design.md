## 디자인 특수성

**판단:** Monkeybot의 실제 운영 도구로 읽힌다. 챔피언 아트는 내전 문맥과 업적의 인물에, 포지션 아이콘은 편성 자리와 전적에 놓인다. MMR·신청/선발 정원·경기/세트·ROFL이라는 정보가 작업 구조를 결정한다. Slate 표면과 STDF 조작은 익숙하지만 내용만 바꿔 다른 업종에 그대로 쓸 수 있는 범용 대시보드는 아니다. 워드마크 외에는 읽는 글꼴을 유지하여 게임 분위기가 업무 조작을 침범하지 않는다.

## 잘 작동하는 점

1. **역할과 읽기 순서가 맞는다.** 운영자 요약은 운영→참가자→내 신청·편성 방식으로 이어진다. 수동은 도구 줄→미배정→팀 자리, 사용자 전적은 핵심 지표→MMR→챔피언·기록으로 이어져 화면의 큰 배치와 실제 읽기 순서가 일치한다.
2. **좁은 화면에서도 판단 정보를 보존한다.** 수동 선택 안내는 두 번째 팀까지 스크롤해도 헤더 아래에 남는다. 표는 수치를 삭제하지 않고 이름을 고정한 채 가로 이동한다. 전적은 6개 핵심 지표와 추가 9개를 구분하고, 레이더의 기존 상위%와 방향을 터치 환경에서도 읽을 수 있다.
3. **진입과 도움말이 구체적이다.** 홈은 헤더의 로그인 한 곳으로 시선을 보낸다. 문서는 참가·기록과 운영을 구분하며 ROFL의 실제 작업 순서와 예외의 다음 행동을 제공한다. 새로 온 사람에게 제품 내부 구조를 외우게 하지 않는다.

## 남은 우선 문제

**최종 동결 source와 재검증한 화면에서 남은 P0·P1·P2·P3 디자인 문제를 확인하지 못했다.** 이 결론은 아래에 적은 화면과 상태에 한정하며 미검증 항목을 통과로 바꾸지 않는다. 문제 개수를 채우기 위한 제안은 추가하지 않았다.

## 인지 부하

체크리스트상 단일 초점·그룹 구분·위계·단계별 결정·작업 문맥 유지·점진 공개는 양호하다. 엄격한 ‘한 묶음 4개 이하’ 기준에는 통계 6개 KPI가, ‘선택 4개 이하’ 기준에는 전체+5포지션과 16개 업적 선택이 걸린다. 따라서 형식상 **2/8 항목 주의, 중간 부하**다.

다만 포지션은 사용자가 이미 아는 게임 역할이고 업적 선택은 별도 팝업에 모여 있다. 매 단계 16개 중 하나를 외워야만 주요 과업을 수행하는 구조는 아니다. 수동의 10개 자리는 팀 2개와 포지션 5개로 묶인다. 숫자 기준만으로 항목을 숨기거나 새 분류를 만드는 것을 우선 수정으로 권하지 않는다.

## 정서 흐름

처음에는 로그인/공개 주소라는 시작점이 명확하고, 운영 중에는 인원·다음 단계·확정 불가 이유가 불확실성을 줄인다. 수동에서 사람을 고른 뒤 멀리 이동해도 선택 문맥이 남으며 취소할 수 있다. 전적과 업적에서는 챔피언 이미지와 실제 수치가 성취를 보여 주되 불필요한 축하 효과나 반복 안내가 앞서지 않는다. 실제 저장 성공/실패가 만드는 감정의 끝 구간은 이번에 실행하지 않았으므로 평가를 확장하지 않는다.

## 소소한 관찰

- 320px에서는 페이지 번호가 두 줄로 배치되고 일부 기록 부제가 줄임표로 끝난다. 버튼과 행은 조작 가능하고 상세 이동 경로가 있으므로 결함으로 세지 않았다.
- 극단적으로 긴 한영 혼합 이름은 통계 고정 이름 열의 행 높이를 늘린다. DOM에만 이름을 치환한 검증에서 전체 이름과 지표가 보존됐으며 페이지 가로 넘침은 없었다. 실제 저장 데이터는 바꾸지 않았다.
- 개발 홈의 과업별 샘플 링크와 보조 URL은 `dev` 분기에만 존재한다. 운영 홈의 정보량으로 계산하지 않았다.
- 챔피언 배경 아트는 새 조회마다 달라질 수 있으므로 아트의 픽셀 일치를 최종 판정 기준으로 삼지 않았다.

## 검증된 사실과 경계

**실제로 확인:** #rofl 앵커의 제목 포커스와 y=80px, FAQ/추가 지표의 aria-expanded와 보이는 패널, 12개 챔피언 펼침, 통계 키보드 가로 스크롤(scrollLeft=40), 시야 정렬, 순위 팝업 Escape 뒤 원래 버튼 복귀, 업적 ‘골드 왕’ 이동, 수동 선택 안내의 헤더 아래 유지와 Escape 취소. 최종 수동 320/640의 기본·교환 대상에서 희망 외 문구를 읽었고 기존 76px 행과 취소 후 해제 조작을 확인했다. 최종 레이더 1440/390/320 양테마는 기존 6개 상위%·방향 설명이 모두 보이고 차트·듀오·푸터와 겹치지 않았다.

**판단:** 위 사실과 현재 source에 근거한 디자인 특수성·위계·인지 부하·정서 적합성, 31/40 휴리스틱 점수와 잔여 우선 문제 없음.

**미검증:** 실제 인증 세션의 관리자/참가자/비소속자별 전체 상태, 저장·신청·배치·확정 등 서버 쓰기, 네트워크 실패/경합/재전송, 실기기 터치와 스크린리더 발화, 전 UI의 색상 대비/성능. 실제 보조기기나 모든 오류 상태가 통과했다고 주장하지 않는다. CLI detector는 독립 B의 범위로 남겼다.

신규 캡처는 모두 직접 이미지로 읽었다. 파일별 SHA256·크기·검토 여부는 `screenshots-a.json`, 로컬 상호작용 결과는 `browser-evidence-a.json`, 현재 관련 source의 지문은 `source-fingerprints-a.json`에 기록한다. 마지막 source 보완 뒤의 수동/전적은 `a-final-*`와 `a-final2-*`가 최종 근거이며 앞선 같은 화면 PNG는 해당 source를 대표하지 않는다.

## 마지막 추가 확인 — 참가자 선발 관리

`ParticipantBoard`의 관리 fieldset 안에서만 적용되는 20rem 미만 container 보완을 읽고, 신규 독립 탭에서 **320/390/640px × 라이트/다크**의 관리 열기→Enter로 행 선택→완료/보기 복귀를 확인했다. 이 추가 판정은 해당 관리 상태에 한정하며 앞선 A 판단을 다른 상태로 확대하지 않는다.
