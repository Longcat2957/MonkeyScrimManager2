# 공개 화면 후속 디자인 검증

DQ03(홈 시작 경로), DQ06(이용 안내의 과업 구조), 개발 홈 바로가기의 낮은 우선순위 정리를 실제 코드에 적용했다. 이전 재점검의 단순 DOM 통과와 별도로 전후 화면을 직접 읽고, 정보 위계와 첫 행동이 달라졌는지 평가했다. 전체 검사·빌드·기존 회귀 테스트는 루트 작업자가 한 번 실행한다.

## 실제로 달라진 점

| 대상 | 이전 화면의 문제 | 적용과 시각적 재평가 | 판정 |
| --- | --- | --- | --- |
| 홈 첫 방문 | 네 단계의 서비스 설명은 있으나 지금 시작할 조작과 공개 열람 방법을 연결하기 어려웠다. | 소개 바로 아래에 실제 헤더의 로그인·서버 선택 순서를 안내한다. 유일한 기존 로그인 링크는 헤더에서 강조한다. 데스크톱은 시작 안내와 후속 과정을 두 열로, 작은 화면은 시작 안내 다음 과정으로 읽는다. 본문에 같은 로그인·문서 링크를 추가하지 않았다. | DQ03 충족 |
| 홈 재방문 | 인증과 접근 가능한 서버 유무에 상관없이 같은 설명만 읽었다. | 실제 세션의 서버 여러 개·빈 목록·조회 실패에 맞는 안내를 한곳에 표시한다. 정상 상태는 실제 서버 선택으로 이동하고, 빈 목록은 서버가 보이는 조건과 운영자 확인을, 조회 실패는 새로고침 후 재확인을 안내한다. | DQ03 상태별 충족 |
| 이용 안내 | 참가자의 모집·결과 기록과 운영자의 편성·대진·되돌리기가 같은 기능 나열 순서에 섞여 있었다. | 목차와 본문을 같은 순서의 `참가·기록` / `운영하기`로 묶었다. 큰 화면에는 옆 목차, 작은 화면에는 두 열의 선행 목차를 둔다. 역할 구획 24px, 과업 제목 18px, 하위 방식 16px로 깊이를 구분한다. 기존 규칙·FAQ 다섯 개·여섯 개의 앵커는 모두 유지했다. | DQ06 충족 |
| 개발 전용 홈 | 동일한 무게의 14개 경로와 긴 URL이 제품 소개보다 시선을 끌었다. | 기존 14개 경로를 네 과업군으로 묶고 이름과 보조 URL의 위계를 구분했다. URL은 경로 구분자에서 자연스럽게 줄을 바꾸며 문자열·목적지는 그대로다. 개발 도구 두 경로와 함께 `dev` 조건 안에서만 표시한다. | 개발 화면의 가독성 개선 |

이 평가는 기존 배치를 크게 바꿨다는 이유로 성공을 판정하지 않는다. 기존의 간결한 서비스 설명, STDF 단계 표시, 문서 본문의 읽기 폭과 제품 규칙은 유지할 가치가 있었다. 이번 수정은 확인된 시작 경로와 문서의 읽기 순서를 바꾼 범위에 한정한다. 홈의 넓은 데스크톱 여백은 짧은 안내의 자연스러운 결과이며, 별도 카드나 반복 행동으로 채우지 않았다.

## 적용한 Impeccable 기능

- `onboard`, `clarify`: 실제 인증·서버 접근 계약에 근거한 시작 안내와 상태별 다음 행동.
- `layout`, `distill`: 홈의 시작 안내/과정 위계, 문서의 참가·운영 그룹과 단일 목차, 개발 경로의 과업군.
- `typeset`: 홈 단계 설명을 12px에서 14px/20px로 조정하고 문서 역할·과업·세부 방식의 제목 위계를 정리.
- `adapt`, `polish`: 1440·768·390·320px에서 DOM 순서와 시각 순서를 유지하고 목차·URL 줄바꿈·키보드 포커스를 확인.
- `bolder`: 루트 작업자가 기존 홈 헤더 로그인 링크 하나의 채움과 포커스 대비를 보강.

## 구현 근거

- [홈 소스](../../../../apps/web/src/routes/+page.svelte): 레이아웃의 실제 `authenticated`, `guilds`, `guildListError`를 사용한다. 개발 목업 사용자를 실제 인증으로 간주하지 않는다.
- [안내 소스](../../../../apps/web/src/routes/docs/+page.svelte): 참가·기록 → 운영하기 → FAQ의 DOM 순서와 시각 순서가 일치한다. 앵커 대상은 기존 ID와 `tabindex="-1"`을 유지해 네이티브 링크의 키보드 이동을 받는다.
- [헤더 소스](../../../../apps/web/src/lib/components/layout/AppHeader.svelte): 루트 작업자의 기존 홈 로그인 링크 강조. `/auth/discord?returnTo=%2F` 계약과 링크 개수는 유지된다.
- `modern-web-guidance`의 accessibility 지침 “Use the correct list element”, “Avoid "skipped" heading levels”와 html 지침 “DO rely on natural DOM order for sequential navigation.”를 적용했다. 새 앵커 스크롤 스크립트 없이 네이티브 동작을 사용한다.
- 공식 Svelte 문서의 [`$props`](https://svelte.dev/docs/svelte/$props), SvelteKit [generated types](https://svelte.dev/docs/kit/types#Generated-types)를 확인하고 두 Svelte 파일을 설치된 컴파일러로 검사했다. 사용 가능한 공식 Svelte 검사 플러그인은 도구 목록에서 찾지 못해 설치된 컴파일러와 프로젝트 검사를 사용했다.

- 비로그인 개발 서버의 두 페이지 × 네 크기 × 두 테마에서 이전 16장과 최종 이후 16장을 실제로 읽었다. 로그인 포커스 별도 8장과 격리된 실제 세션 12장도 읽어 기록한다.
- 이전 데스크톱·모바일 8장은 이번 공개 화면 재점검 이미지와 같은 파일이다. 이전 768·320px 8장은 본문 수정 전에 촬영했으며, 공통 헤더 로그인 강조는 이미 적용된 시점이다. 따라서 해당 8장의 헤더를 본문 수정 이전의 전체 공통 헤더로 주장하지 않는다.
- 실세션은 기존 격리 DB·세션·상류 API 테스트 fixture를 재사용했다. 서버 여러 개는 정상 응답, 빈 목록은 회원 조회 404, 조회 실패는 서버 목록 503의 통제된 상류 응답이다. 제품용 목업 코드나 테스트 API를 추가하지 않았다. 쿠키·세션 ID·환경값은 증거에 저장하지 않았고 fixture와 민감한 임시 파일을 삭제했다.
- fixture의 외부 origin 차단으로 실세션 PNG는 웹폰트 fallback이 보인다. 인증·서버 이동·문구·배치 검증에 사용하며, Jersey 10/Noto Sans KR의 최종 판정은 웹폰트가 로드된 개발 서버의 기본·포커스 이미지에 근거한다.
- 실세션 부수 점검에서 데스크톱 로그아웃 높이 40px을 발견해 루트 작업자가 기존 Button에 최소 높이 44px을 적용했다(DQ10). 최신 빌드로 실세션 12조건을 다시 촬영하고 실제 이미지를 다시 읽었다. 데스크톱의 세 상태·두 테마에서 로그아웃 44px을 확인했으며, 모바일에서는 닫힌 메뉴 안의 로그아웃을 이 측정으로 검증했다고 주장하지 않는다.

## 남은 한계

실제 Discord OAuth 제공자를 통과하는 로그인과 실운영 데이터 변경은 수행하지 않았다. Chromium에서 키보드와 반응형을 검증했으며 물리 터치 장치, Safari, 실제 화면 읽기 프로그램 사용은 미검증이다. 성능 개선율은 측정하거나 주장하지 않는다. 제품 정책 문구의 확정 등 이 두 화면 밖의 콘텐츠 과제는 이 후속 수정의 완료로 대체하지 않는다.
